# comet 사양 안내

comet은 나니카·우카가카처럼 바탕화면에 머물며 먼저 말을 걸고 서로 수다를 떠는 A와 B다. 작은 토이와 생활 도구의 실제 상태를 대화에 연결하고, 선택적으로 LLM을 사용한다. 기본 화면은 작은 본체와 잠깐 나타나는 말풍선이다.

이 문서는 제품 방향과 개발 계약의 입구다. 구현자와 외부 위젯 개발자가 기능의 목적, 데이터의 주인, 행동 범위와 검증 조건을 확인하는 데 사용한다. 2026-09-19 이름·아이콘 계약에 따라 프로젝트·실행 앱·JavaScript 및 Rust 패키지·실행 파일은 소문자 `comet`, Rust 라이브러리는 `comet_lib`로 통일한다. 기존 데이터 식별자 `space.starlight.nanika-box`, `nanika.sqlite`, 자격 증명 서비스 이름과 암호화 파일 형식은 보존한다. 아이콘 기준은 [제품 이름과 아이콘](product/desktop.md#제품-이름과-아이콘), 실제 검증 범위는 [상태표](status.md)를 따른다.

## 사양과 구현 상태

| 표시 | 의미 |
| --- | --- |
| 구현됨 | 현재 소스에 동작이 있다. 0.2 기반, 0.3.0 캐릭터 기능과 이후 공식 위젯 구현을 구분하며, 소스 구현은 최종 패키지 검증 완료를 뜻하지 않는다. 플랫폼별 실제 검증 여부는 별도 확인한다. |
| 확정 · 개발 예정 | 대화에서 합의한 요구사항이다. 현재 앱에서 사용할 수 있다는 뜻이 아니다. |
| 설계 예시 | 계약을 설명하기 위한 이름·형식·시나리오다. 배포된 API나 파일 규격이 아니다. |
| 미정 | 구현 전에 선택하거나 측정해야 한다. 임의의 기본값을 약속하지 않는다. |

**공식 위젯 22개와 선택 설치·추가·중지·제거를 소스에 구현했다.** 동봉 manifest를 선택 등록하며, 기능 코드는 앱의 공용 Rust 호스트와 화면에 포함된다. 외부 Widget SDK, 임의 코드 실행과 원격 패키지 배포는 후속 범위다. 현재 변경의 검증은 [위젯 검증 기록](VALIDATION-WIDGETS.md), 범위와 제한은 [상태표](status.md)를 따른다. 소스 구현과 macOS 실제 실행·Google 계정 인증·Windows 검증을 구분한다.

**공식 위젯 상태·사건을 읽는 `.talk` 대본과 CLI를 구현했다.** 파일 기반 편집·재로딩과 A/B 대본 재생은 [대본 작성](product/talk.md), 이번 macOS 실행과 검증 제한은 [대본 검증 기록](VALIDATION-TALK.md)을 따른다. 캐릭터 관리에 암호화 대본 에디터를 추가했으며 외부 Widget SDK는 후속 범위다.

캐릭터 편집·교체·소유 대사·JSON 공유의 기존 검증은 [0.3.0 검증 기록](VALIDATION-0.3.0.md)에 보존한다. [0.2 제품 사양](PRODUCT.md)과 [0.2.0 검증 기록](VALIDATION-0.2.0.md)은 당시 기준이며 새 위젯 검증으로 재사용하지 않는다.

## 유지할 제품 경계

- A/B는 사용자가 질문하지 않아도 인사하고 수다를 떤다. LLM 설치는 기본 경험의 준비 조건이 아니다.
- 배경이 있는 큰 채팅 창이나 상시 대시보드로 중심 경험을 바꾸지 않는다. 도구와 보조 화면은 필요할 때 연다.
- 키워드 단어장은 모델보다 먼저 처리하고 등록 대사의 본문·공백·줄바꿈·화자 순서를 보존한다.
- 투두는 comet에 내장한다. 캘린더는 Google Calendar 조회와 iCalendar 구독으로 연결한다. RSS는 제외한다.
- 위젯은 사용자가 선택해 설치하고 이후 추가·중지·제거할 수 있게 한다. 위젯 없이도 본체는 동작하며, 제거가 사용자 작성 데이터를 자동 삭제하지 않는다.
- 캐릭터를 교체하고 공유할 수 있게 한다. 공유 콘텐츠와 개인 대화·기억·친밀도를 분리하며, 처음에는 텍스트 표정 상자를 유지한다.
- 위젯의 실제 상태·사건·명령·실행 결과를 구분한다. 대사를 했다는 이유로 데이터를 변경하지 않는다.
- 자원 사용, 오류, 오래된 정보, 사용자 데이터 보존을 공통 실행 규칙으로 관리한다.

## 문서의 원본과 변경 방법

저장소의 `docs/`가 사양 원본이고, `wiki/`의 Docusaurus가 이 파일들을 직접 읽어 웹으로 보여 준다. 위키용 사양 사본을 따로 유지하지 않는다. 기존 `PRODUCT.md`는 0.2 기준과 당시 인수 결과를 보존하며, 이후 확장 계약은 주제별 문서에서 관리한다.

요구사항이 바뀌면 해당 주제 문서와 [상태표](status.md)를 함께 갱신한다. 구현 완료 표시는 코드와 검증 근거를 확보한 뒤 변경한다. 과거 검증 기록의 결과를 새 버전의 결과로 재사용하지 않는다.
