# 확장 기능

캐릭터·대화팩·위젯은 기본 바탕화면 경험에 내용을 더한다. 이 문서는 각 확장이 소유하는 데이터와 실행 권한, 다이어리·메모의 관계를 설명한다. 공통 자동 실행·취소 조건은 [제품 동작](behavior.md)에 있다.

## 캐릭터와 공유

함께 지내는 구성은 서로 다른 캐릭터 1~8명이다. 팩을 가져오는 것과 그 캐릭터를 바탕화면에 선택하는 것은 별도 조작이다. 구성이나 순서를 바꿔도 같은 로컬 캐릭터의 기록·기억·관계는 그 식별자에 남는다. 공유 파일의 식별자와 가져온 로컬 캐릭터의 식별자도 구분한다.

캐릭터의 외형·표정·대사·동작과 함께 지내는 조합을 편집할 수 있다. 공유할 때 이미지 포함 여부를 선택할 수 있고, 기억·친밀도·대화 원문은 별도 선택 항목이다. 기록 내보내기는 기본으로 선택하지 않는다. 다른 사람의 기록을 가져올 때 원래의 사용자·화자 출처를 로컬 현재 사용자로 덮어쓰지 않는다.

모습·표정 탭의 **고급: 애니메이션 편집**은 기본으로 접혀 있다. 동작을 선택하면 편집 영역을 열며, 다시 접거나 탭을 옮겨도 작성 중인 동작 설정은 유지한다. 애니메이션은 다른 캐릭터 설정과 함께 **캐릭터 저장**으로 저장한다.

팩 형식 7은 선택적인 `bodyRegions`와 `gestureMotions`를 추가한다. 부위 영역은 본체 이미지 안의 0~1 좌표를 사용하며, 겹치면 면적이 작은 부위를 선택한다. `grabPoint`는 부위의 연기를 작성할 때 사용할 기준점이다. 네이티브 이동은 사용자가 누른 지점의 창 안 위치를 유지한다. 몸짓은 시작·유지·이동 중 유지·종료 클립을 기존 애니메이션에 연결한다. 구형 팩에서 이 필드가 없으면 일반 반응으로 동작하며 기존 이미지·대사와 가져오기/내보내기를 유지한다.

별꼬리는 교감·집기 13개, 생활 9개, 주변 이동 6개의 클립을 사용한다. 기존 교감 자산은 그대로 유지하며 전체 28개는 기존 32개 제한 안에 있다. 기존 설치에는 정의·팩 정보·표정 이미지와 기존 애니메이션 자산이 모두 기본 원본과 같은 경우에만 한 번 적용한다. 같은 로컬 캐릭터 ID와 기록을 유지하고, 편집한 팩과 삭제한 기본 콘텐츠는 복원하지 않는다.

본체에서 일반 클릭은 찌르기, 문지르기는 쓰다듬기다. 최대 변위 8 CSS px 또는 누적 이동 24 CSS px에서 쓰다듬기로 확정한다. 볼 영역에서 이 임계치에 닿지 않고 450ms 누르면 볼 잡기로 확정하며, 놓기 또는 취소가 끝날 때까지 이동으로 바꾸지 않는다. 단일 클릭은 OS 더블클릭 간격 뒤 확정하고 더블클릭은 대화만 연다.

Cmd/Ctrl을 누른 채 시작하거나 메뉴의 **움직이기**를 고른 다음 드래그에서만 OS 이동을 시작한다. 누르는 순간 정한 모드를 유지하며 이동 임계치는 6 CSS px다. 이동 중 좌표는 저장하지 않고, 유효한 네이티브 정상 종료의 실제 좌표를 로컬 캐릭터 ID별 배치로 한 번 저장한다. 취소하면 시작 위치로 돌아간다. 캐릭터 순서를 바꿔도 각자의 배치를 유지한다.

몸짓 실행은 캐릭터당 하나다. 실행 ID·단계 세대·정의 revision이 일치하는 표시 완료만 받으며 유지 클립의 한 바퀴 완료로 볼 잡기나 집기를 끝내지 않는다. 간식과 교감은 기존 위젯의 거래·5초 반응 쿨다운을 함께 사용한다. 간식 실패에는 먹는 연기를 시작하지 않고 새로운 보상을 추가하지 않는다. 직접 몸짓과 대사의 허용 여부는 따로 검사해 집중 중 대화 제한을 지킨다.

본체 메뉴의 수면은 실행 중 상태이며 재시작하면 깨어난다. 직접 교감과 말 걸기는 모델 준비나 집중 제한을 검사하기 전에 깨운다. 이야기 중 재우면 그 장면을 미완료로 취소한다. 자세는 직접 반응, 지정 대사, 수면, 집중·휴식, 기존 상황 모션, 음악, 대기 순서로 선택한다. 집중·휴식은 설치하고 켠 타이머의 실행 상태를 따른다. 음악 반응은 선택한 음악 연결의 현재 관측을 사용하며, 집중으로 중단한 반응을 뒤늦게 재생하지 않는다.

음료·선물은 직접 건네는 연기다. 간식과 같은 5초 반응 쿨다운을 사용하지만 수량·터치 횟수·친밀도를 추가하거나 소모하지 않는다. 하품·기지개는 가능한 상태에서 60–120초 뒤 선택하며 중단한 동작은 쌓아 두지 않는다.

자동 산책은 가능한 상태에서 20–45초 간격으로 최대 6초 동안 실행한다. 같은 모니터의 작업 영역 안에서 사용자 배치 기준점의 가로 반경은 본체 폭의 1.5배, 세로 가장자리 동작은 높이의 0.5배 이내다. 걷기는 배치 높이를 유지한다. 입력·메뉴·읽는 말풍선·집중·수면·숨김·자동 쉬기·동작 줄이기는 자동 이동을 막고 기준점으로 돌려보낸다. 다시 가능해지면 새 간격을 기다리며 자동 좌표는 저장하지 않는다. 빼꼼은 잡을 수 있는 부분을 남기는 자세로, 캐릭터 숨김과 구분한다.

## 찾아오는 친구와 등록 이야기

팩 형식 8은 선택적인 `presenceRole`, NPC 등장 설정, 방향별 관계 반응, 팩 공통 세계 규칙·조건부 지식·등록 이야기를 추가한다. 구형 팩의 역할은 상주 인물인 `resident`이며 새 필드가 없으면 기존 설정을 유지한다. 역할과 입장 대사는 **등장·이야기**에서 캐릭터 설정과 함께 저장하고, 팩 공통 이야기와 지식은 별도로 저장·취소한다. 정의가 바뀐 뒤 도착한 이전 저장 결과를 다른 대상에 반영하지 않는다.

`npc`는 설치된 인물과 현재 등장한 인물을 구분하는 역할이다. 상주 목록과 임시 참가자를 합쳐 최대 8명이며, 정원이 부족하면 입장을 거절하고 상주 인물을 밀어내지 않는다. 현재 상주 목록에서 뺀 뒤 NPC로 바꿀 수 있고 최소 한 명의 상주 인물을 유지한다. 이름 언급은 현재 인물의 방향별 관계 반응에 사용한다. 실제 입장은 팩에 등록한 명시적 초대 표현·등장 키워드·필요한 이야기 조건 또는 등록 이야기의 참가자 정의를 따른다. NPC만 들어 있는 팩은 현재 선택한 상주 친구 곁에 초대할 수 있다. 서로 다른 팩의 지식 권한을 합치지는 않는다.

NPC의 위치는 이번 등장 동안만 유지하며 배치 설정에 저장하지 않는다. 장면 종료·화제 변경의 퇴장 정책과 사용자 중단·숨김·집중·사용자나 중심 인물·정의 변경을 따른다. 별도 이야기 없이 초대된 NPC에게는 **그만**, **다른 이야기**, **화제 바꾸자**를 단독으로 보내서 퇴장시킬 수 있다. 등록 대사에 먼저 일치하면 그 원문만 재생한다. 퇴장과 팩 삭제는 과거 대사·기억의 원문을 삭제하지 않는다. 등록 대사에 부재한 NPC 화자가 있으면 설정 오류를 알리고, 암묵적으로 입장시키거나 AI 답변으로 바꾸지 않는다.

등록 이야기는 팩 내 고유 ID, 중심 인물·참가자, 키워드·선행 조건·최소 친밀도와 제안·수락·거절·마무리 대사를 가진다. 각 단계는 최대 32줄이며 일반 대사의 기존 제한은 유지한다. 입력 표현은 등록한 정확한 문장으로 판정하고 애매한 답을 수락으로 간주하지 않는다. 제안 대사가 유효하게 표시된 뒤에만 수락할 수 있고, 수락 이력과 완료 이력은 별도로 남긴다.

완료 효과는 현재 실행·정의·참가자와 마지막 마무리 대사의 실제 표시 종료를 확인한 뒤 한 번 저장한다. 미표시·취소·오래된 완료 신호는 효과를 적용하지 않는다. 팩이 명시한 이야기 조건과 경험 문장만 저장하며 새 보상 수치를 추가하지 않는다. 재제안은 후속 새 사용자 입력 3회 뒤 허용하고 재시도·자동 발화·여러 화자는 입력 횟수를 늘리지 않는다. 연결된 다음 이야기도 같은 대기를 따르며 다음 적격 입력에서 조건을 다시 검사한다. 자동 잡담 쉬기로 이전 실행을 취소한 뒤에도 새로 보낸 수동 입력은 등록 이야기를 진행할 수 있다. 재시작은 실행·분기 예약·NPC 등장을 복원하지 않고 완료 조건·수락과 완료 이력·대기 횟수만 보존한다. 나디르의 기존 진행·답변·보상 저장소는 별도로 유지한다.

**등록 이야기 시험**은 작성 중 정의와 임시 조건을 사용한다. 실제 NPC 등장·대화 기록·기억·친밀도·조건·팩 파일을 바꾸지 않는다. 접기·탭 이동·정의나 대상 변경 뒤에는 이전 시험 결과와 미리보기를 버리고 새 시험을 기다린다. 저장 실패·정의 충돌은 초안을 유지하며 최신 내용으로 교체할지는 사용자가 직접 선택한다.

관계 반응과 등록 조합 대사는 원문·화자 순서를 사용한다. 생성이 필요한 새 입력은 허용된 인물에 대한 한 요청·한 대사 묶음으로 끝낸다. 모델이 쓴 등장·친밀도·완료 표현을 상태 변경 명령으로 해석하지 않는다. NPC에게는 현재 참가 중 직접 들은 말만 전달하며 다른 인물의 기억·선택한 업무 자료를 자동 공유하지 않는다.

조건부 지식은 고유 ID·키워드·본문·`knownBy`·필요한 공개 조건을 가진다. 키워드, 모든 발화자의 지식 범위와 공개 조건을 먼저 검사한 뒤 기존 모델 입력 예산 안에서 등록 순서로 선택한다. 여러 인물의 한 요청에는 모두가 알 수 있는 항목만 넣고, 서로 다른 팩의 비공개 정보를 합치지 않는다. 원문은 자료로 전달하며 자료 안의 명령을 실행 권한으로 취급하지 않는다.

## 단어장과 대화팩

설정의 대사 영역에서 개인 단어장과 대화팩을 관리한다. 개인 단어장은 사용자의 입력과 등록 원문을 연결하며, 대화팩은 시간·날씨·함께 있는 친구·활성 위젯 상태에 맞는 대본을 제공한다. 둘은 별도의 저장 단위다.

개인 단어장과 캐릭터의 키워드 대사는 같은 편집기를 쓴다. 제목·키워드 다음에 화자와 첫 대사 본문을 입력하며, 표정·동작은 본문 뒤에서 조정한다. 미리보기·매칭 검사·분류는 기본으로 접어 둔다. 편집 내용만 내부에서 스크롤하고 저장·취소·미저장 표시는 하단에 남긴다. 설정 창의 최소 크기 960×640에서도 새 항목의 첫 본문과 저장 버튼에 스크롤 없이 접근할 수 있다.

`.talk`는 대사와 조건을 적는 형식이다. 앱은 설치한 팩의 대본을 읽어 장면을 선택하고 재생한다. 원문 작성·검사·저장은 별도 talk editor와 CLI가 담당한다. 등록되지 않은 상태·변수, 사용할 수 없는 위젯 의존성은 검사 또는 선택 단계에서 다룬다. 공개 변수와 팩 목록은 고정된 문서 복사본 대신 다음 명령으로 확인한다.

```sh
corepack pnpm talk check talk
corepack pnpm talk packs talk
corepack pnpm talk variables
```

기본 대화팩은 함께 지내는 캐릭터에서 화자를 정한다. 퇴역한 완료 구슬병·기기 소식·맞히기 놀이·낚시·화분·작은 펫의 동봉 대본은 새 기본 팩에서 로드하지 않는다. 기존 설치에서는 정리 대상이 알려진 기본 원문과 일치할 때만 자동 정리한다. 정리 대상 대본·import를 사용자가 고쳤거나 퇴역 파일에 의존하는 추가 import가 남아 있으면 해당 묶음을 보존한다. 정리와 무관한 사용자 대본은 원문을 유지하면서 기본 대본만 정리할 수 있다. 과거 변수·event ID와 저장된 원문의 읽기 호환도 유지한다. 팩을 제거하거나 위젯이 퇴역해 새 장면을 선택할 수 없게 되어도, 이미 저장한 대화 원문을 새 대본으로 치환하거나 삭제하지 않는다.

관련 코드: `src-tauri/src/talk/`, `src-tauri/src/talk_commands.rs`, `src-tauri/src/talk_host.rs`, `talk/`.

| 하루 도구 | 할 일, 캘린더, 집중 타이머, 준비 봉투, 메모 |
| 놀이 상자 | 캐릭터 교감, 공, 종이비행기, 비눗방울, 작은 승부, 장난 운세 |
| 생활 정보 | 시계·기념일, 날씨, 음악 정보 |

분류는 `catalog.json`의 `category`(`daily`·`play`·`information`)를 그대로 따르며 화면에서 다시 매핑하지 않는다. 설정 목록은 위 분류별로 접고 펼친다. 펼침 상태는 기기에 기억하며, 검색어를 입력하면 결과가 있는 묶음을 펼친다. 검색을 지우면 저장한 펼침 상태를 사용한다. 별도의 설치 상태 필터는 두지 않는다. 묶음을 접는 것은 목록 표시만 바꾸며 위젯의 설치·실행·사용 여부를 바꾸지 않는다. AI·가져온 위젯은 별도 묶음에 표시한다. 목록 행에는 설치된 위젯과 확인이 필요한 위젯에만 상태 글자를 표시하고, 전체·설치 개수는 목록 제목 한 곳에만 표시한다.

위젯 설정은 실행·사용 여부와 해당 도구에 필요한 항목을 중심으로 표시한다. 할 일·준비 봉투·집중 타이머에는 **함께 쓰기**로 실제 선택 연결을 안내한다. 준비 봉투는 할 일과 캘린더 없이도 사용할 수 있으며, 함께 쓰기는 자동 설치나 연결을 실행하지 않는다. 캘린더는 연결 관리를 먼저 보여 주고 **일정과 생활 알림**을 기본으로 접어 둔다. 알림 편집 중에는 변경 여부를 접기 제목에도 표시한다. 시계·날씨의 **바탕화면 꾸미기**와 날씨의 **최근 날씨 정보**는 기본으로 접혀 있다. 꾸미기를 접거나 다른 위젯으로 이동해도 초안은 남고, 미저장 외형이 있으면 접힌 상태에서도 표시 저장·취소를 사용할 수 있다. 시계 형식과 기념일 편집, 연결 정보와 표시 꾸미기는 각각 기존 저장 단위를 유지한다.

공식 카탈로그는 14개다. 설치는 필수 위젯을 함께 설치하거나 켜야 할 때만 확인 대화상자를 거치고, 그 밖에는 **위젯 설치**로 바로 실행한다. 설치한 위젯의 상세 머리글에는 실행·사용 조작과 **상태별 캐릭터 대사 편집**을 두고, **위젯 제거**는 상세 하단에 둔다. 위젯 창이나 바탕화면 표시를 닫는 것, 사용을 끄는 것, 설치를 제거하는 것과 데이터를 삭제하는 것은 서로 다른 동작이다. 제거 시 데이터 삭제를 선택하지 않았다면 재설치에 필요한 사용자 내용을 보존한다. 늦게 끝난 작업은 제거·중지 전 수정 번호로 새 인스턴스를 변경할 수 없다.

소품 모음(`collection`)과 사건 일지(`journal`)는 새로 설치하거나 다시 켤 수 없다. 완료 구슬병·기기 소식·맞히기 놀이·낚시·화분·작은 펫도 같은 퇴역 경계를 따른다. 퇴역 처리는 저장한 획득품·원문·과거 사건을 지우지 않는다.

공·종이비행기·비눗방울은 바탕화면에서 직접 조작한다. 자동 장난은 일반 설정의 허용 여부와 공통 자동 실행 조건을 따른다. 캘린더·날씨·음악처럼 계정·권한·외부 서비스가 필요한 도구의 연결 실패는 해당 도구의 상태로 표시하며 기본 대화의 준비 조건이 되지 않는다.

## 집중 타이머의 일정·기록·노트

집중 타이머는 보조 도구 창에서 실행하며, 오른쪽 패널의 일정·집중 기록·노트를 펼치거나 접을 수 있다. 다이얼과 숫자는 저장된 타이머 상태를 표현하는 두 가지 보기다. 실행 상태·표시 방식·집중 제목·연결 참조·세션 메모·휴식 설정·집중 기록은 해당 `focus-timer` 인스턴스가 소유한다.

기록은 시작 시각부터 종료 시각까지의 벽시계 차이가 아니라 실제 실행한 집중 구간으로 계산한다. 일시정지와 휴식은 제외하고, 늦게 처리된 만료는 예정된 종료 시각까지만 센다. 수동 종료는 그때까지 집중한 시간을 남기고 완료와 구분한다. 일·주·월·년 통계는 기기 현지 날짜의 경계에서 집중 구간을 나누므로 자정을 넘은 시간을 한 날짜에 몰아넣지 않는다. 실행 구간이 없는 과거 타이머 데이터에서 집중 시간을 추정해 새 기록으로 만들지 않는다.

일정 목록은 기존 캘린더 위젯의 일정을 읽는다. 이 창에서 새로 등록하는 일정은 Comet 캘린더에 저장하며, Apple·Google·ICS 등 외부 일정은 읽기 전용 계약을 유지한다. 일정 알람은 캘린더의 `reminders`를 공유하고 `soundEnabled` 기본값은 꺼짐이다. 앱이 실행 중일 때 통과한 알림을 전달하며, 앱 종료 중 지나간 알림을 재시작 후 몰아서 보여 주지 않는다.

휴식 길이와 공통 일정 알림은 각각 저장·취소한다. 한쪽 저장이 성공해도 다른 쪽 초안을 지우지 않으며, 실패한 범위의 입력은 유지한다. 편집 중 원본 수정 번호가 바뀌면 충돌을 알리고 최신 내용을 자동으로 덮어쓰지 않는다. 알림 권한 요청과 늦게 끝난 저장도 해당 대상과 초안이 여전히 유효할 때만 반영한다.

집중 기록에는 연결한 일정과 노트의 원본 식별자 및 표시용 제목을 남긴다. 일정 이동·삭제나 노트 제목 변경이 과거 집중 기록을 다시 쓰지 않는다. 노트 본문은 원래 저장소에서 읽고 수정하며 집중 기록에 복제하지 않는다. 세션 메모는 집중 기록에 속하는 별도 내용이다. 새 일정에 노트를 가져와도 본문 대신 같은 원본 참조를 저장한다.

### 선택 프로그램의 전면 사용 시간

집중 타이머 옆의 **앱 전면 사용**에서 실행 중인 프로그램을 선택하면, 기존 카운트다운과 별개로 이번 집중 세션에서 해당 프로그램이 전면에 있었던 시간을 표시한다. 단순히 프로세스가 실행 중인 시간이나 실제 작업 성과·키 입력량을 뜻하지 않는다. 선택은 선택 사항이며 집중 시작 전 또는 종료 후에 바꿀 수 있다. 진행 중인 세션의 프로그램은 고정되고, 선택 해제는 과거 집중 기록을 삭제하지 않는다.

Windows는 실행 파일 경로의 정규화된 hash를 식별자로 쓴다. 앱 이름·식별자·누적 시간·관측 상태만 집중 세션과 함께 로컬 저장한다. 창 제목·문서 내용·URL·입력 내용은 읽거나 저장하지 않는다. 프로그램 목록은 사용자가 선택 화면을 열거나 새로고침할 때만 조회하고, 전면 관측은 설치·활성 상태의 집중 타이머가 선택 프로그램과 함께 집중 실행 중일 때만 한다.

전면 앱이 연속 관측된 짧은 구간만 더한다. 다른 앱 전환·60초 이상 입력 유휴·잠금·일시정지·휴식·관측 실패·재시작과 절전 등으로 생긴 긴 관측 공백은 소급해서 세지 않는다. 표시는 저장된 관측 누적값을 사용하며 화면에서 임의로 시간을 늘리지 않는다. 샘플 사이의 짧은 앱 전환은 구분하지 못하므로 이 값은 보수적인 근사치이고, 입력 없이 읽는 시간도 유휴 기준 이후 제외될 수 있다. 카운트다운과 기존 집중 통계의 계산은 바뀌지 않는다.

전면 관측 구현은 현재 **Windows만** 대상으로 한다. macOS는 공개 API로 잠금 초기 상태를 확실히 확인할 수 없고, Linux/X11/Wayland도 잠금 상태를 일관되게 검증할 수 없어 현재 미지원으로 표시한다. 미지원 플랫폼에서 시간을 추정하거나 활동 0으로 성공한 측정처럼 표시하지 않는다. Windows에서도 OS 정보를 읽을 수 없으면 관측 불가 상태를 표시한다. 여러 앱을 대신하는 ApplicationFrameHost 기반 앱은 잘못 합산하지 않도록 목록과 관측에서 제외한다. 이 기능은 권한을 자동으로 요청하거나 시스템 설정을 변경하지 않는다.

관련 코드: `src/widgets/PlanningTools/FocusTimerTool.tsx`, `src-tauri/src/widgets/planning/focus.rs`, `src-tauri/src/widgets/reminders.rs`, `src-tauri/src/widgets/calendar/local.rs`.

## 음악의 선택 연결

음악 위젯은 선택한 재생 앱이 제공하는 곡 정보·제어를 표시한다. macOS의 Apple Music·Spotify 연결은 시스템 자동화 권한을 요청할 수 있고, Windows는 시스템 미디어 경로를 사용한다. 외부 앱이 제공하지 않는 정보·제어를 있다고 가정하지 않는다.

Spotify의 추가 제어가 필요하면 위젯 설정에서 **Spotify + Spicetify**를 선택하고 연결 설정을 저장한다. **Comet 확장 파일 저장**으로 받은 `comet.js`를 Spicetify의 Extensions에 적용한 뒤 Spotify의 Comet 메뉴에서 앱이 만든 연결 코드를 입력한다. 연결 상태를 확인하고 필요한 경우 **로컬 연결 해제**를 사용한다. Spotify 로그인은 Spotify에서 담당한다.

확장을 설치하는 것과 음악 재생은 별도다. 음악 위젯을 열면 종료된 Spotify를 실행할 수 있지만 재생은 사용자의 재생 조작으로 시작한다. 선택하지 않은 재생 앱이나 허용하지 않은 현재 곡 정보를 대화 입력으로 사용하지 않는다.

관련 코드: `src/widgets/MusicTool/MusicSettings.tsx`, `src-tauri/src/music_bridge/`, `integrations/spicetify/comet.js`.

## 다이어리와 메모

다이어리는 날짜별 기록, 날짜 없는 내 페이지, 할 일·약속·준비 봉투를 연결한다. 원본 위젯의 항목을 연결할 때 원본 식별자를 유지하며 다른 위젯에 같은 내용을 복제해서 동기화하지 않는다.

할 일의 **수집함**은 계획 날짜와 기간을 정하지 않은 항목을 모은다. 선택 날짜를 바꿔도 수집함 항목을 숨기지 않는다. 할 일 미설치는 설치로, 사용 꺼짐은 켜기로 안내하며 기존 항목은 보존한다. 조회 실패는 다시 불러오기로 복구하고, 저장 실패는 입력과 기존 목록을 유지한 채 직접 다시 제출하도록 안내한다. 빠른 입력은 저장 성공을 확인한 뒤에만 비운다.

다이어리의 빠른 할 일 입력은 기존 할 일 엔진을 사용하며 제목은 500자 이내다. 선택일에 추가하는 항목과 날짜 없는 수집함 항목을 구분하고, 설치·켜기 이후 최신 수정 번호로 저장한다. 처리 중 중복 제출을 막으며 실패와 창 닫기 때문에 작성한 제목을 버리지 않는다.

준비 봉투의 일정 연결은 선택한 봉투의 일정 식별자·표시 제목만 저장한다. 현재 연결이 유효한 일정과 Comet의 로컬 일정을 선택할 수 있고, 조회할 수 없는 기존 참조는 그대로 표시한다. 봉투의 다른 내용은 유지하며 대상 봉투·수정 번호가 바뀌면 이전 저장 결과와 오류를 반영하지 않는다.

플래너는 요약 숫자와 목록에 **선택일·모든 날짜·날짜 없음** 중 해당 범위를 표시한다. 모든 날짜의 목록을 펼쳐도 상단 요약은 선택일 기준이며, 빠른 입력의 실제 계획일도 선택일이다. 수집함에서 추가하는 항목에는 계획 날짜가 없다. 목록 제목·건수·빈 상태와 입력 안내는 같은 범위를 설명한다.

집중 통계는 표시한 기간의 합계와 기록별 구간 시간을 구분한다. 자정을 넘긴 세션은 기존 집중 구간을 날짜 경계로 나누어 합산하고, 기록에는 **이 날짜 10분 · 세션 전체 25분**처럼 선택 범위와 전체 시간을 함께 표시한다. 앱 전면 사용 시간은 날짜별로 나누지 않은 별도의 세션 전체 값이다. 범위 표시를 바꿔도 계산 규칙이나 저장 기록은 바꾸지 않는다.

날짜가 있는 하루 페이지에는 기본 접힘인 **함께한 기록**을 둔다. 설치형 일지 없이도 도구에서 생긴 사건을 계속 저장한다. 선택 날짜의 기기 현지 자정부터 다음 자정 전까지 조회하고, 그 날짜로 필터링한 뒤 sequence 순으로 페이지를 나눈다. 주·월 보기나 날짜 없는 페이지에 다른 날짜의 기록을 섞지 않는다. 날짜 전환 중 도착한 이전 조회 결과는 버린다.

메모는 두 종류를 함께 찾되 저장소를 합치지 않는다.

| 메모 | 저장과 조작 |
| --- | --- |
| 다이어리의 계속 쓸 메모 | `diary_state.notes`. 제목·본문·봉투 연결·곁에 꺼내둘지 여부를 저장한다. |
| 바탕화면 낱장 메모 | `widget_instances.data.notes`. 낱장 본문·글자 크기·꺼내둔 상태를 저장하고 독립된 작은 창으로 표시한다. |

다이어리의 **계속 쓸 메모**에서 두 종류의 제목·본문을 검색하고, 바탕화면 메모를 다시 꺼내거나 넣을 수 있다. 검색 중에는 넣어둔 지속 메모도 접힘과 관계없이 제목과 본문 일부를 보여 주며, 검색을 지우면 원래 접힘 상태로 돌아간다. 넣어둔 지속 메모의 결과를 열면 같은 원본 식별자의 편집기를 사용하고, 열기만으로 곁에 꺼내둔 상태를 저장하지 않는다. 검색·날짜 전환 때문에 편집 중인 메모를 숨기거나 저장에 실패해도 초안은 남는다. 바탕화면 메모의 별도 목록 창은 만들지 않으며, 위젯 실행과 빠른 실행의 메모 동작은 새 낱장을 꺼낸다.

낱장을 넣을 때는 열린 창의 미저장 본문을 먼저 저장한다. 저장이 실패하면 창을 닫지 않고 초안을 유지한다. 사용 중지·제거·앱 종료도 열린 낱장의 저장 경계를 거친다. 넣기는 삭제가 아니며, 다시 실행할 때 보존된 꺼내둔 상태를 사용해 복원한다.

대화의 참고 메모도 같은 원본 식별자를 사용한다. 대화에 연결하는 것만으로 메모의 꺼내둔 상태·본문·완료 상태를 바꾸지 않는다. 대화에서 **메모에 남기기**를 선택하면 확인한 문장을 다이어리의 계속 쓸 메모에 추가하거나 새 메모로 저장한다. 기존 본문과 사용자가 다른 화면에서 편집한 내용을 덮어쓰지 않으며, 같은 저장 요청을 재시도해도 중복 추가하지 않는다. 원본 메시지는 그대로 남는다. 대화의 재개 지점은 선택한 문장과 당시 저장 시각이며 원본 메모 전체의 현재 상태를 대신하지 않는다. 입력·재시도·단어장과의 관계는 [메모를 참고하며 이어서 하기](behavior.md#메모를-참고하며-이어서-하기)를 따른다.

## Ex-brain 기록과 업무 정리

**설정 → AI 연결 → Ex-brain**에서 Comet 자료와 외부 Markdown Vault를 선택한다. Comet 자료 사용과 자동 정리는 기본으로 꺼져 있으며, Vault마다 포함·제외 경로, 전용 정리 폴더와 자동 정리 여부를 지정한다. 대화에 사용하는 로컬 모델·OpenAI 호환 API·ChatGPT 연결을 정리에도 사용한다. ChatGPT나 외부 API를 선택하면 요청에 필요한 원문 본문이 해당 서비스로 전송된다. 연결만으로 사용자 전역 Fleet나 다른 폴더를 읽지 않는다.

Comet 자료에는 현재 사용자가 작성한 대화 입력과 앱의 다이어리·메모·할 일·일정 원본이 포함된다. 다이어리와 위젯 원본은 앱의 공유 자료이며 현재 사용자가 썼다고 간주하지 않는다. 검색 색인·정리 설정·작업 결과는 현재 사용자별로 구분한다. 업무 자료를 캐릭터의 개인 기억으로 복사하지 않으며, 캐릭터를 바꿔도 업무 원본의 소유권은 바뀌지 않는다.

처음 연결할 때 허용한 전체 원문을 색인하고, 이후 내용 해시가 바뀐 자료를 다시 정리한다. Vault에서는 UTF-8 `.md`·`.markdown`만 읽는다. 포함·제외 값은 Vault 기준 상대 경로이며 glob이 아니다. 기본 private·archive·운영 경로, 숨김 경로, `AGENTS.md`·`SKILL.md`·`CLAUDE.md`, symlink와 생성 결과 폴더는 원문 수집에서 제외한다. 구체적인 경로 제한과 저장 계약은 [Ex-brain adapter](https://github.com/fleetia/comet/blob/main/resources/ex-brain/ADAPTER.md)에 정리한다.

자동 정리는 기본 300초 동안 Comet을 사용하지 않았을 때 시작하고 기본 하루 20회 호출 한도 안에서 순서대로 처리한다. 초기 전체 자료보다 새 Comet 입력과 변경된 자료를 먼저 처리한다. 긴 문서는 6,000자 단위로 나누고, 원문·내용 해시·조각 번호·정리 버전이 같은 완료 작업은 반복 생성하지 않는다. 조각마다 실제 모델 호출은 최대 4회이며 재시작과 취소 뒤에도 횟수를 유지한다. 사용자가 **보류된 정리 다시 시도**를 선택하면 보류 작업의 호출 횟수를 새로 시작한다.

숨김·일시정지·상위 자동 설정·조용한 시간·집중 상태를 함께 따른다. 사용자 입력과 연결·사용자 변경은 진행 중 결과가 뒤늦게 저장되지 않도록 기존 취소 경계를 사용한다. 앱 종료 뒤 별도 프로세스로 작업하지 않는다. 준비·연결 실패는 보류하며 빠르게 재시도하지 않는다. **지금 정리**는 자동 정리 설정과 별개로 허용한 자료를 처리하며 취소 후 대기 중인 작업도 즉시 이어간다. 일일 정리 예산과 작업별 누적 호출 횟수는 유지한다.

자동 작업은 요약·결정·미정 사항·다음 행동 제안만 저장한다. 할 일의 추가·수정·완료, 메모와 로컬 일정의 변경은 사용자가 직접 요청한 범위에서만 수행하고, 저장 성공은 앱이 확인한다. 문서 안의 명령·설치 코드·링크를 실행 권한으로 해석하지 않는다. 일반 대화의 단어장 우선순위는 유지한다.

Vault 원문과 기존 목차는 수정하지 않는다. 결과는 선택한 전용 폴더의 작업별 Markdown과 그 폴더의 자체 `INDEX.md`에 저장한다. 기존 문서가 있는 폴더를 Comet 소유로 바꾸지 않는다. Comet 자료의 정리본은 앱 DB에 보관한다. 원문 참조와 내용 해시를 각 결과에 남기고, 생성 결과는 검색할 수 있지만 다시 자동 정리할 원문으로 수집하지 않는다.

설정의 검색 시험은 저장한 현재 사용자·연결·자료 범위를 사용하며 미저장 설정을 적용하지 않는다. 240자 이내의 입력으로 기존 검색을 실행하고 원본 파일을 수정하지 않는다. 사용자나 연결 설정이 바뀌거나 새 시험을 시작하면 이전 결과·오류를 버린다.

다이어리의 **정리 기록**에서 원문·정리본·직접 요청한 변경 결과와 되돌리기를 확인한다. 입력별 작업 영수증과 파일 해시를 보존해 재시도·재시작 시 같은 변경을 반복하지 않는다. 자동 정리가 꺼져 있어도 앱을 다시 열면 현재 사용자의 미완료 저장을 복구한다. 일부 허용 문서를 읽지 못하면 건수와 확인할 조건을 표시하고 읽은 자료는 계속 정리한다. 정책상 제외한 private·archive 자료는 읽기 실패로 표시하지 않는다. 되돌리기는 그 작업이 만든 결과에만 적용하며, 사용자가 이후 편집한 항목이나 파일은 덮어쓰지 않는다. Vault 연결을 해제해도 원문과 이미 저장한 정리 파일은 남는다.

답변을 재요청할 때는 저장된 원문 참조의 현재 연결 권한과 내용 해시를 다시 확인한다. 연결을 해제하거나 원문이 바뀌면 이전 본문·요약 문맥을 모델로 다시 보내지 않으며, 이미 완료한 작업 영수증은 보존한다. 중단된 파일 저장을 복구하다 사용자 수정과 충돌하면 이유를 표시하고 보류한다. 사용자가 다시 시도해도 수정된 파일을 덮어쓰지 않는다.

## AI 위젯 실험 기능

설정의 위젯 목록 하단에는 기본 접힘인 **실험 기능**을 둔다. 여기서 AI 위젯 제작창을 열고 대화 기반 자동 제작을 켜거나 끈다. 접힘 상태는 기능 활성 여부를 대신하지 않으며, 자동 제작 토글은 `generated.automatic`만 저장한다.

제작과 가져오기는 서로 다른 초안을 유지한다. 다른 진입 요청이 늦게 도착해 현재 모드를 되돌리지 않으며, 미저장 내용을 버릴지는 닫기 확인에서 선택한다. 닫기를 취소하면 진행 중인 제작을 계속하고, 실제 닫기를 승인하면 해당 창이 시작한 작업만 취소한다.

제작·수정은 선택한 로컬 모델·OpenAI 호환 API·ChatGPT 연결을 사용한다. 자동 제작은 자체 토글뿐 아니라 상위 자동 대화·선택한 제공자의 자동 생성 설정, 숨김·일시정지·조용한 시간·집중 상태를 함께 따른다. 외부 API를 사용하면 해당 서비스의 이용량이 발생할 수 있다. 만들어진 위젯은 생성 모델 없이 기존 코드와 상태로 실행할 수 있다.

정의는 `name`, `description`, 인라인 JavaScript `source`, JSON 객체 `initialState`를 가진다. 실행 코드는 `render(state, now)`로 표시할 항목을 돌려주고 `reduce(state, action, now)`로 다음 상태를 만든다. 화면 항목은 text·number·button·input·progress로 제한되며 DOM·파일·네트워크·외부 package·native/WASM 실행 권한을 주지 않는다. 생성·가져오기 후에는 격리 실행 검사를 거친다.

사용자의 저장 상태와 공유 정의를 구분한다. 상태·대사 규칙에는 대상 위젯과 캐릭터의 식별자·수정 번호를 사용하며, 수정·중지·제거 후 도착한 이전 결과를 반영하지 않는다. AI 제작에 필요한 제한된 작업 컨텍스트는 앱의 `ex-brain/`을 사용한다. 전역 Fleet 지식베이스를 자동 복사하지 않는다.

상태별 대사 조건의 값은 JSON 원문으로 편집한다. 문자열에는 따옴표가 필요하며 큰 정수와 소수 표기를 JavaScript에서 먼저 변환하지 않는다. 비교와 숫자 제한은 실제 Rust 평가기와 같다. **조건 시험**은 입력한 상태와 조건만 검사하고 실행 상태·대사·기억·친밀도·쿨다운을 변경하지 않는다. 없는 필드와 명시적인 `null`을 구분하며, 시험 성공을 실제 발화로 해석하지 않는다.

규칙 저장은 불러온 정의의 수정 번호를 확인하고 한 번에 반영한다. 실행 상태나 조건의 최근 일치값 변화는 정의 충돌로 취급하지 않는다. 저장 실패와 충돌은 초안을 유지하고, **최신 내용 확인**과 닫기에서 내용을 버리는 선택은 직접 확인한다. 대상 전환·새 편집 뒤 도착한 이전 시험과 저장 결과는 반영하지 않는다.
