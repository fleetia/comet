# 위젯 확장 개요

> **상태: 확정된 설계 방향 · SDK 미구현.** 이 문서는 설치 가능한 위젯 제품이나 공개 API의 제공을 선언하지 않는다. 공개 필드명, 패키지 형식과 호환성 규약의 최종 안정화는 별도 결정이 필요하다.

Comet 위젯은 외부 기능의 상태와 사건을 캐릭터에게 전달하는 확장이다. 외부 개발자는 정보를 연결하고 필요한 상세 화면과 사용자 동작을 제공한다. 작은 A/B 본체와 잠깐 나타나는 말풍선이 중심이며, 위젯을 설치했다고 큰 대시보드를 상시 표시하지 않는다. 기본 대화는 위젯·네트워크·LLM 없이도 동작해야 한다. 기존 화면과 단어장 동작은 [제품 사양](../PRODUCT.md)을 따른다.

## 호스트와 위젯의 역할

Comet의 Rust 호스트가 연결 상태, 인증, 저장 공간, 갱신 일정과 발화 대기열을 관리한다. 위젯은 자신의 상태와 사건을 제공하고 수행 가능한 동작을 선언한다. 외부 데이터와 위젯 본문은 모델에게 지시할 권한을 갖지 않는다.

기본 화면은 호스트가 제목·상태·짧은 목록·버튼을 그리는 방식이다. 상세 조작이 필요하면 사용자가 화면을 연다. 별도 HTML/JS 화면은 선택 확장이며, 닫힌 뒤에도 위젯마다 WebView와 타이머를 계속 실행하는 설계는 채택하지 않는다.

| 연결 대상 | 설계상 원본 소유자 | 범위 |
| --- | --- | --- |
| 내장 투두 | Comet SQLite | 사용자 작성 항목과 완료 상태 |
| Google Calendar | 연결한 외부 계정 | 읽기 연결; 캘린더 쓰기를 전제하지 않음 |
| iCalendar 구독 | 구독 원본 | 읽기 전용 일정과 갱신 상태 |
| 외부 위젯 고유 상태 | 위젯별 호스트 저장 공간 또는 선언한 외부 원본 | 다른 위젯·계정과 분리 |

이 표는 추가 기능의 소유권 결정이며 구현 완료 표가 아니다. RSS는 연결 범위에서 제외한다.

## 먼저 검증할 확장 범위

공식 위젯의 선택 설치·추가·중지·제거는 첫 개발 단계에 포함한다. 외부 공개 SDK보다 먼저 같은 설치 상태·수명 관리 경계를 사용한다. 사용자가 위젯을 하나도 선택하지 않아도 기본 캐릭터 경험을 사용할 수 있어야 한다.

1. 타이머와 식물 같은 내장 예제도 같은 상태·사건·명령 계약을 사용한다.
2. 개발 폴더에서 읽는 위젯, ZIP 설치, 작은 예제와 모의 이벤트로 외부 작성자가 호스트 수정 없이 기능을 연결하는지 검증한다.
3. 기본 화면으로 부족한 사례를 확인한 뒤 선택적 HTML/JS 화면을 추가한다.

HTTP JSON과 선언적인 필드 매핑은 첫 연결 구현의 유력한 **후보**다. 채택한 실행 방식은 아직 아니며 인증 방식, 갱신 책임과 표현 가능한 변환 범위를 별도로 결정해야 한다. 이 후보만으로 임의의 로컬 프로그램 실행이나 모든 외부 서비스 연결을 지원한다고 약속하지 않는다.

## 보류한 결정

마켓플레이스, 원격 자동 설치·업데이트, 임의 native 코드, 범용 WASM/스크립트 실행기와 위젯 간 직접 통신은 미정이다. 특히 별도 WebView는 완전한 샌드박스를 자동으로 제공하지 않는다. 실제 권한 경계는 [공통 계약](contract.md#권한과-실행-주체)에 따라 구현·검증해야 한다.

SDK 범위, 데이터 소유권 또는 화면 실행 방식을 바꾸면 이 문서와 해당 계약·인수 기준을 함께 갱신한다. 실행 가능 여부는 구현과 검증 기록에서 확인하며 이 설계 문서만으로 판단하지 않는다.
