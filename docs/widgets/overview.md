# 위젯 확장 개요

> **2026-09-29 소스 기준:** 공식 위젯 16개, AI 위젯 제작·수정·JSON 가져오기와 상태별 대사 메뉴가 구현되어 있다. 범용 외부 Widget SDK, ZIP 설치와 임의 native 프로그램 실행은 제공하지 않는다. 소스 구현과 실제 데스크톱 실행·모델 생성 품질은 [상태표](../status.md)에서 구분한다.

Comet 위젯은 작은 생활 도구를 제공하고 그 상태와 사건을 캐릭터에게 전달한다. 공식 도구를 선택하거나 AI에게 필요한 도구를 만들어 달라고 요청할 수 있다. 작은 A/B 본체와 잠깐 나타나는 말풍선이 중심이며, 위젯을 설치했다고 큰 대시보드를 상시 표시하지 않는다. 기본 대화는 위젯·네트워크·LLM 없이도 동작해야 한다. 기존 화면과 단어장 동작은 [제품 사양](../PRODUCT.md)을 따른다.

## 호스트와 위젯의 역할

Comet의 Rust 호스트가 연결 상태, 인증, 저장 공간, 갱신 일정과 발화 대기열을 관리한다. 위젯은 자신의 상태와 사건을 제공하고 수행 가능한 동작을 선언한다. 외부 데이터와 위젯 본문은 모델에게 지시할 권한을 갖지 않는다.

공식 위젯은 동봉 manifest와 공용 Rust 처리기·화면으로 실행한다. AI 위젯은 선택한 로컬 모델 또는 OpenAI 호환 API가 만든 정의를 저장하거나 다른 AI의 JSON 정의를 가져온다. `render(state, now)`와 `reduce(state, action, now)` JavaScript는 origin이 분리된 iframe의 호출별 Worker에서 실행하고, 호스트가 검사한 텍스트·숫자·버튼·입력란·진행률만 그린다.

한 번 만든 위젯은 AI 없이 실행되며 창을 닫으면 해당 tick과 Worker 실행도 끝난다. 기본 WebView를 사용하므로 별도 runtime 설치가 필요 없다. 임의 HTML 화면과 native 프로그램 실행은 지원하지 않는다. 실행 시간과 결과 크기 제한은 있지만 엄격한 Worker 메모리 상한은 없으므로 완전한 OS 샌드박스로 표현하지 않는다.

| 연결 대상 | 설계상 원본 소유자 | 범위 |
| --- | --- | --- |
| 내장 투두 | Comet SQLite | 사용자 작성 항목과 완료 상태 |
| Google Calendar | 연결한 외부 계정 | 읽기 연결; 캘린더 쓰기를 전제하지 않음 |
| iCalendar 구독 | 구독 원본 | 읽기 전용 일정과 갱신 상태 |
| AI 위젯 정의·상태·상태 대사 규칙 | Comet SQLite | UUID별 저장, 수정 시 기존 state 보존 |
| 외부 위젯 고유 상태 (후속 설계) | 위젯별 호스트 저장 공간 또는 선언한 외부 원본 | 다른 위젯·계정과 분리 |

이 표는 소유권 계약이며 플랫폼별 검증 완료 표가 아니다. RSS는 연결 범위에서 제외한다.

## AI 제작과 내부 컨텍스트

AI 제작은 요청에 따라 정의를 만들고 검사 오류를 수정해 실행 창을 연다. 자동 제작을 켜면 새로운 사용자 대화에서 기존 도구에 없는 오프라인 위젯의 필요를 판단한다. 상태 조건이 성립할 때 말할 캐릭터·원문 대사·표정·동작은 별도 메뉴에서 편집하며 모델 없이 재생한다. 사용 방법과 제한은 [AI 제작 계약](ai-creation.md)을 따른다.

작업 문맥은 실제 `fleetia/ex-brain` 원본 skill을 사용하는 내부 adapter가 관리한다. 앱 전용 기록과 현재 위젯 이력만 제한적으로 조회하며 사용자 전역 Fleet나 KnowledgeBase를 복사하지 않는다. `.talk` 원문 편집은 기존 외부 editor의 책임을 유지한다. 상태별 대사 메뉴를 일반 대본 편집기로 확장하지 않는다.

현재 AI JSON 가져오기는 범용 패키지 SDK를 구현했다는 뜻이 아니다. 개발 폴더·ZIP 로딩, 선언적인 HTTP 연결과 선택적 HTML 화면은 별도 후속 결정 대상이다.

여기서 네이티브 위젯은 Comet의 위젯 관리·실행·상태별 캐릭터 반응에 통합되는 사용 경험을 뜻한다. 외부 위젯의 배포 형식·실행 방식·업데이트 정책은 아직 결정하지 않았다. 현재 AI 제작·수정과 수동 JSON 가져오기는 그대로 제공한다.

원격 자동 설치·업데이트, 임의 native/WASM 코드, package import와 위젯 간 직접 통신은 제공하지 않는다. 새 runtime 설치를 추가하려면 구체적인 패키지·출처·크기·권한과 목적을 보여 주고 사용자 동의를 받아야 한다. 현재 소스는 그런 설치 경로를 제공하지 않으며 모델이 만든 설치 명령을 실행하지 않는다. 실제 권한 경계는 [공통 계약](contract.md#권한과-실행-주체)에 따라 구현·검증한다.

[0.2 제품 사양](../PRODUCT.md)은 기존 본체·대화·단어장 기준을 보존한다. 이후 위젯과 제작 기능은 이 문서군이 소유한다. SDK 범위, 데이터 소유권 또는 화면 실행 방식을 바꾸면 해당 계약·인수 기준과 상태표를 함께 갱신한다.
