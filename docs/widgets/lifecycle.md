# 위젯 수명주기와 발화

> **상태: 공식 위젯 호스트 구현 + 외부 SDK 설계.** 2026-09-19 기준 `src-tauri/src/widgets/`와 `widget_commands.rs`, `widget_connections.rs`가 공식 위젯의 수명주기를 처리한다. 외부 ZIP·임의 코드·커스텀 WebView를 실행하는 공개 SDK는 아직 제공하지 않는다. 실제 데스크톱·외부 연결 검증 결과는 [상태 문서](../status.md)에서 구분한다.

위젯이 연결되고 조용히 갱신되다가 필요한 순간에만 말하도록 호스트가 수명주기를 관리한다. 데이터 구조와 권한의 기준은 [공통 계약](contract.md)이다.

## 현재 공식 호스트의 경계

- 선택한 공식 패키지만 설치 공간에 등록한다. 패키지 검사 실패는 해당 위젯의 오류·비활성 상태로 격리하고, 다른 위젯과 기본 A/B 경험을 막지 않는다. 남아 있는 사용자 데이터는 보존한다.
- 끄기·제거는 해당 인스턴스의 조회 취소 토큰과 revision을 무효화한다. 실행 중인 외부 조회가 나중에 끝나도 `action` 잠금 안에서 설치·활성 상태, revision과 작업 토큰을 다시 확인해야 저장할 수 있다. 표준 mutex guard는 `await` 너머로 유지하지 않는다.
- 화면만 닫으면 설치·활성 상태는 유지한다. 숨김·일시정지·자동 발화 끄기는 대사를 중지하지만, 켜 둔 외부 정보 연결의 읽기 갱신 권한까지 취소하지 않는다.
- 타이머는 끄면 일시정지한다. 재시작 전에 끝난 타이머는 종료 상태만 복원하고 종료 대사를 다시 만들지 않는다. 공·비행·낚시·펫 이동은 중단하고 화분은 저장된 성장 단계와 물을 보존하며 성장 시각을 다시 잡는다.
- 음악 정기 조회는 15초, 기기는 60초, 날씨는 30분의 최소 조회 간격을 사용한다. 음악의 직접 재생 명령은 현재 revision·30초 이내 관측·제공자 capability를 검사하고 명령 직후 다시 조회한다. 명령은 동시에 하나만 처리하며, 연결 변경·끄기·제거 뒤에는 취소하고 재연결 시 재전송하지 않는다. 공용 자동 조회는 동시에 최대 2개이며, 실패 시 간격을 늘린다. 정보 연결은 연속 5회 실패 또는 권한 오류·미지원 상태에서 자동 재시도를 멈춘다. 수동 재조회·설정 변경 경로는 별도로 제공한다.
- macOS `NSWorkspaceDidWakeNotification`과 Windows `WM_POWERBROADCAST`의 복귀 사건만 기기 복귀로 기록한다. 스케줄러가 늦게 실행됐다는 이유로 사용자 부재나 절전을 추측하지 않는다.

## 설치부터 갱신까지

최초 선택·후속 추가·의존성·제거 시 데이터 정책은 [선택 설치와 제거](installation.md)를 따른다. 아래 실행 단계는 사용자가 설치를 선택한 항목에만 적용한다.

1. 패키지의 경로·용량·manifest·호환성·요청 권한을 검사한다. 검사 실패 시 코드와 갱신 작업을 시작하지 않는다.
2. 인스턴스와 연결 범위를 생성하고 허용된 기능만 활성화한다. 최초 동기화는 상태를 채우는 과정이며 과거 항목을 새 사건으로 쏟아내지 않는다.
3. Rust 호스트의 공용 스케줄러가 갱신을 묶어 실행한다. 위젯마다 상주 타이머·프로세스·WebView를 요구하지 않는다. 사용자가 꺼냈거나 장난 모드가 선택한 바탕화면 물체만 별도 창을 가지며 아래 수명을 따른다.
4. 결과를 schema와 revision으로 확인한 뒤 상태를 저장하고 필요한 사건만 전달한다. 실패 시 이전 성공 상태와 오류를 구분해 유지한다.
5. 재시도에는 backoff를 적용한다. 공식 연결의 간격·동시 실행 제한은 위 기준과 연결 구현을 따른다. 외부 SDK의 자원 계약은 공개 전에 별도로 정한다.

현재 공식 위젯은 상태가 갱신될 때마다 LLM을 실행하지 않는다. 사건은 저장된 `event.text` fallback 또는 LLM을 호출하지 않는 `.talk` 대본으로 발화할 수 있다. 모델이 없거나 준비에 실패해도 내장 대사와 등록 대사는 사용할 수 있다. 위젯 사건의 선택적 LLM 표현은 외부 연동의 후속 범위이며, 준비 작업이 모델 상주 시간을 계속 연장하지 않아야 한다.

`.talk`는 허용된 상태·사건만 읽어 장면을 선택하며 LLM을 호출하지 않는다. 위젯 상태 대본은 기존 일반 자동 수다와 번갈아 기회를 얻고, 사건 대본은 아래 사건 대기열의 우선순위와 만료를 따른다.

## 연결 상태와 시간

| 상태 | 표시와 발화 규칙 |
| --- | --- |
| 유효한 최신 상태 | 출처와 관측 시각을 유지하고 현재 데이터로 사용한다. |
| 오래된 캐시 | 마지막 성공 시각과 오래됨을 표시한다. 실시간 사실처럼 말하지 않는다. |
| 오프라인 | 연결 실패와 보관 중인 데이터를 함께 표현한다. |
| 인증 실패 | 재연결이 필요한 상태로 구분하고 빠른 인증 재시도를 반복하지 않는다. |
| 정상적인 빈 목록 | 조회가 성공했고 항목이 없다는 의미다. 연결 실패를 빈 목록으로 바꾸지 않는다. |

실제 시각은 일관된 기준 시각으로 비교하되 원본 시간대도 보존한다. 종일 일정은 날짜 구간으로 다루며 임의의 자정 시각으로 바꿔 전날 일정처럼 표시하지 않는다. 반복 일정은 시리즈와 개별 회차를 구분한다. iCalendar의 UID와 회차 식별 정보, 제공 서비스의 항목 ID를 원본 범위 안에서 유지한다.

항목 링크는 검증한 원본 참조에서 만들고 LLM이 URL을 지어내게 하지 않는다. 내부 표시용 제목과 링크 대상을 분리한다. 일정 이동·취소·시간대 변경 시 이미 준비한 알림과 대사도 다시 판단한다.

프로세스 안의 타임아웃·대기 시간에는 단조 시계를 사용한다. 저장된 일정과 만료 시각은 실제 시각을 사용하며, 재시작·절전 복귀·시계 변경 후 다시 계산한다. 이전 실행의 타이머나 발화 커서를 그대로 이어 붙이지 않는다.

[`.talk` 변수의 최신성 기준](../development/talk-reference.md)은 위젯의 원본 캐시를 변경하지 않는 별도 읽기 projection이다. 최초 조회 중인 `syncing`, 오래된 `stale`, 조회 실패와 성공한 빈 결과를 구분한다.

## 발화 대기열과 오래된 생성 결과

우선순위는 **사용자 직접 입력 → 시각이 중요한 알림 → 위젯 사건 → 일반 자동 잡담**이다. 시각이 중요한 알림도 사용자 입력을 가로막거나 자동 발화 중단 설정을 우회하지 않는다.

- 공식 호스트의 대기열은 8개, 사건 발화 유효기간은 30초다. 타이머 종료·캘린더 알림을 일반 놀이 사건보다 우선 유지·선택한다. 선택 시 나머지 대기 사건은 비워 알림이 연달아 몰리지 않게 한다. 일지에서 참조하지 않는 사건 본문은 5분이 지나면 정리한다.
- 생성 대사에는 사용한 인스턴스·연결·항목의 revision과 유효기간을 연결한다. 표시 직전에 다시 확인한다.
- 사용자 입력, 관련 데이터 변경, 권한 해제, 연결 종료와 설정 변경으로 무효화된 생성 결과와 남은 장면은 재생하지 않는다.
- 숨김·일시정지·상위 자동 설정 끄기는 위젯 자동 발화와 자동 대사 생성을 막는다. 다시 켰다고 만료된 알림을 몰아서 읽지 않는다.
- 자동 재생이 꺼져도 사용자가 직접 입력한 단어장 키워드는 처리한다. 사용자 요청을 자동 발화 취소와 함께 버리지 않는다.
- 준비만 한 대사는 대화 기록에 남기지 않는다. 실제 표시한 줄만 기록한다.
- `.talk`의 `cooldown`은 첫 줄을 실제 표시한 시점에 기록한다. 재시작해도 기록을 유지하며 준비만 한 장면은 간격을 소비하지 않는다.
- 대본을 다시 읽어 오류가 나면 마지막 정상 프로그램을 유지한다. 유효한 변경이 적용되면 이전 프로그램으로 준비한 남은 장면을 취소한다. 최초 설치 이후 삭제한 파일은 복원하지 않는다. 상세는 [대본 수명주기](../product/talk.md)를 따른다.

발화 중단과 원본 데이터 동기화 중단은 구분한다. 숨김 상태에서 캘린더 캐시 갱신까지 중지할지는 연결별 정책으로 명시해야 하며, 자동 발화 허용으로부터 동기화 권한을 추론하지 않는다.

## 화면의 수명

공식 위젯 보기는 앱에 포함된 화면으로 렌더링하며 요청할 때 열고 닫을 때 해제한다. 상태는 호스트에 보관해 화면을 파괴해도 데이터가 사라지지 않는다. 화면 코드가 닫힌 뒤 상태 갱신을 계속 수행하는 구조에 의존하지 않는다.

메모는 목록과 메모별 낱장 창의 수명을 나눈다. `src-tauri/src/memo_notes.rs`는 설치·활성 상태와 저장된 `isOpen`을 확인해 낱장을 열고, 목록을 닫아도 낱장을 유지한다. 낱장 닫기 요청은 화면에 먼저 전달해 대기 중인 본문·글자 크기를 저장하며, 저장 실패 시 창을 유지한다. 재시작하면 설치·활성 위젯의 열림 상태를 복원한다.

메모 위젯 끄기·제거는 열린 낱장의 편집을 잠시 막고 저장 결과를 확인한 뒤 진행한다. 응답은 요청 ID와 창 이름이 일치해야 하며, 모든 창의 성공 응답 후 열린 창 구성이 같은지 다시 확인한다. 저장 실패·10초 응답 제한 초과·창 구성 변경 시 위젯 변경을 취소하고 편집 잠금을 해제한다. 성공하면 목록과 낱장을 해제하며, 데이터 보존과 상세 인수 조건은 [낱장 메모](../product/planning.md#낱장-메모)를 따른다.

### 생활 위젯의 바탕화면 표시

시계·기념일, 날씨, 기기 소식은 설정 화면과 별도로 읽기 전용 표시 창을 연다. 표시 창은 현재 snapshot을 구독하고, 상태를 자체 복제하거나 외부 조회를 시작하지 않는다. 창을 닫아도 위젯 설치·활성 상태와 연결 갱신은 유지하며, 끄기·제거 시 일반 도구 창과 표시 창을 함께 닫는다.

표시 배경은 색상 또는 위젯 전용 SQLite 이미지이고, 글자와 이미지의 위치는 각각 3×3 배치값이다. 이미지 파일은 허용된 MIME을 내용으로 확인하고 크기를 제한한다. 설정 변경은 일반 위젯 revision 경계를 사용한다. 파일 선택 창이 열린 동안 다른 화면에서 위젯이 바뀌면 파일을 적용하지 않으며, 이미지 변경도 표시 URL의 갱신 시각과 revision을 함께 갱신한다. 이미지 바이트는 snapshot·LLM 문맥·로그에 넣지 않는다.

날씨의 실패는 마지막 성공 관측과 분리해 표시하고, 기기의 배터리 없음은 0%로 바꾸지 않는다. 기념일·날씨·배터리의 표시 내용은 저장된 원본 상태만 읽으며, 표시 창을 위해 새로운 사건·자동 대화·외부 조회를 만들지 않는다.

외부 SDK의 커스텀 화면은 제한된 별도 WebView와 전용 통신 경로가 필요하다. 아직 구현된 외부 실행 경계가 아니며, 이것만으로 완전한 샌드박스나 위젯별 CPU·메모리 격리를 보장한다고 표현하지 않는다. 공개 전에 응답하지 않는 화면의 종료와 확장 비활성화가 기본 대화를 보존하는지 검증해야 한다.

## 바탕화면 물체의 수명

0.4의 공·비행기·비눗방울·펫은 `desktop_toys::Runtime`의 메모리 상태와 별도 투명 창으로 실행한다. macOS는 native `NSPanel`과 그리기·포인터 callback, Windows는 Tauri 화면과 native window region을 사용한다. 시작은 기존 위젯 명령에서 설치·활성·revision을 확인한 뒤 허용한다. 명령은 actor를 등록하고 창 생성을 예약한 뒤 반환하며, action·DB 잠금 안에서 UI thread의 완료를 기다리지 않는다. 예약 뒤 취소된 actor는 창을 표시하지 않고, 창 생성 실패는 actor를 제거한다. 재시작 시 위젯 데이터와 설정은 보존하지만 actor·위치·속도·진행 중 물리는 복원하지 않는다.

| 경계 | 처리 |
| --- | --- |
| 수동 시작 | 설치·활성 위젯만 열며 자동 장난 허용 여부와 구분한다. |
| 자동 시작 | `behavior.rs`가 허용 종류·대화 상태·epoch를 확인한다. actor ID와 소유 캐릭터를 기록하고 동시에 하나만 실행한다. |
| 프레임 | 고정 timestep의 운동은 메모리에서 처리한다. 프레임마다 DB·전체 앱 snapshot을 저장하지 않는다. 정지한 물체에 불필요한 표시 갱신을 계속 보내지 않는다. |
| 정지·착지·터짐 | 결과를 큐에 넣는다. 저장 시 설치·활성·widget revision을 다시 확인하고 자동 물체는 actor ID·epoch·현재 허용 상태도 검사한다. |
| 정리·끄기·제거 | actor와 창을 없애고 해당 소유자의 대기 결과도 폐기한다. 기존 위젯 데이터와 대화·기억·친밀도는 유지한다. |
| 자동 놀이 취소 | 자동 actor와 그 대기 결과만 취소한다. 수동 actor와 다른 생활 도구는 유지한다. |
| 긴 실행 공백·재시작·종료 | 물리를 지난 시간만큼 몰아서 재생하지 않는다. 1초를 넘는 loop 공백은 물체·대기 결과를 폐기하는 보수적 중단 조건이며, 이를 사용자의 부재나 OS 절전 사건으로 기록하지 않는다. |

수동 공·비행기는 정리 전까지 두며 세션 안전 상한은 1시간이다. 수동 방울·펫은 최대 45초, 자동 물체는 최대 20초로 제한한다. 사용자가 비눗방울을 꺼낼 때는 사용 가능한 actor 수 안에서 3~6개를 만들고, 자동 장난은 기존처럼 한 actor만 만든다. 전체 actor는 최대 8개이며 한도를 넘으면 추가 생성 요청을 거절한다. 장난 모드의 다음 실행 간격과 중단 상태는 [바탕화면](../product/desktop.md#장난-모드와-대화-상태)을 따른다.

새 물리 결과는 `desktop_toy_results`에 단위를 명시해 저장하며 legacy 0~100 좌표의 위젯 데이터와 합치지 않는다. 결과 기록은 표시할 대사가 확정됐다는 뜻이 아니다. 기존 대본 변수·사건에 연결할 때는 단위와 발화 취소 계약을 유지해야 한다.

다른 앱 창의 bounds는 원문 내용·제목을 저장하지 않는 일시 geometry다. 조회 실패를 성공한 빈 화면으로 바꾸지 않으며, 오래된 외곽을 계속 벽으로 사용하지 않는다. geometry·DPI·입력 통과에 대한 macOS·Windows 실제 검증은 [구현 상태](../status.md)에 수행한 범위만 기록한다.

## 연결 해제와 제거

| 조작 | 반드시 처리할 내용 |
| --- | --- |
| 비활성화 | 예약 작업·진행 중 작업 취소, 대기 사건·발화 무효화, 커스텀 화면 해제. 재활성화를 위한 설정과 사용자 데이터는 보존한다. |
| 권한 철회 | 해당 기능의 후속 호출을 거절하고 진행 중 결과도 권한을 다시 확인한다. 이미 완료된 외부 변경을 자동으로 되돌렸다고 주장하지 않는다. |
| 계정 연결 해제 | 해당 연결의 작업·캐시·인증 접근을 정리한다. 다른 인스턴스가 공유하는 인증은 연결 참조를 확인한 뒤 처리한다. |
| 위젯 제거 | 패키지와 전용 캐시·예약 작업을 제거한다. 사용자 작성 데이터의 보존·내보내기·삭제 선택과 인증 정리를 분리한다. |

위젯 제거로 Comet의 투두·대화 기록·단어장·수동 기억을 함께 삭제하지 않는다. 위젯 고유 사용자 데이터도 캐시라는 이유로 몰래 폐기하지 않는다. 삭제한 기본 예시를 빈 목록이나 재시작을 이유로 복원하지 않는다.
