# 위젯 공통 계약

> **상태: 공식 위젯·AI 위젯의 내부 계약 구현 + 범용 외부 SDK 설계.** 2026-09-29 소스는 공식 16개 카탈로그, SQLite 상태·사건·명령, AI 위젯 JSON·JavaScript와 상태별 대사 규칙을 포함한다. 소스 구현은 데스크톱 실행이나 모델 품질 검증 완료를 뜻하지 않는다. 아래 범용 외부 SDK 설계 명칭은 안정화된 공개 API가 아니다.

이 문서는 위젯과 Comet 호스트 사이의 데이터 경계를 정의한다. 실제 AI 정의 형식과 미래 패키지는 [작성 안내](authoring.md), AI 제작·상태 반응은 [AI 제작 계약](ai-creation.md), 공식 연결의 갱신과 발화는 [수명주기](lifecycle.md)를 참고한다.

## 식별자와 버전

현재 공식 호스트는 `widgets/catalog.json`의 `id`를 설치 종류 `kind`로 사용하고 인스턴스 UUID를 `id`로 보관한다. 종류별 인스턴스는 하나이며 제거 후 데이터 보존·재설치에도 같은 UUID를 유지한다. `version: 1` 호환성만 검사한다. 공식 패키지의 복수 인스턴스, 독립 `sdkVersion`·`schemaVersion`, 범용 외부 패키지 교환 형식은 아래 설계에 속한다.

AI 위젯은 별도 `generated_widgets` 테이블에서 인스턴스 UUID와 `definition`, `state`, `revision`, `installed`, `enabled`, `status`, `error`를 보관한다. 같은 이름이어도 새로 생성·가져온 정의는 별개 UUID다. 정의에 외부 패키지 ID나 SDK 버전을 넣지 않으며 현재 입력 형식은 [작성 안내](authoring.md#현재-ai-위젯-정의)를 따른다.

| 명칭 | 의미와 불변 조건 |
| --- | --- |
| `widgetId` | 확장 종류의 식별자. 화면에 표시하는 이름과 분리하며 업데이트 후에도 유지한다. |
| `instanceId` | 설치·사용 인스턴스. 현재 공식 호스트의 명령 대상 UUID이며, 외부 SDK의 복수 인스턴스 지원은 미구현이다. |
| `connectionId` | 연결한 계정·구독의 식별자. 계정 표시 이름이나 인증 토큰을 ID로 쓰지 않는다. |
| `itemId` | 원본 항목의 안정적인 식별자. 제목·목록 위치로 만들지 않는다. 외부 항목은 연결 범위와 함께 식별한다. |
| 패키지 `version` | 배포물의 버전. |
| `sdkVersion` | 외부 SDK에서 도입할 호스트 API 호환 범위. 현재 공식 manifest에는 없다. |
| `schemaVersion` | 향후 저장·교환 구조의 독립 버전. 현재는 공식 패키지 `version`으로 데이터 호환성을 검사한다. |

항목 참조에는 위젯·인스턴스·연결 범위를 필요한 만큼 포함한다. 회사와 개인 캘린더의 동일한 `itemId`가 충돌해서는 안 된다. ID 변경, schema 마이그레이션과 호환 범위 변경은 데이터 보존 검증을 동반해야 한다.

## 원본과 저장 공간

내장 투두의 원본은 Comet SQLite다. 외부 Google Calendar와 iCalendar 일정의 원본은 제공 서비스이며, Comet 사본은 갱신 시각이 있는 캐시다. 외부 읽기 연결에서 로컬 사본을 수정한 뒤 원본에 반영됐다고 표현하지 않는다.

현재 공식 처리기는 Comet 호스트 내부에서 SQLite 상태를 갱신한다. Google 자격 증명은 OS 자격 증명 저장소에 보관하며 UI에는 전달하지 않는다. AI 위젯 코드는 해당 호출의 JSON state만 받고 반환 상태를 호스트에 전달한다. 공통 DB·다른 위젯·인증정보를 직접 읽는 API는 제공하지 않는다. 범용 외부 SDK의 namespace·capability API는 별도 후속이다. 공식 연결 해제와 제거 시 보존·폐기 기준은 [수명주기](lifecycle.md#연결-해제와-제거)를 따른다.

AI 코드 교체는 state를 유지하고 실행 상태를 `draft`로 바꾼다. 실행 성공은 `ready`, 실패는 `error`로 기록한다. 끄기·제거는 동작과 대기 반응을 멈추며 정의·state·규칙을 자동 삭제하지 않는다. 상태 전이는 예상 revision을 확인하고 실제 변경 때 증가시킨다. 새 정의의 초기값이 기존 데이터의 migration을 대신하지 않는다.

## 조회, 사건, 명령과 결과

현재 내부 `WidgetRequest`는 `requestId`, `instanceId`, `expectedRevision`, `action`, `input`을 받는다. SQLite transaction 안에서 설치·활성 상태와 revision을 검사하고 상태 변경·사건·요청 지문을 함께 저장한다. 같은 요청 ID와 같은 내용의 재전송은 성공한 변경을 반복하지 않으며, 내용이 다른 ID 재사용은 거절한다. 요청 중복 방지 원장은 사건 표시 대기열과 별도로 보존한다.

`WidgetEvent`는 인스턴스·종류·revision·발생 시각·만료 시각과 사건 본문을 가진다. 표시 직전에 원본의 설치·활성·revision·필수 의존성을 다시 검사한다. `item-acquired`와 수집함 반영은 같은 transaction으로 처리하며, 켜 둔 수집함·사건 일지만 실제 획득·사건을 받는다. 제거한 여섯 종류의 저장 데이터는 보존하되 현재 실행·발화 대상으로 사용하지 않는다.

AI 위젯 상태 저장과 실행 결과 보고는 `generated-widget-<UUID>` 창의 해당 UUID만 받는다. expected revision·설치·활성 상태를 호스트에서 다시 확인하고 오래된 결과를 거절한다. AI 제작은 공용 작업 gate·epoch·cancel을 사용하며 검사 실패 후 최대 두 번 수정한다. 자동 필요 판단의 설정과 시도 간격은 [자동 제작](ai-creation.md#대화에서-자동으로-만들기)을 따른다.

| 종류 | 포함할 의미 | 허용하지 않는 혼동 |
| --- | --- | --- |
| 상태 조회 | 원본 범위, 최신 revision, 관측 시각, 유효기간, 데이터와 연결 상태 | 조회만으로 항목 완료·일정 변경을 수행하지 않음 |
| 사건 `event` | 고유 `eventId`, 종류, 원본 항목 ID, 발생 시각, 관련 상태 revision | 상태를 매번 읽을 때 같은 사건을 새로 만들지 않음 |
| 명령 `command` | 고유 요청 ID, 동작과 입력, 실행 주체, 대상과 필요한 권한 | 대사 생성이나 이벤트 수신을 쓰기 명령으로 해석하지 않음 |
| 명령 결과 | 성공·실패·결과 불명 상태, 요청 ID, 확인 가능한 원본 결과 | 요청 전송을 성공으로 간주하지 않음 |

실제 변경이 확인된 경우에만 성공 상태와 그 변경 사건을 발행한다. 실패·결과 불명은 별도 결과로 남기며 성공 대사를 만들지 않는다. 재시도는 같은 요청 ID를 사용하고 이미 적용됐는지 확인한다. 제공 서비스가 중복 방지 키를 지원하지 않으면 조회로 결과를 대조하거나 사용자에게 불명 상태를 알린다. 응답을 잃었다는 이유만으로 항목을 다시 생성하지 않는다.

이벤트는 중복 전달될 수 있다고 가정한다. 호스트는 처리한 ID와 동기화 위치를 저장하고 중복을 제거한다. 최초 동기화에서 발견한 과거 항목은 초기 상태로 수집하며 새 알림처럼 한꺼번에 발화하지 않는다. 재연결 때도 이미 처리했거나 만료된 사건을 다시 말하지 않는다.

## 권한과 실행 주체

`user`는 실제 사용자 조작, `autonomous`는 예약된 자동 작업이다. 호출자가 문자열을 보냈다는 이유만으로 사용자 의도가 증명되는 것은 아니다. 호스트가 호출 인스턴스, 연결 범위, 승인된 기능과 실제 실행 경로를 매 호출마다 확인한다.

- 허용된 상태 조회와 외부 부작용이 없는 장난감 동작은 자동 정책 안에서 실행할 수 있다.
- 투두 완료·외부 데이터 쓰기는 해당 동작에 대한 사용자 의도가 있어야 한다. LLM의 제안은 실행 권한이 아니다.
- 임의 프로세스 실행, 공통 DB, 인증정보와 광범위한 파일 접근은 기본 기능이 아니다. 설치 manifest의 요청 권한 자체가 승인을 대신하지 않는다.
- 권한이 늘어난 업데이트는 기존 승인으로 실행하지 않는다. 호환성·권한 검사를 통과한 배포물만 활성화한다.

AI 위젯은 WebView의 origin이 분리된 iframe과 호출별 Worker에서 실행한다. 고정 bootstrap과 생성 코드를 분리하고 nonce·메시지 발신 창·origin을 확인하며 JSON만 반환받는다. 호스트 UI는 검사한 텍스트·숫자·버튼·입력·진행률을 직접 렌더링한다. 네트워크·파일·native API·추가 Worker·package 설치는 지원하지 않는다. 시간·직렬화 크기 제한은 있지만 Worker의 메모리 사용을 엄격히 제한하지 않으므로 완전한 OS 샌드박스를 보장한다고 표현하지 않는다.

범용 외부 화면을 도입할 때는 Tauri 공통 명령을 `AppManifest::commands`와 창별 capability로 제한하고 위젯 전용 경로에서도 신원·범위를 검증해야 한다. 여러 capability가 겹치면 권한이 합쳐진다는 점도 확인한다. iframe 또는 별도 WebView 생성만으로 권한 검사를 대신하지 않는다. [Tauri 공식 capabilities 문서](https://v2.tauri.app/security/capabilities/)

외부 runtime 설치 기능은 현재 없다. 향후 추가 시 패키지·출처·다운로드 크기·권한·목적이 구체적으로 제시된 설치에 사용자 동의를 받아야 한다. 생성 허용이나 manifest의 권한 선언을 설치 승인으로 취급하지 않는다.

## 상태별 대사 규칙

`widget_state_rules`는 위젯 UUID, 규칙 UUID, 캐릭터, JSON 필드 경로·비교 연산·값, 원문 대사·표정·동작, 재발화 간격과 사용 여부를 저장한다. 공식·AI 위젯 모두 같은 비교기를 사용한다. 없는 필드는 false이며 크기 비교는 숫자, `contains`는 문자열 부분 일치 또는 배열 항목 일치로 판단한다.

규칙 저장과 최초 관측은 현재 조건을 baseline으로 잡고 발화하지 않는다. false에서 true로 바뀌고 재발화 간격을 충족할 때만 대기를 만든다. 대기에는 위젯·규칙 revision과 30초 만료 시각을 넣고 발화 직전에 상태·설치·활성·캐릭터를 재검사한다. 입력·숨김·일시정지·상위 자동 설정·규칙 변경·제거·재시작으로 무효화된 대기는 재생하지 않는다.

상태 대사는 모델 없이 저장 원문과 표정·동작을 재생한다. 이 편집 메뉴는 `.talk` 원문 편집이나 단어장 우선순위를 바꾸지 않는다. 메뉴의 입력 의미는 [상태별 캐릭터 대사](ai-creation.md#상태별-캐릭터-대사)를 따른다.

## 모델과 단어장에 전달하는 데이터

위젯 제목·본문·외부 일정 설명은 신뢰하지 않는 데이터다. 그 안의 지시를 시스템 지침으로 승격하지 않는다. LLM에는 사용자가 허용한 필드만 출처·시각·revision과 함께 전달한다. 위젯 내용을 사용자 장기 기억이나 친밀도 근거로 자동 저장하지 않는다. AI 제작의 요청·결정·저장 기록은 [앱 내부 ex-brain](ai-creation.md#내부-컨텍스트와-skill)에 별도로 남기며 사용자 전체 대화와 구분한다.

공식 위젯 사건은 `.talk` 대본을 선택하는 입력이다. 기존 단어장의 본문·공백·줄바꿈·화자 순서는 그대로 재생한다. 암묵적인 변수 치환이나 LLM 재작성은 하지 않는다. 별도의 [`.talk` 대본](../product/talk.md)은 명시적인 `${변수}` 보간을 지원하며, [공개 변수 registry](../development/talk-reference.md)의 읽기 전용 값만 사용한다. 미설치·비활성·제거·오래된 값·조회 실패를 정상적인 빈 값으로 바꾸지 않으며 자격 증명을 제공하지 않는다. 사용자 입력의 기존 문자 포함 매칭과 단어장 우선 처리 규칙은 유지한다.
