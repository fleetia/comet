# AI 위젯 제작과 상태별 대사

AI 위젯은 필요한 도구를 설명하면 작은 화면과 동작을 만들고, 사용하다가 다시 고칠 수 있는 기능이다. 뜨개질 단수 세기처럼 텍스트·숫자·버튼·입력란·진행률과 자체 JSON 상태로 표현할 수 있는 도구를 대상으로 한다. 한 번 저장한 위젯의 실행과 상태별 캐릭터 대사는 AI 없이 동작한다.

> **상태: 2026-09-29 소스 구현.** 이 문서는 구현된 경로와 제한을 설명한다. 데스크톱 실행·취소 동작·모델별 생성 품질의 실제 검증 결과는 [상태표](../status.md)를 따른다. 임의 프로그램 제작과 자동 설치를 제공한다는 뜻이 아니다.

## 만들고 고치기

위젯 관리에서 **AI로 위젯 만들기**를 열고 필요한 도구를 설명한다. 제작 화면은 새 제작·자동 제작 설정·JSON 가져오기를 담당한다. 저장한 위젯은 공식 위젯과 같은 목록에 표시하며 검색·설치 상태·분류 필터로 찾는다. **만들기**는 설정에서 선택한 로컬 모델 또는 OpenAI 호환 API 중 아래 제작 조건을 충족한 모델을 사용한다. 모델 준비가 안 되어 있으면 설정을 안내하며, 기본 캐릭터 대화나 이미 만든 위젯의 실행을 막지 않는다.

AI는 질문이나 계획만 반환하는 대신 실행 정의를 만들도록 요청받는다. 정의 검사 오류는 최대 두 번 자동 수정한 뒤 저장하고 실행 창을 연다. 실행 오류가 발생하면 그 창에서 최대 두 번 수정을 시도한다. 모델 준비 실패·취소·저장 충돌을 빠른 무한 재시도로 처리하지 않는다.

공통 위젯 목록에서 항목을 선택하면 오른쪽 상세에서 실행·켜기/끄기·제거·상태별 대사·AI 수정을 관리한다. AI 수정은 같은 UUID의 정의를 수정한다. 모델에는 기존 source 전체와 현재 state의 필드 이름·타입을 제공하며 실제 저장 값은 보내지 않는다. 새 `initialState`로 기존 값을 초기화하지 않는다. 수정 요청은 예상 revision을 포함하고 저장 직전에 최신 상태를 검사한다. 제작·수정 중에는 **제작 중단**으로 취소할 수 있다.

**설치 정보**에는 AI 직접 제작·대화에서 자동 제작·JSON 가져오기 중 최초 등록 경로, 최초 제작 모델, 설치 시각과 마지막 정의 수정 시각을 표시한다. 앱이 이 정보를 저장하며 가져온 JSON이 출처를 지정하지 않는다. 상태 변경·중지·제거·AI 수정으로 최초 설치 정보를 덮어쓰지 않는다. 기존 위젯의 미기록 정보는 알 수 없음으로 남기며, 가져온 정의의 원래 제작 모델이나 제작자를 추정하지 않는다.

로컬 모델의 입력 예산은 system·사용자 입력·출력 schema를 합쳐 UTF-8 3,000 bytes다. 큰 위젯 수정이 이 범위를 넘으면 원래 코드와 state를 보존하고 요청 축소 또는 API 사용을 안내한다. API 모드도 합계 64KiB 제한을 적용한다. 실행 가능한 위젯 크기와 모델의 수정 한도는 다르며 상세는 [모델 입력과 큰 위젯 수정](authoring.md#모델-입력과-큰-위젯-수정)을 따른다.

### 제작할 수 있는 모델

**로컬 코드 생성·수정에는 9B를 초과하는 모델이 필요하다. 9B도 차단 대상이다.** 같은 조건을 자동 제작과 오류 자동 수정에도 적용한다. 작업실은 현재 모델의 사용 가능 여부와 이유를 표시하며, 실행 중 모델 설정이 바뀌면 호스트가 다시 검사한다.

| 모델 경로 | 크기 판정과 제작 조건 |
| --- | --- |
| 내장 로컬 카탈로그 | 등록된 명목 매개변수 크기로 검사한다. 현재 목록에서는 Gemma 4 12B만 허용한다. |
| 직접 지정한 GGUF | `general.size_label`에 명확한 숫자와 `B`가 있는 경우만 판정한다. 9B 이하이거나 크기가 없고 모호하면 차단한다. 파일명이나 tensor 수로 추측하지 않는다. |
| OpenAI 호환 API | 모델 ID의 명시적 `B` 크기가 9 이하이면 차단한다. 9B 초과 표기는 허용하지만 ID 표기 자체가 제공자의 실제 매개변수 수를 검증하지는 않는다. 크기를 공개하지 않은 API 모델 ID는 허용하며, 이를 9B 초과 확인으로 표시하지 않는다. |

이 제한은 앱 안에서 위젯 코드를 생성하는 경로에만 적용한다. JSON 가져오기, 이미 저장한 위젯 실행, 상태별 등록 대사와 일반 캐릭터 대화에는 큰 모델을 요구하지 않는다. 크기 조건 통과가 원하는 동작이나 생성 품질의 검증 완료를 뜻하지는 않는다.

### 로컬 추론 모드

AI 연결의 로컬 추론 모드는 일반 대화·모델 테스트에 적용하며 기본값은 꺼짐이다. 위젯 정의 생성·수정·오류 자동 복구에서는 설정값을 덮어쓰지 않고 요청에만 추론을 강제로 켠다. 대화에서 위젯이 필요한지 판단하는 단계는 일반 설정을 따른다. 모델의 chat template이 추론을 지원해야 하며 추론을 켜도 9B 이하 제작 제한은 유지한다.

일반 요청은 추론을 끄면 기존 4,096 token context를 사용하고, 켜면 8,192 context와 최대 2,048 추론 token을 사용한다. 로컬 위젯 코드는 16,384 context, 최대 4,096 추론 token과 4,096 최종 응답 token을 사용한다. 추론·최종 응답의 합계를 출력 상한으로 전달하므로 추론이 짧으면 남은 범위는 최종 응답에 쓸 수 있다. 입력의 3,000 bytes 제한은 유지한다. 추론 과정은 대사나 위젯 JSON으로 저장하지 않으며 출력 한도에 도달한 응답은 완성된 정의로 취급하지 않는다.

직접 요청의 HTTP 대기 상한은 추론을 켠 일반 로컬 요청 300초, 위젯 코드 요청 600초다. 기존 취소와 백그라운드 작업의 더 짧은 기한이 우선하며 이 시간 동안 항상 실행한다는 뜻은 아니다. 추론이 꺼진 일반 요청과 외부 API는 기존 180초를 유지한다. 외부 API에는 제공자마다 다른 추론 매개변수를 추가하지 않으며 기존 최종 응답 상한 2,048 token을 유지한다.

## 대화에서 자동으로 만들기

**대화에서 필요한 도구가 보이면 자동으로 만들기**는 독립적인 설정이며 새 설정의 기본값은 켜짐이다. 상위 자동 대화와 현재 AI의 자동 생성 설정(`local_idle_enabled` 또는 `api_idle_enabled`)이 켜져 있고 위 제작 조건을 충족한 모델이 준비되었으며 백그라운드 실행이 가능한 경우에만 판단한다. 위젯 자동 제작 토글만 켜서 꺼진 상위 설정을 우회하지 않는다.

판단 입력은 최근 30분 안의 가장 최근 사용자 메시지와 기존 공식·생성 위젯의 이름·설명이다. 같은 메시지는 한 번만 판단하고 최대 5분에 한 번 시도한다. AI는 이미 있는 도구와 겹치지 않는 구체적인 오프라인 사용 필요를 찾도록 요청받는다. 인사·인용된 명령·추상적인 논의와 네트워크·외부 앱·package가 필요한 요청은 제작 이유로 삼지 않는다.

필요하다고 판단하면 추가 질문 없이 정의 생성·검사·저장·실행 창 열기로 이어진다. 필요 판단과 실제 코드 생성 모두 모델 추론을 사용하므로 API 모드에서는 이용량이 발생할 수 있다. 실패해도 같은 메시지를 즉시 반복 처리하지 않는다. 토글을 끄면 후속 자동 제작을 멈춘다.

사용자 입력·설정 변경·숨김·일시정지와 제작 중단은 공용 task·epoch·cancel 경계와 함께 다룬다. 취소되거나 오래된 결과는 위젯 저장·캐릭터 대사에 다시 적용하지 않아야 한다. 이 경계의 실제 동작은 소스 구현과 별도로 검증한다.

## 다른 AI가 만든 정의 가져오기

직접 연결하는 생성기는 설정한 로컬 모델과 OpenAI 호환 API다. 그 밖의 AI는 [작성 형식](authoring.md)에 맞는 JSON을 만들어 **다른 AI가 만든 위젯 가져오기**에 붙여 넣는 경로를 사용한다. 임의 AI 서비스의 인증·CLI를 자동 연결하는 기능은 없다.

가져온 정의도 같은 크기·형식 검사와 격리 실행을 거친다. 가져오기 자체에는 모델이 필요 없으며 실행 오류의 AI 수정에는 위 제작 조건을 충족하고 준비된 모델이 필요하다. **위젯 코드와 공유 정의**에서 확인하는 JSON은 `name`, `description`, `source`, `initialState`로 구성되고 현재 사용 상태는 포함하지 않는다.

## 상태별 캐릭터 대사

공통 위젯 목록의 **상태별 캐릭터 대사 편집** 또는 생성 위젯 실행 창의 **상태별 대사**에서 상태 필드와 비교 값, 캐릭터, 원문 대사, 표정, 동작과 다시 말하기 간격을 저장한다. **현재 위젯 상태와 필드 보기**에서 JSON을 확인하고 `count`, `timer.remainingMs`처럼 점으로 구분한 필드를 지정한다.

| 비교 | 판정 |
| --- | --- |
| 같음·다름 | JSON 값의 동등성 비교 |
| 이상·초과·이하·미만 | 양쪽 값이 숫자인 경우의 크기 비교 |
| 포함 | 문자열의 부분 문자열 또는 배열의 같은 항목 포함 |

필드가 없으면 조건을 충족하지 않은 것으로 처리한다. 대사는 조건이 **충족되지 않다가 충족되는 순간** 발생한다. 저장 시 이미 성립한 조건이나 앱 재시작 직후 현재 상태를 새 사건으로 말하지 않는다. 다시 말하기 간격이 지나도 같은 상태에서 반복하지 않으며, 조건이 해제되었다 다시 성립해야 한다.

등록 본문·공백·줄바꿈을 LLM으로 다시 쓰거나 암묵적으로 변수 치환하지 않는다. 선택한 캐릭터가 함께 지내는 상태인지 확인한 뒤 지정한 표정·동작과 함께 한 대사로 재생한다. 이 메뉴는 상태에 따른 반응을 편집하며 일반 대화팩의 `.talk` 원문 편집기는 아니다. 기존 [대본 작성과 외부 editor](../product/talk.md) 계약은 유지한다.

사용자 입력을 우선하고 숨김·일시정지·자동 대화 끄기 중 쌓인 반응은 나중에 몰아서 재생하지 않는다. 대기 반응은 30초에 만료하며 발화 전 위젯·규칙 revision, 설치·활성 상태와 조건을 다시 확인한다. 제거·규칙 수정·재시작으로 오래된 반응을 재생하지 않는다.

## 실행과 설치 경계

JavaScript 실행환경은 기본 WebView에 포함된다. origin이 분리된 iframe에는 고정 실행기만 넣고, 생성 코드는 매 호출 새 Worker에서 실행한다. 호스트는 반환 JSON을 검사한 뒤 지원하는 화면 항목만 그린다. 위젯 코드에 Tauri 호출·공통 DB·다른 위젯 상태·인증정보·파일·네트워크·추가 Worker 권한을 주지 않는다.

각 호출에는 약 1초의 종료 제한과 입력·결과 크기 제한이 있다. **Worker 내부의 메모리 할당에는 엄격한 상한이 없다.** 이 구조를 임의 native 프로그램까지 안전하게 실행하는 완전한 OS 샌드박스로 해석하지 않는다. 창을 닫으면 tick과 실행을 정리하며, 닫힌 위젯은 백그라운드 작업을 계속하지 않는다.

현재는 외부 runtime·package 설치를 지원하지 않는다. 지원 범위를 벗어난 기능을 만든 것처럼 표시하거나 AI가 제시한 shell 명령을 실행하지 않는다. 향후 설치 경로를 추가하려면 필요한 패키지 이름·배포 출처·다운로드 크기·권한·사용 목적을 보여 주고 **그 설치에 대한 명시적 동의**를 받아야 한다. 포괄적인 AI 제작 허용이나 과거 설치 승인은 이를 대신하지 않는다.

## 내부 컨텍스트와 skill

`fleetia/ex-brain`의 `ai-session-kit` 0.2.0 원본을 `resources/ex-brain/`에 포함했다. 원본 revision은 `ec28e0ccd1b60263321cdcf7fa20240129fa801f`이며 `provenance.json`에 파일별 hash와 GPL 출처를 기록한다. 기존 installer나 global hook을 실행하지 않는다.

`src-tauri/src/exbrain.rs`는 앱 데이터의 `ex-brain/` 아래에 AGENTS·INDEX·LICENSE·provenance·adapter 문서를 없는 경우만 준비한다. AI 생성·수정의 요청·결정·저장 결과는 `00.memory/tasks/done/<위젯 UUID>/`에 남기고, 실제 코드와 사용 상태는 SQLite가 소유한다. 위젯 제작 문맥의 자동 관리는 이 기능의 일부이므로 저장 때마다 session-end 동의를 반복하지 않는다.

조회는 활성 INDEX에서 질의에 맞는 줄과 현재 UUID의 최신 기록으로 제한한다. private 존, 다른 위젯의 작업 기록, 사용자 전역 Fleet·KnowledgeBase·Claude/Codex 설정을 자동으로 읽거나 복사하지 않는다. 기록은 모델 지시가 아닌 과거 데이터로 전달한다.

API 모드에는 실제 `guided-development`, `kb-lookup`, `kb-routing`, `change-verification`의 필요한 부분을 최대 3,500자, 조회 context를 최대 6,000자로 구성한다. 로컬 모드에는 이 네 skill의 행동 원칙을 담은 별도 요약을 사용한다. 요약 상한은 600 UTF-8 bytes이며 이 소스의 실제 요약은 479 bytes다. 로컬 context는 문서 heading을 잘라 넣지 않고 최신 요청·결과·revision 또는 관련 INDEX 항목을 추출한 400 bytes 이하의 완결 JSON이다.

이 수치는 adapter 출력 상한이다. 최종 호스트는 실행 계약·요청·기존 source·state 필드 정보·schema를 모두 더해 모델 입력 한도를 검사한다. compact 지침이나 JSON을 재절단해서 한도에 맞추지 않으며 초과하면 생성·저장 전에 오류를 반환한다. 전체 대화를 기록에 복사하지 않는다.

알려진 credential 패턴은 기록에서 제거하지만 임의 비밀 문자열을 완전히 판별하는 기능은 아니므로 요청·정의·상태에 인증정보를 넣지 않는다. API 모드에서는 제작 요청, 수정 대상의 source 전체·state 필드 이름과 타입, 선택된 내부 context가 설정한 API로 전달된다. 현재 state의 실제 값은 모델 입력에 포함하지 않지만 source에 직접 적은 문자열·상수는 전송 범위에 포함된다.

## 저장과 기존 기능의 관계

AI 위젯 정의·상태·규칙은 Comet DB에 저장한다. 코드 수정·모델 전환 때문에 사용자 상태를 초기화하지 않는다. 끄기·제거는 실행과 대기 반응을 멈추며 저장 데이터를 자동 삭제하지 않는다. 제거한 생성 위젯을 다시 설치하는 별도 복원 흐름은 이 문서에서 약속하지 않는다.

공식 목록에서 제거한 완료 구슬병·기기 소식·맞히기 놀이·낚시·화분·작은 펫의 과거 데이터는 별도로 보존한다. AI 위젯 기능이 이 여섯 도구를 자동 복원하거나 새 위젯의 상태로 이전하지 않는다. 현행 공식 목록은 [16개 카탈로그](catalog.md)를 따른다.

[0.2 제품 사양](../PRODUCT.md)은 역사적 기본 경험을 보존한다. 작은 본체·말풍선·단어장 우선 처리와 모델 없는 기본 대화를 유지하면서 위젯 제작과 상태 반응만 이 문서의 새 계약으로 추가한다.
