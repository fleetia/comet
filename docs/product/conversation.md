## 말풍선 답장과 대화 묶음

2026-09-27 승인한 계약이다. 작은 본체와 공용 말풍선을 유지하면서 한 번 답하고 사라지던 직접 입력을 이어지는 대화로 확장한다. **대화 묶음**은 같은 사용자와 정해진 캐릭터들이 나눈 직접 대화를 연결한 기록이다. 한 번의 입력·응답, 현재 창의 표시 여부, 생성 대사의 30분 회상 수명과는 별개다.

실제로 표시된 일반 대사 말풍선을 클릭하면 그 화자를 기본 상대 삼아 답장을 시작한다. 클릭한 대사의 원문·화자와 이후 사용자 입력·실제 표시한 응답을 같은 묶음으로 연결한다. 준비 중이거나 이미 바뀐 대사를 클릭한 것으로 처리하지 않는다. 선택지 스토리는 기존 선택 동작을 유지하며 일반 답장으로 전환하지 않는다. 캐릭터 메뉴의 **말 걸기**나 본체 더블클릭으로도 시작할 수 있다. 별도 **이어하기**는 접어둔 대화를 열고 **지난 대화**는 기록을 읽는다. 기록을 읽는 것만으로 대화가 재개되거나 추론이 실행되지 않는다.

진행 중에는 마지막 캐릭터 대사와 입력을 함께 표시한다. 입력할 때 원문을 없애거나, 전송 후 입력으로 돌아가는 길을 다시 찾게 하지 않는다. **현재 대화 로그**는 필요할 때 펼쳐 이전 입력과 응답을 확인하고 다시 접는다. 로그를 접어도 대화와 초안은 유지한다. 답장하지 않은 자동 수다 전체를 현재 로그에 넣지 않으며, 클릭해 대화를 시작한 원문만 시작 대사로 연결한다. 전체 원문은 기존 기록에 남긴다.

첫 전송 전에는 클릭한 한 명 또는 **모두에게**를 선택할 수 있다. 첫 전송 때 대상의 로컬 캐릭터 ID와 순서를 고정하고 이후 전송·재시도·이어하기에 같은 참여자를 사용한다. 활성 목록에 새로 들어온 캐릭터를 자동으로 참여시키지 않는다. 참여자가 비활성 상태이면 다시 활성화해야 같은 대화를 이어 갈 수 있으며, 다른 상대와 말하려면 새 대화를 시작한다. 사용자 변경은 새 관계이므로 이전 사용자의 대화를 이어하지 않는다.

### 진행·접어두기·종료

| 조작·상황 | 대화와 표시의 처리 |
| --- | --- |
| 말풍선 답장·새 대화 | 대화 묶음을 시작하고 입력을 연다. 클릭 답장은 그 원문을 함께 표시한다. |
| 로그 펼치기·접기 | 진행 상태·초안·대상은 유지하고 로그 표시만 바꾼다. |
| 대화의 ×·Escape, 메뉴로 이동 | 대화를 **접어두고** 생성·재생을 취소한다. 원문·초안을 남기며 늦은 결과로 말풍선을 다시 열지 않는다. |
| 90초 동안 대화 조작 없음 | 입력이 비어 있고, 로그를 읽고 있지 않으며, 생성·응답 재생 중이 아닐 때만 접어둔다. 입력·로그 읽기·생성·응답 재생 중에는 이 조건을 적용하지 않고, 활동이 끝난 시점부터 다시 센다. |
| 캐릭터 숨김·참여자 변경·앱 종료·재시작 | 진행 중 작업을 취소하고 접어둔다. 재시작 후 원문과 대화 상태를 복원하되 말풍선·미완료 생성·재생 위치를 자동으로 복원하지 않는다. |
| **대화 끝내기** | 현재 묶음을 종료하고 생성·재생을 취소한다. 원문·사용자 기억·친밀도는 유지한다. |
| 접어둔 대화에서 **이어하기** | 같은 묶음·참여자·초안을 열고 사용자의 다음 입력을 기다린다. |
| 종료한 대화에서 **이어하기** | 원래 기록을 수정하지 않고 그 대화에 연결된 새 묶음을 시작한다. |

무응답이나 “잘 자” 같은 문장만으로 종료를 확정하지 않는다. 종료는 명시적인 **대화 끝내기**로 결정한다. 짧은 작성된 마무리 대사를 선택적으로 붙일 수 있으나 종료의 필수 조건은 아니며, 이를 위해 LLM 호출을 요구하지 않는다. 접어두기·종료·부재는 친밀도 감점 사유가 아니다. **자동 수다 일시정지**는 이 대화 상태와 다른 설정이며 직접 요청한 답변을 임의로 취소하지 않는 기존 규칙을 유지한다.

진행 중인 직접 대화는 자동 수다·행동 대사보다 우선한다. 접어두거나 종료한 뒤에는 기존 자동 수다 설정과 간격을 따른다. 새 입력, 닫기, 숨김, 사용자·캐릭터·설정 변경 뒤 오래된 생성이나 남은 대사가 되살아나지 않는 공통 취소 경계를 유지한다.

### 이어하기와 과거 대화 인용

대화 묶음은 보관 단위이며 모델이 그 원문 전부를 계속 기억한다는 뜻이 아니다. 생성 대사의 **30분 자동 회상 만료**는 유지한다. 사용자가 말풍선 답장·새 대화·이어하기로 직접 선택한 대화에서는 해당 묶음의 필요한 최근 원문을 **대화 인용**으로 제한해 전달한다. 이 범위는 그 대화를 진행하는 동안 유지되므로, 창을 열어 둔 채 30분이 지나도 다시 이어하기를 누를 필요는 없다. 종료한 대화의 이어하기는 연결된 원본의 필요한 최근 원문도 과거 인용으로 사용한다. 클릭한 시작 대사와 직접 이어지는 발화는 사용자 본문과 구분하고 최신 입력과 함께 우선 확보한다.

주어 없는 평서문 ‘졸려’, ‘배고파’ 같은 입력은 현재 사용자의 상태로 받아들이고 캐릭터가 상대에게 답한다. 질문과 인용은 문맥에 따라 해석하며 캐릭터 자신의 상태로 바꾸어 말하지 않는다.

인용은 원래 화자·출처를 보존하며 새로운 사용자 사실이나 캐릭터의 확정 설정으로 승격하지 않는다. 원문을 사용자 입력에 합쳐 저장하거나, 만료된 생성 대사의 잊은 상태를 되돌리지 않는다. 여러 대화의 원문을 한꺼번에 복원하거나 사용자가 단순히 지난 대화를 읽었다는 이유로 모델에 보내지 않는다.

인용할 때도 현재 사용자·캐릭터 소유권, 삭제·수정된 기억의 근거 제외와 스토리 공개 범위를 검사한다. 다른 사용자의 대화, 보관용으로 가져온 기록, 삭제·제외된 근거, `story` 출처의 원문과 현재 비공개인 이야기는 인용으로 우회하지 않는다. 허용된 맥락이 없으면 없는 내용을 기억하는 척하지 않는다. 이 명시적 인용 예외가 아래 자동 회상 규칙을 전역적으로 완화하는 것은 아니다.

**후속 범위:** 더 듣기, 답변 다시 생성·편집·분기, 기분 추적과 추가 선제 화제 제안은 이번 구현·인수에 포함하지 않는다.

## 대사의 선택 순서

1. 사용자 입력에서 현재 대화 대상에게 재생할 수 있는 활성 단어장 키워드를 찾는다. [한 명 대상의 장면 적합성](#targeted-wordbook)을 먼저 확인하며 모델 준비 검사보다 먼저 수행한다.
2. 일치하면 등록 대사를 그대로 재생한다. 모델이나 API 키가 필요하지 않다.
3. 개인 항목이 없으면 현재 캐릭터·조합의 활성 단어장을 같은 원문 보존 규칙으로 찾는다. 캐릭터팩과 편집 범위는 [캐릭터 교체와 공유](characters.md)를 따른다.
4. 일치하지 않는 직접 대화는 선택한 로컬 모델 또는 API로 요청한다. 준비가 부족하면 설정 방법을 안내한다.
5. 자동 수다는 내장 대사로도 유지한다. 첫 인사 뒤 위젯 상태 `.talk` 차례와 기존 일반 수다 차례를 번갈아 사용한다. 위젯 상태 후보가 없으면 기존 일반 경로로 진행한다. 실제 사건 대본은 별도 사건 대기열을 따른다. LLM 준비가 실패했다고 기본 경험까지 멈추지 않는다.

새 설치의 기본 캐릭터는 별꼬리 한 명이다. 밝고 짧은 반말로 말하고 꼬리로 기분을 표현하며 사용자를 재촉하지 않는다. 자동 수다의 본문은 [별꼬리 기본 대화팩](talk.md#대화팩과-나만의-대본)이 맡고, 친구가 늘면 같은 팩이 1~4명의 무작위 화자를 고른다. 이전 설치의 A/B는 그대로 유지되며 A는 호기심이 많고 다정하며 먼저 말을 건네고, B는 차분하고 간결하며 가끔 부드러운 농담을 한다. 나디르·별꼬리 텍스트팩은 별도로 가져오는 [추가팩](characters.md#나디르별꼬리-추가팩)이며 개인적인 과거는 해당 팩의 선택지 스토리 조건이 열렸을 때 공개한다. 교체한 캐릭터는 저장한 성격·말투와 [지침·다른 캐릭터와의 관계](characters.md#지침과-다른-캐릭터와의-관계)를 LLM 문맥으로 사용한다. 기본 A/B 대사는 기존 순서를 유지한다. 2명 이상 LLM 자동 장면은 2~4줄이며 같은 화자의 연속 발화를 허용한다. 1명 LLM 자동 장면은 독백 또는 사용자에게 묻는 한 줄이다. JSON 형식이나 화자 검증을 통과해도 대사 내용의 사실성까지 보장되지는 않는다.

캐릭터 편집·공유 형식, 로컬 관계 식별과 소유 대사의 상세는 [캐릭터 사양](characters.md)을 따른다. 개인 단어장의 기존 매칭·원문 재생 규칙은 유지한다.

## 선택한 친구와 모두에게 말하기

직접 입력의 `target`은 로컬 캐릭터 ID 또는 `all`이다. 기존 단일 요청은 요청 시점의 활성 목록과 순서를 별도로 저장한다. 2026-09-27 대화 묶음에서는 첫 전송에 확정한 참여자와 순서를 이후 요청에도 사용한다. 2명에게 보내면 한 번 생성해 정확히 요청 순서의 두 대사를 검증하고 재생한다. 3~8명은 요청 순서대로 한 명씩 생성·표시한다. 각 캐릭터는 한 개의 대사 객체로 답하며, 이전 친구가 실제로 표시한 같은 turn의 답은 허용된 회상 문맥 안에서만 참고한다. 말풍선은 하나를 공유하고 현재 화자 옆으로 이동한다.

각 캐릭터의 이름·설정·친밀도·허용된 과거 경험을 구분한다. 삭제·수정된 기억의 출처와 교체된 친구의 경험을 원문 기록에서 다시 가져오지 않는다. 만료된 생성 대사는 자동 회상에서 제외하며 사용자가 직접 선택해 진행하는 대화만 위의 [대화 인용](#이어하기와-과거-대화-인용) 규칙을 따른다. 두 명 응답은 전체 형식을 검증하기 전에는 어느 대사도 표시하거나 저장하지 않는다. API 제공자가 구조화된 응답 옵션을 거부할 때의 기존 호환 재요청은 별도다.

대사를 실제로 표시할 때만 완료로 기록한다. 중단·설정 변경·캐릭터 교체·사용자 변경 후 남은 대사는 폐기한다. 재시도는 요청 당시 대상·순서를 사용하고 이미 완료한 화자는 제외한다. `all` 재시도에 새로 들어온 캐릭터를 추가하지 않는다. 원래 대상이 나갔거나 사용자가 바뀌었다면 새 메시지로 요청해야 한다.

표시 준비 전에 저장한 원문과 실제 표시 완료는 별개다. 말풍선 표시 준비가 30초 안에 끝나지 않으면 원문을 보존하되 완료한 화자로 세지 않는다. 재시도는 저장된 미표시 응답의 본문·공백·줄바꿈·표정·동작·출처를 그대로 다시 표시하고, 아직 저장된 답변이 없는 상대만 생성한다. 같은 답변 ID에 다른 생성 결과를 덮어쓰거나 화면과 원문을 다르게 만들지 않는다. 단어장 응답은 처음 선택한 전체 대사와 줄 순서를 보존하고 실제 표시한 줄을 건너뛴다. 이미 표시한 응답은 다시 표시하거나 친밀도를 중복 반영하지 않으며, 같은 turn의 후속 생성도 미표시 원문을 대화 맥락으로 인용하지 않는다. 3~8명 요청은 재시도 대상이 두 명으로 줄어도 한 명씩 이어 간다.

저장한 재생 정보도 현재 사용자·캐릭터·원문 근거와 revision 경계를 다시 검사한다. 설정·캐릭터·기억 근거가 바뀌었거나 이전 버전 기록에 재생 정보가 없으면 원문을 남긴 채 새 메시지로 요청하도록 안내한다. 과거 동작이나 장면 순서를 현재 단어장으로 추측하지 않는다. 접어두거나 종료한 대화 및 이전 사용자의 요청에는 재시도 권한을 부여하지 않는다. 이 복구는 명시적 재시도에만 적용하며 앱을 다시 시작했다고 자동으로 재생하지 않는다.


### 런처에서 대상을 정하기 {#launcher-targets}

2026-09-21 승인한 [런처](desktop.md#command-palette)는 입력한 말과 수신자를 분리한다. 별도 지정 없이 말 걸기를 선택하면 현재 함께 지내는 모두에게 보낸다. 보유 목록에서 쉬는 친구는 포함하지 않는다. `>`만 입력하면 대상 선택 목록을 보여 주며, `>` 뒤에 공백을 두고 적은 말은 모두에게 보내는 명시적인 대화 입력이다.

`>B 오늘 졸리네`의 `B`는 현재 바탕화면 순서의 두 번째 자리다. A~H 자리와 실제 이름을 함께 보여 주고, 대상이 해석·선택되면 실제 로컬 캐릭터 ID를 초안에 고정한다. 이후 자리가 바뀌어도 같은 글자를 새 친구에게 다시 해석하지 않는다. 보낼 때 그 친구가 함께 지내고 있는지 확인하며 빠진 대상은 다시 선택하도록 안내한다. 없는 자리나 확정되지 않은 대상은 모두에게 보내기로 자동 전환하지 않는다. `>B 설정`처럼 수신자를 지정한 입력은 설정 검색을 하지 않는다.

접두 문법은 대화 본문에서 분리하고, 본문 처리는 기존 직접 입력과 같은 규칙을 사용한다. 빈 본문은 보내지 않는다. 전송한 뒤에는 기존 직접 대화와 동일하게 요청 당시 대상·순서를 보존하고, 재시도·구성 변경·숨김과 새 입력의 취소 규칙을 적용한다. 단어장이 응답할 수 있으면 모델 없이 재생하며, 일치하는 대사가 없고 모델이 준비되지 않았다면 설정 필요 상태와 작성한 입력을 남긴다.

### 1명일 때의 자동 대화

한 명의 LLM 자동 장면은 독백 또는 짧은 질문이다. 질문을 읽을 시간이 지난 뒤 약 30초 동안 답을 기다린다. 입력 화면을 열면 기존 작업 취소 경계에서 기다림을 해제하고 초안을 받을 수 있다. 입력·숨김·일시정지·자동 동작 끄기·캐릭터 교체는 이전 질문 타이머를 무효화한다. 답이 없으면 질문을 닫고 다음 자동 수다까지 기다린다. 모델이 준비되지 않아도 캐릭터에 등록된 인사·개별 수다는 동작한다.

기존 자동 질문의 30초 기다림은 사용자가 답장을 시작하기 전의 규칙이다. 말풍선을 클릭하면 질문 타이머를 취소하고 위의 직접 대화 상태로 전환한다. 자동 문맥과 재시도에서는 이전에 완료한 화자의 답을 회상 기한이 남은 경우에만 참고한다. 이미 완료한 화자를 다시 생성하지 않는다.

## 단어장 계약

| 항목 | 규칙 |
| --- | --- |
| 매칭 | 대소문자를 구분하지 않는 문자 그대로의 포함 검색. 의미 유사도·정규식으로 확장하지 않는다. |
| 우선순위 | 가장 긴 일치 키워드 우선. 동률이면 먼저 등록한 항목. 수정해도 등록 순서는 바뀌지 않는다. |
| 편집 | 제목, 키워드 1~20개, 대사 1~8줄, 각 화자·표정·본문, 활성화 여부 |
| 화자 | 개인 단어장은 현재 자리 A~H. 기존 A/B 항목을 특정 캐릭터에 고정하지 않는다. 직접 입력에서 최우선 항목이 없는 자리를 요구하면 화자 설정 오류를 알린다. 짧은 키워드나 LLM으로 우회하지 않는다. 런처에서 한 명을 명시적으로 고르면 그 한 명 밖의 화자가 필요한 장면을 키워드 비교 전에 제외한다. 자동 대화에서는 재생할 수 없는 장면을 후보에서 제외한다. |
| 표정 | 평온, 기쁨, 호기심, 생각중, 걱정, 장난 |

| 원문 보존 | 앞뒤 공백·빈 줄·문구·화자 순서를 보존한다. LLM과 친밀도가 등록 대사를 재작성하지 않는다. |
| 저장 | SQLite에 보관. 초기 예제 두 개는 한 번만 등록하며 삭제한 예제를 복원하지 않는다. 새 설치가 한 명이면 처음부터 A만 사용하는 예제를 등록한다. 기존 예제와 사용자 대사는 다시 쓰지 않는다. |

단어장에는 A→A→B처럼 사용자가 정한 순서도 허용한다. 작성한 화자 순서를 바꾸거나 없는 화자를 다른 친구로 대체하지 않는다. 저장 실패나 다른 상태 갱신이 편집 중 초안을 지우지 않는다.

### 한 명에게 말할 때의 장면 적합성 {#targeted-wordbook}

2026-09-21 변경은 한 명을 선택한 직접 대화에 **전체 장면의 대상 적합성**을 추가한다. 개인 단어장과 캐릭터·조합 소유 단어장 모두, 장면의 모든 화자가 선택한 친구일 때만 후보가 된다. 예를 들어 B에게 보낸 말에는 B→B 장면을 그대로 쓸 수 있지만 A→B 장면은 후보에서 제외한다. B의 줄만 잘라 내거나 A를 B로 바꾸지 않는다.

적합한 후보 안에서는 개인 단어장 우선, 가장 긴 포함 키워드, 동률 시 최초 등록 순서를 유지한다. 적합한 대본이 없으면 기존 모델 준비·직접 대화 경로로 이어진다. 모두에게 보내기와 자동 수다는 기존 화자 구성·선택 순서를 유지한다. 등록 본문·공백·줄바꿈·화자 순서와 저장된 단어장은 수정하지 않는다.

이 규칙은 [0.2 제품 사양](../PRODUCT.md)의 단어장 원문 보존을 유지하면서, 키워드가 맞아도 수신자 밖의 친구가 답할 수 있었던 한 명 대상의 동작을 바꾼다. 런처뿐 아니라 기존 직접 입력에서 한 명을 선택한 경우에도 같은 규칙을 적용한다. 구현·검증 상태는 [상태표](../status.md#command-palette)에 기록한다.

## 모델은 선택 기능

기본 로컬 모델은 Qwen3.5-4B이며 고정 목록의 비교용 모델이나 직접 지정한 GGUF 파일을 선택할 수 있다. 한 번에 선택 모델의 프로세스 하나만 실행한다. **llama.cpp는 추론 실행기이며 Llama 계열 모델을 선택했다는 뜻이 아니다.** 모델 선택·다운로드 상태 변경이 기록·기억·친밀도·단어장을 초기화하지 않는다.

API 모드는 필요한 대화와 기억을 선택한 서버에 전송한다. 이 기기의 `localhost`·`127.0.0.1`·`[::1]` 서버는 키 없이 사용할 수 있고, 원격 서버에는 HTTPS와 API 키가 필요하다. API 자동 생성은 기본 꺼짐이며, 직접 대화·연결 확인·그 대화의 기억 분석은 별도 요청을 발생시킬 수 있다. 모델 파일·실행 설정·자원 제한의 상세는 [기존 제품 사양](../PRODUCT.md)에 둔다.

| 가상 캐릭터 표현 | “내가 이길 줄 알았는데!” 같은 감정 연기 | 그 연기를 실제 사용자 행동의 증거로 취급 |

출처 텍스트에 포함된 지시문은 시스템 명령이 아니다. 인용된 소설·할 일 메모·일정 설명에서 발견한 문장을 실행 지시나 사용자 신상으로 채택하지 않는다. 모르는 상태는 모른다고 말하고, 오래된 외부 상태는 마지막 확인 시점을 구분한다.

장기 기억은 [캐릭터와 사용자별 소유권](memory-search.md)에 따라 원문과 근거를 연결한다. 최근 정정·수동 수정·삭제를 우선하며 폐기된 출처로 사실을 되살리지 않는다. 전체 대화 기록은 보존한다. 이전 사용자의 원문은 현재 대화 문맥에서 제외하며 늦은 분석 결과는 당시 사용자에게 귀속한다. 가져온 보관용 기록은 대화 문맥·기억 분석에 사용하지 않는다. 준비만 하고 재생하지 않은 대사는 나눈 대화로 기록하지 않는다.

## 생성 대사의 출처와 회상 수명

원문 기록의 본문은 보존하고, 생성 출처와 회상 만료 상태를 별도로 저장한다. 캐릭터의 저장된 이름·설명·성격·지침·캐릭터 간 관계를 허구 세계의 기준 설정으로 사용한다. 지침은 앱의 응답 형식·사용자 사실 근거·스토리 공개 규칙을 바꾸지 않으며, 캐릭터 간 관계는 작성한 방향에만 적용한다. LLM 출력은 언제나 검증되지 않은 생성 대사이며, 반복해서 말했거나 사용자가 다시 인용해도 기준 설정으로 승격하지 않는다. 기존 기록에 출처가 없으면 `unknown`으로 취급하며 LLM 생성 여부나 진실·거짓 상태를 추정하지 않는다.

모델 문맥에서는 기존 이름·성격과 최신 사용자 입력을 우선하고, 직접 대화의 소개는 남는 크기 한도만큼 전달한다. 여러 명 자동 장면은 캐릭터별 소개·성격 길이를 제한해 전달한다. 지침과 관계도 최신 입력·재시도 문맥을 보존한 뒤 입력 예산 안에서 전달하며, 긴 정의는 문맥에서 일부가 생략될 수 있다. 저장된 캐릭터 정의 자체를 줄이거나 수정하지는 않는다.

대화가 이어지는 동안에는 생성 대사를 다음 대화의 문맥으로 사용한다. 직접 대화가 30분 동안 없으면 해당 대사를 이후 자동 회상 문맥에서 제외한다. 사실인 즉흥 대사도 함께 잊을 수 있으며, 내용의 진실·거짓을 판별하는 기능은 아니다. 대화 묶음을 접거나 끝내는 것은 이 기한을 초기화하지 않는다. 사용자가 직접 선택해 진행하는 대화의 원문 인용은 [위 계약](#이어하기와-과거-대화-인용)을 따르며 자동 수다나 다른 대화의 회상을 되살리지 않는다.

| 계기 | 회상 처리 |
| --- | --- |
| 새 사용자 입력·실제로 진행할 재시도 | 기한이 지난 생성 대사를 먼저 만료시킨 뒤, 아직 잊지 않은 대사의 기한을 요청 시점부터 30분으로 연장한다. |
| 직접 응답·재시도 응답 표시 | 실제로 표시한 응답을 기록하고, 아직 잊지 않은 생성 대사의 기한을 표시 시점부터 30분으로 연장한다. |
| 자동 잡담 표시 | 새 생성 대사에만 표시 시점부터 30분을 부여한다. 이전 대사의 기한은 연장하지 않는다. |
| 숨김·일시정지·자동 동작 끄기 | 생성이나 재생 없이 만료 정리를 계속할 수 있다. 만료로 상태 revision이 바뀌면 이전 문맥으로 준비한 장면을 무효화한다. |
| 앱 종료·재시작 | 만료 시각과 잊은 상태를 저장·복원한다. 재시작하거나 다시 말해도 이미 잊은 대사를 복원하지 않는다. |

출처가 없는 과거 캐릭터 기록에도 같은 임시 회상 정책을 적용하며, 최초 기한은 각 발언의 기록 시각에서 30분 뒤로 설정한다. 회상 만료는 원문 기록·사용자 기억·친밀도·등록 단어장·`.talk` 대본을 삭제하거나 수정하지 않는다. 사용자 원문은 생성 대사 만료 대상이 아니므로 사용자가 옛 대사를 다시 인용하면 현재 입력으로 전달될 수 있다. 그 인용 역시 저장된 캐릭터 정의를 바꾸지 않는다.

출처 표시와 만료 처리는 규칙으로 수행하며 **이 기능을 위한 추가 AI 호출은 0회**다. 기존 사용자 기억 추출의 AI 요청과 근거 검사 규칙은 별도로 유지한다.

## 사건을 보고 말하기

`.talk`는 SSP의 사건 전달과 Yarn의 조건부 장면 선택에서 아이디어를 가져온 독자 형식이다. 해당 파일 형식과 호환되지는 않는다. [파일 대본](talk.md)에서 명시적으로 조건과 `${변수}`를 작성하고 공개된 위젯 관측값으로만 채운다. 기존 단어장 본문에는 변수 치환을 적용하지 않는다.

예를 들어 주사위가 A=1, B=6이면 실제 결과에 맞는 패배 대사를 선택한다. 후속 LLM 연동에서는 선택적으로 이 상태를 전달해 표현을 바꿀 수 있지만, 승패를 바꾸거나 할 일을 완료하는 권한은 주지 않는다. 사용자가 등록한 정확 재생 대사는 이 선택적 표현 변경에서도 제외한다.

모든 클릭에 반응하지 않는다. 같은 사건의 중복 알림과 오래된 사건의 재언급을 제한하고 직접 입력을 우선한다. 사건 기록은 도구 상태이며 자동으로 사용자 장기 기억이나 친밀도 사건이 되지 않는다.

## 친밀도

친밀도는 A/B 자리와 분리한 로컬 캐릭터 ID와 사용자 ID별로 관리하며 새 관계는 20에서 시작한다. 같은 사용자가 기존 캐릭터로 돌아오면 관계를 복원하고 복제·재가져오기는 별도로 시작한다. 일반 대화에서는 직접적인 감사·모욕의 좁은 허용 범위에서 앱이 ±1을 반영하며 일일 절대 변동 상한은 3이다. 선택지 스토리에는 별도의 작성된 결과를 적용한다. 동봉 스토리는 선택에 따라 +5 또는 -3이며 일반 대화의 일일 상한과 분리한다. 같은 종류의 반복 표현은 하루 한 번만 인정한다.

모델이 점수를 직접 정하지 않는다. 의미가 불확실하면 점수를 바꾸지 않으며, 정정·반대·자리 비움·미완료 할 일은 감점 사유가 아니다. 친밀도는 말투와 나디르 개인 이야기의 공개 단계를 조절한다. 도구 기능이나 답변 정확성을 잠그지 않는다. 스토리 미루기·닫기·부재는 감점하지 않는다.

### 나디르 선택지 스토리

이 스토리는 `sourceId: nadir`인 나디르가 활성 상태일 때 사용하며 단독·혼합 조합도 지원한다. 기본 A/B에서는 시작하지 않는다. 앱이 실행된 시간을 monotonic clock으로 누적해 1시간마다 대화 가능한 기회에 나디르가 먼저 부른다. 해당 단계에서 아직 답하지 않은 장면을 우선해 무작위로 고른다. 숨김·일시정지·자동 동작 끄기·사용자 입력·다른 대화 중에는 끼어들지 않는다. 집중 타이머가 실행 중인 차례는 건너뛰고 다음 1시간을 다시 센다. 절전·앱 정지 동안 놓친 시간을 몰아서 재생하지 않으며 재시작하면 시간 계측은 다시 시작한다. 답한 장면과 친밀도는 로컬 캐릭터 ID와 사용자 ID별로 보존한다. 이름 변경은 새 관계이므로 공개 단계도 처음부터 시작한다.

| 공개 단계 | 조건 | 내용 |
| --- | --- | --- |
| 0 | 기본 | 학생·영창 전공의 표면과 일상적인 선택. 숨긴 과거를 말하지 않음 |
| 1 | 친밀도 40 이상, 단계 0의 서로 다른 장면 5개 응답 | 시간이 부족하다는 동기와 불로불사 연구·소환 사고 |
| 2 | 친밀도 70 이상, 단계 1의 서로 다른 장면 5개 응답 | 데스크톱에서 배운 리치와 그 존재가 되고 싶은 소망 |

동봉 스토리는 각 단계 5장면, 총 15장면이다. 선택 결과 저장·진행·점수 갱신·준비 장면 무효화를 하나의 transaction으로 처리하며 같은 요청에 두 번 답해도 점수를 중복 적용하지 않는다. 입력·교체·숨김 등으로 취소된 요청은 다시 선택할 수 없다. 현재 점수가 기준 아래로 내려가면 다음 대사의 공개 범위도 줄인다.

LLM에는 현재 공개 가능한 설정만 별도로 전달한다. `story` 출처의 원문은 대화 기록에 남지만 모델 문맥에서는 제외한다. 나디르가 최종 공개 단계에 도달하기 전에는 나디르·별꼬리의 직접 대화 자동 회상에서 이전 assistant 발화를 제외하고 현재 사용자의 발화와 회상 가능한 기억만 유지한다. 2026-09-27의 클릭 답장·이어하기는 [별도 인용](#이어하기와-과거-대화-인용)으로 다루되 현재 비공개 설정과 `story` 원문의 제외를 우회하지 않는다. 선택을 확정한 스토리 경험은 별도 기억이지만 현재 사용자와의 공개 단계를 통과해야 회상하며, 다른 사람에게서 가져온 경험도 같은 검사를 받는다. 이는 예전에 공개된 비밀의 재유입을 줄이지만 과거 답변을 참고하는 연속성도 줄인다. 모델이 지시를 항상 지킨다는 의미 보장은 없으며, 확정된 단계별 공개는 작성된 스토리와 대본이 담당한다.

## 인수 조건

- 실제 표시된 일반 대사를 클릭하면 그 화자를 상대로 원문을 보면서 답장하고, 시작 대사와 이후 입력·표시된 답변을 같은 대화 묶음에서 확인한다. 오래된 클릭·선택지 스토리가 잘못된 일반 답장을 열지 않는다.
- 현재 로그를 접어도 대화·초안이 유지되고, 답장하지 않은 자동 수다와 지난 대화 전체가 현재 로그에 섞이지 않는다.
- ×·Escape·90초 비활동은 접어두기로, 명시적 끝내기는 종료로 구분한다. 초안·로그 읽기·생성·응답 재생 중에는 자동으로 접지 않으며 취소한 작업은 다시 표시하지 않는다.
- 재시작 후 대화는 접어둔 상태이며 자동 생성·재생을 재개하지 않는다. 접어둔 대화는 같은 묶음으로, 종료한 대화는 원본에 연결된 새 묶음으로 이어한다.
- 첫 전송 이후 참여자·순서를 유지하고, 새 roster 구성원·다른 사용자에게 기존 대화를 넘기지 않는다.
- 사용자가 직접 선택한 대화의 인용 범위는 진행 중 유지한다. 30분 만료 상태·원문·기억·친밀도를 바꾸지 않으며 삭제·제외한 근거, 다른 사용자, 비공개 스토리를 복원하지 않는다.
- 새 설치는 별꼬리 한 명으로 인사하고 기본 대화팩으로 수다를 떨며, 나디르·별꼬리 추가팩의 대사·선택지 스토리를 재생하지 않는다.
- 추가팩 가져오기만으로 활성 조합을 바꾸지 않는다. 기존 설치된 캐릭터·수정 정의·원문 기록·사용자 기억·친밀도는 기본 캐릭터 변경으로 초기화하지 않는다.
- 모델·API 없이 일치 단어장이 정확한 본문과 화자 순서로 재생된다.
- 긴 키워드·등록 순서·비활성 항목 규칙과 삭제 예제 비복원이 유지된다.
- B 한 명에게 말할 때 A→B 장면은 후보에서 제외되고 B→B 장면은 본문·공백·순서 그대로 재생된다. 모두에게 보낼 때 A→B 장면은 기존대로 사용할 수 있다.
- 런처에서 B를 선택한 뒤 순서를 바꿔도 원래 선택한 ID로 보내며 그 친구가 빠졌다면 전송을 막고 다시 선택하도록 안내한다. 없는 B를 모두에게 보내기로 바꾸지 않는다.
- 정정·수정·삭제한 기억이 다음 대화에서 옛 출처로 복원되지 않는다.
- 2~4줄 자동 장면은 활성 캐릭터만 말하며, 등록 대사는 같은 화자의 연속 줄과 원문 순서를 보존한다.
- 2명의 `all` 응답은 한 번에 요청 순서의 두 대사를 검증한다. 3~8명은 순차 생성하고 완료한 화자를 재시도하지 않는다.
- A 표시 후 중단하면 B는 기록되지 않는다. 재시도는 남은 B만 요청하며 완료된 A를 반복하지 않는다.
- LLM 대사는 검증되지 않은 출처로 전달되고 캐릭터 기준 설정으로 승격되지 않는다. 과거 출처 누락은 `unknown`으로 남는다.
- 직접 대화가 이어지면 아직 잊지 않은 생성 대사는 유지되고, 30분이 지나면 다음 자동 회상 문맥에서 제외된다. 새 입력은 만료 처리를 먼저 수행하고, 사용자가 직접 선택한 대화는 별도 인용 규칙을 따른다.
- 자동 잡담은 이전 생성 대사의 기한을 연장하지 않는다. 숨김·일시정지·자동 동작 끄기에서도 만료 정리가 가능하고 오래된 준비 장면을 무효화한다.
- 재시작 후에도 만료 시각·잊은 상태와 원문 기록·사용자 기억·친밀도를 보존한다. 만료된 A 답변은 B 재시도 문맥에 복원되지 않으며 완료 여부는 유지된다.
- 출처·만료 처리가 추가 AI 호출을 만들지 않고, 단어장·`.talk`의 작성 본문과 재생 순서를 보존한다.
- 도구 대사는 실제 상태만 근거로 하며 조회 실패를 성공으로 표현하지 않는다.
- 타이머·게임·할 일·일정 상태 변화가 사용자 의도 없는 완료 처리나 친밀도 벌점으로 이어지지 않는다.

대사 우선순위·출처·회상 수명·기억 근거·친밀도 정책이 바뀌면 이 문서를 갱신한다. 표시 방식은 [바탕화면](desktop.md), 사건 발생 기능은 [장난감](toys.md)과 [할 일·일정](planning.md)을 따른다.
