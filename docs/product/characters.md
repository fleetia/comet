# 캐릭터 교체와 공유

**상태: 0.3.0 구현, macOS 검증 완료.** 캐릭터 생성·편집·복제·제거, 한 자리 또는 둘의 조합 적용, 캐릭터 소유 대사 편집과 JSON 가져오기·내보내기가 구현되어 있다. 실제 사용 흐름·테스트·패키지와 미검증 범위는 [0.3.0 검증 기록](../VALIDATION-0.3.0.md)에 정리한다. 기존 [0.2 검증](../VALIDATION-0.2.0.md)을 새 기능의 증거로 사용하지 않는다.

캐릭터팩은 이름·성격·텍스트 표정·등록 대사를 옮기는 콘텐츠다. [선택 위젯 22개](../widgets/catalog.md)와 위젯 설치기는 아직 미구현이며 캐릭터팩 가져오기로 설치되지 않는다. 이미지·스킨·원격 업데이트·마켓·SSP 호환·위젯 사건 반응도 후속 범위다.

## 실제 사용 흐름

본체 메뉴에서 **캐릭터 관리**를 연다. 관리 화면은 보조 창이며 기본 바탕화면은 작은 A/B 본체와 일시 말풍선을 유지한다.

1. 설치된 캐릭터를 선택하거나 새 캐릭터를 만든다. 이름·소개·성격·6개 텍스트 표정·인사·개별 수다를 편집하고 저장한다.
2. 선택 캐릭터를 A 또는 B 자리에 적용한다. 둘의 조합도 함께 적용할 수 있다. 같은 로컬 캐릭터를 두 자리에 쓰려면 먼저 복제한다.
3. 대사 편집에서 선택 캐릭터 하나 또는 현재 둘의 조합을 대상으로 장면·키워드 대사를 저장한다. 개인 단어장과 별도로 캐릭터·조합에 소유된다.
4. 공유할 때는 저장된 캐릭터 하나 또는 현재 둘을 선택한다. 기본 제외된 개인 단어장은 필요한 항목만 명시적으로 선택한다.
5. 네이티브 파일 저장 창에서 JSON을 저장한다. 받는 사람은 파일 선택 → 내용 미리보기 → 가져오기 → 원하는 자리 적용 순서로 사용한다. 가져오기만으로 현재 캐릭터를 바꾸지 않는다.

편집 중인 미저장 내용은 공유 파일에 포함되지 않는다. 캐릭터를 제거하면 사용 중인 자리는 기본 캐릭터로 돌아가며, 과거 기록·관계는 삭제하지 않는다. 기본 캐릭터는 제거할 수 없다.

예제 파일은 저장소의 `examples/character-packs/sol-and-dal.comet-character.json`이다. 솔·달 두 명, 장면 두 개와 `별사탕` 키워드의 A→A→B 대사를 포함한다. 앞뒤 공백과 빈 줄을 포함해 정확 재생을 확인할 수 있다.

## 공유 파일 규격

첫 구현은 ZIP 제안 대신 **UTF-8 JSON**을 사용한다. 권장 파일명은 `*.comet-character.json`이며 파일 선택기는 JSON을 받는다. `formatVersion`은 `1`, 전체 크기는 최대 **1 MiB**다. 외부 코드·이미지·별도 manifest를 묶지 않는다. 알 수 없는 필드와 잘못된 대사 구조를 거절한다.

| 범위 | 필드·제약 |
| --- | --- |
| 팩 | `formatVersion`, `name`(1~80자), `author`(최대 120자), `license`(최대 2,000자), `characters`, `pairScenes`, `wordbook` |
| 캐릭터 수 | 1~2명. 팩 내부 `sourceId` 중복 금지 |
| 정의 | `sourceId`(1~128자), `version`(1 이상 정수), `name`(1~40자), `description`(최대 500자), `personality`(최대 500자), `expressions`, `greeting`, `idleLines` |
| 텍스트 표정 | 평온·기쁨·호기심·생각중·걱정·장난 정확히 6개 키. 각 표시 문자열 1~40자 |
| 인사·개별 수다 | `greeting` 1~8줄, `idleLines` 1~32줄. 각 줄은 `expression`, `text` |
| 장면 | `pairScenes` 최대 64개, 장면당 1~8줄. 각 줄은 `persona`, `expression`, `text` |
| 본문 | 각 대사 1~500자, 공백만 있는 본문 거절. 등록 원문 자체는 다듬지 않음 |
| 키워드 대사 | `wordbook` 최대 100개. UUID `id`, 제목 1~80자, 키워드 1~20개·각 1~80자, 1~8줄, `enabled`, `useForIdle` |

키워드는 항목 안에서 대소문자를 무시한 중복을 거절한다. 단일 캐릭터 팩의 대사 화자는 `a`만 사용한다. 두 명 팩에서는 `a`가 첫 캐릭터, `b`가 두 번째 캐릭터를 뜻하며 적용한 자리로 연결한다. 작성 장면에는 같은 화자의 연속 대사를 허용한다. 이는 LLM 자동 장면의 교대 규칙과 별개다.

`author`와 `license`는 공유 콘텐츠 설명이며 인증된 제작자나 자동으로 부여되는 권리를 뜻하지 않는다. 빈 값도 허용한다. 저장은 검증된 JSON을 임시 파일에 쓴 뒤 대상 파일로 교체한다.

## 로컬 정체성과 기록

A/B는 자리다. 설치된 캐릭터에는 별도 로컬 ID가 있으며, 공유 정의의 `sourceId`와 관계를 구분한다. 새로 만든 캐릭터와 가져온 캐릭터에는 새 로컬 UUID를 부여한다. 내장 기본 ID는 `builtin-a`, `builtin-b`다.

- 같은 로컬 캐릭터 편집은 ID·관계를 유지하고 정의 버전을 올린다.
- 복제와 재가져오기는 새 로컬 캐릭터다. 같은 이름·`sourceId`라도 덮어쓰거나 기존 친밀도를 이어받지 않는다.
- 내보낼 때 `sourceId`를 팩 내부의 `character-1`, `character-2`로 다시 부여한다. 공유 ID로 다른 기기의 로컬 정체성을 연결하지 않는다.
- 새 캐릭터의 친밀도는 20에서 시작한다. 기존 캐릭터를 다시 선택하면 저장된 관계를 복원한다.
- 메시지 원문 JSON과 기존 친밀도 표는 보존하고 별도 표에 당시 로컬 ID·이름·정의 버전을 기록한다. 이름 변경이 과거 화자를 소급 변경하지 않는다.
- 기존 A/B 기록·친밀도는 내장 ID로 한 번 이전한다. 늦게 분석한 사용자 발화도 당시 대상 캐릭터에 귀속한다.
- 생성 문맥은 캐릭터의 과거 경험을 구분한다. 공통 사용자 사실 기억은 보존하며 허구 설정과 섞지 않는다.

교체·활성 정의 변경은 진행 중인 재생과 준비 결과를 무효화한다. 교체 전 요청을 현재 캐릭터에게 재시도해 다른 캐릭터의 답변으로 저장하지 않는다. 관계 규칙과 사용자 사실의 근거는 [대화와 기억](conversation.md)을 따른다.

## 대사의 소유권과 공유 범위

**개인 활성 단어장 → 현재 캐릭터·조합의 활성 단어장 → 일반 대화** 순서로 처리하며 모델 준비 확인보다 먼저 매칭한다. 각 범위에서 긴 키워드·동률 등록 순서를 따른다. 본문·공백·빈 줄·화자 순서를 바꾸거나 캐릭터 이름을 암묵적으로 치환하지 않는다.

개인 단어장의 A/B는 현재 자리다. 특정 캐릭터에 개인 항목을 묶는 UI는 아직 없다. 구현된 캐릭터 소유 대사 편집기는 별도 기능이며 한 캐릭터 또는 두 캐릭터의 조합에 대사를 저장한다. 상대가 교체되면 이전 조합 전용 대사를 사용하지 않는다. 혼합 조합에는 각 캐릭터의 개별 수다를 사용할 수 있다.

| 공유 내용 | 처리 |
| --- | --- |
| 저장된 정의·텍스트 표정·캐릭터 소유 대사 | 선택 대상의 공유 콘텐츠로 포함 |
| 개인 단어장 | 기본 제외. 사용자가 선택한 항목만 포함하며 내보낼 대상에 없는 화자는 거절 |
| 원문 대화·사용자 기억·친밀도 | 제외 |
| API 키·모델·연결 정보·투두·일정·위젯 개인 상태 | 제외 |

## 후속 범위와 검증

이미지 자산·스킨, 원격 마켓·자동 업데이트, 기존 우카가카·SSP 형식, 위젯 사건용 대사 연결, 개인 단어장 캐릭터 한정 UI는 아직 구현하지 않았다. 재가져오기를 자동 업데이트처럼 안내하지 않는다.

최종 검증에서는 모델 없는 적용·인사·키워드, A→A→B와 공백 보존, 내보내기·재가져오기, 교체·복귀·이름 변경 시 기록·관계, 늦은 응답 거부와 개인 데이터 제외를 구분해 확인한다. 소스 구현과 실제 패키지 검증 결과를 별도로 기록한다.

규격·공유 범위·정체성·단어장 우선순위를 바꾸면 이 문서와 [상태표](../status.md)를 함께 갱신한다.
