# 캐릭터 교체와 공유

**상태: 2026-09-19 소스 구현.** 1~8명 관리·대화, 캐릭터 소유 대사, JSON v2 공유와 v1 읽기를 다룬다. 최신 코드·자동 검증·실제 데스크톱 검증은 [상태표](../status.md)에서 구분한다. [0.3.0 검증 기록](../VALIDATION-0.3.0.md)은 당시 2명 구성을 검증한 기록이며 이번 확장의 증거로 사용하지 않는다.

캐릭터팩은 이름·성격·표정(텍스트와 이미지)·등록 대사를 옮기는 콘텐츠다. [선택 위젯 22개](../widgets/catalog.md)와 설치기는 별도로 구현되어 있으며 캐릭터팩 가져오기로 설치되지 않는다. 위젯 사건 반응은 별도의 [`.talk` 대본](talk.md)으로 작성한다. 실행 코드와 `.talk` 파일은 캐릭터팩에 넣지 않는다. 원격 마켓·캐릭터팩 자동 업데이트·SSP 호환은 제공하지 않는다.

## 표정과 표정 이미지

**상태: 2026-09-16 소스 구현. 네이티브 검증은 별도 기록 전까지 미완료.** 표정은 캐릭터마다 자유롭게 추가·삭제하는 이름 목록이다. 기본 표정 `평온`은 삭제할 수 없으며, 대사·`.talk` 대본·LLM 응답의 표정이 캐릭터에 없으면 `평온`으로 표시한다. 표정마다 텍스트 표정(1~40자)을 두고, 저장된 캐릭터에는 표정별 이미지를 붙일 수 있다.

| 항목 | 규칙 |
| --- | --- |
| 표정 이름 | 앞뒤 공백 없는 1~20자, 캐릭터당 1~24개, `평온` 필수 |
| 이미지 형식 | SVG·PNG·GIF·WebP·JPEG. 확장자가 아니라 파일 내용으로 판별하며 2 MiB 이하 |
| 이미지 저장 | `nanika.sqlite`의 `character_sprites` 표. 캐릭터 제거 시 함께 삭제, 복제 시 함께 복사 |
| 본체 표시 | 현재 표정의 이미지를 `spriteSize`(32~512px, 기본 64) 정사각형으로 상자·배경·창 그림자 없이 투명 창에 표시하고 내부 × 버튼은 감춘다(숨기기는 메뉴). 본체 창 크기는 이미지 크기에 맞춰 자동 조정한다. 그 표정에 이미지가 없으면 `평온` 이미지, `평온` 이미지도 없으면 기존 112×88 상자와 텍스트 표정 |
| 따로 움직이는 텍스트 표정 | 캐릭터 설정 `faceIcon`이 켜진 경우 `face-<characterId>` 투명 창에 같은 표정의 텍스트 표정을 표시한다. 처음에는 본체 오른쪽에 두고 이후 위치는 사용자가 끌어서 정하며 창 위치를 저장한다. 숨기기 때 함께 숨긴다. 기본 꺼짐 |
| 말풍선 화자 이름 | 화자가 이미지로 표시되는 동안에는 말풍선 머리글의 이름을 생략한다 |
| 말풍선 이미지 | 예약 키 `$balloon`으로 캐릭터마다 말풍선 스킨 이미지를 하나 붙인다. 현재 화자의 캐릭터 이미지를 쓰며, 말풍선이 이미지보다 커지면 CSS `border-image` 9-slice로 **정중앙 1px 행·열만** 늘린다(홀수 크기 권장). 말풍선 창은 투명·그림자 없음이고 이미지가 없는 화자는 기존 상자 스타일이다. 표정 이름은 `$`로 시작할 수 없다 |
| 삭제 규칙 | 표정을 삭제하고 저장하면 그 표정의 이미지도 삭제한다. 삭제한 표정을 쓰는 대사는 지우지 않고 `평온`으로 표시한다 |

이미지는 `sprite://` 내부 주소로 본체에 전달하며 상태 이벤트에 이미지 바이트를 싣지 않는다. 캐릭터 본체 창은 투명 창으로 만들며 macOS에서는 Tauri `macOSPrivateApi`를 켠다. 브라우저 미리보기는 이미지를 표시하지 않는다. 예제는 [별꼬리 캐릭터팩](../../examples/character-packs/byulkkori.comet-character.json)이며 9가지 표정 SVG를 포함한다.

## 실제 사용 흐름

본체 메뉴에서 **캐릭터 관리**를 연다. 관리 화면은 보조 창이며 기본 바탕화면은 작은 본체와 하나의 공용 말풍선을 유지한다. 새 설치에서는 그림 없는 기존 A/B의 텍스트 얼굴·성격·대화를 사용한다. 이 기본 콘텐츠는 `src-tauri/content/default.comet-character.json`에 들어 있고 처음 한 번만 등록한다. 기존 사용자 캐릭터와 정의는 덮어쓰지 않는다.

1. 설치된 캐릭터를 선택하거나 새 캐릭터를 만든다. 이름·소개·성격·표정 목록과 텍스트 표정·인사·개별 수다를 편집하고 저장한다. 저장한 뒤 표정마다 이미지를 붙인다.
2. 선택 캐릭터를 "함께 지내기"로 바탕화면 목록에 넣거나 "내보내기"로 빼고, "앞으로 / 뒤로"로 순서를 바꾼다. 목록은 1~8명이며 마지막 1명은 내보낼 수 없다. 같은 로컬 캐릭터를 두 번 두려면 먼저 복제한다. 모든 활성 캐릭터에서 메뉴와 직접 대화를 사용할 수 있다.
3. 대사 편집에서 선택 캐릭터 하나 또는 현재 활성 캐릭터의 조합을 대상으로 장면·키워드 대사를 저장한다. 개인 단어장과 별도로 캐릭터·조합에 소유된다.
4. 공유할 때는 저장된 캐릭터 하나 또는 현재 함께 지내는 조합을 선택한다. 기본 제외된 개인 단어장은 필요한 항목만 명시적으로 선택한다.
5. 네이티브 파일 저장 창에서 JSON을 저장한다. 받는 사람은 파일 선택 → 내용 미리보기 → 가져오기 → 함께 지내기 순서로 사용한다. 가져오기만으로 현재 목록을 바꾸지 않는다.

편집 중인 미저장 내용은 공유 파일에 포함되지 않는다. 캐릭터를 제거하면 바탕화면 목록에서도 빠지고, 과거 기록·관계는 삭제하지 않는다. 기본 캐릭터 A/B도 제거할 수 있다. 마지막 활성 캐릭터는 다른 캐릭터를 먼저 함께 지내게 한 뒤 제거해야 한다. 삭제한 기본 캐릭터는 재시작 때 되살리지 않는다. 화면을 비우려면 숨기기를 사용한다.

### 관리 화면 구성

설치 목록과 함께 지내는 순서를 유지하며, 선택 캐릭터의 작업을 세 탭으로 나눈다. 화면 검증 범위는 [상태표](../status.md)를 따른다.

| 탭 | 편집 대상 |
| --- | --- |
| 기본 정보 | 이름·소개·성격·표정과 캐릭터 정의에 포함되는 인사·개별 자동 수다. 같은 저장·수정 취소를 사용한다. |
| 등록 대사 | 선택 캐릭터 또는 활성 조합의 키워드 대사·장면. 개인 단어장과 소유권을 구별해 안내한다. |
| 공유 | 저장된 캐릭터·조합 내보내기, 파일 미리보기와 가져오기. |

탭을 옮겨도 초안을 유지한다. 기본 정보의 수정은 캐릭터별로 남고, 대사 편집 중에는 대상 선택을 잠가 다른 캐릭터에 잘못 저장하지 않게 한다. 미저장 상태에서 적용·공유가 제한되면 이유를 표시한다. 새 캐릭터는 먼저 저장한 뒤 등록 대사와 공유를 사용할 수 있다. 캐릭터 수정 취소는 저장 버튼 옆에 두며 좁은 화면에서는 목록과 편집기를 세로로 배치한다.

예제 파일은 저장소의 `examples/character-packs/sol-and-dal.comet-character.json`이다. 솔·달 두 명, 장면 두 개와 `별사탕` 키워드의 A→A→B 대사를 포함한다. 앞뒤 공백과 빈 줄을 포함해 정확 재생을 확인할 수 있다.

## 공유 파일 규격

첫 구현은 ZIP 제안 대신 **UTF-8 JSON**을 사용한다. 권장 파일명은 `*.comet-character.json`이며 파일 선택기는 JSON을 받는다. 내보내기는 `formatVersion: 2`이며 기존 `formatVersion: 1` 파일을 계속 읽는다. 전체 크기는 최대 **32 MiB**다. 표정 이미지는 `sprites`에 base64로 넣으며 외부 코드·별도 manifest를 묶지 않는다. 알 수 없는 필드와 잘못된 대사 구조를 거절한다.

| 범위 | 필드·제약 |
| --- | --- |
| 팩 | `formatVersion`, `name`(1~80자), `author`(최대 120자), 선택 `sourceUrl`(빈 값 또는 HTTPS URL, 최대 2,048자), `license`(최대 2,000자), `characters`, `pairScenes`, `wordbook`, 선택 `sprites` |
| 캐릭터 수 | v2는 1~8명, v1은 1~2명. 팩 내부 `sourceId` 중복 금지 |
| 정의 | `sourceId`(1~128자), `version`(1 이상 정수), `name`(1~40자), `description`(최대 500자), `personality`(최대 500자), `expressions`, 선택 `faceIcon`(기본 false), 선택 `spriteSize`(32~512, 기본 64), `greeting`, `idleLines` |
| 텍스트 표정 | 1~24개 키, `평온` 필수. 키 1~20자, 각 표시 문자열 1~40자 |
| 표정 이미지 | `sprites` 항목마다 `sourceId`, `expression`, `mime`, base64 `data`. 대상 캐릭터의 표정에 있거나 예약 키 `$balloon`(말풍선 이미지)이어야 하며 같은 표정 중복 금지, 내용으로 판별한 형식이 `mime`과 일치, 2 MiB 이하 |
| 인사·개별 수다 | `greeting` 1~8줄, `idleLines` 1~32줄. 각 줄은 `expression`, `text` |
| 장면 | `pairScenes` 최대 64개, 장면당 1~8줄. v2 각 줄은 `speaker`, `expression`, `text`; v1은 `speaker` 대신 `persona` |
| 본문 | 각 대사 1~500자, 공백만 있는 본문 거절. 등록 원문 자체는 다듬지 않음 |
| 키워드 대사 | `wordbook` 최대 100개. UUID `id`, 제목 1~80자, 키워드 1~20개·각 1~80자, 1~8줄, `enabled`, `useForIdle` |

키워드는 항목 안에서 대소문자를 무시한 중복을 거절한다. v2의 `speaker`는 팩 안 캐릭터 정의의 `sourceId`를 참조한다. 정의 목록을 재정렬해도 대사의 화자는 같은 캐릭터를 가리킨다. v1의 `persona: a/b`는 첫째·둘째 캐릭터에 대응시켜 읽는다. 없는 화자, 중복 sourceId, 잘못된 이미지 참조는 설치 전에 거절한다. 작성 장면은 같은 화자의 연속 대사와 원문 공백을 유지한다.

`author`, `sourceUrl`, `license`는 콘텐츠 설명이며 인증된 제작자나 자동으로 부여되는 권리를 뜻하지 않는다. 미확정 제작자·출처는 빈 값으로 시작한다. 공유 화면은 선택한 캐릭터의 원본 패키지 정보를 불러오며, 출처 저장은 같은 패키지에 속한 모든 캐릭터에 적용된다. 저장한 값은 앱 재시작과 내보내기 후에도 유지한다. 원본 패키지가 없는 로컬 생성 캐릭터는 이 편집 대상이 아니다. 저장은 검증된 JSON을 임시 파일에 쓴 뒤 대상 파일로 교체한다.

GitHub의 패키지 목록에서 파일을 받아 미리본 후 설치한다. 재가져오기는 새 로컬 복사본이며 자동 업데이트가 아니다. 별꼬리 콘텐츠의 공식 Comet 배포는 원작자 허락 범위에 따른다. 수정·파생 제작·재배포 금지와 출처 표시 조건은 `examples/character-packs/byulkkori.LICENSE.txt`에 별도로 두며, 앱 코드의 라이선스를 자산에 적용하지 않는다. 확인되지 않은 제작자 이름이나 출처 URL을 추정해서 채우지 않는다.

## 로컬 정체성과 기록

개인 단어장의 A~H는 바탕화면 순서 1~8의 자리 표기다. 실제 대화 명령·재생·기록은 캐릭터 ID를 사용한다. 설치된 캐릭터에는 별도 로컬 ID가 있으며, 공유 정의의 `sourceId`와 관계를 구분한다. 새로 만든 캐릭터와 가져온 캐릭터에는 새 로컬 UUID를 부여한다. 내장 기본 ID는 `builtin-a`, `builtin-b`다.

- 같은 로컬 캐릭터 편집은 ID·관계를 유지하고 정의 버전을 올린다.
- 복제와 재가져오기는 새 로컬 캐릭터다. 같은 이름·`sourceId`라도 덮어쓰거나 기존 친밀도를 이어받지 않는다.
- 내보낼 때 `sourceId`를 팩 내부의 `character-1`부터 `character-8`까지 다시 부여한다. 공유 ID로 다른 기기의 로컬 정체성을 연결하지 않는다.
- 새 캐릭터의 친밀도는 20에서 시작한다. 기존 캐릭터를 다시 선택하면 저장된 관계를 복원한다.
- 메시지 원문 JSON과 기존 친밀도 표는 보존하고 별도 표에 당시 로컬 ID·이름·정의 버전을 기록한다. 이름 변경이 과거 화자를 소급 변경하지 않는다.
- 기존 A/B 기록·친밀도는 내장 ID로 한 번 이전한다. 늦게 분석한 사용자 발화도 당시 대상 캐릭터에 귀속한다.
- 생성 문맥은 캐릭터의 과거 경험을 구분한다. 공통 사용자 사실 기억은 보존하며 허구 설정과 섞지 않는다.

교체·활성 정의 변경은 진행 중인 재생과 준비 결과를 무효화한다. 교체 전 요청을 현재 캐릭터에게 재시도해 다른 캐릭터의 답변으로 저장하지 않는다. 관계 규칙과 사용자 사실의 근거는 [대화와 기억](conversation.md)을 따른다.

## 대사의 소유권과 공유 범위

**개인 활성 단어장 → 현재 캐릭터·조합의 활성 단어장 → 일반 대화** 순서로 처리하며 모델 준비 확인보다 먼저 매칭한다. 각 범위에서 긴 키워드·동률 등록 순서를 따른다. 본문·공백·빈 줄·화자 순서를 바꾸거나 캐릭터 이름을 암묵적으로 치환하지 않는다.

개인 단어장의 A~H는 현재 자리다. 기존 A/B 항목을 현재 캐릭터 ID에 고정 이전하지 않는다. 캐릭터 소유 대사 편집기는 별도 기능이며 1~8명의 정렬된 로컬 ID 집합을 소유 범위로 저장한다. 편집 화면의 A~H는 선택한 조합 안의 순서다. 상대가 교체되면 이전 조합 전용 대사를 사용하지 않는다. 혼합 조합에는 각 캐릭터의 개별 수다를 사용할 수 있다.

필요한 화자·소유 조합이 없으면 장면 전체를 후보에서 제외한다. 없는 화자의 줄만 지우거나 다른 캐릭터에게 넘기지 않는다. 재생할 때 자리 참조를 실제 ID로 해석하며, 진행 중 조합 변경은 작업 epoch/revision으로 나머지 재생을 취소한다.

| 공유 내용 | 처리 |
| --- | --- |
| 저장된 정의·텍스트 표정·표정 이미지·캐릭터 소유 대사 | 선택 대상의 공유 콘텐츠로 포함. 저장된 팩 기록에는 이미지를 중복 저장하지 않음 |
| 개인 단어장 | 기본 제외. 사용자가 선택한 항목만 포함하며 내보낼 대상에 없는 화자는 거절 |
| `.talk` 대본 파일 | 이 JSON 규격에 포함하지 않음. 파일로 별도 관리하며 `pair`·`cast`는 로컬 캐릭터 ID를 사용 |
| 원문 대화·사용자 기억·친밀도 | 제외 |
| API 키·모델·연결 정보·투두·일정·위젯 개인 상태 | 제외 |

## 후속 범위와 검증

스킨·애니메이션 시퀀스, 원격 마켓·캐릭터팩 자동 업데이트, 기존 우카가카·SSP 형식, `.talk` 대본의 캐릭터팩 가져오기·내보내기 연동, 개인 단어장 캐릭터 한정 UI는 아직 구현하지 않았다. 표정 이미지는 정지 이미지 또는 GIF 한 장이며 표정별 프레임 시퀀스는 지원하지 않는다. 재가져오기를 자동 업데이트처럼 안내하지 않는다.

최종 검증에서는 모델 없는 적용·인사·키워드, A→A→B와 공백 보존, 내보내기·재가져오기, 교체·복귀·이름 변경 시 기록·관계, 늦은 응답 거부와 개인 데이터 제외를 구분해 확인한다. 소스 구현과 실제 패키지 검증 결과를 별도로 기록한다.

규격·공유 범위·정체성·단어장 우선순위를 바꾸면 이 문서와 [상태표](../status.md)를 함께 갱신한다.
