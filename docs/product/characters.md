# 캐릭터 교체와 공유

**상태: 2026-09-24 애니메이션·반응 확장 구현·macOS QA 검증 완료.** 1~8명 관리·대화, 설치한 캐릭터팩 선택, 캐릭터 소유 대사·스프라이트 동작·행동 반응, JSON v2~v5 공유와 v1 읽기를 다룬다. 최신 코드·자동 검증·실제 데스크톱 검증은 [상태표](../status.md)에서 구분한다. [0.3.0 검증 기록](../VALIDATION-0.3.0.md)은 당시 2명 구성을 검증한 기록이며 이번 확장의 증거로 사용하지 않는다.

캐릭터팩은 이름·성격·지침·캐릭터 간 관계·표정(텍스트와 이미지)·스프라이트 동작·등록 대사를 옮기는 콘텐츠다. [선택 위젯 22개](../widgets/catalog.md)와 설치기는 별도로 구현되어 있으며 캐릭터팩 가져오기로 설치되지 않는다. 위젯 사건에는 [캐릭터 반응](character-reactions.md) 또는 별도의 [`.talk` 대본](talk.md)을 연결한다. 새 반응을 등록한 사건은 그 반응이 우선하며 미등록 사건은 기존 대본을 유지한다. 실행 코드와 `.talk` 파일은 캐릭터팩에 넣지 않는다. 원격 마켓·캐릭터팩 자동 업데이트·SSP 호환은 제공하지 않는다.

## 지침과 다른 캐릭터와의 관계

**상태: 2026-09-22 소스 구현.** 설정 → 캐릭터 → 프로필에서 성격·말투와 별도로 **지침**을 적고 **다른 캐릭터와의 관계**를 설정한다. 지침은 “질문은 한 번에 하나씩 하기”, 관계는 “오래 알고 지낸 친구. 장난을 치지만 고민할 때는 진지하게 듣는다”처럼 작성할 수 있다. 저장한 설정은 직접 LLM 대화와 자동 생성 대화의 문맥으로 전달한다. 작성된 인사·자동 수다·단어장·`.talk` 원문은 이 설정으로 다시 쓰지 않는다.

| 항목 | 저장 규칙 |
| --- | --- |
| `instructions` | 선택 문자열, 최대 2,000자. 생략한 기존 정의는 빈 문자열 |
| `relationships` | 선택 배열, 최대 32개. 생략한 기존 정의는 빈 배열 |
| 관계 항목 | `targetId`와 `description`(공백만인 값 제외, 1~500자). 같은 대상 중복과 자기 자신은 허용하지 않음 |
| 관계 방향 | 선택 캐릭터가 상대를 대하는 방식. 반대쪽 관계는 자동 생성하지 않고 상대 캐릭터에서 따로 편집 |
| 대상 | 함께 지내는지와 무관하게 보유 중인 다른 캐릭터. 로컬 ID로 연결하므로 이름·순서 변경이나 같은 이름의 다른 캐릭터와 혼동하지 않음 |

편집한 지침과 관계는 기존 캐릭터 저장·취소·초안 보존을 함께 사용한다. 저장은 현재 정의를 갱신하며 원문 기록·사용자 기억·친밀도를 초기화하지 않는다. 활성 캐릭터 설정을 저장하거나 그 관계에 연결된 상대의 이름·존재 여부가 바뀌면 이전 설정으로 준비하거나 재생하던 대화를 기존 중단 경계에서 무효화한다. 무관한 비활성 캐릭터 편집은 대화를 중단하지 않는다. 사용자와의 친밀도 점수와 캐릭터끼리 작성한 관계 설정은 별개다.

상대를 보유 목록에서 제거해도 작성한 관계 문장은 보존한다. 편집 화면은 삭제된 대상으로 표시해 수정·제거할 수 있게 하고, LLM 문맥에는 존재하지 않는 대상을 넣지 않는다. 같은 이름의 캐릭터를 다시 가져와도 자동으로 관계를 이어 붙이지 않는다. 복제는 원래 캐릭터가 다른 캐릭터를 향해 가진 관계를 복사하며, 다른 캐릭터들이 복제본을 향한 관계를 자동으로 만들지 않는다.

공유 파일은 지침과 **함께 내보내는 캐릭터 사이의 관계만** 포함한다. `targetId`는 팩 안의 `sourceId`로 변환하고, 가져올 때 새 로컬 ID로 다시 연결한다. 단독 내보내기에는 다른 캐릭터에 대한 관계가 포함되지 않는다. 팩에 없는 대상·자기 자신·중복 대상은 가져오기 전에 거절한다. 기존 v1·v2 파일은 새 필드 없이 계속 읽는다.

지침은 캐릭터의 행동·화법을 정하는 용도다. 앱의 출력 형식·허용 화자·사용자 사실 근거·스토리 공개 규칙이나 도구 실행 권한을 바꾸지 않는다. 모델에 전달할 때는 상대 ID와 현재 이름을 함께 제공하며 한쪽 관계를 상호 관계로 해석하지 않도록 명시한다. 긴 설정은 모델 입력 예산에 따라 일부가 생략될 수 있고, 저장한 원문은 보존한다. 모델이 설정을 항상 준수하는지는 별도의 의미 품질 검증 대상이다.

## 표정과 표정 이미지

**상태: 2026-09-16 소스 구현. 네이티브 검증은 별도 기록 전까지 미완료.** 표정은 캐릭터마다 자유롭게 추가·삭제하는 이름 목록이다. 기본 표정 `평온`은 삭제할 수 없으며, 대사·`.talk` 대본·LLM 응답의 표정이 캐릭터에 없으면 `평온`으로 표시한다. 표정마다 텍스트 표정(1~40자)을 두고, 저장된 캐릭터에는 표정별 이미지를 붙일 수 있다.

| 항목 | 규칙 |
| --- | --- |
| 표정 이름 | 앞뒤 공백 없는 1~20자, 캐릭터당 1~24개, `평온` 필수 |
| 이미지 형식 | SVG·PNG·GIF·WebP·JPEG. 확장자가 아니라 파일 내용으로 판별하며 2 MiB 이하 |
| 이미지 저장 | `comet.sqlite`의 `character_sprites` 표. 캐릭터 제거 시 함께 삭제, 복제 시 함께 복사 |
| 본체 표시 | 현재 표정의 이미지를 `spriteSize`(32~512px, 기본 64) 정사각형으로 상자·배경·창 그림자 없이 투명 창에 표시하고 내부 × 버튼은 감춘다(숨기기는 메뉴). 본체 창 크기는 이미지 크기에 맞춰 자동 조정한다. 그 표정에 이미지가 없으면 `평온` 이미지, `평온` 이미지도 없으면 기존 112×88 상자와 텍스트 표정 |
| 따로 움직이는 텍스트 표정 | 캐릭터 설정 `faceIcon`이 켜진 경우 `face-<characterId>` 투명 창에 같은 표정의 텍스트 표정을 표시한다. 처음에는 본체 오른쪽에 두고 이후 위치는 사용자가 끌어서 정하며 창 위치를 저장한다. 숨기기 때 함께 숨긴다. 기본 꺼짐 |
| 말풍선 화자 이름 | 대사·선택지 스토리에서는 이미지 유무와 관계없이 이름 머리글 전체(여백·구분선 포함)를 표시하지 않는다. 모서리의 닫기 버튼과 Escape는 유지하며 메뉴·입력·기록에는 기존 제목과 탐색을 표시한다 |
| 말풍선 이미지 | 예약 키 `$balloon`으로 캐릭터마다 말풍선 스킨 이미지를 하나 붙인다. 현재 화자의 캐릭터 이미지를 쓰며, 말풍선이 이미지보다 커지면 CSS `border-image` 9-slice로 **정중앙 1px 행·열만** 늘린다(홀수 크기 권장). 이미지에 어두운 밑색·덮개를 더하지 않고 로딩·화자 전환 중에도 창 배경과 기본 테두리를 투명하게 유지한다. 말풍선 창은 그림자가 없으며 이미지가 없는 화자는 기존 상자 스타일이다. 표정 이름은 `$`로 시작할 수 없다 |
| 말풍선 글자 | 설정 → 캐릭터 → 말풍선에서 글자 크기·색·폰트를 캐릭터별로 편집하고 캐릭터 저장으로 반영한다. 대사와 선택지 스토리 본문은 현재 화자의 설정을 사용하며 메뉴·입력·기록의 UI 서식은 유지한다 |
| 글자 출력 속도 | 캐릭터별 초당 0~100글자. 0은 기존처럼 즉시 표시하며 1~100은 한 글자씩 출력한다. 조합 문자·이모지는 묶어서 표시하고 대사 전체의 크기를 먼저 확보한다. 선택지 스토리는 선택을 바로 읽도록 전체 본문을 표시한다 |
| 삭제 규칙 | 표정을 삭제하고 저장하면 그 표정의 이미지도 삭제한다. 삭제한 표정을 쓰는 대사는 지우지 않고 `평온`으로 표시한다 |

`balloonStyle`은 기존 정의에서 생략할 수 있다. `fontSize`는 12~40px 정수(기본 19), `fontFamily`는 제어문자 없는 100자 이하의 설치된 폰트 이름(기본 빈 문자열), `textColor`는 `#RRGGBB` 또는 `null`(기본색), `textSpeed`는 0~100 정수(초당 글자 수, 기본 0)다. 빈 폰트는 기존 앱 글꼴을 쓰며 지정한 폰트가 없으면 시스템 글꼴로 표시한다. 폰트 파일을 내려받거나 팩에 동봉하지 않는다. 편집 미리보기·저장·취소는 기존 캐릭터 초안을 따르고, 복제·팩 공유에는 글자 설정이 포함된다. 설정 변경으로 원문·기억·친밀도를 초기화하지 않는다.

이미지는 `sprite://` 내부 주소로 본체에 전달하며 상태 이벤트에 이미지 바이트를 싣지 않는다. 캐릭터 본체 창은 투명 창으로 만들며 macOS에서는 Tauri `macOSPrivateApi`를 켠다. 브라우저 미리보기는 이미지를 표시하지 않는다. 예제는 [별꼬리 캐릭터팩](../../examples/character-packs/byulkkori.comet-character.json)이며 9가지 표정 SVG를 포함한다.

2026-09-22 표시 보정은 현재 화자의 표정과 `평온` 대체 이미지에 맞춰 네이티브 본체 크기와 분리 표정 창의 표시를 함께 결정한다. 다른 표정에만 이미지가 있다는 이유로 텍스트 본체를 이미지 크기로 줄이지 않는다. 32px 이미지도 텍스트 본체의 최소 높이 제한을 적용하지 않는다. 실제 화면 검증 범위는 [상태표](../status.md)에서 구분한다.

장난감은 이미지의 투명 영역을 제외한 본체에 충돌한다. 표시 크기와 현재 표정에 맞춘 alpha 외곽을 캐시하고, 이동·숨김·비활성화에 맞춰 갱신한다. 이미지 없는 본체는 버튼 영역을 사용하며 별도 텍스트 표정과 말풍선은 충돌 대상이 아니다. 표본 해상도와 애니메이션 이미지의 제한은 [장난감 물리 계약](toys.md#바탕화면-물리-계약)을 따른다.

## 실제 사용 흐름

본체 메뉴의 **캐릭터 관리**는 [통합 설정창](settings.md)의 **캐릭터** 탭을 연다. 설정에서 직접 캐릭터 탭으로 이동해도 같은 작업 영역을 사용하며 별도 관리창을 만들지 않는다. 기본 바탕화면은 작은 본체와 하나의 공용 말풍선을 유지한다.

2026-09-20 후속 결정에 따라 새 설치는 **별꼬리 한 명**으로 시작한다. 공식 별꼬리 이미지팩 `examples/character-packs/byulkkori.comet-character.json`을 처음 한 번 일반 캐릭터팩처럼 가져와 함께 지내게 하며, 이 캐릭터는 다른 가져온 팩과 같은 규칙으로 편집·복제·제거할 수 있다. 같은 날 앞선 결정이던 그림 없는 A/B(`src-tauri/content/default.comet-character.json`, `builtin-a`·`builtin-b`)는 새 설치에 등록하지 않고, 이미 A/B나 나디르·별꼬리를 가진 설치는 그대로 둔다. 어떤 경우에도 사용자가 수정한 정의를 덮어쓰지 않으며 원문 기록·사용자 기억·친밀도도 초기화하지 않는다. 별꼬리의 기본 자동 수다는 [별꼬리 기본 대화팩](talk.md#대화팩과-나만의-대본)이 맡고, 친구를 8명까지 늘리면 같은 팩이 무작위 화자를 고른다.

1. 보유 목록에서 설치된 캐릭터를 선택하거나 새 캐릭터를 만든다. **프로필 / 모습·표정 / 말풍선 / 대사·반응 / 기억 / 설정** 탭에서 항목을 편집하며 캐릭터를 바꿔도 선택한 탭을 유지한다. 캐릭터를 저장한 뒤 표정마다 이미지를 붙인다.
2. 선택 캐릭터를 **함께 지내기**로 바탕화면 목록에 넣거나 **바탕화면에서 빼기**로 빼고 **앞으로 / 뒤로**로 순서를 바꾼다. 목록은 1~8명이며 마지막 1명은 뺄 수 없다. 파일로 내보내기와 보유 목록에서 제거는 별도 행동이다. 같은 로컬 캐릭터를 두 번 두려면 먼저 복제한다. 모든 활성 캐릭터에서 메뉴와 직접 대화를 사용할 수 있다.
3. **대사·반응** 탭에서 선택 캐릭터의 인사·자동 수다를 편집하고, 선택 캐릭터 하나 또는 현재 활성 캐릭터의 조합을 대상으로 키워드 대사·장면을 저장한다. 개인 단어장과 별도로 캐릭터·조합에 소유된다. 사건별 대사·표정·동작 후보도 이 탭에서 편집한다.
4. 선택 캐릭터의 **설정** 탭에서 개별 내보내기를, 목록 관리 영역에서 현재 함께 지내는 조합 내보내기를 연다. 스프라이트는 기본 포함하고 기억·친밀도·대화 기록은 각각 선택한다. 기본 제외된 개인 단어장은 필요한 항목만 명시적으로 선택한다.
5. 네이티브 파일 저장 창에서 JSON을 저장한다. 받는 사람은 파일 선택 → 내용 미리보기 → 가져오기 후, 상단의 **설치한 팩으로 바꾸기**에서 팩을 골라 **이 팩으로 함께 지내기**를 누르거나 캐릭터별 **함께 지내기**를 사용한다. 가져오기만으로 현재 목록을 바꾸지 않는다.

편집 중인 미저장 내용은 공유 파일에 포함되지 않는다. 캐릭터를 제거하면 바탕화면 목록에서도 빠지고, 과거 기록·관계는 삭제하지 않는다. 기본 캐릭터 별꼬리도, 이전 설치의 A/B도 제거할 수 있다. 마지막 활성 캐릭터는 다른 캐릭터를 먼저 함께 지내게 한 뒤 제거해야 한다. 삭제한 기본 캐릭터는 재시작 때 되살리지 않는다. 화면을 비우려면 숨기기를 사용한다.

### 설치한 캐릭터팩 선택

**설정 → 캐릭터** 상단의 현재 바탕화면 구성에서 **설치한 팩으로 바꾸기**를 사용한다. 이미 설치한 팩을 고르면 이름·남아 있는 인원수·함께 지낼 순서를 확인할 수 있다. **이 팩으로 함께 지내기**를 누르면 현재 바탕화면 목록 전체를 그 팩의 캐릭터로 바꾼다. 팩을 고르기만 해서는 바뀌지 않으며, 현재 구성과 캐릭터·순서가 모두 같으면 **함께 지내는 중**으로 표시하고 다시 적용하지 않는다.

- 적용 순서는 처음 팩을 가져왔을 때의 순서다. 그 뒤 제거한 캐릭터는 건너뛰고, 남은 캐릭터가 없는 팩은 목록에서 제외한다.
- 팩 선택은 설치된 로컬 캐릭터를 다시 활성화한다. 수정한 이름·성격·표정·대사, 로컬 ID와 원문 기록·기억·친밀도를 보존하며 원본을 다시 가져오거나 삭제한 캐릭터를 복구하지 않는다.
- 이전 설치의 팩 소속 없는 A/B와 직접 만든 캐릭터는 기존 개별 **함께 지내기**로 조합한다. 복제한 캐릭터는 독립된 1명 팩으로 목록에 나타난다.
- 캐릭터 또는 등록 대사에 미저장 초안이 있으면 먼저 저장하거나 취소해야 한다. 적용 중에는 다른 캐릭터 작업을 잠그고, 전환에 실패하면 오류를 표시한다.
- 구성 변경은 기존 교체와 같은 revision·중단 경계를 사용한다. 이전 캐릭터 구성의 재생과 준비 결과를 무효화하며, 동일 구성 재적용으로 진행 중인 대화를 중단하지 않는다.

설치한 팩이 없으면 캐릭터 작업의 파일 가져오기를 안내한다. 이 선택기는 원격 카탈로그 조회·다운로드·설치를 맡지 않으며, `.talk` 대화팩의 설치 상태도 바꾸지 않는다. 작은 본체와 잠깐 나타나는 말풍선, 모델 없이 동작하는 기본 경험과 데이터 보존이라는 [0.2 제품 계약](../PRODUCT.md)은 유지한다.

### 캐릭터 탭 구성 {#관리-화면-구성}

2026-09-20 승인한 R2는 [통합 설정창](settings.md)의 캐릭터 영역에 보유 목록과 선택 캐릭터 편집을 나란히 둔다. 2026-09-23의 4개 편집 탭에 2026-09-24 기억·설정을 추가해 6개 내부 탭으로 나눈다. 이전의 모든 편집 영역을 한 화면에 펼치는 배치를 대체하며 캐릭터 정의의 저장 경계는 유지한다. 소스와 실제 데스크톱 검증 범위는 [상태표](../status.md)에 구분한다.

보유 목록에는 함께 지내는 친구와 쉬는 친구를 모두 표시하고 활성 순서와 편집 선택을 구분한다. 목록에서 친구를 선택해도 바탕화면 구성은 바뀌지 않는다. 설치 팩 적용은 구성 전체를 바꾸는 별도 작업이다. 선택 캐릭터의 작은 미리보기와 핵심 상태를 편집 영역 가까이에 둔다.

편집 탭은 아래 순서로 둔다. 캐릭터를 바꿔 선택해도 같은 탭을 유지한다. 선택 캐릭터 이름·탭·팩 정보와 정의 편집 탭의 공통 저장은 고정하고 각 탭의 편집 내용만 세로로 스크롤하며 탭별 스크롤 위치를 유지한다. 보유 목록은 별도로 스크롤하고 목록과 편집 영역 사이의 세로 구분선은 내용 길이와 관계없이 작업 영역 하단까지 이어진다. 보유 목록과 함께 지내기·순서 변경·추가·복제·가져오기·조합 내보내기·팩 선택·제거는 탭 밖의 관리 동작으로 둔다. 개별 내보내기는 선택 캐릭터의 설정 탭에서 연다. 작성자·출처 URL 요약은 한 줄로 표시하며 전체 내용 편집은 선택 대상의 보조 작업으로 연다. 라이선스 편집은 제공하지 않는다.

| 내부 탭 | 편집 대상 |
| --- | --- |
| 프로필 | 이름·소개·성격·말투·지침·다른 캐릭터와의 관계. 관계는 선택 캐릭터가 상대를 바라보는 관점이다. |
| 모습·표정 | 텍스트 표정·표정별 이미지·표정 추가와 삭제·본체 이미지 크기·따로 움직이는 텍스트 표정 표시. PNG·APNG 동작 편집·속도 미리보기·평소/말하기/클릭 연결. |
| 말풍선 | 말풍선 이미지·글꼴·글자 크기와 색·출력 속도·글자 미리보기. |
| 대사·반응 | 선택 캐릭터의 인사·자동 수다, 캐릭터 또는 활성 조합의 키워드 대사, 조합의 자동 수다 장면과 대사별 동작. 사건별 대사·표정·동작 후보와 쿨다운·미리보기. |
| 기억 | 선택 캐릭터가 가진 유효한 기억의 유저명·내용·날짜·근거 조회, 개별 수정·잊기. 캐릭터 정의와 별도로 저장한다. |
| 설정 | 개별 내보내기와 스프라이트·기억·친밀도·대화 기록 포함 선택, 모든 사용자의 기억 전체 잊기. 각 명령을 독립 실행한다. |

대사·반응 탭은 **선택 캐릭터 / 현재 함께 지내는 조합**의 소유 범위를 명시하고 개인 단어장과 구별한다. 인사·개별 자동 수다·행동 반응은 선택 캐릭터의 정의에 속하며 조합 대상으로 바꾸지 않는다. 자동 대화 간격·생성 허용, 개인 단어장·대화팩·AI 연결은 [통합 설정창](settings.md)의 전역 영역에서 관리한다. 기억 내용은 캐릭터의 기억 탭에서, 검색 모델·설정·분석 재시도는 AI 연결에서 관리한다.

내부 탭과 다른 설정 영역으로 옮기거나 다른 캐릭터를 선택해도 대상별 초안을 유지한다. 캐릭터 정의에 속한 프로필·모습·말풍선 설정과 인사·개별 자동 수다·행동 반응은 탭과 무관하게 같은 캐릭터 저장·수정 취소를 사용한다. 공통 저장 영역은 이 4개 정의 편집 탭에 두고 수정 취소를 저장 버튼 가까이에 둔다. 기억·설정 탭에는 독립 작업의 조작만 표시한다. 표정·말풍선 이미지는 선택·제거 즉시 저장한다. 애니메이션 이미지·동작·연결은 초안으로 보관하고 공통 캐릭터 저장·취소에 포함한다. 키워드·조합 대사와 패키지 출처는 각각 별도로 저장한다. 다른 대상에 잘못 저장하지 않게 대상과 초안을 연결한다. 미저장 상태에서 구성 적용·공유가 제한되면 이유를 표시한다. 새 캐릭터는 먼저 저장한 뒤 키워드·조합 대사와 기억·공유를 사용할 수 있다. 설정창 숨김과 다시 열기의 초안 보존은 [통합 설정의 초안과 실패](settings.md#초안과-실패)를 따른다.

2026-09-23 결정에 따라 캐릭터 저장 버전은 관리하지 않는다. 편집기의 저장 버전 표시와 공유 미리보기의 캐릭터 버전을 없애며 일반 저장·수정 취소는 유지한다. 이 변경은 캐릭터 관리에 추가됐던 메타데이터만 제거하고 [0.2 제품 계약](../PRODUCT.md)의 원문·기억·친밀도 보존과 내부 revision·재생 중단 경계는 유지한다.

나디르·별꼬리 추가팩은 `examples/character-packs/nadir-and-star-tail.comet-character.json`이다. 공개 소개와 인사·일상·조합 대사를 포함하며 별도로 가져온 뒤 [팩 전체를 선택](#설치한-캐릭터팩-선택)하거나 캐릭터별로 함께 지내기를 선택한다. 개인 단어장은 포함하지 않으며 키워드 원문 재생 규칙은 유지한다.

## 공유 파일 규격

첫 구현은 ZIP 제안 대신 **UTF-8 JSON**을 사용한다. 권장 파일명은 `*.comet-character.json`이며 파일 선택기는 JSON을 받는다. [반응 규칙 또는 대사별 동작](character-reactions.md)을 포함하면 `formatVersion: 5`로 내보낸다. 그 외에는 개인 데이터가 있으면 v4, 애니메이션이 있으면 v3, 둘 다 없으면 v2를 사용한다. v5도 선택적인 [archive](#개인-데이터를-포함한-공유)를 지원하며 v1~v4 파일은 계속 읽는다. 전체 크기는 최대 **32 MiB**다. 표정 이미지는 `sprites`, 애니메이션 이미지는 v3~v5의 `animationAssets`에 base64로 넣으며 외부 코드·별도 manifest를 묶지 않는다. 알 수 없는 필드와 잘못된 대사 구조를 거절한다. 2026-09-23부터 캐릭터 정의의 `version`은 저장하거나 내보내지 않는다. 이전 DB와 공유 파일의 `version`은 호환 읽기에서만 무시하며 나머지 필드는 그대로 읽는다. 새 공유 파일을 이전 앱에서 읽는 역방향 호환은 보장하지 않는다.

| 범위 | 필드·제약 |
| --- | --- |
| 팩 | `formatVersion`, `name`(1~80자), `author`(최대 120자), 선택 `sourceUrl`(빈 값 또는 HTTPS URL, 최대 2,048자), `license`(최대 2,000자), `characters`, `pairScenes`, `wordbook`, 선택 `sprites`·v3~v5 `animationAssets`, v4/v5의 `archive` |
| 캐릭터 수 | v2~v5는 1~8명, v1은 1~2명. 팩 내부 `sourceId` 중복 금지 |
| 정의 | `sourceId`(1~128자), `name`(1~40자), `description`(최대 500자), `personality`(최대 500자), 선택 `instructions`·`relationships`(위 규칙), `expressions`, 선택 `faceIcon`(기본 false), 선택 `spriteSize`(32~512, 기본 64)·`animation`(v3~v5, [동작 규칙](#상황별-스프라이트-재생))·`reactions`(v5, [반응 규칙](character-reactions.md)), `greeting`, `idleLines` |
| 텍스트 표정 | 1~24개 키, `평온` 필수. 키 1~20자, 각 표시 문자열 1~40자 |
| 표정 이미지 | `sprites` 항목마다 `sourceId`, `expression`, `mime`, base64 `data`. 대상 캐릭터의 표정에 있거나 예약 키 `$balloon`(말풍선 이미지)이어야 하며 같은 표정 중복 금지, 내용으로 판별한 형식이 `mime`과 일치, 2 MiB 이하 |
| 인사·개별 수다 | `greeting` 1~8줄, `idleLines` 1~32줄. 각 줄은 `expression`, `text`, v5의 선택 `motion` |
| 장면 | `pairScenes` 최대 64개, 장면당 1~8줄. v2~v5 각 줄은 `speaker`, `expression`, `text`, v5의 선택 `motion`; v1은 `speaker` 대신 `persona` |
| 본문 | 각 대사 1~500자, 공백만 있는 본문 거절. 등록 원문 자체는 다듬지 않음 |
| 키워드 대사 | `wordbook` 최대 100개. UUID `id`, 제목 1~80자, 키워드 1~20개·각 1~80자, 1~8줄, `enabled`, `useForIdle` |

키워드는 항목 안에서 대소문자를 무시한 중복을 거절한다. v2~v5의 `speaker`는 팩 안 캐릭터 정의의 `sourceId`를 참조한다. 정의 목록을 재정렬해도 대사의 화자는 같은 캐릭터를 가리킨다. v1의 `persona: a/b`는 첫째·둘째 캐릭터에 대응시켜 읽는다. 없는 화자, 중복 sourceId, 잘못된 이미지 참조는 설치 전에 거절한다. 작성 장면은 같은 화자의 연속 대사와 원문 공백을 유지한다.

`author`, `sourceUrl`, `license`는 콘텐츠 설명이며 인증된 제작자나 자동으로 부여되는 권리를 뜻하지 않는다. 미확정 제작자·출처는 빈 값으로 시작한다. 출처 편집은 선택 캐릭터의 원본 패키지에서 `author`와 `sourceUrl`만 바꾸며 같은 패키지의 모든 캐릭터에 적용된다. `license`는 가져오기 미리보기의 읽기 전용 정보이고 출처 편집에서 수정하지 않는다. 저장한 출처는 앱 재시작과 내보내기 후에도 유지한다. 원본 패키지가 없는 로컬 생성 캐릭터는 이 편집 대상이 아니다. 저장은 검증된 JSON을 임시 파일에 쓴 뒤 대상 파일로 교체한다.

GitHub의 패키지 목록에서 파일을 받아 미리본 후 설치한다. 재가져오기는 새 로컬 복사본이며 자동 업데이트가 아니다. 별꼬리 콘텐츠의 공식 Comet 배포는 원작자 허락 범위에 따른다. 수정·파생 제작·재배포 금지와 출처 표시 조건은 `examples/character-packs/byulkkori.LICENSE.txt`에 별도로 두며, 앱 코드의 라이선스를 자산에 적용하지 않는다. 확인되지 않은 제작자 이름이나 출처 URL을 추정해서 채우지 않는다.

## 로컬 정체성과 기록

개인 단어장의 A~H는 바탕화면 순서 1~8의 자리 표기다. 실제 대화 명령·재생·기록은 캐릭터 ID를 사용한다. 설치된 캐릭터에는 별도 로컬 ID가 있으며, 공유 정의의 `sourceId`와 관계를 구분한다. 새로 만든 캐릭터와 가져온 캐릭터에는 새 로컬 UUID를 부여한다. 내장 기본 ID는 `builtin-a`, `builtin-b`다.

- 같은 로컬 캐릭터 편집은 ID·관계를 유지하고 현재 정의를 갱신한다. 저장 버전이나 버전별 이력은 만들지 않는다.
- 복제와 재가져오기는 새 로컬 캐릭터다. 같은 이름·`sourceId`라도 덮어쓰거나 현재 사용자와의 친밀도를 이어받지 않는다. 복제에는 개인 데이터를 복사하지 않으며, v4/v5 archive 재가져오기로 선택한 자료는 별도의 과거 사용자에게 귀속한다.
- 일반 캐릭터를 내보낼 때 `sourceId`를 팩 내부의 `character-1`부터 `character-8`까지로 다시 부여한다. 나디르·별꼬리는 대본·스토리 연결을 위해 `nadir`·`star-tail`을 보존한다. 같은 정본의 복사본 둘은 ID 중복을 막기 위해 각각 내보내야 한다. 공유 ID가 같아도 다른 기기의 현재 사용자 관계나 스토리 진행을 이어받지는 않는다.
- 새 캐릭터의 친밀도는 20에서 시작한다. 같은 사용자로 기존 캐릭터를 다시 선택하면 저장된 관계를 복원한다. 사용자 이름 변경은 새 관계다.
- 메시지 원문 JSON과 기존 친밀도 표는 보존하고 별도 표에 당시 로컬 ID·이름을 기록한다. 이름 변경이 과거 화자를 소급 변경하지 않는다.
- 기존 A/B 기록·친밀도는 내장 ID로 한 번 이전한다. 늦게 분석한 사용자 발화도 당시 대상 캐릭터에 귀속한다.
- 생성 문맥은 캐릭터의 과거 경험을 구분한다. 각 캐릭터와 사용자에게 속한 사실·경험을 구분하며 허구 설정과 섞지 않는다.

교체·활성 정의 변경은 진행 중인 재생과 준비 결과를 무효화한다. 교체 전 요청을 현재 캐릭터에게 재시도해 다른 캐릭터의 답변으로 저장하지 않는다. 관계 규칙과 사용자 사실의 근거는 [대화와 기억](conversation.md)을 따른다.

## 대사의 소유권과 공유 범위

**개인 활성 단어장 → 현재 캐릭터·조합의 활성 단어장 → 일반 대화** 순서로 처리하며 모델 준비 확인보다 먼저 매칭한다. 각 범위에서 긴 키워드·동률 등록 순서를 따른다. 본문·공백·빈 줄·화자 순서를 바꾸거나 캐릭터 이름을 암묵적으로 치환하지 않는다.

개인 단어장의 A~H는 현재 자리다. 기존 A/B 항목을 현재 캐릭터 ID에 고정 이전하지 않는다. 캐릭터 소유 대사 편집기는 별도 기능이며 1~8명의 정렬된 로컬 ID 집합을 소유 범위로 저장한다. 편집 화면의 A~H는 선택한 조합 안의 순서다. 상대가 교체되면 이전 조합 전용 대사를 사용하지 않는다. 혼합 조합에는 각 캐릭터의 개별 수다를 사용할 수 있다.

필요한 화자·소유 조합이 없으면 장면 전체를 후보에서 제외한다. 없는 화자의 줄만 지우거나 다른 캐릭터에게 넘기지 않는다. 재생할 때 자리 참조를 실제 ID로 해석하며, 진행 중 조합 변경은 작업 epoch/revision으로 나머지 재생을 취소한다.

| 공유 내용 | 처리 |
| --- | --- |
| 저장된 정의·지침·공유 대상 사이 관계·텍스트 표정·캐릭터 소유 대사 | 선택 대상의 공유 콘텐츠로 포함 |
| 표정·말풍선 이미지·애니메이션 | 스프라이트 포함이 켜져 있으면 포함. 저장된 팩 기록에는 이미지를 중복 저장하지 않음 |
| 개인 단어장 | 기본 제외. 사용자가 선택한 항목만 포함하며 내보낼 대상에 없는 화자는 거절 |
| `.talk` 대본 파일 | 이 JSON 규격에 포함하지 않음. [대화팩](talk.md#대화팩과-나만의-대본)으로 별도 설치·제거하며 `pair`·`cast`는 로컬 ID 또는 `source:` 정본 ID를 사용 |
| 원문 대화·사용자 기억·친밀도 | 기본 제외. 각각 독립적으로 선택하면 v4 또는 v5 archive로 포함 |
| API 키·모델·연결 정보·투두·일정·위젯 개인 상태 | 제외 |

## 개인 데이터를 포함한 공유

캐릭터 설정 탭에서 개별 내보내기, 목록 관리 영역에서 조합 내보내기를 한다. 캐릭터 정의 저장과 기억 편집·잊기는 독립 작업이다. 기억 탭은 [캐릭터 기억](memory-search.md)의 유저명·날짜·근거와 개별 편집을 제공하고 설정 탭은 모든 사용자의 기억 전체 잊기를 제공한다.

| 옵션 | 기본값·내용 |
| --- | --- |
| 스프라이트 포함 | 켜짐. 정적 표정·말풍선 이미지와 애니메이션 자산·정의를 함께 포함. 끄면 이미지·동작 참조를 제거하고 텍스트 표정 유지 |
| 기억 포함 | 꺼짐. 유효한 기억과 필요한 근거·사람 정보만 포함 |
| 친밀도 포함 | 꺼짐. 과거 사람별 친밀도 기록 |
| 대화 기록 포함 | 꺼짐. 선택 캐릭터의 발화와 해당 캐릭터에게 보낸 사용자 원문. 제외 캐릭터의 발화·대상 ID는 제외 |

캐릭터만 프리셋은 개인 데이터 옵션을 끈다. 기억 포함 프리셋은 기억만 켜며 친밀도·기록은 별도로 고른다. 개인 데이터가 하나라도 선택되면 `archive`를 사용한다. 반응·대사 동작이 있으면 v5, 없으면 v4다. 개인 데이터 없이 반응·대사 동작도 없으면 애니메이션 여부에 따라 v2/v3이며 v1~v4 가져오기도 유지한다.

내보내기 시각을 한 번 고정한다. 보내는 쪽의 현재 사용자는 파일 안에서만 그 시각에 관계가 종료된다. 이미 종료된 관계의 시각은 유지하며 원본 앱은 변경하지 않는다. 가져올 때 사람·캐릭터·기억·근거·발화 ID를 새 로컬 ID로 바꾸고 동명 사용자나 기존 관계에 병합하지 않는다. 가져온 친밀도와 발화는 과거 자료이며 현재 친밀도·스토리 진행·자동 분석에 반영하지 않는다.

가져온 개인 데이터는 정규 저장 표에만 보관하고 팩 메타데이터에서 제거한다. 대화 기록은 당시 이름·시각·출처를 보존하는 읽기 전용 자료이며 현재 대화의 문맥·기억 재추출·재시도에 사용하지 않는다. 재내보내기는 현재 기억의 수정·삭제·망각 상태를 읽는다. 재전달로 90일 수명을 갱신하지 않는다. 전체 파일 32 MiB 한도를 넘거나 참조가 잘못되면 저장·설치 전체를 중단하며 기록을 몰래 잘라 넣지 않는다.

## 상황별 스프라이트 재생

**상태: 2026-09-24 구현.** 설정 → 캐릭터 → 모습·표정에서 PNG·APNG 여러 장 또는 격자 스프라이트 시트로 동작을 만들고 평소·말하기·클릭에 연결한다. 실제 검증 결과는 [상태표](../status.md)에 기록한다. 기존 정적 표정·GIF와 텍스트 표정은 유지한다.

동작은 이름·프레임 순서·속도를 가진다. APNG는 프레임 추가에서 가져오며 원본 프레임별 간격 대신 지정한 동작의 균일한 fps로 재생한다. 격자 시트는 정지 PNG 한 장을 사용한다. 프레임을 추가·삭제·재정렬하고 재생·정지·한 프레임 이동으로 확인한다. 시트는 칸 너비·높이와 사용할 프레임 수로 나누며 왼쪽 위부터 행 순서다. 한 동작의 모든 프레임은 같은 크기로 지정한다. 본체와 미리보기는 같은 재생 로직을 사용하고 프레임의 투명 여백과 위치를 유지한다.

| 항목 | 계약 |
| --- | --- |
| 속도 | 초당 1~30프레임, 새 동작은 8fps. 대사 글자 출력 속도와 독립 |
| 기본·말하기 연결 | 캐릭터 공통 설정과 표정별 덮어쓰기. 표정별 `공통 설정 사용 / 다른 동작 / 동작 없음` 제공 |
| 반복 | 기본·말하기 연결마다 한 번 또는 반복, 반복 간격 0~60초. 기본 초기값은 반복·3초 간격, 말하기는 반복·간격 없음 |
| 클릭 | 한 번 재생으로 고정. 다시 클릭하면 처음부터 재생하며 누적하지 않음. 우클릭 메뉴·더블클릭 입력·끌기 이동. 새 `click` 반응이 없을 때 사용하는 호환 연결 |
| 우선순위 | [행동 반응·대사 지정 동작](character-reactions.md#시각-반응과-발화)이 표정 연결보다 우선. 공통 말하기 미지정은 기본 동작을 사용하고 표정별 명시적 끄기는 정적 표정 표시 |
| 말하기 | 해당 화자의 대사 또는 선택지 본문 말풍선이 실제 표시되는 동안. 메뉴·입력·기록·답변 준비 제외 |
| 종료·간격 | 반복 간격에는 현재 정적 표정 표시. 클릭 종료 후에는 최신 상황을 다시 판단 |
| 중단 | 숨김·일시정지·캐릭터 교체·정의 변경 시 취소. 재시작 때 클릭 반응 복원 금지. OS 동작 줄이기에서는 수동 미리보기만 재생 |
| PNG 제한 | 파일당 2MiB 이하, 최대 4096×4096. 실제 디코딩 검증. APNG는 프레임 합성과 이전 프레임 정리 규칙을 반영한 정지 PNG 시퀀스로 변환. 한 번 선택할 때 펼친 프레임 합계 64MiB·64프레임 이하. 캐릭터별 고유 자산 RGBA 합계 64MiB, 최대 32동작·동작당 64프레임 |

새 애니메이션의 이미지 선택·동작·연결은 캐릭터별 초안이며 공통 저장·수정 취소에 함께 속한다. 기존 표정 이미지의 즉시 저장과 구별한다. 다른 캐릭터나 탭으로 이동해도 초안을 유지하고 저장 전 팩 적용·공유를 제한한다. 파일 선택 도중 취소하거나 대상을 바꾸면 늦은 결과를 적용하지 않는다. 정의와 이미지 추가·정리는 한 transaction으로 저장한다.

정의의 선택 `animation`은 `clips`, `bindings`, `overrides`를 가진다. 클립은 `id`, `name`, `fps`, `frames`, 프레임은 `assetId`, `x`, `y`, `width`, `height`다. 연결은 `clipId`, `repeat`, `intervalMs`이며 표정별 덮어쓰기의 키 생략은 상속, `null`은 끄기다. 바이트는 `character_animation_assets`에 캐릭터별로 저장하고 SHA-256 자산 ID로 조회한다. 상태 이벤트에는 이미지 바이트를 넣지 않는다. 디코딩은 DB·action 잠금 밖에서 수행한다.

반응·대사 동작·개인 데이터 없이 애니메이션을 포함하면 `formatVersion: 3`으로 내보내며, 애니메이션도 없는 팩은 v2를 유지한다. v3는 v2 화자 참조와 기존 `sprites`를 유지하고 `animationAssets`에 `sourceId`, `assetId`, `mime`, `width`, `height`, base64 `data`를 추가한다. 전체 32MiB 한도는 동일하다. 새 앱은 v1~v4도 읽으며, 이전 앱이 새 형식을 읽는 역방향 호환은 보장하지 않는다. 복제·제거·팩 왕복에 동작과 자산을 함께 처리하고 개인 데이터는 기본 공유하지 않으며 선택하면 [archive 계약](#개인-데이터를-포함한-공유)을 따른다. 반응·대사 동작을 포함하면 v5를 사용하며 v4/v5에서도 애니메이션 자산 구조는 같다.

본체 크기는 프레임마다 바뀌지 않는다. 이미지가 준비되면 경과 시간으로 프레임을 선택하고 실패하면 정적 표정으로 복귀한다. 프레임별 충돌 외곽은 미리 계산해 캐시하며 [장난감의 투명 영역·구멍 통과 규칙](toys.md#바탕화면-물리-계약)을 유지한다. 프레임 전환마다 DB 저장이나 전체 상태 이벤트를 보내지 않는다.

[캐릭터 행동과 반응](character-reactions.md)은 클릭·잡기·놓기와 지원 위젯 사건의 대사·표정·동작, 대사별 동작 지정을 구현한다. 사건 목록·종료·발화 우선순위·팩 v5 계약은 해당 문서를 따른다. 음악 사건과 임의 조건식은 후속 범위다.

## 후속 범위와 검증

원격 마켓·캐릭터팩 자동 업데이트, 기존 우카가카·SSP 형식, `.talk` 대본의 캐릭터팩 가져오기·내보내기 연동, 개인 단어장 캐릭터 한정 UI는 후속 범위다. 기존 표정 이미지는 정지 이미지 또는 GIF 한 장이며 새 프레임 시퀀스는 위 동작 설정으로 관리한다. 재가져오기를 자동 업데이트처럼 안내하지 않는다.

최종 검증에서는 모델 없는 적용·인사·키워드, A→A→B와 공백 보존, 내보내기·재가져오기, 교체·복귀·이름 변경 시 기록·관계, 늦은 응답 거부와 개인 데이터 기본 제외·선택 포함을 구분해 확인한다. 소스 구현과 실제 패키지 검증 결과를 별도로 기록한다.

규격·공유 범위·정체성·단어장 우선순위를 바꾸면 이 문서와 [상태표](../status.md)를 함께 갱신한다.

## 나디르·별꼬리 추가팩

2026-09-20부터 나디르(`sourceId: nadir`)와 텍스트 별꼬리(`sourceId: star-tail`)는 기본 캐릭터와 분리한 추가팩이다. 배포용 텍스트팩은 `examples/character-packs/nadir-and-star-tail.comet-character.json`이며 **설정 → 캐릭터 → 공유**에서 가져와 설치한 뒤 함께 지내기를 선택한다. 기본 초기화는 이 팩을 자동 설치하거나 활성화하지 않는다. 표정 이미지를 포함한 `examples/character-packs/byulkkori.comet-character.json`은 새 설치의 기본 캐릭터이면서 갤러리에서 다시 받을 수 있는 공식 팩이다. 이전 기본 구성으로 설치된 나디르·별꼬리는 로컬 ID·정의·소유 대사·관계·기록을 그대로 보존한다.

두 캐릭터 전용 `.talk`는 `nadir-and-star-tail` 대화팩으로 분리했다. 앱에 동봉하지만 기본 설치하지 않으며 **설정 → 대화팩**에서 설치한다. 0.5.0에서 `talk/` 폴더에 그대로 두었던 동봉 대본은 수정하지 않았을 때만 이 팩 폴더로 자동 이동한다. 자세한 규칙은 [대화팩](talk.md#대화팩과-나만의-대본)을 따른다.

나디르는 반존대와 자주 고치는 문장, 영창의 박자에 관심을 보이는 소심한 학생이다. 별꼬리는 밝고 짧게 말하며 나디르의 비밀을 대신 폭로하지 않는다. 이미지 없는 본체의 표정은 기존 A/B와 같은 `(・_・)`·`(^‿^)` 등의 문자 이모티콘으로 표시한다. 배포팩의 일반 소개와 수다에는 숨긴 과거를 넣지 않는다. 공개 단계는 [선택지 스토리](conversation.md#나디르-선택지-스토리)를 따른다.

인사·일상·위젯 행동마다 5개 이상의 작성된 변주를 제공한다. 시간 대사는 기기 현지 시각을 사용하며 시계 위젯 설치가 필요하지 않다. 날씨 연결이 없거나 오래되었으면 관측값을 지어내지 않고 확인하지 못했다는 기본 대사를 사용한다. 지역을 고르고 날씨 위젯을 활성화하면 유효한 관측값에 맞는 날씨 대사를 고른다.

`.talk`의 `pair("source:nadir", "source:star-tail")` 범위는 재가져온 팩과 자리 교환에도 화자를 따라간다. 대본·스토리 자산은 앱에 동봉한다. `.talk`는 대화팩을 설치하고 해당 source 조합이 활성 상태일 때만 사용하며, 선택지 스토리는 나디르가 활성 상태이면 단독·혼합 조합에서도 사용할 수 있다. 다른 캐릭터 조합에서는 이 팩 전용 대사와 선택지 스토리가 나오지 않는다. 기존 JSON 교환 형식 자체에 암호화 대본·스토리 파일을 추가하지 않는다. 이 팩의 모든 기능은 이 변경을 포함한 앱에서 사용한다.

설정의 캐릭터 탭에는 `.talk`·story 원문을 편집하는 내부 화면을 두지 않는다. 암호화 대본의 작성·검사·저장은 별도 talk editor가 맡고, Comet은 앱 데이터의 파일을 읽어 재생한다. 자세한 파일·재로딩 규칙은 [대본 작성](talk.md)을 따른다.
