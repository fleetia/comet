# 캐릭터 기억과 선택 NLP

2026-09-24 승인한 캐릭터별 기억·사용자 구분 계약이다. 기억의 소유권, 유효 기간, 분석·검색과 수동 편집을 변경할 때 읽는다. Fleet의 프로젝트별 구분 원리를 적용하지만 Fleet 파일에는 연결하지 않는다. 소스 구현·자동 검사·네이티브 검증·모델 의미 품질은 [상태표](../status.md)에서 구분한다.

## 사용자와 관계

최초 실행에 이름을 등록하며 변경은 설정 → 사용자에서 한다. 앞뒤 공백을 제외한 1~40자를 받는다. 같은 이름 저장은 아무것도 바꾸지 않지만 실제 변경마다 새 내부 사용자 ID를 만든다. `민수 → 지연 → 민수`는 세 관계다. 화면에는 유저명만 표시하고 현재·이전 표시나 동명이인 접미사는 붙이지 않는다.

등록 전에도 내장 인사와 자동 수다는 동작한다. 직접 대화·기억·친밀도는 등록 후 시작하며 위젯 첫 설정은 이름 등록 다음에 열린다. 이름 변경은 이전 관계의 종료 시각을 저장하고 새 친밀도 20·새 스토리 진행으로 시작한다. 이전 원문·관계·스토리 응답은 보존한다. 진행 중 생성·재생·스토리 요청은 취소하고 늦은 결과를 반영하지 않는다.

## 기억의 소유권과 근거

기억은 로컬 캐릭터 ID와 사용자 ID에 귀속된다. 원문에도 작성 당시 사용자와 실제 대상 캐릭터를 저장한다. 모두에게 한 발화는 캐릭터별 독립 기억이므로 한쪽의 수정·잊기가 다른 쪽을 바꾸지 않는다. 비활성 캐릭터에게 뒤늦게 분석 결과가 도착해도 당시 소유자를 유지한다.

`user_fact`는 기존 원문 근거 검증을 통과한 명시적 사용자 사실이다. `experience`는 완료된 직접 대화의 주제 또는 확정된 선택지 스토리다. 대화 경험은 실제 완료된 답변이 있는 사용자 발화의 정확한 인용이며 모델의 허구를 실제 사건으로 승격하지 않는다. 스토리 경험은 선택 확정 transaction에서만 만든다. 위젯 행동·미응답·취소·중복·오래된 선택은 기억 근거가 아니다.

함께 대화하는 캐릭터의 관련 기억을 함께 읽되 소유 캐릭터·사람·종류·근거를 문맥에 전달한다. 이전 사용자 원문은 현재 대화 문맥에 직접 넣지 않는다. 스토리 경험은 현재 사용자와의 공개 단계를 다시 검사한다. 모델이 이 구분을 항상 지키는지는 별도 의미 검증 대상이다.

## 망각과 수동 편집

이전 관계 종료 후 검색 점수에 `max(0, 1 − 경과일/90)`을 곱한다. 사람별 회상 상한은 `ceil(8 × 가중치)`, 전체 상한은 8개다. 본문을 흐릿하게 다시 쓰지 않는다. 90일이 지나면 만료 상태를 저장하고 목록·검색·프롬프트에서 제외한다. 앱 종료 시간도 포함하며 저장된 시계의 최댓값을 사용해 시계 역행·수정·재전달로 수명이 늘어나지 않게 한다.

캐릭터 기억 탭은 유효한 기억을 50개씩 보여 준다. 유저명·내용·날짜·근거와 개별 수정·잊기를 제공한다. 캐릭터 설정의 전체 잊기는 그 캐릭터가 가진 모든 사용자의 기억에 적용하고 건수를 확인한다. 원문 기록과 친밀도는 별도로 보존한다. 수동 수정·잊기는 캐릭터·사용자·근거별 재추출 차단을 남긴다.

생성 답변·준비 장면에 제공한 기억과 최근 대화의 의존성을 저장한다. 기억 수정·잊기·만료·사용자 전환으로 근거가 무효가 되면 해당 답변을 재생하거나 다음 대화의 문맥으로 재사용하지 않는다. 파생 답변을 여러 번 거쳐도 이 차단을 이어받는다.

## 기존 데이터 이전

기존 사용자 원문·친밀도·스토리 진행은 첫 등록 사용자에게 연결한다. 기존 기억은 저장된 발화 대상별로 배분하며 공동 발화는 독립된 기억으로 복사한다. 대상을 확인할 수 없으면 원문과 기억을 보존하고 설정 → 사용자 → 기존 기억 정리에서 하나 이상의 캐릭터를 지정한다. 지정 전에는 회상하지 않는다.

이전은 transaction 안에서 한 번 수행한다. 원문·시각·수동 잠금·삭제 상태를 유지하고 검색 색인은 재구축할 수 있다. 가져온 과거 기록은 분석 대기열에 넣지 않는다. 파일의 개인 데이터 계약은 [캐릭터팩 공유](characters.md#개인-데이터를-포함한-공유)를 따른다.

## 설치 직후와 선택 기능

내장 인사·대본·단어장·위젯·기본 기억 검색에는 모델이 필요하지 않다. 자유 대화와 유휴 시간의 기억 후보 추출은 기존 로컬 LLM 또는 API를 사용한다. 새 설치는 LLM 자동 장면 생성을 끄고 내장 자동 수다는 유지한다. 이미 저장한 생성 설정은 바꾸지 않는다.

한국어 분석(Kiwi)과 의미 검색(E5)은 각각 선택해서 내려받는다. 하나만 설치하거나 둘 다 사용하지 않아도 된다. 미설치·초기화·비활성·오류에서는 사용 가능한 검색으로 이어간다. 검색 설정은 AI 연결의 독립된 기억 검색 영역에서 별도로 저장한다.

| 검색 방식 | 역할 |
| --- | --- |
| 기본 검색 | SQLite FTS5로 기억 원문을 검색한다. 모델 없이 유지한다. |
| 한국어 분석 | Kiwi v0.24.0 CoNg의 형태소를 검색어와 파생 색인에 추가한다. 원문을 다시 쓰지 않는다. |
| 의미 검색 | multilingual-e5-small로 표현이 다른 기억을 찾는다. 배포 파일과 관련도 기준을 검증한 profile만 사용한다. |

캐릭터의 기억 탭에 초안이 있으면 저장하거나 취소한 뒤 다음 페이지로 이동한다. 검색 모델의 다운로드 크기·진행·중단·사용 여부·제거와 색인 준비 상태·분석 재시도는 AI 연결의 기억 검색 영역에서 확인한다. 모델 제거는 모델과 재생성 가능한 색인만 지우며 원문·기억·친밀도·설치 캐릭터팩은 보존한다. 실패는 설정에 표시하고 반복 말풍선을 띄우지 않는다.

## 입력과 검색 순서

1. 사용자 원문과 해당 발화의 분석 작업을 함께 저장한다.
2. 기존 단어장 규칙으로 긴 키워드와 최초 등록 우선순위를 적용한다. 일치하면 등록 본문·공백·줄바꿈·화자 순서를 그대로 재생한다.
3. 미일치하면 대상 캐릭터의 관련 기억을 검색한 뒤 선택한 LLM에 전달한다. 어휘와 의미 후보를 각각 최대 20개 가져와 같은 가중치의 RRF(`k=60`)로 합친 다음 관계 종료에 따른 가중치·사람별 상한과 공개 단계 조건을 적용해 최대 8개를 선택한다.
4. 프롬프트에는 유효한 기억의 온전한 원문·ID·소유 캐릭터·유저명·종류·출처를 넣는다. 원래 프롬프트 예산에 들어가는 기억 단위로 선택하며, 빈자리를 무관한 최신 기억으로 채우지 않는다.
5. 모델 결과와 작업의 최신성을 확인한 뒤 재생한다. 검색 실패는 입력·단어장·위젯을 막지 않는다.

기억 수정·삭제와 검색 색인 무효화는 같은 transaction에서 처리한다. 검색·색인 결과가 늦게 도착하면 기억 내용 버전과 모델 fingerprint를 다시 확인한다. 수동 편집으로 잠긴 기억도 현재 본문으로 검색한다.

## 유휴 기억 분석

분석은 검색 모델 설치 여부와 무관한 LLM 작업이다. 원문 전체가 요청 예산에 들어가는 발화만 제출하고 실제 제출한 ID 목록을 기록한다. 응답의 출처는 이 목록 안에 있어야 한다. 기억 반영·원문 검색 색인 갱신·제출 작업 완료는 한 transaction으로 저장한다. 분량 때문에 빠진 발화는 다음 배치에 남는다.

각 발화는 `pending`, `done`, `deferred`, `legacy_unverified` 중 하나다. 개별 발화가 예산을 넘으면 이유와 함께 보류한다. 문장 단위로 잘라 인용·부정·정정의 문맥을 잃지 않는다. 취소·오래된 revision은 완료나 실패로 처리하지 않는다. 실제 분석 실패는 1분·5분·15분 후 재시도하고 이후 보류한다. 설정에서 보류된 작업을 다시 시도할 수 있다.

이전 cursor 이후 발화는 `pending`, 이전 발화는 `legacy_unverified`로 이전한다. 이때 과거 누락이 복구됐다고 표시하거나 자동 재분석하지 않는다. 정확한 감사·모욕 표현은 입력 시 Rust 규칙으로 처리한다. 기존 화자 정체성·중복 방지·일일 상한을 유지하고 이전 표현을 다시 적용하지 않는다.

## 자원과 출시 조건

Rust가 대화·취소·재생을 제어하며 NLP는 앱 소유 보조 실행기 하나에서 수행한다. 모델은 필요할 때만 불러오고 준비된 검색 대기는 최대 2초다. 초기화 중에는 기본 검색을 사용한다. 기억 색인은 유휴 시간에 한 건씩 보강하며 직접 검색을 우선한다. 생성 LLM 실행 중에는 새 배경 색인 작업을 시작하지 않는다.

작업 없이 120초가 지나면 실행기를 종료한다. 시간 초과·충돌 시 앱이 만든 자식만 종료·회수하며 자동 재기동 간격은 최소 60초다. 종료·업데이트는 신규 접수를 막고 취소한 뒤 최대 5초 정리한다. 긴 대화·재생·네이티브 조회와 별개로 500ms 주기의 타이머·일정·OS 알림 처리는 계속한다.

| 검증 | 출시 목표 |
| --- | --- |
| 기준 Windows 기기 | RAM 8GB, 논리 CPU 4개, SSD, GPU 없음 |
| macOS | arm64 설치물 실제 실행 |
| 검색 품질 | 공개 한국어 검증셋 Recall@5 ≥ 90%, 무관 질문 오탐률 ≤ 5% |
| NLP 자원 | 전체 peak RSS ≤ 1GiB, 준비된 검색 p95 ≤ 2초 |
| 데이터 규모 | 기억 100·1,000·10,000개에서 초기 로딩·p50/p95·유휴 CPU·취소·종료 측정 |

이 값은 측정 전 지원 성능으로 광고하지 않는다. 생성 LLM의 실행 사양은 별도다. 모델 없는 설치, 각 모델 단독·함께 설치, 오프라인·손상·취소·충돌·재시작·업데이트도 실제 설치물에서 확인한다. 구현 세부는 [NLP 실행과 모델 배포](../development/nlp.md)를 따른다.
