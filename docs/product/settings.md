# 통합 설정창

2026-09-20 승인한 R2는 캐릭터 관리·설정·위젯 관리를 하나의 보조 설정창으로 합친다. 2026-09-24 변경은 기억 편집을 캐릭터 안으로 옮기고 사용자 영역을 추가해 8개 영역을 직접 노출한다. 이 문서는 화면을 변경할 때 지킬 탐색·저장·창 경계의 기준이며, 소스 구현과 실제 데스크톱 검증 상태는 [상태표](../status.md)에서 구분한다.

기존 관리 화면과 R1의 중첩 탭·넓은 여백은 새 구현의 기준으로 사용하지 않는다. 기능·원문·데이터 보존 계약은 유지하며, 이전 화면 구조를 고정하던 테스트는 새 탐색·초안·저장 책임에 맞춰 교체한다. 과거 빌드의 실행 결과는 이번 검증 근거로 재사용하지 않는다.

## 창과 탐색

바탕화면의 작은 캐릭터와 잠깐 나타나는 말풍선이 중심 경험이다. 설정창은 요청하거나 최초 이름 등록이나 위젯 선택이 필요할 때 연다. 기본 크기는 1120×720, 최소 크기는 960×640이다. 제목·닫기·왼쪽 탐색을 고정하고 긴 작업 내용만 스크롤한다.

32px 제목줄의 왼쪽에 기존 컬러 앱 아이콘과 `comet`, `설정`을 함께 놓고 닫기 버튼과 수직 중앙을 맞춘다. 왼쪽 탐색과 본문 사이에는 경계선 하나만 두며, 탐색 항목은 선에서 8px 안쪽에 배치한다. 관리·대화·앱 그룹 제목은 항목의 글자 시작점에 맞추고 그룹 사이 간격을 유지한다.

왼쪽 세로 탭은 다음 순서로 항상 노출한다. 그룹을 접거나 별도 홈·요약 화면을 두지 않는다. 처음에는 캐릭터를 열고 이후 앱이 실행 중인 동안 마지막 선택 영역을 기억한다. 캐릭터·위젯 바로가기는 같은 창의 해당 영역으로, 업데이트 바로가기는 일반으로 이동한다. 이전 `updates` 목적지는 `general`로, `memory` 목적지는 선택 캐릭터의 기억 탭으로 해석한다.

| 그룹 | 영역·ID | 기능과 저장 책임 |
| --- | --- | --- |
| 관리 | 캐릭터 · `characters` | 팩 선택, 1~8명 구성·순서, 만들기·복제·편집·제거, 모습·애니메이션·등록 대사·행동 반응·기억, JSON 공유. 캐릭터·대사·출처·기억을 각각 저장 |
| 관리 | 위젯 · `widgets` | 설치·추가 통합 목록, 켜기·끄기, 표시·연결·제거, 별도 실행 창 열기. 설치·활성·제거는 개별 명령 |
| 대화 | 자동 대화 · `automatic` | 먼저 이야기하기, 1~60분 간격, 로컬/API 생성 허용, 일시정지 해제. 자동 대화 설정만 저장 |
| 대화 | 개인 단어장 · `wordbook` | 제목·키워드·화자·표정·동작·원문·활성·자동 사용 여부. 항목별 저장 |
| 대화 | 대화팩 · `talk` | 설치된 팩 조회·제거, 동봉 팩 설치. 원문 편집은 앱 밖 talk editor |
| 앱 | 사용자 · `user` | 유저명 등록·변경, 기존 미배분 기억 정리. 이름 변경은 새 관계로 시작 |
| 앱 | AI 연결 · `model` | 로컬 모델·GGUF·다운로드·테스트, API 주소·모델·키·연결 테스트·호환성 설정. AI 연결만 저장. 별도의 기억 검색 영역에서 선택 NLP 설치·검색 설정·분석 재시도 |
| 앱 | 일반 · `general` | 캐릭터 표시·숨김·종료, 장난 허용, 앱 정보·업데이트. 장난 저장과 업데이트를 구분 |

8개 설정 영역은 왼쪽 탐색에 직접 노출하고, 캐릭터 영역 안에서는 아래의 6개 편집 탭을 사용한다. 왼쪽 세로 탭은 위·아래 방향키와 Home·End로 이동하며 선택과 키보드 초점을 구분한다. 검색·필터는 같은 목록의 표시 범위를 바꾸며 설치 선택이나 편집 초안을 지우지 않는다.

## 작업 영역

### 캐릭터

보유 목록과 선택 캐릭터 편집을 나란히 둔다. 목록 선택은 편집 대상 선택이며 함께 지내기·바탕화면 순서 변경과 구분한다. 2026-09-24 승인한 변경에 따라 편집 영역은 **프로필 / 모습·표정 / 말풍선 / 대사·반응 / 기억 / 설정**의 6개 내부 탭으로 나눈다. 이 구조가 R2의 모든 캐릭터 편집 영역을 한 화면에 펼치던 배치를 대체한다. 모습·표정 탭에는 [스프라이트 동작 편집과 상황 연결](characters.md#상황별-스프라이트-재생)을 함께 둔다. 탭별 항목은 [캐릭터 탭 구성](characters.md#관리-화면-구성)을 따른다.

보유 목록과 함께 지내기·순서·추가·복제·가져오기·조합 내보내기·팩 선택·제거 등 관리 동작은 내부 탭 밖에 둔다. 캐릭터를 바꿔 선택해도 같은 내부 탭을 유지하며, 내부 탭이나 왼쪽 설정 영역을 옮겨도 대상별 초안을 보존한다. 선택한 탭 안에서는 작은 미리보기, 짧은 행과 2열 입력을 사용한다. 캐릭터 이름·내부 탭·팩 정보와 정의 편집 탭의 공통 저장을 고정하고 편집 내용과 보유 목록을 각각 스크롤한다. 기억·설정 탭은 독립 작업의 조작을 사용한다. 목록과 편집 영역 사이의 세로 구분선은 작업 영역 하단까지 이어진다.

탭 분리는 저장 단위를 바꾸지 않는다. 캐릭터 정의에 속한 모든 탭의 변경은 공통 캐릭터 저장·수정 취소를 사용하고, 표정·말풍선 이미지는 선택·제거 즉시 저장한다. 애니메이션 이미지·동작·연결과 행동 반응은 초안에 보관하며 공통 캐릭터 저장·취소로 처리한다. 키워드·조합 대사와 패키지 출처는 각각 별도로 저장한다. 대사·반응 탭은 등록 원문·대사별 동작과 [사건별 반응](character-reactions.md)을 편집하며 자동 대화의 간격·생성 허용, 개인 단어장·대화팩·AI 연결은 전역 영역에서 관리한다. 기억 편집·잊기는 선택 캐릭터의 기억 탭에서 독립 저장하며 개별 내보내기·전체 기억 잊기는 설정 탭에 둔다.

팩 적용과 공유는 미저장 초안을 보호한다. 파일 가져오기만으로 활성 구성을 바꾸지 않으며 같은 구성을 다시 적용해 진행 중 대화를 끊지 않는다. 패키지 출처에서 편집하는 필드는 `author`와 `sourceUrl`이다. `license`는 가져오기 미리보기에서 읽는 정보이며 이번 재설계에 라이선스 편집 기능을 추가하지 않는다. 상세는 [캐릭터](characters.md)를 따른다.

### 위젯 설정과 별도 실행

위젯은 설치된 항목과 추가 가능한 항목을 같은 목록에 두고 검색·분류·상태로 찾는다. 선택한 항목의 오른쪽에는 설치·켜기/끄기·표시·연결 등 설정만 배치한다. 미설치 항목은 설명과 필수 의존성을 확인한 뒤 설치한다. 선택 연동은 자동 설치하지 않으며 제거의 기본값은 작성 데이터 보존이다.

할 일 작성·완료, 메모 편집, 타이머 실행은 위젯을 실행할 때 열리는 별도 창에서 수행한다. 할 일·캘린더는 [플래너 R2](planning.md)의 960×640 실행 창을 공유하며 오늘·기간 계획·캘린더·템플릿을 직접 탐색한다. 메모·타이머 등 다른 도구의 실행 창은 유지한다. 설정창에 작업 목록·작성 폼을 넣지 않으며 설정창과 실행 창 사이에 메모 초안을 이전하는 동작도 두지 않는다. 위젯 켜짐, 실행 창 열림, 바탕화면 표시는 서로 다른 상태다.

개별 위젯 실행 창의 내부 UI는 후속 전면 재설계 대상이다. 이번 통합 설정창 작업은 설정·실행 창의 경계까지만 확정하며, 현재 할 일 창과 다른 위젯 내부 배치를 최종 디자인 기준으로 사용하지 않는다.

시계·기념일·날씨·기기 소식의 바탕화면 표시는 **바탕화면 표시**와 **표시 닫기** 명령으로 조작한다. 실제 표시 여부를 snapshot에서 확인하지 않는 상태에서 표시 체크박스를 만들어 켜짐·꺼짐을 추정하지 않는다. 이는 Figma 예시의 표시 체크박스를 실제 명령·상태 계약에 맞춘 차이다. 표시·실행 창만 닫으면 설치·활성 상태와 필요한 예약은 유지한다. 상세는 [위젯 설치](../widgets/installation.md)와 [수명주기](../widgets/lifecycle.md)를 따른다.

### 사용자·대화·AI·일반

사용자는 최초 이름 등록과 이후 이름 변경을 맡는다. 실제 이름 변경은 새 사람과의 관계를 시작하므로 이전 이름으로 돌아가도 기존 관계를 복원하지 않는다. 이전 원문·친밀도·스토리 응답은 보존하며 새 관계에 합치지 않는다. 최초 등록과 기존 미배분 기억 정리의 상세는 [캐릭터 기억](memory-search.md#사용자와-관계)을 따른다.

자동 대화는 상위 설정·간격·일시정지·생성 허용을 함께 보여 준다. 상위 설정을 꺼도 하위 선택은 지우지 않는다. 개인 단어장, 캐릭터·조합 등록 대사, 독립 설치 단위인 `.talk` 대화팩은 소유권과 공유 범위가 다르므로 합치지 않는다. 대화팩 활성화·수동 재읽기 UI를 현재 기능으로 추가하지 않는다.

AI 연결은 실제 사용할 방식을 명시하고 로컬 모델과 외부 API 설정을 2열로 함께 보여 준다. 다운로드·테스트·입력 편집은 사용 방식의 저장과 다르다. `localhost`·`127.0.0.1`·`[::1]`의 OpenAI 호환 API는 키 없이 연결 테스트하고 사용할 수 있으며 원격 API는 키가 필요하다. 입력한 API 키는 OS 보안 저장소에 저장하고 저장 후 입력란을 비운다. 기본 인사와 자동 수다는 모델이나 API 없이 사용할 수 있다.

AI 연결 안의 기억 검색 모델 설치·설정은 자동 대화·AI 연결 저장과 독립적이다. 기억 내용의 편집·잊기는 캐릭터의 기억 탭에서 수행하며 편집 중인 페이지는 저장·취소 후 이동한다. 상태 갱신으로 초안을 덮어쓰지 않는다. 상세 계약은 [캐릭터 기억과 선택 NLP](memory-search.md)를 따른다.

일반은 바탕화면 동작·장난 허용·앱 정보와 업데이트를 열린 섹션으로 보여 준다. 자동 대화 간격을 중복 배치하거나 업데이트를 하위 탭으로 숨기지 않는다.

## 디자인 시스템

배포된 `@fleetia/lagrange`의 Tabs·SectionHeader·Typography·Button·FormField·Dialog·SaveStatus·StatusMarker·Layout을 사용한다. 기본 `lagrangeThemeClass`와 semantic token을 유지하며 앱 CSS로 컴포넌트의 선택·초점·disabled 상태를 다시 디자인하지 않는다. 현재 대조 기준은 0.2.2의 Eulyoo1945, 본문 13px·라벨 12px, 기본 컨트롤 30px·compact 24px이다. Figma의 compact Tab은 실제 높이 25px으로 구분한다.

을유1945는 [공식 이용 조건](https://www.eulyoo.co.kr/member/font.html)에서 폰트 임베딩·재배포를 허용하지 않으므로 앱에 동봉하지 않는다. `src/fonts.css.ts`는 설치된 `Eulyoo1945-Regular`·`Eulyoo1945-SemiBold`를 로컬에서만 찾고, 없으면 시스템 serif로 표시한다. 별도 CSS 가족 이름과 세 가지 family token을 연결해 Lagrange의 CDN 폰트를 요청하지 않으며 CSP도 완화하지 않는다. 오프라인에서도 화면을 사용할 수 있지만 폰트가 설치되지 않은 기기까지 Figma와 같은 서체를 보장하지는 않는다.

정보 밀도는 글자를 임의로 더 줄이는 대신 빈 공간과 탐색 단계를 줄여 확보한다. 큰 제목·미리보기·카드를 반복하지 않고 섹션을 펼쳐 필드와 관련 동작을 가까이 둔다. 창 크기·열 너비·스크롤은 comet의 배치 책임이다.

R2의 대표 디자인은 [캐릭터](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr/Lagrange-Library-Playground?node-id=174-7083), [위젯 설정](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr/Lagrange-Library-Playground?node-id=175-7760), [별도 할 일 실행 창](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr/Lagrange-Library-Playground?node-id=175-7960)이다. 캐릭터 편집 배치는 2026-09-24 승인한 6개 내부 탭 계약을 우선하며 기존 코드와 로컬 렌더·네이티브 검증으로 확인한다. 라이선스 편집과 표시 체크박스처럼 실제 기능 계약과 다른 예시는 위의 명시적 경계를 따른다. 대표 디자인이 모든 위젯·상태·클릭 프로토타입의 완성을 뜻하지 않는다.

## 초안과 실패

내부 탭·왼쪽 설정 영역 이동과 설정창 닫기는 저장·취소가 아니다. 방문한 작업 영역을 유지하며 대상별 캐릭터·대사·출처·단어장·기억·설정 초안, 위젯별 설정 초안과 설치 선택을 보존한다. 다른 캐릭터나 위젯을 선택해도 작성 중이던 설정을 지우지 않는다. snapshot 갱신으로 편집 중 값을 덮어쓰지 않는다. 창을 닫으면 숨기며 앱 실행 중 초안은 유지한다. 앱 종료 후 미저장 초안 복원은 제공하지 않는다.

전역 전체 저장은 두지 않는다. 자동 대화와 AI 연결은 서로 다른 저장·취소 영역이며 한 영역의 잘못된 미저장 입력이 다른 영역의 저장을 막지 않는다. Rust의 `save_settings`는 `scope: automatic` 또는 `scope: model`을 받아 `action`과 DB transaction 안에서 최신 설정을 읽고 해당 필드만 병합한다. API 키는 모델 저장에서만 적용한다. 공유 revision 갱신과 기존 생성·재생 중단 경계는 유지한다.

저장 중인 대상만 중복 제출·수정하지 못하게 하며 실패하면 초안과 오류를 남긴다. 개별 명령의 성공을 확인한 뒤 결과를 표시한다. 트레이 등에서 바꾼 최신 설정을 다른 영역의 오래된 초안으로 되돌리지 않는다.

앱 종료 시 미저장 편집이 있으면 계속 편집하거나 변경을 버리고 종료하도록 확인한다. 저장하려면 해당 영역으로 돌아가 저장한다. 트레이 종료와 macOS 앱 메뉴·⌘Q도 같은 보호를 적용한다. macOS의 기본 종료 메뉴는 확인 경로를 거치는 앱 명령으로 교체하고 복사·붙여넣기 등 기본 편집 메뉴는 유지한다. 운영체제의 강제 종료나 Dock에서 직접 종료하는 경로까지 초안 보존을 보장하지는 않는다. 업데이트 설치는 미저장 설정이 있으면 시작하지 않으며 다운로드 뒤 실제 설치 직전에도 재검사한다. 업데이트 다운로드·설치 중에는 설정 편집을 잠근다.

창을 만들 때 요청 영역을 URL에 넣는다. 로딩 중 다른 바로가기가 들어오면 이벤트 연결 뒤 최신 목적지를 조회하며 늦은 초기 응답이 이후의 사용자 선택이나 이벤트를 덮어쓰지 않게 한다. 영역 선택은 앱 실행 중 네이티브 상태에도 기록한다.

## 유지할 계약과 인수 조건

원문 기록·기억·친밀도·개인 단어장·설치 팩·모델을 초기화하지 않는다. [대화](conversation.md), [대화팩](talk.md), [캐릭터](characters.md), [위젯 설치](../widgets/installation.md), [수명주기](../widgets/lifecycle.md), [업데이트](../development/releases.md)의 도메인 계약을 유지한다. [0.2 사양](../PRODUCT.md)의 작은 본체·말풍선·모델 선택 경험은 보존하며 당시 분리된 보조 화면 배치는 이 문서가 대체한다.

- 설정·캐릭터·위젯·업데이트 바로가기를 연속 실행해도 설정창 하나만 존재하고 목적 영역이 보인다.
- 캐릭터는 **프로필 / 모습·표정 / 말풍선 / 대사·반응 / 기억 / 설정**의 6개 내부 탭에서 편집한다. 목록·팩 관리·조합 내보내기는 탭 밖에서, 개별 내보내기·전체 기억 잊기는 설정 탭에서 접근한다. 위젯 작업은 별도 실행 창에서 수행한다.
- 캐릭터 선택을 바꿔도 선택한 내부 탭을 유지한다. 내부 탭·왼쪽 설정 영역 이동·snapshot 갱신·설정창 숨김과 다시 열기 뒤에도 미저장 초안과 설치 선택이 남는다.
- 캐릭터의 여러 내부 탭을 편집한 뒤 공통 저장·수정 취소를 실행하면 애니메이션 이미지·동작·연결과 행동 반응을 포함한 해당 정의의 전체 초안에 적용한다. 기존 표정·말풍선 이미지의 즉시 저장과 키워드·조합 대사의 별도 저장은 유지한다.
- 자동 대화와 AI 연결을 번갈아 저장해도 다른 영역의 최신 값과 사용자 데이터가 보존된다.
- 미저장 편집이 있으면 일반·트레이 종료와 업데이트 설치가 이를 버리고 진행하지 않는다.
- 최소 크기에서도 탐색·닫기·저장에 접근하고 긴 목록은 작업 영역에서 스크롤한다.
- 현재 소스로 데스크톱 패키지를 만들어 실제 탐색·저장·위젯 실행을 확인한다. 브라우저 검증은 네이티브 실행 증거로 사용하지 않는다.
