# 장난감과 작은 도구

기준일: 2026-09-15. 캐릭터 옆에 꺼내 놓고 잠깐 만지는 놀이와 생활 도구의 제품 목록이다. 표의 대사는 동작을 설명하는 예시이며 고정 원문으로 확정한 대사집은 아니다.

| 상태 | 범위 |
| --- | --- |
| 구현됨 · 0.2 | 0.2의 본체·말풍선·내장 수다·단어장. 아래 장난감 구현 완료를 뜻하지 않는다. |
| 확정 · 개발 예정 | 여러 작은 장난감, 실제 상태에 따른 A/B 반응, 내장 할 일·읽기 전용 일정과의 연결 |
| 미정 | 각 장난감의 제작 순서·세부 규칙·아트, 날씨·음악 제공 방식, 위젯 SDK 인터페이스 |

기본 화면 원칙은 [바탕화면](desktop.md), 실용 기능의 상세는 [할 일·일정](planning.md)을 따른다. **RSS는 범위에서 제외한다.**

## 첫 구현 묶음

기능 목록을 설치 단위로 묶은 제안은 [위젯 카탈로그](../widgets/catalog.md)에 둔다. 첫 개발에서는 선택 설치·중지·제거와 주사위·동전을 먼저 연결해 위젯의 전체 수명주기를 검증한다.

실용 기능은 내장 할 일 → 캘린더 조회·알림 → 할 일에 연결한 집중 타이머 → 일정 준비 봉투 순서로 시작한다. 놀이에서는 주사위와 화분을 함께 우선 검토한다. 작은 승부와 느린 변화를 통해 도구마다 다른 대화 소재를 만든다. 이 순서는 구현 계획이며 완료 일정은 정하지 않는다.

## 놀이 목록

| 장난감 | 조작과 명시적인 상태 | A/B 반응 예시 |
| --- | --- | --- |
| 쓰다듬기·콕 찌르기 | 본체를 짧게 만지는 제스처와 반응. 반복 입력에 매번 말하지 않는다. | A “간지러워!” B “버튼은 아니야.” |
| 공 | 던지기·튀기기·멈춘 위치. 전체 바탕화면의 범용 물리 시뮬레이션으로 확대하지 않는다. | B 옆에 멈춤: A “받아!” B “이미 멈췄는데.” |
| 종이비행기 | 드래그 발사, 비행 거리와 착지 | 최고 기록: A “신기록!” B “벽이 조금만 늦게 왔으면.” |
| 간식 | A/B에게 나누기, 남은 조각 수 | 마지막 조각: A “내 건?” B “다음 봉지의 가능성.” |
| 비눗방울 | 만들기·터뜨리기와 연속 기록 | A “열 개!” B “청소할 건 안 남네.” |
| 주사위·동전 | 실제 난수 결과, 선택한 한 판의 승패 | A=1, B=6: A “다시!” B “결과 보고 규칙 바꾸기야?” |
| 가위바위보 | 사용자와 A/B의 선택, 승패·무승부 | A “마음이 통하나 봐!” B “손이 세 종류뿐이기도 하고.” |
| 낚시 | 입질 조작, 획득한 물고기·잡동사니 | 양말 획득: A “대어다!” B “발에 끼는 종류네.” |
| 컵 찾기·숫자 맞히기 | 숨긴 위치·정답·시도 횟수를 앱이 관리 | 오답: A “거기인 줄 알았는데.” B “한 번 더 볼까?” |
| 장난 운세 | 사용자가 뽑는 가벼운 가상 문구 | A “오늘의 행운은 간식!” B “어제도 그랬던 것 같은데.” 예측 사실로 말하지 않는다. |
| 화분 | 물 주기·성장 단계·꽃 피우기 | 첫 싹: A “우리 셋이네!” B “쟤는 조용해서 좋다.” |
| 작은 펫·달팽이 | 먹이 놓기·이동·도착 | A “드디어 도착!” B “쟤 기준으론 급행일 수도.” |
| 수집품 | 놀이로 실제 얻은 돌·우표 등과 중복 개수 | 같은 돌 세 번째: A “또 이 돌이야.” B “이쯤 되면 취향이지.” |
| 소품 | 왕관 등 장식 꺼내기·옮기기·정리 | 패자에게 왕관: A “내가 왕이다!” B “결과와는 무관하네.” |
| 기념일 | 사용자가 등록한 날짜와 이름 | A “등록한 기념일이 오늘이네.” B “잠깐 축하하고 갈까?” |
| 함께한 사건 일지 | 실제 놀이 사건을 짧게 모아 다시 보기 | A “그날 양말을 낚았지.” B “물고기는 아니었어.” |

화분과 펫은 자리 비움 때문에 죽거나 친밀도를 깎지 않는다. 수집은 출석 강요·재화 상점·벌점을 기본 조건으로 삼지 않는다. 사건 일지는 실제 플레이 기록이며 사용자에 관한 장기 기억과 구분한다.

## 생활 도구 목록

| 도구 | 범위와 상태 근거 |
| --- | --- |
| 타이머 | 남은 시간·종료·계속·쉬기. 할 일 연결과 완료 경계는 별도 사양을 따른다. |
| 시계 | 기기의 시간과 선택한 표시. 매 분 대사를 출력하지 않는다. |
| 날씨 | 사용자가 선택한 지역의 조회 결과·갱신 시각. 위치를 추측하거나 기기 위치 권한을 기본 요구하지 않는다. 제공자는 미정이다. |
| 음악 정보 | 허용된 연결에서 받은 재생 곡 메타데이터만 언급한다. 음원 재생·자동 재생목록 수정은 이 범위에 포함하지 않는다. 연결 방식은 미정이다. |
| 배터리·기기 깨어남 | 읽을 수 있는 배터리 상태·기기 복귀 사건에 반응한다. 복귀를 사용자의 장기 부재나 활동 내용으로 해석하지 않는다. |
| 메모 | 사용자가 쓰고 고치는 작은 메모. 메모 내용의 명령문을 앱 실행 권한으로 취급하지 않는다. |
| 할 일·캘린더 | 오늘 쪽지, 다음 일정 티켓, 준비 봉투 등. 아래 별도 문서의 데이터·권한 계약을 따른다. |

## 캐릭터가 놀이를 참조하는 방법

장난감은 결과와 상태를 먼저 확정하고 대사에 전달한다. 예를 들어 “주사위 A=1, B=6”에 해당하는 등록 대사를 재생한다. 선택적으로 LLM이 실제 상태를 바탕으로 표현을 더할 수 있지만 결과를 결정하거나 없는 물건을 만들지는 않는다.

사용자 단어장 대사는 정확히 재생한다. 사건용 등록 대사와 LLM 표현의 경계도 [대화 규칙](conversation.md)을 따른다. 같은 사건의 반복 반응과 오래된 상태를 줄이고, 직접 입력이 오면 자동 반응을 중단한다.

캐릭터가 스스로 공을 건드리거나 주사위를 굴리는 자율 놀이는 행동별로 허용 여부를 정한다. 이 허용이 할 일 완료·일정 수정·외부 앱 쓰기의 포괄 권한은 아니다. 숨긴 장난감을 다시 꺼내거나 정리한 소품을 복원하는 동작도 별도 의도 없이 수행하지 않는다.

## 확장 방식

위젯 SDK와 외부 확장은 계획 단계다. 아직 공개 인터페이스·설치 형식·권한 체계가 구현된 것으로 간주하지 않는다. 첫 도구들을 구현하며 공통으로 필요한 상태·사건·수명 주기를 확인한 뒤 최소 계약을 정한다. 미리 거대한 플러그인 플랫폼을 구축하지 않는다.

## 인수 조건

- 놀이 결과를 앱이 확정하며, A/B 대사가 그 결과와 모순되지 않는다.
- 등록 대사는 본문과 순서를 보존하고 LLM 없이 동작한다.
- 정리한 도구가 사라지고, 활동이 없는 도구 때문에 지속 애니메이션·추론이 필요하지 않는다.
- 반복 클릭·여러 도구 사건이 말풍선 독촉으로 누적되지 않는다.
- 자리 비움·패배·미완료 할 일로 친밀도나 이용 가능한 기능을 제한하지 않는다.
- 외부 정보는 조회 실패·오래된 결과를 구분하고, RSS 수집을 추가하지 않는다.
- 상태를 보존하는 도구는 재시작 후 같은 결과를 유지하고 일회성 반응을 다시 재생하지 않는다.

장난감 채택·폐기, 자율 행동 범위, 외부 데이터 연결을 바꿀 때 이 목록을 갱신한다.
