## 설치와 현재 구현 범위

설치 단위의 기준은 [위젯 카탈로그](../widgets/catalog.md)다. 최초 선택은 모두 건너뛸 수 있고, 이후 관리 화면에서 추가 설치·켜기·끄기·꺼내기·제거한다. 설치와 바탕화면 표시를 구분한다. 생활 도구와 다른 놀이는 작은 보조 창에서 조작하고, 공·종이비행기·비눗방울·펫은 바탕화면에 별도 물체로 꺼낸다. 큰 관리 화면을 상시 띄우지 않는다.

0.4는 공·종이비행기를 보조 창 안의 0~100 좌표로 움직이던 0.3 표현을 대체한다. 놀이판 없이 화면 전체에서 물체를 잡아 던지며 비눗방울은 눌러 터뜨리고 펫은 바탕화면을 걷는다. 현재 물체는 기본 도형·문자를 사용한다. 본체 위에서 직접 쓰다듬는 제스처와 전용 캐릭터·소품 아트는 별도 후속 범위다. 아래 대사와 왕관·우표 등의 항목은 제품 방향을 설명하는 예시이며 현재 획득품 목록을 보장하지 않는다.

지속 데이터는 호스트가 저장한다. 바탕화면 물체의 진행 중 위치·속도는 메모리에서만 관리한다. 타이머 종료, 낚시 입질과 화분 성장은 저장 상태를 화면에 표시하고, 완료 구슬병은 할 일의 실제 완료·취소를 반영한다. 내장 할 일·일정·준비 봉투의 상세 계약은 [할 일·일정](planning.md)을 따른다.

## 바탕화면 물리 계약

`src-tauri/src/desktop_toys.rs`가 공통 운동과 물체 창을, `desktop_geometry.rs`가 운영체제의 화면·창 외곽을 소유한다. macOS의 창·그리기·마우스 callback은 `desktop_toys_macos.rs`, Windows의 WebView 화면은 `src/components/DesktopToy/DesktopToy.tsx`가 담당한다. 공·비행기는 화면 가장자리와 다른 앱 창의 **보이는 외곽선 양쪽**에 충돌한다. 창 내부도 놀이 공간이므로 최대화된 창 위에서 놀 수 있다. 물체를 잡아 끄는 동안에는 충돌을 우회하고 놓은 위치에서 다시 적용한다. 다른 앱 창을 이동하거나 조작하지 않는다.

충돌은 고정 timestep과 swept collision으로 계산한다. 앞 창에 가린 뒤 창의 외곽은 제외하고, 창 이동·크기 변경·최소화·종료를 새 geometry에 반영한다. 실제 앱의 둥근 모서리·그림자·투명 구멍까지 픽셀 단위로 재현하지는 않는다. 물체의 충돌 외형은 원형 근사이며 표시·입력 외형과 구분한다.

캐릭터 본체도 충돌 대상이다. 이미지가 있으면 실제 표시 크기로 읽은 alpha가 0보다 큰 픽셀의 외곽을 사용하고, 투명 여백과 내부 구멍은 통과한다. 최대 512×512 표본을 사용하며 장난감 자체의 원형 근사는 유지한다. 이미지가 없으면 보이는 본체 버튼 영역을 사용한다. 별도 텍스트 표정 창과 말풍선은 대상이 아니다. 공·비행기는 반발·착지하고 비눗방울은 닿으면 터진다. 본체 이동·크기·표정 변경을 반영하고 숨김·비활성화·종료 시 영역을 해제한다.

이미지 alpha는 로드·표정·크기 변경 때 읽고 외곽 선분 생성은 별도 작업에서 수행한다. 물리 tick에서는 캐시한 인접 선분을 조회한다. [PNG·APNG 프레임 동작](characters.md#상황별-스프라이트-재생)은 프레임별 외곽을 준비해 캐시하고 재생 시 해당 프레임을 선택한다. 반복 간격에는 정적 표정의 외곽을 사용한다. 기존 GIF·애니메이션 WebP 단일 표정 이미지의 내부 프레임별 alpha는 추적하지 않는다. 새 이미지가 로드되는 동안 이전 외곽을 지우며, 이미지 판독 실패를 사각형이나 여러 프레임을 합친 외곽으로 대체하지 않는다. 숨김·창 재생성·새 캐시 이후 도착한 이전 세대의 작업은 반영하지 않는다.

물리 루프는 창 외곽 조회의 완료를 기다리지 않는다. macOS의 Quartz 조회는 AppKit 화면 반영과 같은 main thread에서 순서대로 실행해 시스템 잠금 충돌을 피하고, Windows 조회는 별도 blocking 작업으로 실행한다. 수동 꺼내기도 action·DB 잠금에 들어가기 전에 조회를 마친 뒤 설치·활성·revision과 대기 중 정리 여부를 다시 확인한다. macOS 표시 큐에는 물체별 최신 위치만 남기고, 모양이 그대로면 다시 그리지 않는다.

macOS는 Quartz point, Windows는 physical pixel로 창 위치를 읽는다. 렌더링 변환과 monitor별 배율은 adapter에서 처리하고, 비행 거리는 배율로 정규화한 logical distance로 누적한다. 모니터 사이 연결된 면은 통과하고, 모니터 사이 빈 공간·음수 원점·복제 화면의 경계를 구분한다. 화면 배치가 바뀌어 물체가 바깥에 남으면 유효 화면 안으로 옮긴다.

창 제목·앱 문서 내용·스크린샷은 수집하지 않는다. macOS의 `CGWindowListCopyWindowInfo`, Windows의 창 목록·DWM bounds 조회를 사용하며, 권한 없는 실행을 지원 OS별로 검증해야 한다. 실행 도중 외곽 조회가 실패하면 오류 상태를 표시하고 마지막 외부 창 외곽을 짧게 유지한 뒤 화면 경계와 별도로 관리하는 캐릭터 외곽만 남긴다. 이 축소 동작을 외부 창 충돌 검증 성공으로 취급하지 않는다.

물체 밖 클릭은 아래 앱으로 통과시키고, 생성·이동·조작이 기존 앱의 키보드 초점을 빼앗지 않아야 한다. 현재 Windows adapter는 native window region을 사용하며 macOS는 nonactivating `NSPanel`에 직접 그린 투명 영역을 입력 경계로 사용한다. macOS 물체는 native 마우스 callback으로 잡기·놓기·우클릭을 처리한다. WebView나 cursor polling 기반 입력 전환은 사용하지 않으며, 드래그 좌표 갱신에만 현재 포인터 위치를 읽는다. **macOS의 투명 영역·첫 클릭·앱 활성화, Windows 실제 실행과 mixed-DPI는 네이티브 인수 대상이다.** 코드 존재나 브라우저 렌더만으로 완료를 선언하지 않는다. 최신 실행 증거는 [구현 상태](../status.md)를 따른다.

새 물리 결과는 `desktop_toy_results`에 별도로 저장한다. 0.3의 좌표·최고기록·먹이 도착 수를 새 단위로 덮어쓰거나 기존 `.talk` 변수에 다른 단위로 전달하지 않는다. 진행 중인 물체는 재시작 후 복원하지 않는다. 결과 저장·취소 경계는 [수명주기](../widgets/lifecycle.md#바탕화면-물체의-수명)를 따른다.

## 캐릭터가 놀이를 참조하는 방법

장난감은 결과와 상태를 먼저 확정하고 대사에 전달한다. 예를 들어 “주사위 A=1, B=6”에 해당하는 등록 대사를 재생한다. 선택적으로 LLM이 실제 상태를 바탕으로 표현을 더할 수 있지만 결과를 결정하거나 없는 물건을 만들지는 않는다.

지원 놀이 사건에는 [캐릭터 반응](character-reactions.md#연결할-수-있는-사건)의 대사·표정·동작 묶음을 연결할 수 있다. 새 반응을 명시적으로 등록한 사건은 기존 `.talk` 사건 대사보다 우선하며 미등록 사건의 대본과 대체 대사는 유지한다. 이 반응은 확정된 놀이 결과를 표현하며 물체 조작이나 보상을 다시 실행하지 않는다. 반응의 프레임도 위의 캐릭터 충돌 캐시를 사용한다.

사용자 단어장 대사는 정확히 재생한다. 사건용 등록 대사와 LLM 표현의 경계도 [대화 규칙](conversation.md)을 따른다. 같은 사건의 반복 반응과 오래된 상태를 줄이고, 직접 입력이 오면 자동 반응을 중단한다.

0.4의 장난 모드는 기본 꺼짐이며 공·종이비행기·비눗방울·펫 중 설치·활성·허용된 항목만 선택한다. 대화와 자동 장난을 구분하는 상태 전이·간격·중단 규칙은 [바탕화면 행동](desktop.md#장난-모드와-대화-상태)을 따른다. 주사위 등 다른 도구의 자율 조작은 이 허용에 포함하지 않는다. 이 허용이 할 일 완료·일정 수정·외부 앱 쓰기의 포괄 권한은 아니다. 숨긴 장난감을 다시 꺼내거나 정리한 소품을 복원하는 동작도 별도 의도 없이 수행하지 않는다.

## 확장 방식

위젯 SDK와 외부 확장은 계획 단계다. 공식 내장 패키지의 설치·수명주기 구현을 제삼자 코드용 공개 인터페이스·설치 형식·권한 체계가 완성된 것으로 간주하지 않는다. 외부 코드를 실행하는 공개 계약은 별도로 정한다. 미리 거대한 플러그인 플랫폼을 구축하지 않는다.

## 외부 연결과 검증 범위

- 날씨는 입력한 지역 이름을 검색한 뒤 사용자가 고른 좌표만 저장한다. 자동 위치 권한은 요구하지 않는다. 제공자 조회 실패나 오래된 기상 모델 정보는 이전 정보로 표시하고 마지막 성공 값을 현재 정보로 꾸미지 않는다.
- 음악은 제공되는 선택 메타데이터·일시정지 곡을 보존하고 앱 미실행·곡 없음·권한 부족·미지원을 구분한다. 로컬 재생 제어·Spicetify와 실제 검증 범위는 [음악 위젯](music.md)을 따른다.
- 기기 소식은 배터리 없음과 잔량 조회 실패를 구분한다. `src-tauri/src/device_wake.rs`가 macOS `NSWorkspaceDidWakeNotification`과 Windows `WM_POWERBROADCAST`를 받아 설치·켜짐·조회 허용 상태에서만 사건을 기록한다. 이 코드 경로와 실제 기기를 절전시켰다가 깨운 검증은 다르며, 후자는 아직 확인하지 않았다.
- 최소 외부 조회 간격은 날씨 30분, 음악 15초, 기기 1분이다. 캘린더 계정·구독의 인증과 최신성 검증은 [할 일·일정](planning.md)의 범위를 따른다.
- 자동 테스트와 렌더 확인은 제공자 계정 인증, 실제 음악 앱 자동화 권한, Windows 실행, 실제 절전·복귀나 모델 대사의 의미 품질을 대신하지 않는다. 현재 데스크톱 확인 결과는 [구현 상태](../status.md)에 기록한다.

## 인수 조건

- 공·비행기는 놀이판 없이 바탕화면과 다른 창 외곽 양쪽에 충돌하며 빠른 발사가 경계를 뚫지 않는다.
- 물체 밖 클릭·기존 앱 입력을 보존하고, monitor 배율·배치·연결 변경에도 물체를 회수할 수 있다.
- 자동 장난이 직접 입력·대화·숨김·일시정지·전체 화면·설정 해제를 우회하지 않는다.
- 놀이 결과를 앱이 확정하며, A/B 대사가 그 결과와 모순되지 않는다.
- 등록 대사는 본문과 순서를 보존하고 LLM 없이 동작한다.
- 정리한 도구가 사라지고, 활동이 없는 도구 때문에 지속 애니메이션·추론이 필요하지 않는다.
- 반복 클릭·여러 도구 사건이 말풍선 독촉으로 누적되지 않는다.
- 자리 비움·패배·미완료 할 일로 친밀도나 이용 가능한 기능을 제한하지 않는다.
- 외부 정보는 조회 실패·오래된 결과를 구분하고, RSS 수집을 추가하지 않는다.
- 상태를 보존하는 도구는 재시작 후 같은 결과를 유지하고 일회성 반응을 다시 재생하지 않는다.

장난감 채택·폐기, 자율 행동 범위, 외부 데이터 연결을 바꿀 때 이 목록을 갱신한다.
