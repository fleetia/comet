# 캐릭터 행동과 반응

**상태: 2026-09-24 소스 구현·macOS QA 검증 완료.** 이 문서는 캐릭터 반응과 대사별 동작을 편집하거나 사건·재생 경계를 변경할 때 적용한다. 코드 검사와 실제 데스크톱 검증 결과는 [상태표](../status.md)를 따르며, Windows와 모델 의미 품질의 검증 완료를 뜻하지 않는다.

반응은 한 사건에 대사·표정·동작을 묶어 선택하는 캐릭터 설정이다. “잡기 시작 → 앗, 어디로 데려가는 거야? + 놀람 + 매달리기”를 한 후보로 저장한다. 여러 후보가 있어도 대사·표정·동작을 따로 추첨하지 않는다. 기존 [스프라이트 동작과 자산](characters.md#상황별-스프라이트-재생), 공용 말풍선과 원문 대사 재생기를 사용하며 LLM은 필요하지 않다.

## 본체 조작 {#클릭-조작의-확정-방향}

2026-09-24 승인한 변경은 0.2의 클릭 메뉴 조작을 다음과 같이 대체한다.

| 조작 | 동작 |
| --- | --- |
| 한 번 클릭 | `click` 반응. 연결이 없으면 말풍선이나 메뉴를 새로 열지 않음 |
| 우클릭·메뉴 키·Shift+F10 | 기존 메뉴 열기 |
| 두 번 클릭 | 직접 입력 열기. 앞의 클릭 후보는 반응으로 먼저 실행하지 않음 |
| Enter·Space | 키보드로 클릭 반응 실행 |
| 6px 이상 끌기 | 네이티브 끌기 시작을 요청하고, 실제 시작 확인 시 `grab-start` 발생 |
| 정상 놓기 | 같은 끌기 세션의 네이티브 종료 확인 시 `release` 발생 |
| 조작 취소 | 시작 실패·숨김·창 제거·정의나 활성 구성 변경 등으로 취소. 놓기 반응 실행 안 함 |

더블클릭 판정 시간은 OS 설정에서 읽는다. 누르기만 한 시점에 잡기 대사를 실행하거나, 마지막 이동 시각·`startDragging()` Promise의 반환만으로 놓기를 추측하지 않는다. 긴 누르기는 별도 반응 사건으로 제공하지 않는다. macOS는 AppKit의 이동 요청 반환 후에도 실제 이동 시작 알림과 버튼 해제·취소를 관찰한다. watcher와 플랫폼별 경계는 [구조와 책임](../development/architecture.md#캐릭터-조작반응의-실행-경계)을 따른다.

조작은 안정적인 로컬 캐릭터 ID, 본체 창 인스턴스, 세션 ID와 세대, 정의와 활성 구성의 식별값에 연결한다. Rust에서 네이티브 시작·종료 사건을 순서대로 처리하며 늦은 놓기를 새 캐릭터에게 전달하지 않는다. 본체 위치 이동과 시각 프레임 변경만으로 대화 epoch를 올리지 않는다.

## 연결할 수 있는 사건

사건 목록의 원본은 `src-tauri/src/character_reactions.rs`의 `EVENTS`이며 편집기는 `get_character_reaction_events`로 읽는다. 다음은 현재 등록된 사건의 전체 범위다. 위젯 설치 자체를 실제 사건 발생으로 해석하지 않는다.

| 사건 ID | 의미 |
| --- | --- |
| `click`, `grab-start`, `release` | 클릭, 잡기 시작, 놓기 |
| `todo-completed`, `todo-undone` | 할 일 완료, 완료 취소 |
| `timer-finished` | 타이머 종료 |
| `calendar-reminder`, `planner-reminder`, `planner-mood` | 캘린더 알림, 일정 알림, 일정 분위기 변화 |
| `device-woke` | 기기 잠자기 해제 |
| `interaction.touch` | 교감 위젯 |
| `ball.stopped`, `paper-plane.landed`, `bubbles.streak` | 위젯 공 멈춤, 종이비행기 착지, 비눗방울 연속 기록 |
| `small-match.result`, `guessing.attempt` | 작은 승부 결과, 맞히기 결과 |
| `fishing.bite`, `fishing.missed` | 낚시 입질, 놓침 |
| `item-acquired`, `fortune.draw`, `plant.growth`, `pet.arrived` | 아이템 획득, 운세 뽑기, 화분 성장, 위젯 펫 도착 |
| `desktop.ball.stopped`, `desktop.paper-plane.landed` | 바탕화면 공 멈춤, 종이비행기 착지 |
| `desktop.bubbles.popped`, `desktop.pet.rested` | 바탕화면 비눗방울 터짐, 펫 휴식 |

위젯 반응은 기존 사건의 revision·만료·중복 억제와 실행 가능 조건을 사용한다. 해당 위젯 사건에 새 캐릭터 반응을 명시적으로 등록하면 기존 `.talk` 사건 대본보다 우선하며 둘을 함께 실행하지 않는다. 등록하지 않은 사건은 기존 [`.talk` 선택과 대체 대사](talk.md)를 그대로 사용한다. 음악 상태를 위한 새 사건이나 범용 조건식은 제공하지 않는다.

## 반응 데이터와 후보 선택

캐릭터 정의의 선택 `reactions` 배열에 아래 규칙을 저장한다. 인사·자동 수다와 같은 캐릭터 정의 저장 단위이며 실행 중 상태는 저장하지 않는다.

| 필드 | 제약과 의미 |
| --- | --- |
| `id` | 반응 ID. 앞뒤 공백·제어 문자 없는 1~64자, 캐릭터 안에서 고유 |
| `event` | 위 사건 ID 중 하나. 같은 캐릭터에 같은 사건은 한 번만 등록, 최대 32반응 |
| `variants` | 1~16후보. 후보마다 반응 안에서 고유한 `id`와 선택 `text`, `expression`, `motion` |
| `text` | 생략하면 새 말풍선을 열지 않음. 지정하면 공백만으로 구성되지 않은 1~500자. 등록한 공백·줄바꿈 보존 |
| `expression` | 생략하면 현재 화자의 표정. 지정하면 해당 캐릭터에 등록된 표정 |
| `cooldownMs` | 실제 대사를 표시한 뒤 다시 말하기까지의 간격, 0~60,000ms. 편집기 새 반응은 3,000ms |

후보는 대사·표정·동작 중 하나 이상의 효과를 가져야 한다. 명시적 정적 표정도 효과로 취급한다. 후보가 여러 개면 직전에 선택한 후보를 제외하고 한 묶음을 선택한다. 대사 쿨다운은 시각 반응의 재실행을 막지 않는다.

동작 표현은 일반 대사와 반응이 공유한다.

| `motion` | 의미 |
| --- | --- |
| 생략 또는 `{"mode":"inherit"}` | 현재 표정의 기본/말하기 연결 사용 |
| `{"mode":"static"}` | 명시적 동작 없음. 정적 표정 표시 |
| `{"mode":"clip","clipId":"wave","repeat":false,"intervalMs":0}` | 해당 화자의 동작 ID를 지정. `intervalMs`는 0~60,000ms |

반응에서는 `grab-start`만 반복을 허용한다. 클릭·놓기·모든 위젯 사건의 명시적 동작은 `repeat: false`, `intervalMs: 0`으로 한 번 재생한다. 일반 대사에 지정한 동작은 한 번 또는 대사가 표시되는 동안 반복하도록 고를 수 있다.

## 시각 반응과 발화

본체와 공용 말풍선은 같은 반응 실행 ID를 사용하지만 별도로 우선순위를 판단한다. 진행 중인 답변을 보호하면서 캐릭터의 모습만 반응할 수 있다.

| 출력 | 우선순위·종료 |
| --- | --- |
| 본체 | 숨김·일시정지 적용 → 잡기 반응 → 클릭·놓기·위젯의 일시 반응 → 현재 대사의 지정 동작 → 표정의 말하기/기본 동작 → 정적 표정 |
| 명시적 한 번 동작 | 모든 프레임의 로딩 완료 후 재생 시간을 시작하고 마지막 프레임 시간이 끝나면 최신 상황을 다시 판단 |
| 정적·동작 생략·동작 줄이기의 일시 반응 | 반응 표정을 1,500ms 유지한 뒤 최신 상황으로 복귀. 프레임 재생을 생략해도 행동 대사는 허용 |
| 잡기 반응 | 끌리는 동안 유지. 반복 동작은 놓기·취소로 종료하며 정적 표정도 놓을 때까지 유지. 한 번 동작의 완료·로딩 실패 후에는 잡기 표정의 정적 모습 유지 |
| 반복 간격·로딩 실패 | 정적 표정 표시. 오래된 로드 결과로 취소한 동작을 다시 시작하지 않음 |
| 재클릭 | 새 실행으로 처음부터 재생. 대기열을 만들지 않음 |

기존 `animation.bindings.click`은 새 클릭 규칙이 없을 때만 호환 경로로 사용한다. 새 `click` 반응이 있으면 그것이 우선한다. 반응 대사 자체에 동일한 동작을 다시 붙여 두 번 재생하지 않는다.

메뉴·입력·기록 패널, 선택지, 직접 요청한 진행 중 대화와 위젯 알림이 공용 말풍선을 사용하면 행동 대사를 생략한다. 비어 있거나 평소 자동 수다를 재생 중이면 행동 대사를 시작할 수 있다. 바쁜 동안 생략한 대사는 나중에 몰아서 재생하지 않는다. 잡기 대사는 시작 때 한 번 말하며 놓기·취소는 그 잡기 반응이 소유한 대사만 취소한다.

대사 쿨다운은 실제 말풍선 표시 시점에 캐릭터·반응별로 소비한다. 표시 전 취소·표시 실패는 소비하지 않는다. 실행 ID와 기존 action·epoch 경계가 오래된 대사와 완료 통지를 거절한다. 숨김·일시정지·캐릭터 교체·정의 변경에는 동작과 비동기 작업을 취소하며 재시작 때 조작 상태·반응·대기열을 복원하지 않는다.

행동 대사는 원문 기록에 `source: reaction`으로 구분하며 사용자 사실 추출이나 친밀도 분석 작업을 만들지 않는다. 클릭 횟수와 캐릭터의 반응 대사를 사용자 사실·친밀도 증가의 근거로 쓰지 않는다. 말하기 여부는 글자 출력 완료가 아니라 해당 화자의 대사 또는 선택지 말풍선이 실제 표시되는 동안이다.

## 편집과 미리보기

[캐릭터 편집](characters.md#관리-화면-구성)의 **모습·표정**에서 정적 이미지·동작 라이브러리·평소/말하기 연결을 관리하고, **대사·반응**에서 인사·자동 수다·키워드/조합 대사와 사건별 반응을 편집한다. 기억·설정 등 나머지 탭의 책임은 유지한다.

반응 후보의 대사·표정·동작을 같은 화면에서 편집하며 대사 쿨다운은 추가 설정에 둔다. 인사·자동 수다·개인 및 캐릭터 단어장·조합 대사에도 같은 동작 선택기를 사용한다. 동작 목록은 실제 화자의 정의에서 가져오며 화자를 바꾸면 이전 화자의 지정 동작 참조를 비운다. `.talk`의 선택적 대사 동작 문법은 [대본 참조](../development/talk-reference.md)를 따른다.

반응·인사·자동 수다와 애니메이션 자산의 초안은 공통 캐릭터 저장·취소에 포함한다. 키워드·조합 대사는 기존처럼 별도 저장하며 아직 저장하지 않은 캐릭터 동작을 그 별도 대사에 연결하지 않는다. 다른 캐릭터·탭으로 이동해도 초안을 보존한다. 참조 중인 동작을 지워 유효하지 않은 정의를 저장할 수 없으며, 저장된 외부 대사에서 사용 중이면 해당 대사의 연결을 먼저 바꿔야 한다. 저장 실패 시 초안과 추가 자산은 남는다.

편집기의 **클릭 시험 / 잡기 시작 시험 / 놓기 시험 / 대화 중인 상황**은 데스크톱의 `preview_character_reaction`으로 같은 후보 선택 코어를 호출한다. 선택 후보와 발화 생략 이유를 표시하고 본체와 같은 프레임 로더·재생기로 수동 미리보기한다. 실제 창 이동·기록·친밀도·반응 이력·쿨다운을 변경하지 않는다. 동작 줄이기 설정에서도 이 수동 미리보기는 허용한다.

브라우저 화면에는 데스크톱 앱이 필요하다고 표시하며 별도 FSM을 복제하지 않는다. 미리보기를 정지하거나 탭·정의·시험 상황이 바뀌면 이전 요청 세대를 폐기한다. 탭을 다시 열어도 취소한 미리보기나 늦은 결과가 다시 나타나지 않는다.

## 팩과 호환성

반응 규칙 또는 대사별 `motion`을 포함하는 캐릭터팩은 **`formatVersion: 5`**다. v5는 v2 이후 화자의 `sourceId` 참조, v3 애니메이션 자산, 선택적인 v4 `archive`를 함께 지원하며 전체 32MiB 한도를 유지한다. `archive`는 개인 데이터를 명시적으로 선택했을 때만 포함한다.

새 앱은 v1~v4를 계속 읽는다. 내보내기는 포함한 자료에 필요한 최소 버전을 고른다. 반응·대사 동작이 있으면 v5, 그것 없이 개인 데이터가 있으면 v4, 애니메이션만 있으면 v3, 모두 없으면 v2다. 동작·반응·자산은 저장·복제·제거·팩 왕복에 함께 처리한다. 이미지 제외 공유에서는 동작 참조를 제거하고 효과가 남지 않는 반응 후보도 제거한다. 상세 파일·개인 데이터 규칙은 [공유 규격](characters.md#공유-파일-규격)을 따른다.

프레임마다 DB 저장이나 전체 snapshot을 보내지 않는다. 이미지 준비·경과 시간 재생·프레임별 충돌 캐시는 [스프라이트 계약](characters.md#상황별-스프라이트-재생)을 재사용한다. 기존 자동 놀이 FSM은 놀이를 조절하고 캐릭터 반응은 확정된 사건을 받는다.

사건 추가나 반복·발화·저장 정책을 바꾸면 이 문서와 관련 스키마·선택·취소 테스트를 함께 갱신한다. 네이티브 클릭/더블클릭/끌기·말풍선 위치·포커스와 재시작은 별도 QA 앱에서 실제 확인하며 결과와 미완료 범위를 [상태표](../status.md)에 기록한다. 범용 비주얼 FSM 편집기, 사용자 스크립트, 임의 조건 언어와 음악 사건 확장은 이번 범위에 포함하지 않는다.
