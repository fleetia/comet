# 음악 위젯

2026-09-21 확정한 음악 위젯 확장 계약이다. 재생 프로그램이 실제로 제공하는 메타데이터를 읽고, 작은 위젯에서는 현재 곡을, 필요할 때 여는 상세 화면에서는 나머지 정보를 확인한다. 연결·화면·대본을 구현할 때 제공자별 지원 범위와 현재 정보의 의미를 판단하는 기준으로 사용한다.

**상태: 소스 구현·macOS 로컬 검증 및 Spotify 실계정 주요 기능 확인.** 2026-09-21 사용자가 로컬 재생 제어 구현을 승인하면서 앞선 읽기 전용 디자인의 범위를 확장했다. macOS Music·Spotify, Windows 미디어 세션의 기본 재생 제어와 선택형 Spicetify 연결을 구현했다. 2026-09-22에는 Spotify 실계정의 설치·페어링·재생·랜덤 곡·큐·좋아요를 확인했다. 버전별 실제 결과와 남은 검증은 [상태표](../status.md)에서 구분한다.

이 위젯은 [0.2 제품 사양](../PRODUCT.md)의 작은 본체·잠깐 나타나는 말풍선·선택적 LLM 경험을 유지하는 보조 도구다. 재생 명령은 사용자가 위젯에서 직접 누를 때만 전달한다. 캐릭터·LLM·자동 대화가 음악을 틀거나 재생목록을 수정하지 않는다. 이번에는 사용자의 명시적 요청에 따라 Figma에서 디자인하며, 일반적인 comet 작업의 Figma 미사용 지침을 바꾸지는 않는다.

## 로컬 재생 제어

| 연결 | 지원 범위 | 별도 경계 |
| --- | --- | --- |
| macOS Music | 재생·일시정지, 이전·다음, 탐색, 앱 볼륨, 셔플, 반복 | 사용자가 허용한 앱에 Apple Events를 전달한다. 앱이 닫혀 있으면 자동 실행하지 않는다. |
| macOS Spotify | 재생·일시정지, 이전·다음, 탐색, 앱 볼륨, 셔플, 반복 끄기/전체 | Spotify로 고정한 음악 위젯을 열면 꺼진 앱을 실행한다. 로컬 scripting dictionary는 재생목록 전체 조회·큐·좋아요 쓰기를 제공하지 않는다. |
| Windows 미디어 세션 | 세션이 제공하는 재생·일시정지, 이전·다음, 탐색, 셔플, 반복 | capability와 명령의 성공 여부를 확인한다. 관측한 sourceId로 대상을 고정한다. GSMTC 볼륨은 미지원이다. |
| Spotify + Spicetify | 기본 제어, 플레이리스트 조회·곡 선택·랜덤 곡 재생, 대기열 조회·추가, 현재 곡 좋아요 | 선택적 로컬 확장이 필요하다. Spotify 내부 API 변경에 영향을 받으며 실계정 인수는 별도다. |

2026-09-22 사용자 요청으로 Spotify 자동 실행과 최초 페어링 유지로 계약을 확장했다. Spotify 또는 Spicetify로 고정한 음악 위젯을 열면 꺼진 Spotify를 실행하며, 이미 실행 중이면 그대로 둔다. Comet 시작과 정기 조회만으로 Spotify를 실행하지 않고 음악 재생도 자동으로 시작하지 않는다. 자동 선택과 다른 제공자의 실행 정책은 유지한다.

Spicetify는 처음 연결 코드를 만들 때 `127.0.0.1:18743`을 연다. 코드는 메모리에만 보관하고 3분 안에 페어링해야 한다. 최초 인증 후 Comet의 OS 자격 증명 저장소와 Spotify 확장의 localStorage에 별도 재연결 정보를 저장한다. 앱 시작 시 활성 Spicetify 위젯의 저장된 연결을 복구하고 확장은 자동으로 재연결한다. Origin·Host·경로와 양방향 난수 기반 인증 증명을 확인하며 OAuth·Spotify 세션 토큰은 comet으로 가져오지 않는다. 일반 앱 종료·창 닫기는 페어링을 유지하고, 명시적 연결 해제·제공자 변경·위젯 끄기·제거는 저장된 복구 권한을 폐기한다. 명령은 정해진 이름과 값만 허용하고 크기·동시 요청·시간 제한을 적용한다. 설치·업그레이드 방법과 저장 경계는 [Spicetify 연결 안내](../development/spicetify.md)에 둔다.

랜덤 곡 재생은 선택한 플레이리스트의 페이지를 모두 읽은 다음 재생 가능한 곡 중 하나를 선택한다. 한도나 시간 제한으로 전체 목록을 읽지 못하면 실패를 표시하고 일부 목록에서 임의 선택하지 않는다. 좋아요는 명령을 누른 현재 곡의 URI를 다시 확인한다. 재생 제어는 Spotify 내부 상태에 반영된 것을 확인한 뒤 결과를 갱신하며, 이 대기도 기존 취소·만료 경계를 따른다. 연결이 끊긴 명령을 재연결 후 다시 실행하지 않는다.

## 읽는 범위와 데이터의 원본

음악 위젯 설치와 연결 허용을 구분한다. 사용자가 허용한 제공자만 조회하고, 제공자가 실제로 반환한 값만 표시한다. “전체 정보”는 아래 필드를 받을 수 있게 확장한다는 뜻이며 모든 앱·모든 곡에서 값이 존재한다는 보장이 아니다. 제공자 adapter가 지원 필드와 이번 조회에서 받은 값을 각각 구분한다.

| 정보 묶음 | 받을 수 있는 선택 항목 | 표시 원칙 |
| --- | --- | --- |
| 곡과 앨범 | 제목, 아티스트 목록, 앨범, 앨범 아티스트, 앨범아트, 콘텐츠 종류 | 작은 위젯에는 제목·아티스트·앨범과 앨범아트를 우선 배치한다. 이미지가 없으면 대체 표식을 사용한다. |
| 재생 상태 | 재생·일시정지·정지, 전체 길이, 현재 위치, 반복, 셔플, 볼륨, 음소거 | 현재 상태와 제어 가능 여부를 함께 표시한다. 지원되는 기능만 조작할 수 있다. |
| 작품 정보 | 장르, 발매일·연도, 작곡가, BPM, 트랙 번호·총수, 디스크 번호·총수, 작품명·악장 | 제공자가 반환한 정밀도를 유지한다. 연도만 있으면 월·일을 채우지 않는다. |
| 파일·음질 | 형식, 비트레이트, 샘플레이트 | 현재 항목에 제공된 값만 표시하며, 값이 없을 때 서비스 요금제나 설정으로 추정하지 않는다. |
| 가사·설명 | 가사 원문, 곡·에피소드 설명 | 일반 텍스트로 읽고 원문의 줄바꿈을 보존한다. 텍스트 가사만으로 시간 동기화·현재 줄 강조를 만들지 않는다. |
| 보관함 정보 | 즐겨찾기, 평점, 재생 횟수, 마지막 재생 시각 | 해당 항목에 실제 값이 있을 때 읽기 전용으로 표시한다. 재생 횟수를 comet의 관찰 횟수로 대체하지 않는다. |
| 출처와 식별 | 제공자, 앱, 기기, 트랙 ID, 공식 항목 URL, 관측 시각 | 어느 연결의 결과인지 추적할 수 있게 한다. 기기와 공식 URL도 제공되지 않으면 만들지 않는다. |

빠진 값, 미지원 필드, 조회 실패를 구분한다. 제공자별 미제공 표식을 정규화한 뒤, 유효한 `0`과 `false`를 값 없음으로 취급하지 않는다. 선택 항목 하나를 읽지 못했다고 이미 확인한 곡 전체를 실패 처리하지 않으며, 상세에서는 필요한 경우 `제공되지 않음`을 표시한다. 음원 녹음·오디오 분석, 구매자·계정 개인정보 수집, 다른 제공자의 검색 결과를 이용한 자동 보충은 이 범위에 포함하지 않는다.

공식 URL은 제공자가 반환한 검증 가능한 항목 참조를 사용한다. 제목·가사·설명·URL은 외부 데이터이며 실행 명령이나 대본 문법으로 해석하지 않는다.

## 연결과 출처 선택

| 연결 | 확장 상태와 경계 |
| --- | --- |
| macOS Apple Music | 기존 로컬 앱 연결을 확장한다. 자동화 허용 범위 안에서 제공되는 재생·트랙 정보를 읽는다. 선택 필드 실패는 개별적으로 처리하고 실제 값의 유무를 구분한다. |
| macOS Spotify | 기존 로컬 앱 연결을 확장한다. Apple Music과 같은 필드 수를 보장하지 않으며 로컬 앱이 주지 않는 정보는 비워 둔다. |
| Windows 미디어 세션 | 운영체제 미디어 세션 adapter를 사용한다. 허용된 앱이 세션에 제공하는 정보를 읽는다. Windows의 모든 프로그램이 같은 항목을 제공한다고 가정하지 않는다. |
| macOS 브라우저·기타 앱 | 별도 adapter를 확보하기 전에는 미지원. 브라우저 재생을 Apple Music·Spotify 연결의 지원 범위로 표시하지 않는다. |
| 선택적인 Spicetify 연결 | Spotify 데스크톱 안의 확장과 로컬로 연결한다. 별도 Web API Client ID나 OAuth 연결을 전제로 하지 않는다. |

**자동 선택**은 허용되고 지원되는 출처 중 최신 상태가 재생 중인 앱을 고른다. 여러 앱이 동시에 재생되면 현재 선택도 재생 중인 동안 유지해 화면이 번갈아 바뀌지 않게 한다. **앱 고정**은 지정한 출처만 표시하며, 그 앱이 멈추거나 닫혀도 다른 앱으로 자동 전환하지 않는다. 사용자가 허용하지 않은 앱은 후보가 아니다.

자동 선택에서 재생 중인 후보가 사라지면 그 사실을 표시한다. 마지막 선택의 일시정지 상태를 최신으로 확인했다면 일시정지 화면을 유지할 수 있지만, 조회 실패나 오래된 캐시를 근거로 재생 여부를 결정하지 않는다. 최초 동시 재생은 허용 후보 중 Music → Spotify → Windows 시스템 세션 순서로 선택하며, 이후 선택한 앱이 재생 중이면 유지한다.

연결 허용·출처 선택은 [통합 설정창](settings.md)의 위젯 영역에서 관리한다. 설정 저장의 성공·실패와 조회 권한을 구분하고, 실패 시 초안을 보존한다. 음악 연결을 바꾸거나 끄더라도 원문 기록·기억·친밀도·설치 팩을 초기화하지 않는다.

설정 디자인에는 로컬 제공자별 허용·연결 해제, 자동 선택·앱 고정, 별도의 선택적 Spicetify 연결, 앨범아트·가사 표시와 값이 없는 항목 숨기기를 둔다. 표시 옵션은 조회 가능 여부와 구분하고, 숨긴 값이 있다고 연결 성공으로 표시하지 않는다. 설정 저장 뒤 해당 제공자만 조회한다.

**캐릭터가 현재 곡 이야기하기**는 음악 상태를 자동 대화의 후보로 사용할지 정한다. 이 허용이 상위 자동 대화·숨김·일시정지·사용자 입력에 따른 중단을 우회하거나 읽기 권한을 부여하지 않는다. 매 조회·매 곡마다 말하지 않고 기존 대본의 간격과 최신성 조건을 유지한다.

## 재생 상태와 최신성

| 상태 | 위젯과 상세 화면 | 캐릭터가 읽는 의미 |
| --- | --- | --- |
| 재생 중 | 최신 곡 정보와 유효한 진행률 표시 | 최신 상태에서만 현재 재생 중으로 취급 |
| 일시정지 | 제공자가 반환한 마지막 곡과 정지된 위치 유지 가능. 일시정지라고 명시 | `music.playing=false`. 현재 재생 중이라는 대사에 사용하지 않음 |
| 정지·곡 없음 | 재생 중인 곡이 없다고 표시. 이전 곡을 현재 곡 자리에 남기지 않음 | 성공한 비재생 상태로 구분 |
| 앱 미실행 | 선택한 앱이 실행 중이지 않다고 표시 | 곡 없음·권한 실패와 구분 |
| 조회 중·권한 필요·연결 실패·미지원 | 해당 원인과 가능한 복구 동작 표시 | 실패를 정상적인 빈 곡으로 해석하지 않음 |
| 오래된 결과 | 이전 정보라는 표시와 마지막 확인 시각. 진행률 갱신 중단 | 현재 곡·현재 재생 여부로 사용하지 않음 |

길이 또는 위치가 없으면 진행률을 계산하지 않는다. 유효한 관측 위치에서 화면상 시간을 보간하더라도 관측 시각을 갱신한 것으로 취급하지 않는다. 일시정지·출처 변경·곡 변경·조회 만료 즉시 보간을 멈추고 이전 곡의 앨범아트·가사·진행률을 새 곡에 섞지 않는다. UI 프레임 갱신을 외부 앱 고빈도 조회로 구현하지 않는다.

정기 조회 간격 15초, `.talk` 음악 최신성 기준 30초와 공용 동시 조회·실패 backoff를 유지한다. 직접 재생 명령 직후에는 상태를 다시 조회한다. 음악 명령은 동시에 하나만 처리하고 대기 명령을 쌓지 않는다. OS·Spotify에 이미 전달된 조작을 되돌리는 취소는 보장하지 않으며, 취소를 확인한 작업은 다음 조작을 발송하지 않는다. [수명주기](../widgets/lifecycle.md)와 [대본 변수](../development/talk-reference.md)의 중단 계약을 따른다. 끄기·제거·권한 해제·출처 변경 후 늦게 끝난 조회는 기존 token·revision 경계를 통과하지 못하게 한다.

현재 `.talk` 공개 값은 `music.title`, `music.artist`, `music.running`, `music.playing`과 공통 `ready`·`status`다. 확장 화면의 모든 필드를 자동으로 대본 변수에 공개하지 않는다. 일시정지 곡을 화면에 보존하더라도 기존 `music.title`·`music.artist`의 “현재 재생 중, 비재생 시 null” 의미는 유지한다. 추가 변수는 타입·미지원·최신성 계약을 정하고 대본 reference와 회귀 테스트를 함께 변경해야 한다.

## 화면과 Lagrange 디자인

상주 중심 화면은 기존 작은 캐릭터와 말풍선이다. 음악 위젯은 사용자가 꺼내 보는 보조 창이며, 전체 메타데이터를 작은 창에 한꺼번에 채우지 않는다.

| 화면 | 역할 |
| --- | --- |
| 작은 음악 위젯 | 디자인 폭 440px. 앨범아트, 제목·아티스트·앨범, 출처·재생 상태, 탐색과 기본 제어. 가사·곡 정보 상세로 펼치기 |
| 상세 화면 | 디자인 폭 720px. 가사 첫 탭·곡 정보 두 번째 탭. 공통 곡 요약과 탭은 상단에 고정하고 아래 본문만 전환·스크롤 |
| 가사 탭 | 가사가 없거나 미지원인 상태와 원문 텍스트를 구분 |
| 곡 정보 탭 | 작품·재생·파일·보관함·출처 정보를 읽는 행 배치 |
| 연결 설정 | 기존 폭 1120px 통합 설정창의 위젯 영역. 출처 허용·자동 선택/앱 고정, 표시 옵션·현재 곡 대화 허용·Spicetify 페어링 관리 |
| 비재생·실패 상태 | 작은 위젯의 창 구조를 유지하며 일시정지·곡 없음·권한 필요·연결 실패·미지원·오래됨을 구분 |

창 헤더의 제목·닫기와 드래그 영역, 닫기와 위젯 끄기의 차이는 [공통 창 계약](desktop.md#창-이동과-닫기)을 따른다. 지원되는 재생·이전/다음 곡·탐색·볼륨·셔플·반복 조작을 공통 곡 요약에 둔다. 전체 정보를 보려는 이동과 연결을 변경하려는 이동은 각각 상세 화면과 설정창으로 연결한다.

상세 화면의 공통 곡 요약에는 128×128px 앨범아트, 재생 상태, 곡명, 아티스트·앨범과 진행률을 배치한다. **가사 / 곡 정보** 순서의 탭을 곡 요약 아래에 두고 두 영역 모두 상단에 고정한다. 두 탭에서 곡 요약의 디자인·크기·위치는 같으며 탭 선택과 아래 본문만 바뀐다. 가사나 정보가 길어도 본문만 스크롤하고 곡 요약과 탭을 함께 밀어 올리지 않는다.

[Figma 음악 디자인 보드](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-9948)는 Lagrange의 Foundations·Library를 사용한다. [재생 중](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-9959), [일시정지](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-10024), [상세](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-10110), [가사](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-10300)를 참조한다. 디자인의 곡·아티스트·가사·수치·앨범아트는 가상 예시이며 실제 조회 결과가 아니다.

[연결 설정](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-10373)과 [출처 선택](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-10867)은 연결 허용과 현재 표시할 앱의 차이를 보여 준다. 예외 상태는 [오래된 결과](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-10667)와 [권한 필요](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-10797)를 대표 기준으로 삼고, 나머지 상태는 같은 보드에 둔다. [Windows 미디어 세션](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-10645) 화면은 Windows 연결의 설계 예시이며 실제 Windows 실행 검증을 대신하지 않는다.

Library에 추가한 [MediaProgress](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-9922)는 읽기 전용 진행률, [MetadataRow](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-9945)는 상세의 이름·값 행을 담당한다. 재생 조작을 위해 [MediaSeek](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=201-12148)를 추가했다. 이 컴포넌트들은 Figma 설계이며 `@fleetia/lagrange` 코드나 배포 패키지에 추가된 상태가 아니다. 기존 semantic token·서체·컴포넌트 인스턴스를 유지했다. 앱에서는 기존 Lagrange 컴포넌트·토큰과 native range 입력으로 재생 조작을 구현한다.

[탐색 프로토타입](https://www.figma.com/proto/vKl8h9uoXUUljJ5yEAcNpr?node-id=199-11008&starting-point-node-id=199-11008&page-id=11-22)은 화면 이동 검토용이다. Figma Desktop에서 위젯의 상세 진입, 가사·곡 정보 전환, 상세 본문 스크롤 중 곡 요약·탭·닫기 고정을 확인했다. 기존 Library 인스턴스 연결, Eulyoo1945 서체와 semantic 색상 바인딩도 확인했다. 연결 허용·페어링·설정 저장·실제 재생 정보 갱신은 프로토타입의 실행 범위가 아니다.

## 인수 조건과 남은 검증

- 허용하지 않은 제공자를 조회하지 않고 자동 선택·앱 고정·동시 재생의 선택 결과가 안정적이다.
- 제공자별 필드 지원을 확인하고 미지원·값 없음·`0`·`false`·일부 조회 실패를 구분한다.
- 재생·일시정지·정지·앱 미실행·권한 실패·stale이 화면과 `.talk`에서 모순 없이 구분된다.
- 출처·곡 변경과 조회 만료 뒤 이전 앨범아트·가사·진행률이 새 곡의 정보처럼 남지 않는다.
- 연결 변경·끄기·제거 이후 완료된 조회가 현재 상태를 덮어쓰거나 자동 대사를 재생하지 않는다.
- 작은 위젯에서 긴 제목·이미지 없음·길이 없음과 실패를 읽을 수 있고 상세 본문을 스크롤해도 닫기에 접근할 수 있다.
- 상세 화면은 가사·곡 정보 순서를 유지하며 탭을 전환하거나 본문을 스크롤해도 공통 곡 요약과 탭의 위치·디자인이 유지된다.
- LLM·Web API OAuth 없이 로컬에서 허용한 앱의 정보를 읽고 직접 누른 명령만 전달한다. Spicetify 연결은 별도 명시적 페어링을 따른다.
- Spotify 음악 위젯을 열 때만 꺼진 Spotify를 실행한다. 재연결은 이전 명령을 재실행하거나 일시정지 곡을 자동 재생하지 않는다. 처음 한 번 페어링한 뒤 두 앱의 재시작에도 연결이 복구되며, 명시적으로 해제한 연결은 복구하지 않는다.
- 구현 후 현재 소스의 데스크톱 빌드를 실제 실행해 macOS Music·Spotify와 Windows 미디어 세션을 각각 확인한다. Figma 관찰과 과거 앱 검증을 새 연결의 동작 근거로 쓰지 않는다.

실계정·OS별 검증 범위는 상태표에 기록하며 자동 검사로 대체하지 않는다. 지원 제공자·필드·선택 우선순위·최신성·공개 대본 변수·화면 책임이 바뀔 때 이 문서와 [상태표](../status.md)를 함께 갱신한다.
