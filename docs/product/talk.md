# 상태에 반응하는 대본

`.talk`는 위젯의 상태와 실제 사건에 맞춰 활성 캐릭터의 대사를 고르는 Comet 전용 텍스트 형식이다. 원문 작성·검사·저장은 Comet과 분리된 talk editor가 맡고, Comet은 앱 데이터의 암호화 bundle을 읽어 재생한다. 이 문서는 대본의 소유 범위, 선택 순서, 파일 반영과 중단 규칙을 설명한다. 정확한 문법·변수·검사 명령은 [대본 작성 참조](../development/talk-reference.md)에 둔다.

대본이 만드는 결과는 1~8명의 본체와 하나의 공용 말풍선이다. 대본을 읽기 위해 모델을 다운로드하거나 API를 설정할 필요는 없다. Comet 앱 안에는 `.talk`·story 원문 편집기 UI가 없으며, 원문은 별도 talk editor의 책임이다. 외부 SSP 대본 및 Yarn 파일 호환은 이번 구현에 포함하지 않는다.

## 대화팩과 나만의 대본

앱이 읽는 대본 폴더는 앱 데이터 디렉터리의 `talk/`다. macOS 기본 설치에서는 `~/Library/Application Support/space.starlight.comet/talk/`에 해당한다. 테스트 실행에서 앱 데이터 디렉터리를 바꿨다면 해당 디렉터리를 기준으로 찾는다. 폴더 안에는 두 종류의 대본이 있다.

| 위치 | 소유 | 설명 |
| --- | --- | --- |
| `talk/index.talk` | 사용자 | 나만의 진입 파일. 새 설치에서는 `format: 1`과 주석만 있다. 여기에 장면을 쓰거나 `import`로 파일을 나눈다 |
| `talk/packs/<팩 ID>/index.talk` | 대화팩 | 설치한 대화팩 하나의 진입 파일. 팩의 import는 그 팩 폴더 안에서만 해석한다 |

대화팩(talk pack)은 앱에 동봉한 대본 묶음이며 **설정 → 대화팩**에서 설치·제거한다. 팩 ID는 소문자·숫자·`-`·`_` 1~64자다. 2026-09-20부터 동봉 팩은 두 개다.

| 팩 ID | 이름 | 기본 설치 | 범위 |
| --- | --- | --- | --- |
| `byulkkori` | 별꼬리 기본 대화 | 예 | 공통 범위. 시간·기본 날씨·22개 위젯 상태·사건과 조건 없는 잡담. 함께 지내는 친구 1~8명 중 무작위 화자가 말한다 |
| `nadir-and-star-tail` | 나디르와 별꼬리 | 아니요 | `pair("source:nadir", "source:star-tail")` 범위. 나디르·별꼬리 추가팩이 함께 활성일 때만 선택된다 |

기본 대화팩은 새 설치에 한 번 복사되고 제거할 수 있다. 제거한 팩은 재시작으로 되살리지 않으며, 같은 화면에서 다시 설치할 수 있다. 설치·제거는 `talk/packs/<팩 ID>/` 폴더를 만들거나 지우는 일이며 사용자의 `index.talk`, 대화 기록, 친밀도에는 손대지 않는다. 팩 폴더를 직접 넣어도 `index.talk`가 있고 ID 규칙을 지키면 같은 목록에 "직접 추가한 팩"으로 나타난다. 잘못된 팩이 하나라도 있으면 묶음 전체가 활성화되지 않고 마지막 유효 대본을 유지하며 오류 위치를 로그에 남긴다. 다만 설정에서 명시적으로 제거한 팩은 다른 대본에 오류가 있어도 마지막 유효 대본에서 제외한다.

저장소의 `talk/`는 동봉 원본이다. `talk/index.talk`는 사용자 진입 파일의 초기 내용, `talk/packs/`는 팩 원본이다. 앱 실행 중 수정할 대상은 앱 데이터 디렉터리의 사본이며, 저장소 대본을 바꿨다고 이미 설치된 사용자 파일을 덮어쓰지 않는다.

0.5.0 설치에서 `talk/` 폴더에 그대로 남아 있던 나디르·별꼬리 동봉 대본은 첫 실행에서 한 번 옮긴다. 폴더의 모든 `.talk`가 동봉 원본과 같을 때만 `packs/nadir-and-star-tail/`로 이동하고 사용자 `index.talk`를 빈 진입 파일로 바꾼다. 한 파일이라도 수정했다면 그대로 두고 기본 대화팩만 추가하며, 기존 나디르 대본은 사용자 대본으로 계속 재생된다. 이 이동은 `.talk-packs-v1` 표식으로 한 번만 실행한다.

아래는 실행 중인 집중 타이머에 반응하는 독립 장면이다.

```text
format: 1

scene: timer.focus
on: idle
when: timer.ready and timer.state == "running" and timer.mode == "focus"
cooldown: 30m
---
A[호기심]: 집중 타이머가 가고 있어. 나도 목소리를 좀 줄일게.
B[평온]: 이미 말했으니 이제 줄이면 돼.
===
```

`on`은 평가 기회, `when`은 그때 만족해야 하는 조건이다. `cooldown`은 이 장면을 실제로 보여 준 뒤 다시 선택할 수 있을 때까지의 최소 간격이다. 대사를 읽는 동안 루프를 돌거나 위젯 데이터를 수정하는 기능은 없다.

## 지속 상태와 한 번의 사건

`timer.state == "running"`은 여러 번 확인할 수 있는 상태다. 자동 수다 차례의 `idle` 평가에서 장면 후보가 된다. `timer-finished`는 타이머가 끝났을 때 발행한 사건이며 해당 사건을 처리할 때만 평가한다.

```text
format: 1

scene: timer.finished-focus
on: timer-finished
when: timer.ready and event.mode == "focus"
cooldown: 30m
---
A[기쁨]: 정해 둔 집중 시간이 끝났어.
B[평온]: 하던 일을 어디까지 했는지는 네가 제일 잘 알지. 잠깐 쉬어도 좋고.
===
```

위젯의 원본 JSON 전체를 대본에 넘기지 않는다. 호스트가 [공개 변수 목록](../development/talk-reference.md#공개-변수-전체-목록)으로 정리한 읽기 전용 값만 제공한다. 메모 본문, 숨겨진 맞히기 정답, 자격 증명과 임의 사건 payload는 이 목록에 없다.

`ready`와 `status`는 데이터의 의미를 구분하는 데 사용한다. 정상적으로 조회한 빈 목록은 오류가 아니다. 오래된 관측값과 연결 실패는 빈 목록이나 숫자 `0`으로 바꾸지 않고 상태와 `null`로 나타낸다. nullable 숫자는 `!= null`을 먼저 검사한 뒤 비교하고, nullable 문자열은 치환 전에 존재를 확인한다.

미설치·비활성 또는 필수 의존 위젯이 없는 대본은 후보에서 제외한다. 설치된 연결 위젯의 인증 필요·오류·오래됨은 별개의 상태이므로 그 상태를 설명하는 장면을 작성할 수 있다. 위젯 화면을 닫는 것과 위젯을 비활성화하는 것은 다르다.

## 공통 대본과 캐릭터 조합

기본 범위는 모든 조합에서 사용할 수 있는 공통 대본이다. 다음 import는 특정 두 로컬 캐릭터가 함께 있을 때 사용할 장면을 등록한다.

```text
format: 1

import "./widgets/index.talk" for pair("source:nadir", "source:star-tail")
import "./situations/index.talk" for pair("source:nadir", "source:star-tail")
import "./pairs/default.talk" for pair("source:nadir", "source:star-tail")
# 별도의 세 친구 대본이 있다면:
# import "./casts/three.talk" for cast("first-local-id", "second-local-id", "third-local-id")
```

조합은 표시 이름 대신 설치된 캐릭터의 로컬 ID 또는 `source:` 뒤의 정본 `sourceId`로 식별한다. 나디르·별꼬리 추가팩은 가져오기·복사·자리 교환 뒤에도 같은 정본 대사를 사용하도록 `source:nadir`·`source:star-tail`을 쓴다. ID를 확인하는 명령은 [CLI 참조](../development/talk-reference.md#cli-명령)에 있다. 조합 범위는 그 파일의 하위 import에도 이어진다.

`cast`는 서로 다른 로컬 ID 1~8개를 순서대로 받는다. `pair`는 두 ID를 받는 기존 구문으로 계속 지원한다. 조합 파일의 A~H는 선언한 ID의 순서이며, 바탕화면 순서를 바꿔도 같은 캐릭터를 따른다. 공통 파일의 A~H는 현재 자리 1~8이다. 선언한 cast에 없는 화자는 문법 검사에서 거절하고, 현재 활성 목록에 필요한 화자나 cast 구성원이 없으면 장면 전체를 제외한다. 없는 화자의 줄을 지우거나 다른 캐릭터에게 넘기지 않는다.

장면 ID는 공통 범위 안에서, 또는 같은 순서의 ID 목록 범위 안에서 고유해야 한다. 서로 다른 범위에서는 같은 ID를 쓸 수 있다. 재생 이력의 key는 순서가 있는 조합 ID 목록과 장면 ID로 만들기 때문에 파일 위치를 옮겨도 유지된다. 대화팩의 장면 key에는 팩 ID가 앞에 붙으므로 두 팩이 같은 장면 ID를 써도 충돌하지 않는다. 장면 ID를 바꾸면 다른 장면으로 취급한다.

### 무작위 화자와 인원 조건

공통 범위의 장면에 `speakers: random`을 적으면 그 장면의 A~H는 자리 1~8이 아니라 **현재 함께 지내는 친구를 무작위로 섞은 순서**다. 같은 seed·같은 인원이면 순서가 같으므로 표시 직전 재검증도 같은 화자를 본다. 장면이 쓰는 글자 수보다 친구가 적으면 그 장면은 후보에서 빠진다. 따라서 1명만 있을 때는 A만 쓰는 장면이, 8명이 있을 때는 A~D를 쓰는 장면까지 열리지만 여덟 명이 한 번에 말하는 장면은 없다.

```text
scene: duo.tail-race
on: idle
when: character.count >= 2
cooldown: 30m
speakers: random
---
A[장난]: 누가 더 빨리 꼬리 흔드나 시합!
B[기쁨]: 준비, 시작! 앗, 벌써 졌어.
===
```

`character.count`는 현재 활성 캐릭터 수(1~8)다. 기본 대화팩은 혼자 말하는 장면, `character.count >= 2`의 둘 장면, `>= 3`·`>= 4`의 셋·넷 장면을 섞어 두고 선택 규칙(미표시 우선, 그다음 seed)으로 매번 다른 인원과 화자를 고른다. `cast`·`pair` 범위의 장면에는 `speakers: random`을 쓸 수 없다. 교감처럼 대상 자리가 정해진 사건은 기본값 `speakers: slots`로 두고 `event.character`에 따라 분기한다.

## 어떤 대본을 고르는가

### 장면 후보 안의 선택

1. 현재 `on`, 활성 캐릭터 조합, 위젯 의존성, `when`, cooldown을 검사한다.
2. 본문 분기와 치환을 실행하고 대사의 길이·줄 수를 검사한다. 빈 장면이나 치환할 수 없는 `null`은 재생하지 않는다.
3. 재생 가능한 조합 전용 장면이 있으면 공통 장면보다 먼저 선택한다. 조합 장면이 모두 cooldown 중이거나 조건에 맞지 않으면 공통 장면도 선택할 수 있다.
4. 같은 범위에서는 한 번도 표시하지 않은 장면을 먼저, 그다음에는 마지막 표시가 가장 오래된 장면을 고른다. 같은 순위는 seed를 사용해 결정한다.

장면의 `priority`를 직접 지정하는 header는 없다. 선택 결과와 탈락 이유는 `talk simulate`에서 확인한다.

### 일반 수다와 함께 재생하기

앱의 첫 인사는 기존 캐릭터 인사를 유지한다. 이후 수다 기회에서 `.talk`와 일반 수다가 교대로 차례를 얻는다. `.talk`에 재생 가능한 장면이 없으면 같은 차례에 일반 수다로 넘어간다. 일반 수다의 단어장·준비된 LLM 대사 선택 순서는 일반 수다가 실제로 선택될 때만 진행된다.

따라서 위젯 대본을 추가해도 단어장과 LLM 대사가 사라지지 않는다. 직접 사용자 입력의 키워드 단어장은 [대화와 기억](conversation.md)의 기존 우선순위대로 모델 준비 검사 전에 처리한다.

### 실제 사건에 반응하기

위젯 사건은 기존 호스트 대기열에서 하나를 선택한 뒤 `.talk`에 전달한다. 나디르·별꼬리가 자리와 무관하게 함께 활성이면 같은 사건에 맞는 대본이 없거나 모두 재생 불가일 때 발화를 생략한다. 원시 사건 문구를 캐릭터의 대사로 사용하지 않으며 사건 자체와 위젯 상태는 유지한다. 다른 캐릭터 조합은 기존 내장 사건 문구 fallback을 유지한다. `.talk`가 별도의 사건 대기열을 만들지는 않는다.

사용자 입력, 시각이 중요한 알림, 위젯 사건, 일반 수다의 우선순위와 대기열 정리 기준은 [위젯 생명주기](../widgets/lifecycle.md#발화-대기열과-오래된-생성-결과)를 따른다. 타이머 종료·캘린더 알림이 먼저 선택되고, 선택 후 나머지 대기 사건을 비우는 정책도 유지한다. 나디르·별꼬리 조합의 발화 생략 조건은 시각이 중요한 사건에도 적용된다. 두 동봉 팩 모두 실제 사건에 반응하는 장면의 cooldown을 0초로 두어 연속 행동에도 새 변주를 선택하고, `idle` 장면은 30분 간격을 유지한다. 사건 중복·과다 입력 제어는 호스트 대기열이 담당한다.

## 저장과 재로딩

최초 초기화에서 사용자 진입 파일을 한 번 만들고 앱 데이터 디렉터리에 `.talk-initialized-v1` 표식을 남긴다. 기본 대화팩은 `.talk-packs-v1` 표식으로 한 번만 설치한다. 이미 존재하는 대본 폴더와 수정한 파일은 보존한다. 이후 삭제한 파일·폴더·대화팩을 앱 재시작으로 복원하지 않는다.

실행 중에는 250ms 간격으로 `talk/` 아래 전체(사용자 파일과 `packs/`)의 변화를 관측하고, 350ms 이상 변화가 멈춘 뒤 묶음을 다시 읽는다. 외부에서 팩 폴더를 바꾼 경우도 같은 경로로 반영되며, 재생 중인 `.talk` 장면은 유효한 새 묶음이 적용되면 중단한다. 읽기 전후 파일 상태가 같아야 반영한다. 따라서 350ms는 정확한 반영 지연 보장이 아니라 저장 안정성 검사 기준이다. 여러 파일을 수정할 때는 `talk check`로 묶음을 검증한 뒤 저장하면 오류 위치를 찾기 쉽다.

설정에서 팩을 제거하면 그 팩의 준비·재생을 즉시 중단하고 후보에서 제외한다. 다른 대본의 문법 오류로 재로딩이 실패해도 제거한 팩을 계속 재생하지 않는다. 제거 전에 읽기 시작한 감시 작업은 이전 묶음을 다시 활성화할 수 없다. 나머지 마지막 유효 대본은 유지한다.

| 저장 결과 | 동작 |
| --- | --- |
| 전체 파일이 유효함 | 새 대본 묶음을 한 번에 활성화. 기존 `.talk` 재생은 중단 |
| 문법·타입·import 오류(사용자 파일 또는 어느 팩) | 오류 위치를 기록하고 마지막으로 유효했던 대본 유지 |
| 최초 로드부터 실패 | 일반 수다와 위젯 내장 사건 문구로 동작 |
| `format: 1`만 남긴 사용자 진입 파일 | 사용자 장면만 비운다. 설치된 대화팩은 계속 재생 |
| 사용자 진입 파일 삭제 | 설치된 대화팩만 읽는다. 팩도 없으면 `.talk` 후보가 없음 |
| 설정에서 대화팩 제거 | 다른 파일의 오류와 무관하게 그 팩의 장면을 제외하고 해당 재생을 중단. 재시작으로 되살리지 않음 |

모든 `.talk` 대사를 끄려면 대화팩을 제거하고 사용자 진입 파일에 `format: 1`만 남긴다. 잘못된 파일을 고쳐 저장하면 같은 watcher가 다시 검사한다. 오류 진단은 앱 로그에 `.talk 경로:줄:열 [코드] 메시지`로 남는다.

## 표시 직전의 재검증과 기록

후보 조회와 미리보기는 재생 이력이나 cooldown을 소비하지 않는다. 실제 첫 줄을 표시하는 경계에서 대화 기록과 `talk_history`를 같은 데이터베이스 transaction으로 저장한다. 첫 줄을 표시하기 전에 취소된 장면은 이력을 소비하지 않는다. 일부만 표시한 장면은 표시한 줄만 대화 기록에 남는다.

각 줄을 표시하기 전에 다음을 다시 확인한다.

- 작업 epoch, 일반 저장 revision, 대본 generation이 유효한가.
- 활성 캐릭터 ID와 참조한 모든 위젯·필수 의존 위젯의 revision 및 활성 상태가 같은가.
- 사건이 만료되지 않았는가.
- 최신 상태에서 `when`, `@if`, 데이터 최신성, 치환 가능 여부와 대사 제한을 여전히 만족하는가.

시간이 흐른다는 이유만으로 진행 중인 타이머의 모든 대사를 취소하지 않는다. 조건과 분기는 최신 값으로 다시 판단하되, 본문 변수 치환은 준비 시점의 값으로 유지한다. 최신 상태로는 더 이상 만들 수 없는 문구, 달라진 분기, 위젯 수정·비활성화, 캐릭터 교체, 대본 교체는 남은 장면을 무효화한다. 타이머 잔여 시간을 치환한 문장은 준비 시점의 관측값이며 계속 갱신되는 숫자 화면이 아니다.

사용자 입력·숨김·일시정지·자동 동작 끄기·재시작의 중단 규칙도 기존 호스트 경계를 따른다. 파일 재로딩과 캐릭터 교체를 이유로 원문 대화·기억·친밀도를 초기화하지 않는다.

## 검증과 후속 범위

2026-09-19의 `cast`·A~H 확장과 2026-09-20의 대화팩·`speakers: random`은 소스와 자동 테스트로 확인한다. 예전 A/B 대본 검증 기록을 이번 확장의 데스크톱 검증으로 재사용하지 않는다. 캐릭터팩 v2는 `.talk`를 포함하지 않으며, 다른 설치에 대본을 옮길 때는 그 설치의 로컬 ID로 cast를 연결해야 한다. 대화팩은 캐릭터팩과 별개의 설치 단위다.

[대본 검증 범위](../development/talk-coverage.md)에서 기본 위젯·상태·사건별 대본과 고정 입력을 연결한다. 문법 검증, 상태 시뮬레이션, 실제 데스크톱 결과는 [대본 검증 기록](../VALIDATION-TALK.md)에서 구분한다. 파일이 문법 검사를 통과했다는 사실만으로 모든 외부 연결이나 플랫폼에서 실행을 검증했다고 보지는 않는다.

Comet은 앱 데이터의 암호화 대본을 복호화해 읽고, parser가 원문과 장면·문장의 source span을 유지해 오류의 파일·줄·열을 계산한다. 원문 작성·편집·저장 UI와 그에 필요한 충돌 처리는 별도 talk editor의 책임으로 둔다. 이 문서의 선택·재로딩·중단 계약을 바꿀 때는 해당 코드와 테스트, 이 문서, `docs/status.md`를 함께 갱신한다.

## 암호화 저장과 별도 talk editor 경계

2026-09-19부터 동봉 `.talk`와 앱 데이터 폴더의 `.talk`는 `COMET-TALK-AES256GCM-V1` envelope를 사용한다. AES-256-GCM과 매 저장의 무작위 nonce로 암호화·인증하며 손상되거나 인증되지 않은 암호문은 활성화하지 않는다. 이전 설치의 envelope도 읽은 뒤 새 형식으로 저장한다. key는 앱과 함께 제공되므로 파일의 직접 열람을 막는 포장 방식이며 사용자 자신이나 역공학을 막는 DRM은 아니다. 실제 대화 기록·기억은 이 파일 암호화의 대상이 아니다.

기존 평문은 호환 입력으로 읽을 수 있으며 유효한 bundle을 초기화할 때 암호화한다. 구 factory 원문 SHA256과 일치하는 파일만 새 기본 대사로 한 번 교체한다. 수정한 원문과 삭제한 파일은 보존한다. 후보 전체의 import graph를 검사한 뒤 교체하며 잘못된 대본이 섞여 있으면 기존 파일을 유지한다.

별도 talk editor는 `.talk` 폴더 안의 상대 경로만 다루고 symlink·상위 경로·폴더 밖 import를 거부해야 한다. 전체 대본을 검증한 뒤 atomic 저장하고, 문법 오류의 파일·줄·열과 revision 충돌을 편집 화면에서 다루는 것이 후속 editor의 책임이다. Comet은 저장된 파일을 재로딩할 때 last-good·취소 규칙을 적용한다.

개발용 CLI는 현재 읽기·검사·시뮬레이션만 제공한다. `check`는 진입 파일과 import graph를 검사하고, `variables`·`simulate`·`characters`는 런타임 입력을 읽기 전용으로 조회한다. 원문 작성과 암호화 저장은 별도 talk editor가 담당하며 Comet 앱이나 현재 CLI가 저장 권한을 제공하지 않는다.

```sh
pnpm talk check talk
pnpm talk packs talk
pnpm talk variables
pnpm talk simulate talk --input input.json
```

`check`·`simulate`에 폴더를 주면 사용자 `index.talk`와 `packs/` 아래 설치된 팩을 한 묶음으로 읽고, 파일을 주면 그 진입 파일만 읽는다.

CLI의 정확한 인수는 [CLI 참고](../development/talk-reference.md)를 따른다.

선택지 스토리 원문도 앱 안에서 편집하지 않는다. 별도 talk editor가 `story/nadir.story.enc`를 작성·검사·저장하는 후속 경계를 가지며, Comet은 유효한 파일을 읽어 선택지를 재생한다. 각 공개 단계에 5개 이상, 전체 15~256개 장면을 두며 장면마다 2~4개 선택지와 -5~5의 점수 변동을 작성한다. 동봉 대사는 +5/-3이다. Comet은 잘못되거나 삭제된 파일을 마지막 정상 catalog로 유지하며 재시작에서는 동봉 catalog로 돌아간다. 삭제한 편집 파일을 자동 복원하지 않는다. 비밀의 단계 배치와 캐릭터 말투는 작성자의 책임이며 JSON 검사는 의미를 판정하지 않는다.
