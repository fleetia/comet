# 상태에 반응하는 대본

`.talk`는 위젯의 상태와 실제 사건에 맞춰 A/B의 대사를 고르는 Nanika Box 전용 텍스트 형식이다. 사람이 직접 수정하거나 AI에게 작성하게 할 수 있다. 이 문서는 대본의 소유 범위, 선택 순서, 파일 반영과 중단 규칙을 설명한다. 정확한 문법·변수·검사 명령은 [대본 작성 참조](../development/talk-reference.md)에 둔다.

대본이 만드는 결과는 기존 A/B 본체와 잠깐 표시되는 말풍선이다. 대본을 읽기 위해 모델을 다운로드하거나 API를 설정할 필요는 없다. 전용 편집기 UI, 외부 SSP 대본 및 Yarn 파일 호환은 이번 구현에 포함하지 않는다.

## 파일 한 곳에서 시작하기

앱이 읽는 진입 파일은 앱 데이터 디렉터리의 `talk/index.talk`다. macOS 기본 설치에서는 `~/Library/Application Support/space.starlight.nanika-box/talk/index.talk`에 해당한다. 테스트 실행에서 앱 데이터 디렉터리를 바꿨다면 해당 디렉터리를 기준으로 찾는다.

진입 파일에 모든 장면을 쓸 수 있고, `import`로 위젯·상황·캐릭터 조합별 파일을 나눌 수도 있다. 저장소의 `talk/`는 최초 설치에 쓰는 기본 대본 원본이다. 앱 실행 중 수정할 대상은 앱 데이터 디렉터리의 사본이며, 저장소 대본을 바꿨다고 이미 설치된 사용자 파일을 덮어쓰지 않는다.

아래는 실행 중인 집중 타이머에 반응하는 독립 장면이다.

```text
format: 1

scene: timer.focus
on: idle
when: timer.ready and timer.state == "running" and timer.mode == "focus"
cooldown: 30m
---
A[호기심]: 집중 타이머가 가고 있어. 나도 목소리를 좀 줄일게.
B[평온]: 이미 말했으니 이제 줄이면 돼.
===
```

`on`은 평가 기회, `when`은 그때 만족해야 하는 조건이다. `cooldown`은 이 장면을 실제로 보여 준 뒤 다시 선택할 수 있을 때까지의 최소 간격이다. 대사를 읽는 동안 루프를 돌거나 위젯 데이터를 수정하는 기능은 없다.

## 지속 상태와 한 번의 사건

`timer.state == "running"`은 여러 번 확인할 수 있는 상태다. 자동 수다 차례의 `idle` 평가에서 장면 후보가 된다. `timer-finished`는 타이머가 끝났을 때 발행한 사건이며 해당 사건을 처리할 때만 평가한다.

```text
format: 1

scene: timer.finished-focus
on: timer-finished
when: timer.ready and event.mode == "focus"
cooldown: 30m
---
A[기쁨]: 정해 둔 집중 시간이 끝났어.
B[평온]: 하던 일을 어디까지 했는지는 네가 제일 잘 알지. 잠깐 쉬어도 좋고.
===
```

위젯의 원본 JSON 전체를 대본에 넘기지 않는다. 호스트가 [공개 변수 목록](../development/talk-reference.md#공개-변수-전체-목록)으로 정리한 읽기 전용 값만 제공한다. 메모 본문, 숨겨진 맞히기 정답, 자격 증명과 임의 사건 payload는 이 목록에 없다.

`ready`와 `status`는 데이터의 의미를 구분하는 데 사용한다. 정상적으로 조회한 빈 목록은 오류가 아니다. 오래된 관측값과 연결 실패는 빈 목록이나 숫자 `0`으로 바꾸지 않고 상태와 `null`로 나타낸다. nullable 숫자는 `!= null`을 먼저 검사한 뒤 비교하고, nullable 문자열은 치환 전에 존재를 확인한다.

미설치·비활성 또는 필수 의존 위젯이 없는 대본은 후보에서 제외한다. 설치된 연결 위젯의 인증 필요·오류·오래됨은 별개의 상태이므로 그 상태를 설명하는 장면을 작성할 수 있다. 위젯 화면을 닫는 것과 위젯을 비활성화하는 것은 다르다.

## 공통 대본과 캐릭터 조합

기본 범위는 모든 조합에서 사용할 수 있는 공통 대본이다. 다음 import는 특정 두 로컬 캐릭터가 함께 있을 때 사용할 장면을 등록한다.

```text
format: 1

import "./widgets/index.talk" for pair("source:nadir", "source:star-tail")
import "./situations/index.talk" for pair("source:nadir", "source:star-tail")
import "./pairs/default.talk" for pair("source:nadir", "source:star-tail")
```

조합은 표시 이름 대신 설치된 캐릭터의 로컬 ID 또는 `source:` 뒤의 정본 `sourceId`로 식별한다. 기본팩은 가져오기·복사·자리 교환 뒤에도 같은 정본 대사를 사용하도록 `source:nadir`·`source:star-tail`을 쓴다. ID를 확인하는 명령은 [CLI 참조](../development/talk-reference.md#cli-명령)에 있다. 조합 범위는 그 파일의 하위 import에도 이어진다.

조합 파일의 `A`는 `pair`의 첫 번째 ID, `B`는 두 번째 ID를 뜻한다. 사용자가 두 캐릭터의 화면 자리를 맞바꿔도 각 대사는 같은 캐릭터를 따라간다. 공통 파일의 `A`와 `B`는 현재의 A/B 자리다.

장면 ID는 공통 범위 안에서, 또는 같은 두 ID의 조합 범위 안에서 고유해야 한다. 서로 다른 범위에서는 같은 ID를 쓸 수 있다. 재생 이력의 key는 정규화한 조합 ID와 장면 ID로 만들기 때문에 파일 위치를 옮겨도 유지된다. 장면 ID를 바꾸면 다른 장면으로 취급한다.

## 어떤 대본을 고르는가

### 장면 후보 안의 선택

1. 현재 `on`, 활성 캐릭터 조합, 위젯 의존성, `when`, cooldown을 검사한다.
2. 본문 분기와 치환을 실행하고 대사의 길이·줄 수를 검사한다. 빈 장면이나 치환할 수 없는 `null`은 재생하지 않는다.
3. 재생 가능한 조합 전용 장면이 있으면 공통 장면보다 먼저 선택한다. 조합 장면이 모두 cooldown 중이거나 조건에 맞지 않으면 공통 장면도 선택할 수 있다.
4. 같은 범위에서는 한 번도 표시하지 않은 장면을 먼저, 그다음에는 마지막 표시가 가장 오래된 장면을 고른다. 같은 순위는 seed를 사용해 결정한다.

장면의 `priority`를 직접 지정하는 header는 없다. 선택 결과와 탈락 이유는 `talk simulate`에서 확인한다.

### 일반 수다와 함께 재생하기

앱의 첫 인사는 기존 캐릭터 인사를 유지한다. 이후 수다 기회에서 `.talk`와 일반 수다가 교대로 차례를 얻는다. `.talk`에 재생 가능한 장면이 없으면 같은 차례에 일반 수다로 넘어간다. 일반 수다의 단어장·준비된 LLM 대사 선택 순서는 일반 수다가 실제로 선택될 때만 진행된다.

따라서 위젯 대본을 추가해도 단어장과 LLM 대사가 사라지지 않는다. 직접 사용자 입력의 키워드 단어장은 [대화와 기억](conversation.md)의 기존 우선순위대로 모델 준비 검사 전에 처리한다.

### 실제 사건에 반응하기

위젯 사건은 기존 호스트 대기열에서 하나를 선택한 뒤 `.talk`에 전달한다. 나디르·별꼬리 조합은 같은 사건에 맞는 대본이 없거나 모두 재생 불가이면 발화를 생략한다. 원시 사건 문구를 캐릭터의 대사로 사용하지 않으며 사건 자체와 위젯 상태는 유지한다. 다른 캐릭터 조합은 기존 내장 사건 문구 fallback을 유지한다. `.talk`가 별도의 사건 대기열을 만들지는 않는다.

사용자 입력, 시각이 중요한 알림, 위젯 사건, 일반 수다의 우선순위와 대기열 정리 기준은 [위젯 생명주기](../widgets/lifecycle.md#발화-대기열과-오래된-생성-결과)를 따른다. 타이머 종료·캘린더 알림이 먼저 선택되고, 선택 후 나머지 대기 사건을 비우는 정책도 유지한다. 기본팩의 발화 생략 조건은 시각이 중요한 사건에도 적용된다. 동봉 대본은 실제 사건에 반응하는 31개 장면의 cooldown을 0초로 두어 연속 행동에도 새 변주를 선택한다. 자동 수다 113개 장면은 30분 간격을 유지하며 사건 중복·과다 입력 제어는 호스트 대기열이 담당한다.

## 저장과 재로딩

최초 초기화에서 기본 파일을 한 번 복사하고 앱 데이터 디렉터리에 `.talk-initialized-v1` 표식을 남긴다. 이미 존재하는 대본 폴더와 수정한 파일은 보존한다. 이후 삭제한 파일이나 폴더를 앱 재시작으로 복원하지 않는다.

실행 중에는 250ms 간격으로 파일 변화를 관측하고, 350ms 이상 변화가 멈춘 뒤 묶음을 다시 읽는다. 읽기 전후 파일 상태가 같아야 반영한다. 따라서 350ms는 정확한 반영 지연 보장이 아니라 저장 안정성 검사 기준이다. 여러 파일을 수정할 때는 `talk check`로 묶음을 검증한 뒤 저장하면 오류 위치를 찾기 쉽다.

| 저장 결과 | 동작 |
| --- | --- |
| 전체 파일이 유효함 | 새 대본 묶음을 한 번에 활성화. 기존 `.talk` 재생은 중단 |
| 문법·타입·import 오류 | 오류 위치를 기록하고 마지막으로 유효했던 대본 유지 |
| 최초 로드부터 실패 | 일반 수다와 위젯 내장 사건 문구로 동작 |
| `format: 1`만 남긴 유효한 진입 파일 | 빈 대본 묶음을 활성화하여 `.talk` 후보를 끔 |
| 진입 파일 삭제 | 로드 오류. 실행 중 마지막 유효 대본은 유지하며 재시작 후에는 기본 대사 경로 사용 |

대본을 끄려면 진입 파일을 삭제하는 대신 `format: 1`만 남긴다. 잘못된 파일을 고쳐 저장하면 같은 watcher가 다시 검사한다. 오류 진단은 앱 로그에 `.talk 경로:줄:열 [코드] 메시지`로 남는다.

## 표시 직전의 재검증과 기록

후보 조회와 미리보기는 재생 이력이나 cooldown을 소비하지 않는다. 실제 첫 줄을 표시하는 경계에서 대화 기록과 `talk_history`를 같은 데이터베이스 transaction으로 저장한다. 첫 줄을 표시하기 전에 취소된 장면은 이력을 소비하지 않는다. 일부만 표시한 장면은 표시한 줄만 대화 기록에 남는다.

각 줄을 표시하기 전에 다음을 다시 확인한다.

- 작업 epoch, 일반 저장 revision, 대본 generation이 유효한가.
- 활성 캐릭터 ID와 참조한 모든 위젯·필수 의존 위젯의 revision 및 활성 상태가 같은가.
- 사건이 만료되지 않았는가.
- 최신 상태에서 `when`, `@if`, 데이터 최신성, 치환 가능 여부와 대사 제한을 여전히 만족하는가.

시간이 흐른다는 이유만으로 진행 중인 타이머의 모든 대사를 취소하지 않는다. 조건과 분기는 최신 값으로 다시 판단하되, 본문 변수 치환은 준비 시점의 값으로 유지한다. 최신 상태로는 더 이상 만들 수 없는 문구, 달라진 분기, 위젯 수정·비활성화, 캐릭터 교체, 대본 교체는 남은 장면을 무효화한다. 타이머 잔여 시간을 치환한 문장은 준비 시점의 관측값이며 계속 갱신되는 숫자 화면이 아니다.

사용자 입력·숨김·일시정지·자동 동작 끄기·재시작의 중단 규칙도 기존 호스트 경계를 따른다. 파일 재로딩과 캐릭터 교체를 이유로 원문 대화·기억·친밀도를 초기화하지 않는다.

## 검증과 후속 범위

[대본 검증 범위](../development/talk-coverage.md)에서 기본 위젯·상태·사건별 대본과 고정 입력을 연결한다. 문법 검증, 상태 시뮬레이션, 실제 데스크톱 결과는 [대본 검증 기록](../VALIDATION-TALK.md)에서 구분한다. 파일이 문법 검사를 통과했다는 사실만으로 모든 외부 연결이나 플랫폼에서 실행을 검증했다고 보지는 않는다.

캐릭터 관리의 대본 에디터에서 파일을 복호화해 편집하고 검사 후 암호화 저장한다. parser는 원문과 장면·문장의 source span을 유지해 오류의 파일·줄·열을 표시한다. 이 문서의 선택·재로딩·중단 계약을 바꿀 때는 해당 코드와 테스트, 이 문서, `docs/status.md`를 함께 갱신한다.

## 암호화 저장과 에디터

2026-09-19부터 동봉 `.talk`와 앱 데이터 폴더의 `.talk`는 `NANIKA-TALK-AES256GCM-V1` envelope를 사용한다. AES-256-GCM과 매 저장의 무작위 nonce로 암호화·인증하며 손상되거나 인증되지 않은 암호문은 활성화하지 않는다. key는 앱과 함께 제공되므로 파일의 직접 열람을 막는 포장 방식이며 사용자 자신이나 역공학을 막는 DRM은 아니다. 실제 대화 기록·기억은 이 파일 암호화의 대상이 아니다.

기존 평문은 호환 입력으로 읽을 수 있으며 유효한 bundle을 초기화할 때 암호화한다. 구 factory 원문 SHA256과 일치하는 파일만 새 기본 대사로 한 번 교체한다. 수정한 원문과 삭제한 파일은 보존한다. 후보 전체의 import graph를 검사한 뒤 교체하며 잘못된 대본이 섞여 있으면 기존 파일을 유지한다.

에디터는 `.talk` 폴더 안의 상대 경로만 편집하며 symlink·상위 경로·폴더 밖 import를 거부한다. 전체 대본 검증 후 atomic 저장한다. 문법 오류의 파일·줄·열을 표시하고 초안을 유지한다. 다른 편집자가 먼저 저장한 내용은 revision 검사로 보호한다. 파일 재로딩의 last-good·취소 규칙은 그대로 적용한다.

개발용 CLI도 같은 읽기·검사·저장을 사용한다. `read`는 `path`·`source`·`revision`이 있는 JSON을 출력한다. `source`를 파일로 추출하면 평문이므로 배포 전에 `save` 또는 `seal`로 암호화한다.

```sh
pnpm talk read talk/index.talk index.talk
pnpm talk seal talk/index.talk
```

`read`·`save`의 정확한 인수는 [CLI 참고](../development/talk-reference.md)를 따른다.

선택지 스토리도 같은 에디터의 `story/nadir.story.enc`에서 JSON으로 편집할 수 있다. 각 공개 단계에 5개 이상, 전체 15~256개 장면을 두며 장면마다 2~4개 선택지와 -5~5의 점수 변동을 작성한다. 동봉 대사는 +5/-3이다. 저장 시 형식·ID 중복·문자 길이를 검사하고 진행 중인 선택지를 취소한다. 잘못되거나 삭제된 파일은 마지막 정상 catalog를 유지하며 재시작에서는 동봉 catalog로 돌아간다. 삭제한 편집 파일을 자동 복원하지 않는다. 비밀의 단계 배치와 캐릭터 말투는 작성자의 책임이며 JSON 검사는 의미를 판정하지 않는다.
