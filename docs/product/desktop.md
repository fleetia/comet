# 바탕화면 상주 경험

기준일: 2026-09-19. comet은 나니카·우카가카처럼 바탕화면에 머무는 A/B와 선택적인 LLM을 결합한다. 이 문서는 창과 상호작용을 변경할 때 기본 경험을 판단하는 기준이다.

| 상태 | 범위 |
| --- | --- |
| 구현됨 · 0.2 | 0.2의 작은 A/B 본체, 공용 말풍선, 내장 자동 수다, 직접 입력, 단어장과 보조 화면 |
| 승인 · 0.4 작업본 | 바탕화면 물체·선택적 장난 모드·운영체제 메뉴. 코드 구현과 실제 데스크톱 인수 결과는 [구현 상태](../status.md)에서 구분한다. |
| 미정 | 캐릭터 아트, 장난감별 배치 세부, 조용한 시간의 정확한 시간대·설정 방식 |

0.2의 기준과 당시 확인 범위는 [기존 제품 사양](../PRODUCT.md), [검증 기록](../VALIDATION-0.2.0.md)에 있다. 이 문서의 계획은 해당 빌드에서 구현됐다는 뜻이 아니다.

## 트레이 아이콘

트레이는 사용자가 제공한 흰색 SVG를 `src-tauri/icons/tray.svg`에 보존한다. 56×52 도형의 다섯 path와 흰색 채움을 유지하고 정방형 캔버스에 상하 2px 투명 여백을 추가한다. 56×56 RGBA `tray.png`를 빌드에 포함하고 macOS에서는 메뉴 막대 배경에 맞춰 색이 바뀌는 template icon으로 사용한다. Windows에서는 흰색 아이콘을 사용한다. 앱·Dock 아이콘과 favicon은 트레이 변경의 영향을 받지 않는다.

## 제품 이름과 아이콘

프로젝트·실행 앱·JavaScript 및 Rust 패키지·실행 파일은 소문자 `comet`을 사용하고 Rust 라이브러리는 `comet_lib`으로 유지한다. 앱 식별자와 SQLite 파일명도 Comet 기준으로 새로 사용하며, 기존 설치의 데이터·자격 증명·대본은 첫 실행 때 새 위치와 이름으로 자동 승계한다. 앱·Dock 아이콘과 favicon은 `src-tauri/icons/source.svg`를 기준으로 하며 트레이 아이콘과 별도 계약이다. 실제 패키징·서명·플랫폼 표시 확인은 [상태표](../status.md)에서 당시 실행 범위와 함께 기록한다.

## 기본 화면

기본 상주 요소는 선택한 캐릭터의 작은 본체이며 새 설치는 A/B 두 명의 얼굴·대화로 시작한다. 나디르·별꼬리는 [추가팩](characters.md#나디르별꼬리-추가팩)을 가져온 뒤 함께 지내기로 선택한다. 사용자는 캐릭터를 숨겨 위젯만 사용할 수도 있다. 배경판이 있는 대시보드나 큰 채팅 패널을 기본 화면으로 만들지 않는다. 필요한 대화·도구를 잠깐 표시하고 다시 바탕화면으로 돌아온다.

| 요소 | 동작 |
| --- | --- |
| 본체 | 기본 A/B의 얼굴·표정을 유지한다. 캐릭터 roster·sprite가 있는 본체의 투명 창과 얼굴 표시는 [캐릭터 사양](characters.md)을 따른다. 아트 완성을 기능의 선행 조건으로 삼지 않는다. |
| 말풍선 | 폭 320의 공용 말풍선 하나가 현재 화자 곁에 나타난다. 대사 길이에 따른 표시 시간이 지나면 다음 줄로 넘어간다. |
| 장면 종료 | 말풍선이 사라지고 본체만 남는다. 마지막 대사를 계속 고정하지 않는다. |
| 메뉴·입력 | 본체 클릭·우클릭으로 메뉴, 더블클릭으로 입력을 연다. 한국어 조합 확정 Enter로 전송하지 않는다. |
| 이동 | 본체를 끌어 위치를 옮긴다. |
| 보조 화면 | 기록·친밀도·설정·단어장과 할 일·일정 상세는 요청했을 때 연다. |
| 장난감 | 사용자가 꺼내거나 별도로 허용한 장난 모드가 선택한 물체만 표시한다. 정리하면 사라지며 기본 바탕화면을 도구 목록으로 채우지 않는다. |

## 메뉴와 보조 화면

2026-09-20 승인한 [통합 설정창 R2](settings.md)가 캐릭터 관리·설정·위젯 관리의 분리된 창과 기존 화면 배치를 대체한다. 캐릭터·위젯·자동 대화·개인 단어장·대화팩·기억·AI 연결·일반을 같은 창에서 직접 탐색한다. 처음에는 캐릭터, 이후에는 앱 실행 중 마지막 영역을 열며 업데이트 바로가기는 일반으로 이동한다. 기능별 보존 계약, 초안 유지와 독립 저장 책임은 통합 설정창 사양이 원본이다.

위젯 설치·켜기/끄기·표시·연결은 설정창에서 관리하고 할 일 작성·완료, 메모 편집, 타이머 실행은 별도 실행 창에서 수행한다. 미저장 설정이 있으면 앱·트레이 종료 전에 확인하며 저장하려면 해당 영역으로 돌아간다. 창 숨김과 앱 종료는 다른 동작이다.

말풍선 메뉴는 대화, 관리, 자동 수다·표시 동작을 구분선으로 묶는다. 입력과 지난 대화에서는 **메뉴로** 돌아올 수 있으며 입력 초안은 유지한다. 자동 수다 일시정지 여부는 메뉴 하단에도 표시한다. 관리 바로가기는 같은 설정창의 해당 탭으로 이동한다.

0.4의 메뉴바·트레이 메뉴는 캐릭터 표시·숨기기, 설치·활성 위젯 바로 열기, 장난 모드, 장난감 모두 정리, 자동 행동 정지·재개, 업데이트 확인, 설정과 완전 종료를 제공한다. 캐릭터 숨기기는 대화와 자동 장난을 중단하지만 사용자가 직접 꺼낸 위젯·장난감을 제거하는 명령은 아니다. 전체 물체를 치울 때는 **장난감 모두 정리**를 사용한다. 다시 표시하거나 재시작해도 정리한 물체를 복원하지 않는다.

자동 말풍선·표정·본체 표시는 다른 앱의 입력 포커스를 요청하지 않는다. macOS에서는 `orderFront`, Windows에서는 `SW_SHOWNOACTIVATE`를 사용하며, 실제 표시 직전에 현재 epoch·숨김·화자를 재검사한다. 사용자가 입력이나 메뉴를 직접 열 때는 해당 말풍선에 포커스를 준다.

## 창 이동과 닫기

2026-09-16 변경은 0.2의 창 조작 계약을 확장한다. A/B·말풍선·설정·캐릭터 관리·위젯 관리·개별 위젯을 포함한 모든 앱 창에서 운영체제 제목 표시줄을 없애고(`decorations: false`) 최대화를 비활성화한다. 별도 제목 표시줄을 콘텐츠 위에 추가하지 않는다.

설정·캐릭터 관리·위젯 화면은 창의 `(0, 0)`부터 현재 보이는 헤더 하단까지를 끌어 창을 옮긴다. 제목뿐 아니라 위쪽·양옆 여백도 포함하며, 헤더 아래 본문과 스크롤바는 제외한다. 드래그 가능한 전체 영역에 `grab` 커서를 표시하고 누르는 동안에는 `grabbing`으로 바꾼다. 같은 헤더 오른쪽에 내부 ×를 두며 버튼·입력 등 조작 요소는 드래그하지 않고 기존 커서를 유지한다. 대화상자가 열린 동안에는 창 드래그를 막고, 로딩이나 오류 상태에서도 ×에 접근할 수 있다.

2026-09-19 개별 도구 22종과 낱장 메모는 공통 `WidgetFrame`으로 창 높이와 헤더·본문·선택적인 하단 조작 영역의 배치를 관리한다. `WindowHeader`가 담당하는 드래그·닫기 경계는 유지한다. 제목과 ×만 한 줄의 고정 헤더에 두고, 긴 내용은 아래 본문에서만 스크롤한다. 내용과 독립된 조작은 헤더와 분리해 오른쪽 아래에 고정하며 별도 테두리나 박스를 두지 않는다. 본문에 붙는 조작과 하단 조작의 구분, 분류 표기·관리 버튼 제거는 [관리 화면과 개별 도구](../widgets/installation.md#관리-화면과-개별-도구)를 따른다. 이 변경은 선택 위젯의 창 배치에 한정하며 0.2의 본체·말풍선 경험을 유지한다.

| 화면 | 내부 × 동작 |
| --- | --- |
| A/B 본체 | 기존 본체 버튼과 분리된 작은 ×가 `hide_boxes`를 실행한다. 두 본체를 함께 숨기고 기존 숨김의 대화·자동 작업 중단 경계를 유지한다. 본체 크기와 기존 드래그는 유지한다. |
| 말풍선 | 기존 ×의 대사 건너뛰기 동작을 유지한다. |
| 통합 설정 | 설정창을 숨긴다. 앱이 실행 중이면 탭별 미저장 초안을 유지한다. |
| 개별 위젯 | 해당 보기만 닫는다. 설치·활성 상태와 실행 중인 타이머 상태를 보존한다. |
| 메모 목록·낱장 | 목록 닫기는 꺼내 둔 낱장을 유지한다. 낱장은 대기 중인 변경 저장에 성공한 뒤 해당 창만 넣는다. 상세는 [낱장 메모](planning.md#낱장-메모)를 따른다. |

공·비행기·비눗방울·펫의 작은 물체 창에는 헤더나 ×를 붙이지 않는다. 물체를 직접 잡고 우클릭으로 정리하며, 메뉴의 모두 정리도 사용할 수 있다. macOS는 비활성 native `NSPanel`에 물체를 직접 그리고 native 마우스 입력을 받는다. Windows는 Tauri 투명 창에 native window region을 적용한다. 이 예외의 물리·입력 계약은 [장난감](toys.md#바탕화면-물리-계약)을 따른다.

### 생활 위젯의 바탕화면 표시

시계·기념일, 날씨, 기기 소식(배터리)은 통합 설정의 위젯 영역에서 별도 표시 창으로 꺼낼 수 있다. 이 창은 관리·설정 화면을 대신하지 않는 작은 투명 창이며, 항상 위에 보이고 작업 표시줄에는 올리지 않는다. **바탕화면 표시**·**표시 닫기** 명령을 제공하며 확인되지 않은 표시 상태를 체크박스 값으로 추정하지 않는다. 설정창을 닫아도 표시 창은 남는다. 표시 닫기는 해당 창만 닫고, 위젯 끄기·제거는 표시 창과 관련 실행 작업을 함께 정리한다.

표시 설정은 위젯 데이터의 `appearance`에 저장한다. 배경 색상, 선택한 배경 이미지와 이미지 위치, 글자 색상과 글자 위치를 각각 저장하며 위치는 3×3(`top-left`부터 `bottom-right`)이다. 이미지는 SVG·PNG·GIF·WebP·JPEG만 허용하고 2MiB를 넘지 않는다. 배경 이미지는 위젯별 SQLite 전용 저장소에 두며 snapshot이나 대화 문맥으로 이미지 바이트를 보내지 않는다.

표시 창의 내용은 원본 위젯 상태에서 읽기 전용으로 만든다. 기념일은 등록된 제목과 D-day를, 날씨는 마지막 관측 지역·온도·상태를, 배터리는 기기별 잔량·충전 상태를 보여 준다. 오래된 날씨 관측은 `이전 정보`로 구분하고, 아직 관측이 없거나 배터리가 없는 기기는 빈 사실을 임의의 0값으로 채우지 않는다. 표시 설정 변경과 이미지 변경은 위젯 revision을 확인한 뒤 저장하며 기념일·연결·대화 기록·기억을 초기화하지 않는다.

소스 검증과 실제 데스크톱 확인 범위는 [구현 상태](../status.md#공통-창-조작-검증)에서 구분한다.

## 자동 수다와 침묵

모델·API·사용자 입력 없이 실행 약 5초 후 내장 인사를 시작한다. 이후 기본 2분 간격에 ±20% 변동을 둔다. 기본 A/B 자동 장면은 2~4줄이며 번갈아 말한다. 한 명일 때는 독백이나 질문을 지원하고, 여러 명의 화자·대상은 [대화 계약](conversation.md)을 따른다. 단어장은 작성한 화자 순서를 보존하는 별도 규칙을 따른다.

| 설정 | 기본값과 범위 |
| --- | --- |
| `autonomousEnabled` | 켜짐. 자동 생성과 내장·단어장·LLM 장면의 자동 재생 전체를 제어한다. |
| `localIdleEnabled` | 켜짐. 로컬 LLM의 새 장면 준비를 제어한다. 내장 수다는 모델 없이도 동작한다. |
| `apiIdleEnabled` | 꺼짐. API로 자동 장면을 만드는 비용은 사용자가 허용한 경우에만 발생한다. |
| 일시정지·숨김 | 자동 생성과 재생을 함께 멈춘다. 자동 수다 일시정지가 직접 요청한 답변을 취소하지 않는다. |

사용자 입력은 자동 장면보다 우선한다. 중단된 장면의 남은 줄이나 오래된 생성 결과가 뒤늦게 끼어들지 않는다. 재시작은 새 인사 흐름이며 이전 실행의 재생 위치·준비 장면을 이어 쓰지 않는다. 기록과 설정은 보존한다.

## 장난 모드와 대화 상태

장난 모드는 자동 수다와 별도로 허용하며 기본값은 꺼짐이다. `src-tauri/src/behavior.rs`의 상태 기계가 `idle`, `conversing`, `playing`, `waitingForReply`, `cooldown`, `suspended`를 구분한다. 기본 A/B 대화·등록 대사·사용자 입력의 우선순위는 유지하고, 놀이를 위해 LLM 호출을 요구하지 않는다.

| 상태·조건 | 자동 장난 규칙 |
| --- | --- |
| `idle` | 설치·활성·허용된 공·비행기·방울·펫 중 하나를 선택한다. 대화가 없는 상태에서 10~20분의 다음 기회를 잡는다. |
| `playing` | 자동 물체는 동시에 하나이며 20초 뒤 정리한다. 상태 기계도 최대 30초 경계를 둔다. |
| `conversing`·`waitingForReply` | 진행 중 자동 놀이를 취소하고 대화·응답 대기를 우선한다. |
| `cooldown` | 자동 놀이 종료·중단 후 30초간 쉬며 다음 장난을 즉시 재시도하지 않는다. |
| `suspended` | 숨김·일시정지·상위 자동 설정 해제·전체 화면 등으로 자동 장난을 막는다. |

직접 입력·열린 대화 패널·대화 epoch 변경은 이전 자동 물체와 늦게 도착한 결과를 무효화한다. 사용자가 물체를 잡고 있거나 생성 지점에 포인터가 가까우면 자동 생성하지 않는다. 장난 모드나 허용 항목을 바꾸거나 전체 화면으로 전환하면 진행 중 자동 물체와 그 결과의 재생 대기를 취소한다. 이미 시작한 자동 놀이 반응도 중단하되 저장된 일지는 보존한다. 이 허용은 외부 앱 조작·할 일 완료·일정 수정 권한을 포함하지 않는다.

수동으로 꺼낸 물체와 자동 물체는 소유권을 분리한다. 자동 장난 취소가 사용자가 직접 연 다른 도구를 닫아서는 안 된다. 위젯 끄기·제거, 모두 정리와 종료는 해당 물체를 명시적으로 없애며 물체를 다시 꺼내야 새 놀이가 시작된다. 저장과 재시작 규칙은 [위젯 수명주기](../widgets/lifecycle.md#바탕화면-물체의-수명)를 따른다.

## 확장에서도 유지할 경계

캐릭터의 개별 교체와 공유도 확정된 확장 요구다. 2026-09-17부터 본체 창은 캐릭터 목록(1~8명)을 따라 캐릭터 ID별로 만들어지며, 캐릭터 관리에서 함께 지내기·내보내기·순서를 바꾸는 설계는 [캐릭터 교체와 공유](characters.md)를 따른다. 교체가 이전 캐릭터의 기록을 새 화자의 기록으로 바꾸지 않아야 한다.

장난감 반응과 일정 알림이 들어와도 공용 말풍선에 무제한 쌓지 않는다. 사용자가 직접 요청한 동작을 우선하고, 지난 사건을 늦게 연달아 읽어 주지 않는다. 발화 순서는 사용자와 진행 중인 대화 → 시각이 중요한 알림 → 위젯 사건 반응 → 평소 수다로 정한다. 같은 사건의 합치기와 만료 기준은 공식 위젯 호스트의 수명주기 계약을 따른다. 상세는 [위젯 수명과 실행 규칙](../widgets/lifecycle.md)을 따른다.

조용한 시간과 알림 빈도 조절은 계획에 포함하지만 정확한 시간대와 기본값은 미정이다. 그 설정을 정하기 전부터 밤 시간이나 회의 참석 여부를 추측해 확정 상태처럼 취급하지 않는다. 할 일을 놓치거나 앱을 오래 켜지 않은 것으로 친밀도를 낮추지 않는다.

가벼운 상주는 Rust 사용만으로 보장되지 않는다. 내장 대사와 도구 사용에 LLM 상시 실행을 요구하지 않으며, 화면이 조용할 때 장난감 애니메이션·폴링이 계속 필요할지 개별 검토한다. 현재 LLM 자원 제한과 미측정 범위는 [기존 제품 사양](../PRODUCT.md)을 따른다.

## 인수 조건

- 모델 없는 첫 실행에서 인사와 다음 정기 수다가 나온다.
- 장면이 끝나면 본체만 남으며, 화자 이동에 따라 공용 말풍선이 따라간다.
- 사용자 입력·일시정지·숨김·자동 설정 해제 후 오래된 자동 대사가 재생되지 않는다.
- 보조 화면과 장난감을 닫으면 별도의 대시보드가 남지 않는다.
- 새 기능이 기존 창 위치·기록·설정을 초기화하지 않는다.
- 설정 탭 이동 후 초안이 남고, 저장 범위·미저장 여부·실패 상태를 구별할 수 있다.
- 입력·기록에서 메뉴로 돌아갈 수 있고 좁은 보조 화면에서도 편집과 저장을 끝낼 수 있다.
- 앱 창에 운영체제 제목 표시줄과 최대화 동작이 없고, 보조 화면은 내부 ×로 닫는다. 물체 창은 우클릭·모두 정리로 회수한다.
- 캐릭터를 숨긴 뒤에도 메뉴에서 위젯을 열 수 있고, 기본 A/B 대화·얼굴·기록이 보존된다.
- 자동 장난과 대화가 서로 입력을 빼앗지 않고 중단한 물체가 stale 결과로 다시 나타나지 않는다.
- 보조 화면 제목·빈 공간 드래그와 버튼 조작이 충돌하지 않으며 로딩·오류 상태에서도 닫을 수 있다.
- 개별 도구와 낱장 메모의 본문을 스크롤해도 제목·× 헤더와 필요한 하단 조작 영역이 같은 위치에 남는다. 최소 창 크기에서도 조작 버튼이 가로로 넘치지 않으며, 하단 조작이 없는 도구에 빈 영역을 남기지 않는다.
- 위젯 보기를 닫아도 설치·활성 상태와 타이머가 유지된다.
- 시계·기념일, 날씨, 배터리 위젯을 별도 바탕화면 표시로 꺼낼 수 있고, 각 설정에서 배경과 글자 색상·3×3 위치를 저장해 표시 내용에 반영한다.
- 배경 이미지의 형식·크기·위젯 소유 범위를 확인하며, 설정 변경·끄기·제거 뒤 오래된 revision의 이미지나 표시 창이 되살아나지 않는다.
- 장시간 자원 사용, Windows와 다중 모니터 검증은 실제 수행한 결과만 별도로 기록한다.

창 구조·기본 주기·입력 우선순위가 바뀌면 이 문서를 갱신한다. 대화 규칙은 [대화와 기억](conversation.md), 도구의 범위는 [장난감](toys.md)과 [할 일·일정](planning.md)을 참고한다.
