# 다이어리·할 일·캘린더

2026-10-03 승인한 다이어리는 날짜를 넘기며 기록하고, 계속 쓸 메모와 준비 봉투를 다시 꺼내 쓰는 별도 실행 화면이다. 이 문서는 화면·데이터 경계와 할 일의 계획·기한·이동 기록, 반복·알림의 규칙을 판단하는 기준이다. 같은 날 승인한 통합에 따라 기간 계획·템플릿·할 일 관리를 다이어리의 오른쪽 본문에서 열고 캘린더는 월간·주간·하루 보기로 모은다. 작은 본체와 잠깐 나타나는 말풍선 중심의 기존 0.2 경험은 바꾸지 않는다. 변경별 소스 구현과 실제 데스크톱·외부 계정 검증은 [구현 상태](../status.md)에서 구분하며, [기존 위젯 검증 기록](../VALIDATION-WIDGETS.md)을 이번 실행 결과로 재사용하지 않는다.

| 상태 | 범위 |
| --- | --- |
| 승인한 화면 계약 | 계속 쓸 메모 → 내 다이어리 → 펼친 페이지, 월·주·하루 보기, 날짜·자유 페이지, 독립 준비 봉투. 기간 계획·템플릿·할 일 관리도 같은 본문에서 연다. 소스 반영·네이티브 인수 여부는 상태표에서 확인한다. |

| 검증 경계 | 저장 회귀 테스트·화면 조작·재시작 보존·실계정 권한을 구분한다. Google 실계정 인증, OS 알림의 실제 표시·버튼 및 Windows 네이티브 검증은 별도 인수 대상이다. 과거 Apple 조회 결과도 이번 다이어리의 검증을 대신하지 않는다. |
| 미구현 | 외부 할 일 서비스, 과거 완료 회차까지 포함하는 시리즈 전체 편집, 외부 SDK |

Todoist 등 외부 할 일 서비스와 다른 사용자와 함께하는 기능은 제공하지 않는다.

## 다이어리와 설정창

할 일이나 캘린더를 열면 같은 `planner` 창을 재사용한다. 기본 크기는 1280×840이고 최소 크기는 720×520이다. 다이어리의 왼쪽부터 **계속 쓸 메모 → 내 다이어리 → 펼친 페이지**를 배치한다. 기록을 쓰는 오른쪽 영역에 가장 넓은 공간을 두고, 메모와 목차는 날짜나 페이지를 바꿔도 다시 찾을 수 있게 한다.

| 영역 | 역할 |
| --- | --- |
| 계속 쓸 메모 | 날짜와 무관한 메모를 쓰고 꺼내 둔다. 넣어둔 메모도 다시 찾을 수 있으며 준비 봉투 안에 연결해도 같은 메모를 편집한다. |
| 내 다이어리 | 작은 달력으로 날짜를 고른다. 달력 아래의 기간 계획·템플릿·할 일 관리 메뉴와 내 페이지·준비 봉투를 탐색하고 새 페이지·봉투를 만든다. |
| 펼친 페이지 | 선택한 월·주·하루, 자유 페이지·준비 봉투 또는 기간 계획·템플릿·할 일 관리의 본문을 펼친다. 하루에는 기록·할 일·일정·봉투 참조를 함께 적는다. |

**월 / 주 / 하루**는 같은 기록의 탐색 범위다. 월 보기는 날짜별 일정·할 일과 기록 유무를 보여 주고, 주 보기는 각 날짜의 일정·할 일과 기록을 함께 훑는다. 날짜를 선택하면 그날의 페이지에 이어 쓴다. 외부 일정은 읽기 전용이며 완료 체크를 붙이지 않는다. 캘린더 연결이나 일정이 없는 날에도 기록을 만들 수 있다.

보기 전환은 펼친 페이지 상단의 **월간·주간·하루** 버튼에 모은다. 작은 달력 아래에는 **기간 계획·템플릿·할 일 관리** 텍스트 메뉴를 두고 **내 페이지**가 이어진다. 날짜 요약·주간·월간 바로가기 카드는 두지 않는다.

**기간 계획·템플릿·할 일 관리**를 선택하면 왼쪽 메모와 목차를 유지한 채 오른쪽 본문이 바뀐다. 기존 **할 일·연결 관리** 전체 화면으로 이동하는 경로와 별도 캘린더 탭은 제거한다. 반복의 세부 편집, 집중 시작과 하루 마무리는 **할 일 관리**에서 사용한다.

기간 계획·템플릿 메뉴를 바꿀 때 작성 중인 패널은 숨긴 상태로 유지해 초안을 보존한다. 열린 편집 대화상자가 있으면 탐색 전에 확인하며, 창을 닫을 때는 다이어리가 숨긴 패널까지 포함해 미저장 변경을 한 번에 확인한다. 각 본문에 별도 창 닫기나 중복 종료 확인을 두지 않는다.

연결 계정·조회 캘린더·알림 채널·무드메이커 설정은 [통합 설정창](settings.md)의 위젯 영역에서 관리한다. 창 상단의 **연결·알림 설정**은 해당 설정으로 바로 이동하며 연결을 자동 승인하지 않는다. 설정 이동이나 캘린더 오류가 로컬 기록·할 일 작성을 막지 않는다.

### 캘린더 정보와 일정 표시

캘린더를 열면 같은 다이어리의 월간 보기를 표시하며 주간·하루로 전환할 수 있다. 접이식 **캘린더 정보**에서 캘린더별 색상, 외부 일정의 조회 상태와 선택 날짜의 빈 시간을 확인한다. 색상은 이름 옆 버튼이나 통합 설정의 연결 관리에서 8가지 중 하나를 고른다. 바로 저장되며 재시작·일정 갱신·같은 연결의 재연결 뒤에도 유지된다. Google·Apple은 연결 안의 개별 캘린더마다, ICS는 구독 주소마다 지정한다. Comet 내부 표시 설정이므로 원본 서비스의 색상을 바꾸지 않는다.

월간 보기의 종일 일정은 옅은 배경과 같은 계열의 글자로 표시한다. 여러 날 일정은 날짜 칸을 가로지르는 막대로 이어지고 주 경계에서 나뉜다. 종료 날짜는 포함하지 않는다. 시간 일정은 색상 표시·제목·시각을 함께 보여 준다. 주간 보기는 날짜별 일정·할 일·기록을 같은 칸에서 훑는 구성이다.

같은 날짜의 일정은 각각 선택할 수 있다. 월간 날짜 칸의 일정·할 일·연결 항목이 세 줄을 넘으면 **더 보기**로 그날의 페이지를 펼친다. 일정 제목·시각·출처를 함께 제공해 색상만으로 구분하지 않는다. 연결 해제는 그 연결의 색상만 제거한다.

## 데이터의 원본과 쓰기 범위

| 데이터 | 원본 | 허용 범위 |
| --- | --- | --- |
| 내장 할 일·목록 | Comet의 SQLite | 사용자 의도에 따른 생성·수정·완료·완료 취소·삭제 |

| 낱장 메모 | Comet의 SQLite | 사용자 의도에 따른 생성·수정·삭제와 열림 상태·글자 크기 저장 |

내장 할 일은 계정이나 외부 연결 없이 사용할 수 있다. 연결 실패가 로컬 작업을 막지 않는다. 캘린더 인증·구독 URL은 필요한 범위에서만 보관하며, 비공개 구독 URL을 일반 로그나 대사로 노출하지 않는다.

조회 중·마지막 갱신 시각·연결 실패를 구분한다. 오래된 일정은 최신 확인 결과처럼 말하지 않는다. 연결 해제가 내장 할 일을 지우지 않는다. 외부 일정 변경·삭제 시 준비 봉투의 연결 끊김을 표시하며 로컬 메모를 조용히 삭제하지 않는다.

## 페이지와 계속 쓸 메모

날짜 페이지는 `YYYY-MM-DD`마다 하나만 저장한다. 같은 날짜를 다시 열거나 동시에 만들려고 해도 기존 페이지에 이어 쓴다. 날짜 없는 자유 페이지는 제목으로 구분하며 생각·목록·주제별 기록에 사용한다. 페이지에는 메모(`note`), 할 일(`todo`), 일정 기록(`event`), 준비 봉투(`envelope`), 위젯·낱장 메모 연결(`widget`)을 함께 저장하고 필요한 항목에 시각을 적는다. 참조 항목은 원본의 ID를 유지한다.

**계속 쓸 메모**는 페이지와 별도로 보존하는 제목·본문을 가진다. 꺼내기·넣어두기는 표시 위치를 바꾸며 삭제와 구분한다. 봉투에 연결한 메모를 어느 쪽에서 편집해도 같은 내용으로 남는다. 이 메모는 기존 [낱장 메모 위젯](#낱장-메모)과 별도 저장 단위이며 기존 메모를 자동 이전하거나 삭제하지 않는다.

페이지를 삭제하면 그 페이지와 페이지 안의 참조만 지우고 원본 Todo·봉투·계속 쓸 메모·낱장 메모·위젯·Comet 일정은 보존한다. 계속 쓸 메모 자체를 삭제하면 함께 표시하던 곳에서도 사라진다. 봉투를 삭제해도 연결했던 Todo와 메모는 남기며, 메모 목록에서 계속 접근할 수 있어야 한다.

### 위젯에서 가져오고 다시 열기

목차의 **위젯**을 펼치면 켜 둔 위젯을 열거나 내용을 페이지에 연결한다. 위젯 이름은 도구를 열고, 내용 옆 **+**는 펼친 페이지에 연결한다. 드래그 손잡이로 하루·자유 페이지나 월·주 보기의 날짜에 놓을 수도 있다. 별도 메모·할 일·준비 봉투 창에서도 같은 손잡이를 사용한다. 메모 편집 중에는 저장을 마친 뒤 끌어 놓는다.

| 가져오는 대상 | 결과 |
| --- | --- |
| 할 일을 날짜에 놓기 | 같은 Todo의 계획 날짜를 옮긴다. 원래 기한과 완료 상태를 보존하고 기존 날짜가 있으면 이동 기록을 남긴다. |
| 할 일을 자유 페이지에 놓기 | 같은 Todo를 참조하며 계획 날짜·기한은 바꾸지 않는다. |
| 낱장 메모 | 위젯과 메모 ID를 연결한다. 저장된 원본 본문을 보여 주고 **열기**로 같은 낱장 창을 연다. 계속 쓸 메모로 복사하거나 이전하지 않는다. |
| 준비 봉투 | 같은 봉투를 여는 참조를 페이지에 추가한다. 봉투의 자체 날짜를 바꾸지 않는다. |
| 위젯 자체 | 해당 도구를 여는 바로가기를 페이지에 추가한다. 할 일은 같은 다이어리의 할 일 관리, 캘린더는 월간 보기로 연결한다. |

같은 페이지에 같은 원본을 다시 놓아도 참조는 하나만 남긴다. 페이지의 **연결 해제**는 참조만 제거하며 원본 메모·위젯을 지우지 않는다. 원본이 삭제되면 마지막 연결 이름과 원본을 찾을 수 없다는 상태를 남긴다. 일반 텍스트·파일을 위젯 항목으로 해석하지 않으며, 드롭한 ID가 현재 설치된 원본 항목을 가리키는지 확인한다.

월·주 보기에서는 위젯·낱장 메모·준비 봉투 참조를 **연결 N개**로 표시하고 누르면 해당 날짜 페이지를 연다. 참조만 있는 날짜도 내용이 있는 날로 다룬다.

### Comet 일정 만들기

2026-10-03 승인한 첫 범위는 Comet 자체 일정이다. **+ 일정**, 주 보기의 날짜별 **+ 일정**, 월 보기의 빈 날짜 칸 두 번 클릭으로 작성창을 연다. 날짜 숫자 한 번 클릭은 기존처럼 하루 기록을 펼친다. 제목·시작과 종료·종일 여부·장소·메모를 저장하며, 저장한 일정을 다시 열어 편집하거나 삭제한다. 실패하면 작성 내용을 남기고, 편집 중 다른 화면에서 변경된 일정을 덮어쓰지 않는다. 다른 일정 변경이나 외부 새로고침만 있었다면 최신 위젯 revision으로 저장한다. 충돌 후 **최신 일정 다시 열기**는 입력한 변경을 버린다는 확인을 거쳐 원본을 다시 읽으며, 불러오기에 실패하면 초안을 유지한다.

종일 일정은 화면에서 마지막 날짜까지 포함해 입력하고 저장 시 `endDate`를 다음 날짜로 둔다. 시간 일정은 기기의 지역 시각으로 입력하며 종료는 시작보다 늦어야 한다. 기존 페이지에 직접 적은 단순 일정 기록은 유지한다. 반복 일정 생성과 시간 격자에서 길이 조절은 이번 범위에 포함하지 않는다. 외부 Apple·Google 캘린더 쓰기는 다음 단계이며, 이번 구현의 외부 연결은 읽기 전용으로 유지한다.

로컬 일정은 캘린더 위젯의 `events`에 `connectionId: "local"`로 저장한다. `create-event`·`update-event`·`delete-event`는 기존 위젯 revision과 요청 중복 방어를 사용하며 외부 일정의 수정·삭제는 거절한다. 로컬 일정도 사용자가 켠 기존 캘린더 알림 설정을 따르고, 외부 연결이나 인증을 준비 조건으로 요구하지 않는다.

`src-tauri/src/diary.rs`의 `get_diary`·`update_diary`가 페이지·메모·이동 기록의 저장 경계다. 저장할 때 전체 revision을 확인하고, 편집 항목의 기존 본문·시각 또는 메모 제목·본문도 비교한다. 다른 화면의 변경과 충돌하면 초안을 남기고 오류를 표시하며 오래된 내용으로 덮어쓰지 않는다. 성공한 변경만 transaction으로 저장하고 `diary-updated`로 전달한다. 본문의 앞뒤 공백과 줄바꿈은 보존하며 재시작 후 저장한 기록을 다시 읽는다.

## 준비 봉투

준비 봉투는 할 일·메모·자료를 한 주제로 모아 다시 꺼내는 묶음이다. 제목만으로 만들 수 있으며 날짜·캘린더 설치·외부 계정을 요구하지 않는다. 날짜를 정하지 않은 봉투도 **내 다이어리**에서 찾는다. 필요할 때 직접 날짜를 정하거나 조회 가능한 외부 일정 하나와 연결한다.

직접 정한 날짜는 로컬 `date`에 저장한다. 외부 일정 연결을 선택하면 직접 날짜를 비우고 `eventId`·표시 이름을 저장하며, 직접 날짜로 바꾸면 외부 일정 연결을 해제한다. 연결 실패나 원본 일정 소실은 연결 상태로 표시하고 봉투의 이름·체크리스트·자료·메모를 보존한다. 보관은 내용을 숨겨 두는 동작이며 다시 꺼낼 수 있고 삭제와 구분한다.

봉투에서 기존 Todo를 연결하면 하루 페이지와 같은 항목·완료 상태를 사용한다. 아직 체크리스트로 적어 둔 준비물을 할 일로 보내는 `check-promote`는 선택 날짜의 Todo를 만들고 봉투 참조를 연결한 뒤 원래 체크를 제거한다. 이 변경들은 한 transaction으로 저장하므로 실패나 같은 요청의 재시도로 중복 할 일이 남지 않는다. 단순 연결 해제·봉투 보관·봉투 삭제로 원본 Todo를 삭제하거나 완료하지 않는다.

## 내장 할 일

각 할 일은 제목, 메모, 소속 목록, 계획 기간, 오늘에 놓을 날짜, 선택적인 기한, 반복과 완료 상태를 가진다. 목록은 일상·업무·장보기처럼 구분할 수 있다. SQLite의 같은 할 일 데이터를 실행 창과 연결 도구가 사용하며 재시작 후 보존한다.

### 계획과 기한

| 필드 | 의미와 저장 규칙 |
| --- | --- |
| `planPeriod` | `none`·`week`·`month`·`year`·`someday`. 계획의 분류이며 기한을 뜻하지 않는다. |
| `planAnchor` | 해당 주·월·연도의 기준 날짜. 호스트가 월요일·매월 1일·매년 1월 1일로 정규화한다. `none`·`someday`는 `null`이다. |
| `plannedDate` | 다이어리의 해당 날짜와 할 일 관리의 오늘 목록에 놓을 `YYYY-MM-DD`. `null`이면 날짜 계획에서 뺀 상태이며 기한으로 되돌려 채우지 않는다. |
| `dueDate` / `dueAt` | 날짜 기한은 `YYYY-MM-DD`, 시각 기한은 Unix 밀리초다. 동시에 저장하지 않는다. UI 입력은 기기의 지역 시각이다. |

기간 계획에서 **오늘로** 가져오거나 **오늘에서 빼기**를 눌러도 원래 기간과 기한은 보존한다. 다이어리에서 미완료 할 일을 옮기면 같은 Todo의 `plannedDate`만 지정한 날짜로 바꾸고, `todoId`·이전 날짜·옮긴 날짜·당시 제목을 이동 기록으로 함께 저장한다. 원래 날짜에는 옮긴 흔적을 남기며 새 Todo를 복제하거나 원래 `dueDate`·`dueAt`을 미루지 않는다. `move-record`는 Todo 변경과 기록 저장을 같은 transaction으로 처리하고 출발 날짜·제목이 이미 바뀌었으면 거절한다.

할 일 관리의 하루 마무리도 선택한 미완료 항목의 `plannedDate`만 바꾸며 선택하지 않은 항목과 완료 상태는 그대로 둔다. 기존 데이터에 `plannedDate` 필드가 없으면 첫 변경 때 기존 기한의 지역 날짜를 승계하며, 명시적으로 저장된 `null`은 보존한다.

기존 `rollover` 명령은 기한 자체를 옮기는 호환 경로로 남긴다. 시각 항목은 기존 지역 시각을 보존한 `dueAtById`를 UI가 전달하고 호스트가 선택 범위·타입·날짜 범위를 검사한다. 날짜 항목은 `dueDate`를 바꾼다. 할 일 관리의 선택 이월은 이 명령 대신 `plan`을 사용하고, 다이어리의 이동 기록은 `move-record`를 사용한다.

### 반복과 완료

새 반복은 `repeatRule`에 저장한다. `interval`은 1~365, `unit`은 `day`·`week`·`month`·`year`다. 요일 번호는 월요일 0부터 일요일 6까지다.

| `mode` | 동작 |
| --- | --- |
| `calendar` | 원래 기한을 기준으로 다음 회차를 계산한다. 주 반복은 선택 요일, 월 반복은 같은 일·마지막 날·몇 번째 요일을 지원한다. 마지막 요일은 `nth: -1`이다. 다섯 번째 요일이 없는 달은 그 요일이 있는 다음 대상 월로 건너뛴다. |
| `completion` | 실제 완료 날짜부터 간격을 계산한다. 예를 들어 1월 31일 기한을 2월 5일 완료한 뒤 1개월 반복이면 다음 날짜는 3월 5일이다. 다음 완료 시점이 정해지지 않았으므로 미리보기는 지금 완료했을 때의 다음 회차만 계산한다. |
| `frequency` | `unit: week`, `interval: 1`, `timesPerWeek: 1~7`. 같은 날 한 번씩 기록하고 해당 주 목표를 채우면 추가 기록을 거절한다. 다음 주에는 다시 기록할 수 있다. |

날짜·완료 기준 반복은 명시적으로 완료했을 때 다음 회차를 하나 생성한다. 새 회차의 `plannedDate`는 다음 기한 날짜로 설정한다. 월의 같은 일 반복은 `dayOfMonth`를 유지하므로 1/31 → 2/28 → 3/31이며, 윤일의 연 반복도 원래 날짜를 유지한다. `timeZone`은 `local` 또는 IANA 이름이다. 시각 기한의 지역 시각을 보존하며 DST 때문에 다음 시각이 없거나 두 번이면 임의 보정하지 않고 직접 지정을 요청한다.

주간 횟수는 `frequencyRecords`의 식별자·날짜·기록 시각으로 남긴다. 목표를 채워도 항목 전체를 완료 처리하거나 다음 항목을 복제하지 않는다. 기록 하나씩 취소할 수 있고 완료 구슬병도 실제 기록을 따라 갱신한다. 주간 계획에 속한 횟수 목표는 시작 주 이후에도 표시하되 진행률은 보고 있는 주의 기록만 센다.

**이번 회차** 편집은 이후 회차의 기존 템플릿을 보존한다. **이번 및 이후 회차** 편집은 선택 회차와 연결된 미완료 후속 회차를 바꾸며 이미 완료한 후속 기록을 덮어쓰지 않는다. 이번 회차에서만 반복을 해제해도 이후 템플릿은 남으므로 시리즈를 중단하려면 이후 회차 범위를 선택한다. 완료 취소는 자동 생성 후 수정하지 않은 회차만 제거하고, 이미 편집·완료한 회차는 보존한다. 다시 완료해도 같은 회차를 중복 생성하지 않는다. 이 비교는 기존 데이터의 생성 스냅샷도 정규화한 뒤 수행한다.

**이번 회차 건너뛰기**는 날짜 기준 반복의 기한을 다음 날짜로 옮기며 완료 사건이나 구슬을 만들지 않는다. 완료 기준 반복과 주간 횟수에는 적용하지 않는다. 완료 기준 반복의 날짜를 바꾸려면 기한을 직접 편집한다.

기존 `repeat` 문자열은 `none`·`daily`·`weekly`·`monthly`·`yearly` 호환 경로다. 새 규칙으로 저장하기 전까지 기존 월말 계산(1/31 → 2/28 → 3/28)과 UTC 시각 보존을 유지한다. 따라서 기존 규칙의 시각은 DST 전후 기기 지역 시각이 달라질 수 있다.

### 템플릿과 입력

**집안일**, **건강 관리**, **월간 정리**, **연간 관리**, **기념일·여행**, **집중·학습**의 6개 템플릿에서 추가할 항목, 날짜와 반복을 고른다. 선택 결과는 `batch-add`로 한 번에 저장하며 1~30개, 전체 할 일은 2000개까지다. 하나라도 잘못된 입력이면 새 목록과 항목을 일부만 남기지 않는다. 템플릿은 사용자 확인 후 로컬 할 일을 만드는 시작점이고 삭제한 항목을 자동 복원하지 않는다.

현재 도구 조작은 일반 입력 화면과 명시적 버튼으로 수행한다. 자연어를 해석해 데이터를 수정하는 실행 경로는 제공하지 않는다. 2026-10-02부터는 [빠른 실행](desktop.md#command-palette)에서 사용자가 **할 일로 적기** 행을 직접 고를 때만 입력한 문장을 그대로 날짜 없는 할 일(수집함)로 저장한다. 문장에서 날짜·반복·완료를 읽어 내지 않으므로 해석 경로가 아니다. “하기 싫다”나 인용된 체크리스트를 보고 자동 완료·연기하지 않으며 LLM은 준비 조건이 아니다.

## 낱장 메모

메모 위젯은 목록과 바탕화면의 낱장 창을 분리한다. 목록은 본문을 한 줄로 보여 주며 각 메모를 꺼내거나 넣고 삭제하는 데 사용한다. 본문이 비어 있으면 기존 제목, 제목도 없으면 `빈 메모`를 표시한다. 표시용 공백 정리는 저장된 원문을 바꾸지 않는다. 목록 창을 닫아도 꺼내 둔 낱장은 유지한다.

목록과 낱장의 새 메모 조작은 각 창의 오른쪽 아래에 고정한다. 낱장의 글자 크기 조작과 저장 상태도 하단에 둔다. 제목 입력 단계 없이 빈 메모를 저장하고 새 창을 연다. 메모마다 하나의 독립된 편집 창을 사용하며 이미 열린 메모를 다시 꺼내면 같은 창에 초점을 준다. 기본 크기는 320×320, 최소 크기는 260×220이며 헤더를 끌어 이동하고 창 크기를 조절할 수 있다. 목록과 낱장 모두 [공통 위젯 창](desktop.md#창-이동과-닫기)의 제목·× 한 줄 고정 헤더를 사용하고, 긴 목록이나 본문만 헤더와 하단 조작 사이에서 스크롤한다. 본문은 낱장에서 바로 편집한다. 새 메모에는 제목 입력란이 없으며, 기존 `title` 메타데이터가 있으면 헤더에서 읽기 전용으로 표시하고 본문 수정 시 보존한다.

본문과 글자 크기는 마지막 입력 400ms 뒤 자동 저장한다. 본문에서 초점이 벗어나거나 낱장을 넣을 때 대기 중인 변경을 즉시 저장한다. 저장 중 새로 입력한 내용도 이어 저장하며, 다른 낱장의 수정이 이 초안을 덮어쓰지 않는다. 저장 대기·저장 중·저장됨·실패를 구분하고 저장 실패 시 초안과 창을 유지해 다시 저장할 수 있게 한다. 본문의 앞뒤 공백과 줄바꿈은 그대로 보존한다.

| 동작·상태 | 계약 |
| --- | --- |
| 글자 크기 | 메모별 기본 16px. **A− / A+**로 12~24px 범위에서 2px씩 바꾸며 다른 메모에는 적용하지 않는다. |
| 넣기·낱장의 ×·OS 닫기 요청 | 변경 저장에 성공한 뒤 그 메모의 `isOpen`을 `false`로 저장하고 낱장 창만 닫는다. 본문과 글자 크기는 보존한다. |
| 삭제 | 목록에서 확인한 메모 데이터와 열린 낱장을 제거한다. 넣기와 구분한다. |
| 재시작 | 설치·활성 메모 위젯의 저장된 `isOpen: true` 항목을 다시 연다. 과거 데이터에 열림 상태가 없으면 닫힌 상태, 글자 크기가 없으면 16px로 읽는다. |
| 일반 앱 종료·업데이트 설치 | 열린 낱장의 대기 중인 변경을 모두 저장한 뒤 종료·설치를 시작한다. 저장 실패·확인 시간 초과·열린 메모 변경 시 작업을 취소하고 초안과 편집을 유지한다. 종료 때문에 `isOpen`을 끄지 않으며 다음 실행에서 복원한다. 강제 종료·프로세스 강제 중단은 이 저장 확인을 보장하지 않는다. |
| 위젯 끄기·제거 | 열린 낱장의 편집을 잠시 막고 대기 중인 변경을 저장한 뒤 해당 위젯의 목록과 낱장을 닫는다. 저장 실패·확인 시간 초과 시 끄기·제거를 취소하고 편집을 다시 허용한다. 저장 데이터는 [설치와 관리](../widgets/installation.md)의 보존·명시 삭제 선택을 따른다. |

열림 상태와 글자 크기는 SQLite의 메모 데이터에 저장한다. 같은 메모의 본문이 다른 경로에서 바뀌었으면 이전 본문을 기준으로 한 저장을 거절하고 초안을 유지한다. 계정·모델·네트워크는 생성·수정·저장의 준비 조건이 아니다. 이 계약은 기존 0.2 본체·말풍선 경험을 유지하는 선택 위젯의 확장이다.

### 메모 인수 조건

- 목록에서 본문을 한 줄로 확인하고 오른쪽 아래 **+ 새 메모**로 빈 낱장을 즉시 연다. 낱장의 새 메모·글자 크기 조작과 저장 상태도 하단에 두며, 긴 목록이나 본문을 스크롤해도 제목·닫기와 하단 조작이 고정된 위치에 남는다. 여러 낱장을 독립적으로 편집하며 같은 메모의 창을 중복 생성하지 않는다.
- 공백·줄바꿈과 기존 제목을 보존하고, 자동 저장 도중의 추가 입력도 빠짐없이 저장한다. 실패 후 초안·창·재시도 조작을 유지한다.
- 글자 크기가 메모별로 저장되며 새 메모·과거 데이터의 기본값과 상·하한을 지킨다.
- 목록 닫기, 낱장 넣기, 데이터 삭제, 위젯 끄기·제거의 범위를 구분한다. 위젯 끄기·제거는 모든 열린 낱장의 저장 성공을 확인한 뒤 수행하고 실패하면 초안과 편집 기능을 유지한다. 재시작 후 설치·활성 위젯의 꺼내 둔 낱장만 복원한다.
- 실제 데스크톱에서 이동·크기 조절·초점과 OS 닫기 저장을 확인한다. 자동 테스트와 플랫폼별 실제 확인은 [구현 상태](../status.md)에 따로 기록한다.
- 입력 직후 일반 종료와 저장 실패 상태의 종료를 확인한다. 마지막 입력이 저장되기 전 종료하거나 실패한 초안을 버리지 않으며, 업데이트 설치도 같은 저장 조건을 따른다.

## 생활 도구의 선택 연동

- **내장 할 일:** 날짜 페이지·봉투에서 같은 할 일을 사용한다. 목록·반복은 할 일 관리에서, 기간별 분류는 기간 계획에서 편집한다.
- **준비 봉투:** 날짜나 외부 일정 없이 만들고, 필요한 Todo·메모·자료를 연결한다.
- **캘린더 조회·알림:** Google Calendar·macOS Apple·URL 구독을 연결했을 때 다이어리에 읽은 일정을 함께 보여 준다.
- **집중:** 사용자가 선택한 할 일에 타이머를 연결하고 종료 후 다음 행동을 선택한다.

연동 항목을 자동 설치하거나 연결하지 않는다. 실용 도구가 캐릭터를 미완료 업무만 읽는 알림기로 만들지 않게 한다.

## 알림과 대화

일정·할 일 기한 알림은 기본으로 꺼져 있다. 켠 뒤에도 캐릭터 말풍선과 OS 알림을 각각 고른다. 채널 기본값은 말풍선 켬·OS 끔이고, 기본 10분 전·종일 일정과 날짜 기한 제외·기기 지역 시각 22:00~08:00을 조용한 시간으로 사용한다. 알림은 0~120분 전에서 고르며 날짜 항목을 포함하면 해당 지역 날짜 09:00을 기준으로 한다. 조용한 시간의 시작과 끝이 같으면 시간 제한이 없다. 캘린더 연결이 없어도 활성 할 일의 기한 알림을 처리한다.

말풍선은 숨김·일시정지·상위 자동 대화 설정과 직접 입력 우선 규칙을 따른다. 집중 타이머가 실행 중이어도 일정·기한 알림 말풍선은 나온다. OS 알림은 별도 동의한 채널로 처리하여 캐릭터 숨김·말풍선 닫기와 분리한다. 두 채널 모두 생활 알림 설정·조용한 시간·1시간 알림 쉬기를 따른다. OS 권한 요청은 설정의 명시적 버튼에서만 수행하며 타이머가 권한창을 띄우지 않는다. macOS는 빌드된 `.app`의 UserNotifications를 사용하고 플래너 열기·10분 뒤 다시 알림 조작을 제공한다. 다른 데스크톱은 시스템 알림 설정을 따르며 macOS와 같은 버튼 동작을 약속하지 않는다.

**10분 뒤 다시 알림**은 최근 1시간 안의 마지막 알림 대상을 재예약하며 원기한·완료 상태를 바꾸지 않는다. 완료·삭제·변경된 대상은 다시 알리지 않고, 오래된 OS 알림의 버튼으로 새 알림을 덮어쓰지 않는다. **1시간 알림 쉬기**는 대기 중인 다시 알림도 해제한다. 앱이 직접 시점을 관리하고 OS에는 즉시 표시만 요청하므로 재시작 뒤 남은 OS 예약을 재생하지 않는다.

무드메이커는 기한 알림 켜기와 별개로 하루 시작·집중 시작·집중 종료 후 쉬기·하루 마무리 말풍선을 각각 선택한다. 모두 기본 꺼짐이며 하루 시작 09:00·마무리 21:00을 수정할 수 있다. 집중 관련 제안은 실제 타이머 상태 전환을 따르고 10분 간격 제한을 둔다. 켜 둔 무드메이커 말풍선은 집중 중 침묵의 예외로 나온다. 기한 알림이 같은 차례에 있으면 무드 제안은 생략한다. 하루 시작과 마무리는 각각 날짜별 한 번만 처리하고, 재시작·긴 공백에 놓친 안내를 몰아 보내지 않는다. 무드 제안 자체가 할 일 완료나 이월을 실행하지 않는다.

A/B는 실제 상태를 저장된 사건 문구나 `.talk` 대본으로 설명한다. 현재 위젯 사건은 저장된 `event.text`를 fallback으로 재생하거나 `.talk`를 선택하며, 사건 본문을 LLM으로 재작성하지 않는다. 일정 설명이나 할 일 메모의 지시를 실행 권한으로 취급하지 않는다. 외부 API에 일정·할 일 정보를 전달하는 세부 동의·선택 범위는 연동 구현 전에 확정하며, 연결만으로 자동 전송을 허용했다고 간주하지 않는다.

완료 구슬 같은 가벼운 표현은 실제 완료 상태를 따른다. 완료 취소도 반영한다. 미완료·기한 초과·자리 비움으로 친밀도를 낮추거나 기능을 잠그지 않는다. 자세한 근거 규칙은 [대화와 기억](conversation.md)을 따른다.

## 읽기 연결과 지원 범위

Google은 사용자가 입력한 Desktop OAuth client ID와 선택적인 client secret을 사용한다. 기본 calendar ID는 `primary`이며 한 연결에서 최대 20개 ID를 읽는다. Loopback 포트·PKCE S256·요청 state·180초 대기 제한을 사용하며 access/refresh token과 client secret은 OS 자격 증명 저장소에 저장한다. 요청 scope는 `calendar.events.readonly`다. 조회는 Google의 `singleEvents=true` 전개·페이지 결과를 사용하며 원본에 쓰지 않는다. 실제 계정 동의·token 갱신은 별도 실환경 검증 대상이다.

Apple 직접 연결은 macOS 14 이상에서 EventKit을 사용한다. 사용자가 접근 버튼을 눌러 허용한 뒤 이 Mac의 캘린더 이름·출처를 보고 조회 대상을 선택한다. EventKit의 읽기에는 OS의 `FullAccess` 권한이 필요하지만 앱은 이벤트 조회만 수행한다. 권한 거부·제한·쓰기 전용 권한과 선택 캘린더 소실을 오류로 구분한다. Apple 연결의 캘린더 ID와 Google 연결의 조회 ID는 사용자 선택을 저장하며 최대 20개까지 허용한다. 같은 Google 계정이 Apple Calendar에도 등록되어 있으면 중복 표시를 피하도록 한 경로에서만 선택한다. 서로 다른 연결을 자동으로 합쳐 일정을 제거하지 않는다. Windows에는 Apple 직접 연결을 제공하지 않으며 iCloud의 ICS 구독은 별도의 읽기 연결이다.

ICS/webcal은 HTTP/HTTPS를 읽으며 `webcal`은 HTTPS로 바꾼다. 사용자 정보가 들어간 URL과 fragment는 거부한다. 비공개 구독 URL은 OS 자격 증명 저장소에 보관하고 스냅샷·오류·대사에 넣지 않는다. 최대 3회 주소 이동을 처리하되 HTTPS에서 HTTP로 내려가는 이동은 거절한다. 요청 20초·연결 10초·OS 자격 증명 읽기 5초·전체 갱신 90초, 본문 4 MiB, 조회 일정 5000개로 제한한다.

조회 범위는 갱신 시각 기준 과거 30일~미래 365일이다. 범위 밖 날짜를 일정 없음이나 온종일 빈 시간으로 해석하지 않는다. 일정 ID는 연결·원본·회차를 포함하며 다른 연결의 동일 UID와 충돌하지 않는다.

| ICS 형식 | 처리 |
| --- | --- |
| UTC, IANA TZID, 종일 DATE | 지원. 종일 종료 날짜는 제외 경계이며 timestamp로 치환하지 않음 |
| DAILY/WEEKLY/MONTHLY/YEARLY RRULE, RDATE, EXDATE | `icalendar` parser와 `rrule`을 사용해 범위 안 회차 전개 |
| RECURRENCE-ID 이동·취소, STATUS:CANCELLED | 원래 회차 ID를 보존해 대체·취소 |
| Floating 시각, 비 IANA VTIMEZONE, 모호하거나 존재하지 않는 DST 시각 | 명시 오류 |
| DURATION, EXRULE, RANGE=THISANDFUTURE, subdaily 반복, 지원하지 않는 규칙 | 명시 오류. DTEND·EXDATE 등 지원 형식으로 제공해야 함 |

종일 반복의 `UNTIL`은 원본 `DTSTART`와 같은 DATE 형식으로 읽으며 마지막 날짜의 회차를 포함한다. 시각 일정의 UTC 종료와 종일 날짜를 혼용하지 않는다. Apple EventKit이 종일 일정의 마지막 날 23:59:59로 반환하는 종료는 다음 날짜로 바꿔 공통 모델의 제외 경계로 저장한다. 하루짜리 일정과 여러 날 일정 모두 마지막 날짜를 보존하며 DST 전환에도 날짜 단위로 계산한다.

자동 갱신의 기본 간격은 15분이다. 수동 캘린더 조회도 30초 최소 간격을 둔다. 실패 시 이전 캐시와 마지막 성공 시각을 유지하고 지수 backoff를 적용한다. 인증 오류 또는 5회 연속 실패는 자동 재시도를 중단하며 수동 재조회·재연결로 복구한다. 전체 정보 조회의 동시 작업은 호스트에서 2개로 제한한다. 작업 token과 위젯 revision을 완료 시 다시 검사한 뒤에만 키와 데이터를 저장한다.

연결 방식을 바꾸거나 연결 입력을 초기화하고 Apple 목록을 새로 읽을 때 이전 조작의 오류 표시를 지운다. 이미 저장된 연결의 실패 상태·오류는 해당 연결이 다시 조회되기 전까지 유지한다.

외부 일정 알림은 최근 30분 안에 성공한 ready/syncing 연결만 사용한다. 같은 실행에서 직전 확인 이후 알림 시점을 통과한 일정·할 일을 묶으며 앱 재시작 첫 확인이나 2분 넘는 공백을 따라잡지 않는다. 발화 직전에도 대상이 같은지 확인하여 완료·변경된 할 일이나 변경된 타이머의 오래된 안내를 버린다. 사건의 유효기간과 발화 중단은 공용 재생 규칙을 따른다. 이 데이터가 LLM으로 자동 전송되지는 않는다.

API 근거: [Google Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [Google events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list), [icalendar parser](https://docs.rs/icalendar/0.17.13/icalendar/parser/), [rrule](https://docs.rs/rrule/0.14.0/rrule/struct.RRuleSet.html).

## 인수 조건

- 계속 쓸 메모 → 내 다이어리 → 펼친 페이지 순서로 탐색하며 월·주·하루를 바꿔도 저장한 기록·메모·선택한 항목을 잃지 않는다.
- 작은 달력 아래의 기간 계획·템플릿·할 일 관리 메뉴는 같은 오른쪽 본문을 바꾼다. 메뉴 전환 후 초안을 복원하고, 열린 편집 대화상자의 탐색 확인과 숨긴 패널을 포함한 단일 종료 확인을 유지한다.
- 캘린더는 월간·주간·하루에서만 탐색하며, 같은 다이어리의 캘린더 정보에서 색상·조회 상태·빈 시간을 확인한다. 연결·알림 설정은 통합 설정창으로 바로 이동한다.
- 날짜 페이지는 날짜별 하나이고 자유 페이지는 날짜 없이 저장한다. 같은 페이지를 다시 열고 앱을 재시작해도 본문·공백·줄바꿈과 참조가 보존된다.
- 동시 편집 충돌과 저장 실패는 초안을 유지하며 다른 화면의 최신 내용을 덮어쓰지 않는다.
- 위젯·낱장 메모·봉투를 날짜·자유 페이지에 연결하고 원본 ID로 다시 연다. 같은 참조를 중복 생성하지 않으며 연결 해제·페이지 삭제로 원본을 지우지 않는다.
- 외부 계정 없이 Comet 일정을 생성·편집·삭제하며, 외부 새로고침·연결 해제 뒤에도 보존한다. 같은 일정의 동시 변경은 거절하고 다른 일정 변경은 편집을 막지 않는다.
- 준비 봉투는 캘린더 없이 만들고 이름·선택 날짜·보관 상태를 바꾼다. 일정 연결·해제와 연결 소실이 로컬 내용을 삭제하지 않는다.
- 봉투의 준비물을 Todo로 보내면 체크 제거·Todo 생성·참조 연결이 함께 성공하거나 함께 취소된다. 봉투·하루 페이지에서 같은 완료 상태를 본다.
- 페이지·봉투 삭제는 원본 Todo와 계속 쓸 메모를 남긴다. 꺼내기·넣어두기·보관은 삭제와 구분한다.
- 계정·모델·네트워크 없이 내장 할 일을 만들고 수정·완료·취소하며 재시작 후 보존한다.
- 오늘 선택·선택 이월이 원래 계획 기간과 기한을 바꾸지 않는다. 다이어리의 이동은 같은 Todo를 옮기고 출발 날짜의 흔적과 함께 저장하며, 실패 시 둘 다 남기지 않는다. 명시적으로 오늘에서 뺀 항목을 기한으로 다시 끌어오지 않는다.
- 반복의 다음 날짜·월말·요일·DST 경계를 확인하고, 회차 편집·완료 취소가 수정한 후속 데이터나 완료 기록을 지우지 않는다. 횟수 목표는 날짜별 기록과 해당 주 진행률을 구분한다.
- 템플릿 저장 실패는 새 목록·선택 항목을 일부만 남기지 않는다.
- 캘린더 연결은 읽기 전용이며 조회·링크 열기·준비 봉투 조작으로 외부 일정이 바뀌지 않는다.
- 일정 시각은 시간대·종일 일정·반복 예외를 구분한다. 지원하지 않는 입력은 조용히 잘못된 시각으로 바꾸지 않는다.
- 동기화 실패·오래된 정보·연결 해제를 표시하며 내부 할 일을 보존한다.
- 타이머 종료가 할 일 완료를 자동 처리하지 않고, 이월도 선택한 항목·날짜만 변경한다.
- 빈 시간은 조회한 캘린더 범위를 명시하고 사용자의 확실한 자유 시간으로 단정하지 않는다.
- 직접 요청과 알림 중단 설정을 존중하며, 알림을 놓쳐도 친밀도 벌점이 없다.
- 캐릭터·OS 채널을 독립적으로 제어하고, 다시 알림은 기한을 변경하지 않는다. 실제 OS 권한·표시·버튼과 Google·Apple 실계정 조회는 소스 테스트와 별도로 검증한다.
- 기한·반복·알림·외부 전송 정책을 바꾸면 이 문서와 해당 회귀 테스트를 함께 갱신한다.

다이어리 탐색·참조와 삭제 범위·저장 충돌·이동 기록, 제공자·쓰기 권한·반복 정책·알림 기본값이 바뀌면 이 문서를 갱신한다. 도구의 표시와 전체 목록은 [바탕화면](desktop.md), [장난감](toys.md)을 참고한다.
