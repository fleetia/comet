# 할 일과 캘린더

기준일: 2026-09-15. Comet 안의 할 일과 외부 일정 조회를 캐릭터의 쪽지·티켓·타이머로 연결하는 확정 계획이다. 새로운 관리 대시보드를 상시 띄우지 않고 필요한 도구를 꺼내 쓴다.

| 상태 | 범위 |
| --- | --- |
| 구현됨 · 0.2 | 0.2의 캐릭터·대화·단어장 기반. 이 문서의 할 일·캘린더 기능은 아직 구현되지 않았다. |
| 확정 · 개발 예정 | 계정 없는 SQLite 할 일, Google Calendar 읽기 전용 연결, iCalendar URL 구독, 집중·준비 도구 |
| 미정 | 인증·동기화 간격, 반복 규칙의 초기 지원 범위, 알림 기본 시점·조용한 시간, 캘린더 중복 처리 세부 |

Apple EventKit 직접 연결과 Todoist 등 외부 할 일 서비스는 선택하지 않았다. 현재 계획에 이미 포함된 제공자로 표시하지 않는다.

## 데이터의 원본과 쓰기 범위

| 데이터 | 원본 | 허용 범위 |
| --- | --- | --- |
| 내장 할 일·목록·메모 | Comet의 SQLite | 사용자 의도에 따른 생성·수정·완료·완료 취소·삭제 |
| Google Calendar 일정 | 연결한 Google Calendar | 선택한 캘린더 조회. 일정 생성·수정·삭제는 하지 않는다. |
| iCalendar 구독 | 사용자가 등록한 `.ics` 또는 `webcal` URL | 일정 읽기와 갱신. 구독 원본에 쓰지 않는다. |
| 준비 봉투 연결 | Comet의 로컬 데이터 | 외부 일정에 내장 할 일·체크리스트·링크를 연결하되 외부 일정은 수정하지 않는다. |

내장 할 일은 계정이나 외부 연결 없이 사용할 수 있다. 연결 실패가 로컬 작업을 막지 않는다. 캘린더 인증·구독 URL은 필요한 범위에서만 보관하며, 비공개 구독 URL을 일반 로그나 대사로 노출하지 않는다.

조회 중·마지막 갱신 시각·연결 실패를 구분한다. 오래된 일정은 최신 확인 결과처럼 말하지 않는다. 연결 해제가 내장 할 일을 지우지 않는다. 외부 일정 변경·삭제 시 준비 봉투의 연결 끊김을 표시하며 로컬 메모를 조용히 삭제하지 않는다.

## 내장 할 일

각 할 일은 제목, 메모, 소속 목록, 선택적인 기한, 반복, 완료 상태를 가진다. 목록은 일상·업무·장보기처럼 사용자가 구분할 수 있다. 완료 취소를 지원하고 변경 결과를 재시작 후 보존한다.

날짜만 있는 기한과 시각까지 있는 기한을 혼동하지 않는다. 반복은 계획에 포함하되 일·주·월 중 초기 지원 범위와 다음 회차 생성 시점은 구현 전에 확정한다. 화면에서 제공하지 않는 반복 규칙을 모델이 임의로 만들어 저장하지 않는다.

캐릭터에게 자연어로 요청하는 경우에도 실제 생성·수정 의도가 있어야 한다. “하기 싫다”나 인용된 체크리스트를 보고 자동 완료·연기하지 않는다. 모호한 날짜나 대상은 확정된 값인 것처럼 저장하지 않는다. LLM 없이 일반 입력 화면으로 같은 작업을 수행할 수 있어야 한다.

## 첫 구현 순서

1. **내장 할 일:** 빠른 입력, 목록, 오늘 쪽지, 완료·취소와 영구 저장.
2. **캘린더 조회·알림:** Google Calendar와 URL 구독, 오늘 일정, 다음 일정 티켓.
3. **집중:** 사용자가 선택한 할 일에 타이머를 연결하고 종료 후 다음 행동을 선택.
4. **준비 봉투:** 일정에 내장 항목과 자료 링크를 연결.

주사위·화분 같은 작은 놀이도 함께 준비한다. 실용 도구가 캐릭터를 미완료 업무만 읽는 알림기로 만들지 않게 한다.

## 구체적인 흐름

| 기능 | 사용자 흐름과 상태 | 캐릭터 표현 예시 |
| --- | --- | --- |
| 오늘 브리핑 | 사용자가 요청하면 오늘 할 일과 연결한 캘린더 일정을 짧게 보여 준다. 자동 브리핑은 별도 선택 사항이다. | A “오늘 쪽지는 세 장이네.” B “일정도 같이 볼까?” |
| 다음 일정 티켓 | 다음 일정의 제목·시각·출처를 작은 티켓에 표시하고 원본을 연다. | A “다음 일정이 곧이야.” B “15시 회의. 준비 봉투도 볼까?” |
| 회의 링크 | 실제 일정에 있는 링크를 사용자가 눌러 연다. 참석 여부를 자동 판단하지 않는다. | 링크가 있을 때만 “회의 링크를 열 수 있어.” |
| 준비 봉투 | 사용자가 일정에 할 일·체크리스트·링크를 묶고 다시 꺼낸다. | A “봉투 열어 볼까?” B “네가 넣어 둔 항목 두 개가 있어.” |
| 집중 타이머 | 할 일 하나와 시간을 선택. 종료 후 완료·계속·쉬기 중 직접 선택한다. | A “모래가 다 내려왔어.” B “계속할지, 잠깐 쉴지 골라 줘.” |
| 루틴 | 반복 할 일을 묶어 확인하고 개별 완료한다. 놓친 회차로 벌점을 주지 않는다. | 실제 완료한 항목만 “오늘 이건 마쳤네.” |
| 장보기 목록 | 목록에 물건을 적고 사용자가 구매한 항목을 체크·취소한다. | A “우유는 체크됐어.” B “목록에는 달걀이 남아 있네.” |
| 빈 시간 | 조회 대상으로 등록한 캘린더에서 겹치지 않는 구간을 표시한다. | “연결한 캘린더에는 40분이 비어 있어.” |
| D-day | 사용자가 선택한 날짜까지 남은 날을 표시한다. | “등록한 여행 날짜까지 사흘이야.” |
| 하루 마무리 | 요청 또는 선택한 알림에서 완료·남은 일을 확인. 이월할 항목과 날짜는 사용자가 고른다. | A “오늘 마친 쪽지부터 볼까?” B “남은 건 옮길 것만 골라 줘.” |

타이머가 끝났다는 사실은 일이 끝났다는 사실이 아니다. 빈 시간 표시는 등록한 캘린더만 반영하며 실제로 자유롭거나 휴식 가능한 시간이라는 보장이 아니다. 장보기 완료도 캐릭터의 추측으로 바꾸지 않는다.

## 알림과 대화

알림 종류·대상·시점은 사용자가 선택할 수 있게 한다. 정확한 기본 시각과 조용한 시간의 범위는 미정이다. 지난 알림을 뒤늦게 연속 재생하거나 미완료 항목을 반복 독촉하지 않는다. 직접 입력과 현재의 사용자 조작을 자동 브리핑보다 우선한다.

A/B는 실제 상태를 등록 대사로 설명한다. 선택적인 LLM은 필요한 상태만 받아 표현을 더할 수 있으며, 일정 설명이나 할 일 메모의 지시를 실행 권한으로 취급하지 않는다. 외부 API에 일정·할 일 정보를 전달하는 세부 동의·선택 범위는 연동 구현 전에 확정하며, 연결만으로 자동 전송을 허용했다고 간주하지 않는다.

완료 구슬 같은 가벼운 표현은 실제 완료 상태를 따른다. 완료 취소도 반영한다. 미완료·기한 초과·자리 비움으로 친밀도를 낮추거나 기능을 잠그지 않는다. 자세한 근거 규칙은 [대화와 기억](conversation.md)을 따른다.

## 인수 조건

- 계정·모델·네트워크 없이 내장 할 일을 만들고 수정·완료·취소하며 재시작 후 보존한다.
- 캘린더 연결은 읽기 전용이며 조회·링크 열기·준비 봉투 조작으로 외부 일정이 바뀌지 않는다.
- 일정 시각은 시간대·종일 일정·반복 예외를 구분한다. 지원하지 않는 입력은 조용히 잘못된 시각으로 바꾸지 않는다.
- 동기화 실패·오래된 정보·연결 해제를 표시하며 내부 할 일을 보존한다.
- 타이머 종료가 할 일 완료를 자동 처리하지 않고, 이월도 선택한 항목·날짜만 변경한다.
- 빈 시간은 조회한 캘린더 범위를 명시하고 사용자의 확실한 자유 시간으로 단정하지 않는다.
- 직접 요청과 알림 중단 설정을 존중하며, 알림을 놓쳐도 친밀도 벌점이 없다.
- 기한·반복·알림·외부 전송의 미정 사항을 구현 전에 확정하고 이 문서에 기록한다.

제공자·쓰기 권한·반복 정책·알림 기본값이 바뀌면 이 문서를 갱신한다. 도구의 표시와 전체 목록은 [바탕화면](desktop.md), [장난감](toys.md)을 참고한다.
