# 개발 순서와 인수 기준

2026-09-15에 정리한 구현 순서다. 선택 설치 요구를 반영해 공식 위젯 관리 기반을 0단계로 앞당겼다. 외부 패키지의 공개 SDK는 내장 도구로 계약을 검증한 뒤 제공한다. 캐릭터 관리·JSON 공유는 0.3.0에 구현하고 macOS에서 검증했다. 공식 위젯 설치기·22개 위젯·외부 SDK·Rust workspace는 개발 예정이며, 완료 조건을 충족한 뒤 [구현 상태](../status.md)를 갱신한다. 위젯 후속 단계의 날짜·공수·앱 버전 번호는 아직 정하지 않았다.

## 0. 선택 설치·캐릭터팩과 첫 놀이

[전체 카탈로그](../widgets/catalog.md)와 [선택 설치 흐름](../widgets/installation.md)을 바탕으로, 첫 실행에서 고르고 캐릭터 메뉴에서 추가·중지·제거하는 경로를 구현한다. 첫 설치 대상은 작은 승부의 주사위·동전이다. 설치부터 실제 결과·등록 대사·제거까지 한 번에 검증한다. 가위바위보는 같은 묶음의 후속 기능이다.

Rust 호스트 안에 설치 상태·패키지 검사·작업 취소의 최소 책임을 둔다. Cargo workspace 도입 판단은 [구조와 책임](architecture.md)을 따른다. 첫 위젯 전에 앱 전체를 여러 crate로 옮기거나 외부 코드 실행 플랫폼을 완성할 필요는 없다.

[캐릭터 교체·공유](../product/characters.md)는 로컬 정체성·관계 이전, 개별·조합 적용, 편집과 JSON 내보내기·가져오기까지 구현했다. 실제 사용 흐름과 한계는 [0.3.0 검증 기록](../VALIDATION-0.3.0.md)을 따른다. 이 구현이 공통 위젯 패키지 검사·설치기의 완성을 뜻하지 않는다. 다음 기반 작업은 공식 위젯 선택·설치 관리와 주사위·동전이며 기존 캐릭터 데이터 보존 경계를 유지한다.

완료 조건:

- 아무 위젯도 선택하지 않고 시작하고, 나중에 주사위를 추가할 수 있다.
- 실제 난수 결과를 먼저 저장하고 그 결과에 맞는 A/B 반응을 모델 없이 표시한다.
- 설치 상태가 재시작 후 유지되고 설치 실패를 성공으로 표시하지 않는다.
- 끄기·제거 시 진행 중 작업과 대기 대사를 중지하며 사용자 데이터를 보존한다.
- 설치한 도구만 실행하고 관리 화면을 닫으면 바탕화면의 작은 A/B 경험으로 돌아온다.
- 모델 없이 새 텍스트 캐릭터를 적용하고, 한 명 또는 둘의 조합을 바꿔 수다를 이어 간다.
- 캐릭터 교체·복귀에서 관계와 과거 화자를 보존하며 교체 전 준비 대사를 재생하지 않는다.
- 공유용 팩을 별도의 테스트 사용자 데이터 공간에 가져올 수 있고 실제 대화·기억·친밀도·연결 비밀정보는 내보내지 않는다.

## 1. 최소 연결 계약과 내장 투두

먼저 상태·사건·명령·결과, 식별자, 데이터 소유권과 중복 처리 규칙을 구현한다. 내장 투두로 사용자 입력부터 영구 저장까지 실제 흐름을 만든다. 투두의 반복 회차 생성·편집 규칙은 저장 구조를 확정하기 전에 결정한다. 이 단계에서는 간단한 타이머 종료 → 사용자의 완료 선택 → 완료 반응을 시제품으로 연결해 계약을 검증한다. 생활 도구의 기능 확장 순서는 내장 투두 → 캘린더 → 집중 타이머 → 준비 봉투다.

완료 조건:

- 계정 없이 투두를 추가·수정·완료·취소하고 재시작 후 복원한다.
- 같은 명령을 재시도해도 항목이 중복 생성되지 않는다.
- 저장 실패를 성공으로 안내하지 않으며, 기존 앱 데이터를 보존한다.
- 도구를 사용해도 작은 A/B와 잠깐 열리는 화면이라는 경험을 유지한다.

## 2. 캘린더 조회와 일정 알림

Google Calendar 읽기 연결과 iCalendar 구독을 추가한다. 오늘 안내·다음 일정·명시된 회의 링크 열기를 연결한다. 투두와 캘린더 구현을 병행해도 되지만, 외부 연결을 핵심 로컬 투두의 준비 조건으로 만들지 않는다.

완료 조건:

- 시간대·종일 일정·반복 회차·일정 취소를 처리한다.
- 첫 동기화에서 과거 일정을 새 알림으로 쏟아내지 않는다.
- 오프라인·인증 실패·조회 결과 없음·오래된 캐시를 구분한다.
- 수정되거나 취소된 일정에 근거한 준비 대사와 알림을 무효화한다.

## 3. 타이머 하나를 끝까지 연결

내장 투두에 집중 타이머를 연결하고, 완료 구슬병 등 작은 반응 토이 하나로 사건 전달을 검증한다. 이후 내장 식물이나 주사위에도 같은 계약을 적용해 특정 기능에만 맞는 SDK가 되지 않게 한다.

완료 조건:

- 타이머 종료와 투두 완료를 별개로 처리한다.
- 완료 버튼을 누르고 저장이 성공했을 때만 다른 토이가 완료 사건을 받는다.
- 중복 사건·숨김·일시정지·취소·재시작으로 대사가 반복되거나 되살아나지 않는다.
- 모델 없이도 전체 흐름이 동작한다.

## 4. 일정 준비 봉투와 생활 도구

특정 일정에 Comet의 투두·체크리스트·링크를 연결한다. 반복 루틴, 장보기, 디데이, 하루 마무리를 같은 저장·알림 경계 위에 확장한다.

완료 조건:

- 반복 일정 중 어느 회차의 준비물인지 구분한다.
- 캘린더 연결을 해제해도 사용자 작성 투두·준비물은 보존하고 연결 상태를 설명한다.
- 미완료 항목을 임의로 완료하거나 미루지 않는다.
- 일정 공백을 실제로 사용자가 한가하다는 사실로 단정하지 않는다.

## 5. 외부 Widget SDK와 패키지 설치

내장 도구로 검증한 계약을 공개하고, 개발용 폴더 불러오기·ZIP 설치·활성화·삭제·이벤트 시험을 제공한다. 패키지 버전과 SDK 호환 범위를 검사한다. 구체 CLI와 공개 함수명은 이 단계에서 확정한다.

완료 조건:

- 외부 패키지를 앱 재빌드 없이 설치하고 자신의 상태·사건·동작을 연결한다.
- 허용되지 않은 투두·캘린더·파일·네트워크 접근을 호스트에서 거부한다.
- 권한 취소·연결 해제·비활성화 뒤 진행 중 작업과 대기 대사가 다시 적용되지 않는다.
- 외부 문자열을 시스템 지시나 사용자 장기 기억으로 자동 승격하지 않는다.
- 예제 위젯과 오류·중복·재시도·최신성 검증 방법을 제공한다.

## 6. 커스텀 화면과 추가 토이

필요한 위젯에 HTML/CSS/JavaScript 화면을 제공한다. 기본 호스트 화면으로 해결되는 기능은 그대로 유지한다. 위젯별 격리와 자원 사용을 측정한 뒤 범위를 넓힌다.

완료 조건:

- 커스텀 화면이 앱의 모든 명령이나 다른 위젯 데이터에 접근하지 않는다.
- 화면을 닫으면 화면 실행 자원을 해제하고, 필요한 예약은 호스트가 유지한다.
- 느리거나 실패한 위젯이 사용자 입력과 A/B의 기본 경험을 지속적으로 막지 않는다.
- 같은 조건의 위젯 없음/사용 중/닫힘과 모델 없음/추론 중 상태를 비교해 자원 변화를 기록한다.

## 전체 카탈로그의 단계 배치

다음은 22개 패키지 제안의 개발 순서다. 첫 배포의 완료 약속이나 모든 포함 기능의 동시 출시를 뜻하지 않는다. 후속 항목의 구체 순서는 앞 단계 검증과 연결 방식 결정 뒤 정한다.

| 단계 | 패키지와 범위 |
| --- | --- |
| 0 | 캐릭터팩 교체·편집·JSON 공유는 구현·macOS 검증 완료. 나머지는 예정: 작은 승부 중 주사위·동전, 공식 위젯 선택·추가·중지·제거 |
| 1 | 할 일의 빠른 입력·목록·오늘 쪽지·완료·취소 |
| 2 | 캘린더의 읽기 연결·티켓·알림·회의 링크 |
| 3 | 집중 타이머, 완료 구슬병, 화분 |
| 4 | 준비 봉투, 시계·기념일, 메모. 할 일의 반복·루틴·장보기·하루 마무리와 캘린더 빈 시간 확장 |
| 5 | 외부 SDK·ZIP 설치·개발 폴더·예제. 새 공식 위젯 패키지 수와 독립인 개발 도구 단계 |
| 6 · 놀이 후속, 내부 순서 미정 | 캐릭터 교감, 공, 종이비행기, 비눗방울, 작은 승부의 가위바위보, 맞히기 놀이, 낚시, 장난 운세, 작은 펫, 수집함·소품, 함께한 사건 일지 |
| 6 · 연결 후속, 방식 결정 필요 | 날씨, 음악 정보, 기기 소식. 각각 제공자·재생 정보 연결·운영체제 조회 범위를 먼저 결정 |

각 단계에서 검증한 범위만 완료로 표시한다. Windows·다중 모니터·장시간 자원 사용과 모델 의미 품질은 별도의 검증 항목으로 유지한다.
