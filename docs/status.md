# 구현 상태와 남은 검증

공식 위젯 22개와 선택 설치·추가·중지·제거, `.talk` 파일 대본을 구현했고, 2026-09-19에는 나디르·별꼬리와 선택지 스토리·암호화 대본 재생을 추가했다. 앱 내부 원문 editor는 제거했으며, 작성·검사·저장은 별도 talk editor로 분리한다. 소스 구현, 자동 테스트, 실제 데스크톱 동작, 외부 계정 인증과 모델 의미 품질을 각각 구분한다. 위젯 변경의 실행 근거는 [위젯 검증 기록](VALIDATION-WIDGETS.md), 별도로 진행한 보조 화면 UI 정리의 범위는 아래에 기록한다.

기존 작은 A/B·내장 인사·단어장·기록·기억·친밀도는 유지한다. 캐릭터 관리·JSON 공유의 0.3.0 검증은 [기존 기록](VALIDATION-0.3.0.md), 0.2 기능과 당시 실측은 [제품 사양](PRODUCT.md)과 [0.2 기록](VALIDATION-0.2.0.md)에 보존한다. 과거의 네이티브 관찰·테스트 수·모델 성능을 새 위젯 결과로 재사용하지 않는다.

## 2026-09-24 캐릭터 기억·사용자 관계·v4 선택 공유

[캐릭터 기억](product/memory-search.md)과 [개인 데이터 선택 공유](product/characters.md#개인-데이터를-포함한-공유)를 소스에 구현했다. 이름 등록·변경은 별도의 사용자 설정이며 같은 이름으로 돌아와도 새 ID와 친밀도 20·스토리 진행으로 시작한다. 화면에는 유저명만 표시한다. 기억은 캐릭터와 사용자별로 분리하고 실제 표시된 직접 대화·확정된 스토리 선택만 경험 근거로 사용한다. 이전 사용자 기억은 90일에 걸쳐 회상 가중치·양이 감소하고 만료 뒤 목록·검색·대화에서 제외한다. 원문 기록은 유지하며 시계 역행·재전달·지연 분석·파생 답변으로 잊은 기억을 복원하지 않는다.

캐릭터 편집은 프로필·모습/표정·말풍선·대사·기억·설정의 6개 탭이다. 기억은 50개씩 편집하며 개별 내보내기와 전체 기억 잊기는 캐릭터 설정에 있다. 검색 모델 설치·분석 재시도는 AI 연결의 독립 영역으로 옮겼다. 개인 데이터가 하나라도 선택되면 v4이며 스프라이트·기억·친밀도·기록을 각각 고른다. v1~v3 읽기와 32 MiB 한도를 유지한다. 가져온 자료는 새 로컬 ID를 받고 기록·친밀도는 과거 자료로만 보존한다. 병행 애니메이션 변경을 보존했다.

자동 검증: 프런트엔드 45개 파일 261개 테스트, TypeScript·Oxlint와 변경 UI 22개 파일 포맷 검사를 통과했다. Rust 라이브러리 471개 테스트가 통과했고 3개는 기본 실행에서 제외했다. 이 중 새 실제 모델 검사는 별도로 실행했다. 회귀는 소유권·지연 결과·실제 표시 영수증·망각과 시계 역행·원문 차단·이전 반복·내보내기 조합·참조 검증·크기 초과·transaction 실패의 원자적 롤백·스토리 0/2단계 왕복을 포함한다. 기본 대화 예산을 유지하고 사용자 식별 규칙에 최대 1,200 UTF-8 바이트를 추가한다. 최대 이름 길이의 실제 추가량은 968바이트다.

모델 의미 품질: 설치된 Qwen3.5-4B의 합성 사례 3개를 현재 프롬프트로 실행했다. 첫 시도는 동명 사람의 커피 취향을 혼동하고 경험에서 직업의 부정을 단정했다. `personContext`와 현재 사실 사용 여부, 근거가 없으면 긍정·부정 모두 추측하지 않는 규칙을 추가했다. 같은 3개 사례의 재검사에서는 이전 사람의 취향을 분리하고 직업을 모른다고 답했으며 비공개 스토리를 밝히지 않았다. 단일 모델·각 1회 샘플 결과이며 일반적 의미 품질 보장은 아니다. 사용자 DB는 읽지 않고 임시 DB와 기존 GGUF만 사용했으며 자체 추론 프로세스 종료를 확인했다.

실제 데스크톱 검증은 `space.starlight.comet.memory-qa`의 별도 합성 데이터로 진행했다. 최초 이름 등록 뒤 위젯 설정, 6개 탭, 52개 기억의 50/2페이지 조회, 개별 수정·전체 잊기, 이름을 민수→지연→민수로 변경하고 독립된 관계 ID를 저장하는 동작을 확인했다. 이름은 접미사·현재/이전 표시 없이 나타난다. 1120×720과 최소 960×640에서 탭·편집·페이지 이동을 확인했으며 내부 스크롤과 탭 복귀, 방향키 왕복 뒤 미저장 기억 초안도 유지됐다.

수정한 52개 기억·친밀도·2개 원문을 v4 파일로 내보내고 다시 설치했다. 수정한 녹차 기억이 새 캐릭터에 그대로 표시되고 사람·캐릭터·기억 ID는 새로 배정됐다. 먼저 설치한 캐릭터에서 전체 잊기를 한 52개는 삭제 상태를 유지하며 그 캐릭터의 원문 2개와 과거 친밀도는 남았다. 정상 종료·재시작 후에도 사용자 등록·위젯 설정 완료, 캐릭터 목록과 수정 기억이 유지되고 현재 친밀도는 20이었다. 읽기 전용 조회의 DB 무결성은 `ok`, 원본 팩 메타데이터에 중복 저장된 개인 자료는 0개였다.

최종 번들은 `src-tauri/target/debug/bundle/macos/Comet Memory QA.app`이며 실행 파일 SHA-256은 `71608812e68167cf074999aaf871dc1b3bf9013de04491fa4c671c2cc67a5a51`이다. 현재 소스의 프런트엔드 production build, strict Clippy(`--lib --tests -- -D warnings`), `codesign --verify --deep --strict`와 실제 재시작을 통과했다. 위키 타입 검사·정적 빌드와 diff 검사도 통과했다. 새 빌드 정상 실행 뒤 실행 중이 아닌 `/tmp/Comet-old-66817.app`·`/tmp/Comet-old-75704.app`을 휴지통으로 옮겼다. 병행 작업의 최신 Animation QA 번들은 유지했다. 사용자 설치본·데이터·설정·팩·모델·빌드 캐시는 보존했다. Windows 실제 실행·notarization·외부 계정은 이번 검증 범위가 아니다.

## 2026-09-24 캐릭터 스프라이트 애니메이션

[캐릭터 동작 계약](product/characters.md#상황별-스프라이트-재생)에 따라 모습·표정에서 PNG 시퀀스·격자 시트·APNG를 편집하고 평소·말하기·클릭에 연결한다. APNG의 합성과 프레임 정리를 반영해 정지 PNG 프레임으로 펼치며 지정한 1~30fps로 재생한다. 클릭은 한 번 재생으로 고정한다. 표정별 상속·별도 연결·명시적 끄기, 반복 간격의 정적 표정 복귀, 동작 줄이기와 중단 조건을 구현했다. 편집기와 본체는 같은 경과 시간 재생기를 사용한다.

자산은 캐릭터별 별도 표에 내용 해시로 저장하고 정의와 함께 transaction으로 추가·정리한다. 이미지 선택은 초안이며 저장·취소와 늦은 선택 결과 차단에 포함된다. snapshot에는 메타데이터만 보내고 PNG는 `sprite://`로 제공한다. 개인 데이터 없이 애니메이션을 포함한 팩은 v3, 애니메이션도 없는 팩은 v2로 내보내며 기존 v1/v2와 화자 참조 변환을 유지한다. 병행 기억 기능의 개인 데이터 선택 공유는 v4를 사용하고 같은 애니메이션 자산을 보존한다. 프레임별 alpha 외곽은 Rust에 캐시해 선택만 전환한다.

캐릭터별 기억·v4 팩 변경을 합친 통합 소스로 프런트엔드 45개 파일·261개 테스트와 Rust lib 471개 테스트를 통과했다. 프런트엔드 기본 병렬 실행은 빌드와 겹쳐 2개 테스트가 5초 제한을 넘겼고, 작업자 2개로 제한한 전체 재실행에서 모두 통과했다. Rust의 NLP 평가·benchmark와 별도 실제 모델 검사는 기본 실행에서 제외한 3개다. 최신 캐릭터 저장·팩 관련 52개 검사와 strict Clippy도 통과했다. 재생 시간·클릭 우선순위·말풍선 표시 판정·중단·무관한 snapshot 보존, 초안과 실패 원자성·v3 왕복·재오픈·제한값·APNG Source/Over와 None/Background/Previous 합성, 충돌 캐시의 세대·revision 거부를 회귀 검사한다. APNG의 선언 프레임 수보다 실제 프레임이 많은 파일이 조용히 잘리던 decoder 동작을 재현해 명시적 개수 검사와 회귀 테스트로 차단했다. TypeScript·Oxlint·strict Clippy(`--lib --tests -- -D warnings`)·diff 검사를 통과했다.

별도 `space.starlight.comet.animation-qa` 앱에서 직접 만든 PNG 시퀀스 2장·시트 4칸·APNG 3프레임을 가져오고 1/2fps 미리보기, 탭 왕복, 공통 저장, v3 내보내기·다시 설치를 실제 조작했다. 본체의 고정 크기 안에서 기본 APNG의 테두리·막대·채운 사각형, 클릭의 초록·보라 시퀀스, 등록 대사의 말하기 시트 전환을 확인했다. 실제 본체 WebView canvas의 픽셀 기록도 첫 두 클릭 프레임 약 1초·말하기 프레임 약 0.5초 간격을 보여 주었다. 복제한 미리보기 창이 아니라 실제 본체를 읽은 기록이며 성능 benchmark는 아니다. 말풍선 종료 뒤 기본 동작 복귀와 일시정지 때 정적 이미지 복귀를 관찰했다.

내보낸 파일은 v3와 고유 자산 6개를 포함하고 다시 설치한 캐릭터의 동작 정의도 동일했다. 정상 종료·재시작 후 캐릭터 정의 전체가 이전과 같고 QA DB 무결성은 `ok`였다. 일반 QA 앱에서도 다시 실행한 APNG와 더블클릭 입력·Escape 닫기를 확인했고, 정상 종료 후 재실행해 저장된 캐릭터 정의가 최초 저장값과 동일한 것을 확인했다.

장난감은 실제 QA 본체의 링 프레임 구멍 안에 공이 생성되도록 QA 전용 위치를 배치하고, 본체 Web Inspector에서 기존 위젯 실행 명령을 프레임 시작에 맞춰 호출했다. 임시 진단 로그의 6회 접촉이 현재 링 프레임의 캐시 포인터와 일치하며 구멍의 네 안쪽 벽 `x=388·452`, `y=336·400`과 안쪽 법선을 사용했다. 다음 막대·채움 프레임은 서로 다른 캐시를 선택했고 이전 링의 접촉이 이어지지 않았다. 채움 프레임과의 직접 접촉은 이 실험의 범위가 아니다. 임시 로그 코드는 최종 소스에서 제거하고 QA 위치도 복원했다. 오래된 캐시·프레임·숨김·창 재생성 결과 거절은 회귀 테스트로 확인한다.

애니메이션 검증 번들은 `src-tauri/target/debug/bundle/macos/Comet Animation QA.app`, identifier는 `space.starlight.comet.animation-qa`, 실행 파일 SHA-256은 `6ec6b4a7f648056a3dd38d27b99edd6ff3f31d765ef8d546f256a2a6f221716b`다. 진단 코드를 제거한 일반 빌드의 `codesign --verify --deep --strict`, 실행과 정상 재시작을 확인했다. 이전 `Comet Version Removal QA.app`과 임시 진단 앱은 프로세스 종료를 확인하고 휴지통으로 옮겼다. 같은 작업 트리에서 별도 검증 중인 `Comet Memory QA.app`은 유지했다. 사용자 설치본·데이터·설정·팩·모델·빌드 캐시는 보존했다.

Windows 실제 실행·notarization·외부 계정·모델 의미 품질은 애니메이션 검증 범위가 아니다. 기존 작업 트리의 말풍선·캐릭터 탭·저장 버전 제거 변경과 병행 캐릭터 기억 작업은 보존한다.

## 2026-09-23 캐릭터 저장 버전 제거

[캐릭터 저장 계약](product/characters.md)에 따라 편집기의 저장 버전 표시, 공유 미리보기의 캐릭터 버전, 정의의 자동 버전 증가와 대화 화자 버전 저장을 제거했다. 일반 저장·수정 취소·공유는 유지하고 동봉·예제 캐릭터 JSON에서도 정의 버전을 제외한다. 앱 업데이트 버전·팩의 `formatVersion`과 내부 revision·epoch 경계는 유지한다.

코드 검토에서 정의의 필수 `version`과 `deny_unknown_fields`, 메시지 표의 `version NOT NULL`이 기존 데이터 읽기·새 메시지 저장과 연결된 것을 확인했다. 이전 정의의 `version`만 호환 입력으로 소비하고 새 직렬화에서는 제외하며 다른 알 수 없는 필드는 계속 거절한다. 기존 `message_characters.version` 열은 초기화 transaction에서 존재할 때만 제거한다. 원문 대화·당시 화자 이름과 로컬 ID·기억·친밀도는 유지한다. 과거 검증 기록의 버전 관련 관찰은 당시 결과로 보존한다.

현재 소스로 프런트엔드 39개 파일·229개 테스트, Rust lib 430개 테스트를 통과했다. Rust의 NLP 평가·benchmark 2개는 기존 명시적 제외 상태다. 구형 v1/v2 팩과 설치 DB 읽기·편집·내보내기, 미등록 필드 거부, 메시지 표 migration 이후 두 차례 재오픈과 신규 대화 저장, 원문·기억·친밀도 보존을 회귀 검사한다. TypeScript·Oxlint·변경 파일 formatting·프런트엔드 production build·위키 타입 검사와 정적 build·diff 검사를 통과했다.

TypeScript·Oxlint·`cargo check --locked --all-targets`·프런트엔드 production build를 통과했다. 전체 Rust fmt는 기존 `lib.rs` 모듈 선언 순서 차이가 남아 있으며 변경한 Rust 파일 포맷은 통과했다.

macOS 검증은 별도 `space.starlight.comet.balloon-qa` 식별자와 합성 캐릭터팩으로 수행했다. 실제 설정에서 두 캐릭터에 28px·Apple SD Gothic Neo·파랑과 16px·Georgia·자주색을 각각 저장하고 이미지 선택 후 설정 보존, 미리보기, 정상 종료·재시작 뒤 두 설정의 독립적 유지를 확인했다. QA SQLite 무결성은 `ok`였다. 포커스를 가져오지 않는 실제 대사 창을 자동 조작 도구가 선택하지 못해, 임시 Tauri override에 동일한 Balloon과 실제 snapshot을 표시하는 네이티브 확인 창을 추가했다. 그 창에서 이름 머리글 없이 표시되는 대사, 서로 다른 크기·색, 긴 대사의 높이 제한과 밝은 반투명 이미지의 표시를 관찰했다. 이 관찰을 일반 말풍선의 이동·자동 소멸·스크롤 조작 검증으로 확대하지 않는다.

임시 확인 창을 뺀 일반 QA 앱을 다시 빌드·서명 검사·실행한 뒤, 실제 메뉴 말풍선의 밝은 스킨과 설정 재시작 보존을 재확인했다. 당시 번들은 `src-tauri/target/debug/bundle/macos/Comet Balloon QA.app`이며 실행 파일 SHA-256은 `38a943a022eacaf08960115c3e9b5d14dce02af79f7f84c92e52501165acd458`다. `codesign --verify --deep --strict`를 통과했고 저장소의 이전 0.5.0 release 앱 번들은 정상 실행 확인 후 휴지통으로 옮겼다. 최신 QA 번들·사용자 설치본·데이터·팩·모델·빌드 캐시는 보존했다. 사용자 설치본·DB 교체, Windows·notarization·외부 계정·모델 의미 품질 검증은 수행하지 않았다.

## 2026-09-22 캐릭터 지침과 관계

## 2026-09-22 Spotify 자동 실행과 페어링 유지

매번 코드를 입력해야 하는 불편을 해결해 달라는 사용자 요청으로 [음악 연결 계약](product/music.md)을 확장했다. Spotify 또는 Spicetify로 고정한 음악 위젯을 열면 꺼진 Spotify를 실행하고, 이미 실행 중인 앱은 다시 열지 않는다. Comet 시작 시에는 저장된 Spicetify listener만 복구한다. 자동 선택·정기 조회에서 앱을 실행하거나 재생 명령을 자동으로 보내지 않는다. 기존 0.2의 작은 본체·말풍선·선택적 LLM 경험은 그대로다.

최초 페어링 코드는 일회용으로 유지하고 별도 재연결 인증 정보를 OS keyring과 Spotify localStorage에 저장한다. DB에는 현재 허용한 페어링 ID만 남기며 제공자 변경·위젯 끄기·제거·명시적 해제는 이 권한을 먼저 폐기한다. 일반 앱 종료는 페어링을 보존한다. 양방향 HMAC 증명에 역할·모드·연결 ID·양쪽 난수를 묶어 자동 재연결 과정에서 secret을 전송하지 않는다. 연결별 요청을 폐기하고 새 연결에 재생 명령을 재전송하지 않는다. Spotify에서 오프라인으로 해제를 요청하면 다음 인증은 해제만 수행한다.

검증은 Spicetify 확장 60개, MusicTool UI 10개, macOS 실행 분기 5개, Rust 브리지 4개와 위젯 연결·설정·native 집중 테스트 23개를 통과했다. TypeScript·Oxlint·Rust Clippy도 통과했다. 독립 보안 검토에서 확인된 취약점은 없었으며, 가짜 서버 증명·nonce 재사용·인증 전 메시지·저장 실패·취소·이전 소켓·연결 해제 경계를 확인했다. Rust credential 테스트는 메모리 대역이며 실제 keyring 실패 상황을 재현한 결과는 아니다.

macOS 26.5.2 arm64 / Spotify 1.3.1.234 / Spicetify 2.45.1에서 새 앱을 빌드·실행하고 최초 한 번 페어링했다. Spotify 프로세스가 종료된 상태에서 음악 위젯을 열어 실제 Spotify 실행을 확인했고, 코드 입력·수동 새로고침 없이 곡 정보가 복구됐다. 이어 Comet을 완전히 종료했다가 같은 새 앱을 실행해 Spotify 확장의 자동 연결을 확인했다. 두 경우 모두 일시정지를 유지했다. Comet이 꺼진 상태에서 Spotify의 연결 해제를 누른 뒤 Comet을 실행하자 해제 대기가 완료됐고 자동 연결이 중단됐다. 사용을 계속할 수 있도록 새 페어링을 만들어 연결해 뒀다. 이 흐름은 실제 OS keyring 저장·읽기·삭제와 Spotify 저장소를 함께 사용했다.

현재 앱은 `src-tauri/target/release/bundle/macos/comet.app`, 설치물은 `src-tauri/target/release/bundle/dmg/comet_0.5.0_aarch64.dmg`다. 실행 파일 SHA-256은 `7e21f1aea0fffa38976457bf41ae3893c7d533e187b1ca555d5a44486faf88ca`이며 ad-hoc 서명 검사와 DMG 검사를 통과했다. 이전 동일 경로 빌드는 새 빌드로 교체했으며 저장소 안에 이전 앱·DMG를 추가로 남기지 않았다. 사용자 데이터·설정·팩·모델·빌드 캐시는 보존했다. 병행 캐릭터 변경과 모델 의미 품질·성능은 이 음악 검증 결과에 포함하지 않는다.

## 2026-09-22 Spotify와 Spicetify 실계정 검증

사용자 요청으로 보류했던 [Spicetify 연결](development/spicetify.md)의 실계정 검증을 재개했다. macOS 26.5.2 arm64, Spotify 1.3.1.234, Spicetify 2.45.1의 로그인된 Premium 계정에서 공식 CLI 설치·원본 백업·확장 적용과 로컬 코드 페어링을 진행했다.

실제 Spotify 시작 중 `Menu.Item`은 노출됐지만 React JSX 모듈이 준비되지 않아 메뉴 등록이 중단되는 오류를 재현했다. 확장이 메뉴에 필요한 모듈을 기다리도록 수정했다. 재생 명령의 내부 Promise 반환과 Player 상태 갱신 사이에 차이가 있어 Comet에 이전 재생 상태가 남는 오류도 재현했다. 이제 변경을 관측한 뒤 응답하며, 그 대기는 기존 취소·만료·연결 세대 검사를 따른다. 탐색은 정수 밀리초를 전달하고 새 상태 이벤트의 위치를 확인한다. 이전/다음은 곡 전환이나 실제 재시작을 확인하며 관계없는 갱신·중간 빈 상태를 성공으로 처리하지 않는다. 현재 wrapper의 재생 제한과 앨범 트랙·디스크 번호도 반영했다.

## 2026-09-22 캘린더별 색상과 주간·월간 일정 표시

캘린더에 월 보기를 기본으로 적용했다. Google·Apple은 연결 안의 개별 캘린더, ICS는 구독별로 8가지 색을 고르고 플래너·통합 설정에서 같은 설정을 사용한다. 종일 일정은 날짜 칸을 가로지르는 색상 막대로, 시간 일정은 월 보기의 색상 표시·시각과 주 보기의 겹침 그룹별 블록으로 표현한다. 날짜와 개별 일정을 따로 선택하고 월 칸을 넘는 시간 일정은 선택한 날짜 목록에서 확인한다. 외부 서비스의 일정·색상은 수정하지 않는다.

`set-calendar-color`는 기존 위젯 revision·중복 요청 트랜잭션으로 저장한다. 캘린더 ID 범위와 6자리 HEX를 검증하고, 구형 연결은 선택 목록이 없을 때만 같은 연결의 캐시 source ID를 사용한다. 갱신·재연결·알림 저장은 색상을 보존하며 연결 해제는 해당 연결의 색상만 제거한다. Apple·Google의 기존 조회 응답에서 캘린더 이름을 수집하고, 이름을 아직 조회하지 못한 경우 연결 이름으로 표시한다.

공·종이비행기·비눗방울이 캐릭터 본체에도 충돌한다. 기존 외부 창 목록은 Comet 자신의 창을 제외했으므로 본체가 충돌 대상에 없었다. 본체 WebView가 표시 이미지의 alpha를 읽고, Rust가 별도 작업에서 투명 여백·구멍을 보존한 외곽 선분을 만들고 캐시한다. 물리 tick에서는 물체 근처의 선분만 조회한다. 이미지 없는 본체는 버튼 영역을 사용한다. 이미지 로드·표정·크기 변경 시 외곽을 갱신하고, 이동은 네이티브 창 위치에 맞춰 변환한다. 숨김·삭제와 엇갈린 show·이미지·위치 갱신은 세대 검사로 배제한다. [캐릭터](product/characters.md)와 [장난감](product/toys.md#바탕화면-물리-계약) 사양에 반영했으며 기존 0.2 대화·저장 계약은 유지한다.

현재 소스의 Rust 라이브러리 291개와 프런트엔드 22개 파일 130개 테스트, TypeScript·oxlint, Vite 빌드와 strict Clippy가 통과했다. alpha 외곽·투명 구멍·음수 원점·배율·늦은 갱신 배제, 공·비행기 반발·비눗방울 터짐·캐릭터 위 정지와 지지 제거를 검사했다.

macOS의 별도 Tauri 검증 앱에서 현재 프런트 빌드와 실제 WKWebView를 실행했다. `sprite://`의 앱 origin CORS 응답을 거쳐 128×128 표시 이미지의 불투명 표본 4,096개를 읽었고, 투명 여백과 가운데 구멍은 제외됐다. 표정 변경 뒤 1,024개 표본으로 바뀌었으며 숨김 뒤 충돌 보고가 비워졌다. 실제 Rust host에 연결했을 때 구멍을 포함한 8개 경계가 새 표정의 4개 경계로 바뀌었다. Retina 배율 2에서 physical 좌표 (80,80)을 (40,40)으로 변환했고, 실제 Moved 이벤트 뒤 (400,240)은 (200,120)으로 갱신됐다. 숨김 뒤 더 높은 revision의 늦은 mask에도 collider는 0개였고 네이티브 창도 숨겨진 상태였다. 원래 창의 Destroyed 이벤트 뒤 같은 label로 새 창을 만든 경우에도 이전 창의 명령은 거절됐고 새 창의 collider는 0개로 유지됐다. 사용자 DB와 설치 앱은 변경하지 않았다.

현재 물리·native panel 소스와 8개의 합성 512×512 alpha 외곽(타원·내부 구멍)을 사용한 별도 10초 계측에서 물리 갱신 632회의 95백분위는 17.3ms, 최대는 22.9ms였으며 25ms 초과는 없었다. 물리 step 최대는 2.0ms, 인접 외곽 조회 최대는 1.2ms였다. 이 계측은 캐시된 합성 외곽의 비용을 측정하며 실제 본체의 위치 조회·mask 전달, 모든 이미지 패턴이나 디스플레이 FPS를 보장하지 않는다. 최초 외곽 생성 비용은 이 계측에서 제외했고, 제품에서는 화면 스레드 밖으로 옮겼다.

## 2026-09-20 바탕화면 장난감 끊김 수정

공·종이비행기·비눗방울이 공유하는 물리 루프에서 150ms마다 창 목록을 동기 조회하던 경로를 수정했다. macOS 실행 스택에서 `CGWindowListCopyWindowInfo`의 WindowServer transaction 대기와 AppKit 화면 반영의 connection lock 대기가 겹쳤다. 조회를 worker로 옮기기만 하면 물리는 계속되지만 실제 화면 반영은 여전히 멈췄다. 최종 구현은 물리 루프가 조회를 기다리지 않게 하고, macOS 조회는 AppKit과 같은 main thread에서 순서대로 실행한다. 꺼내기·자동 행동의 조회도 이 경로를 사용하며 action·DB 잠금 밖에서 완료한다.

## 2026-09-20 대화팩과 별꼬리 기본 캐릭터

`.talk` 대본을 설치·제거할 수 있는 [대화팩](product/talk.md#대화팩과-나만의-대본)으로 나눴다. 앱 데이터의 `talk/index.talk`는 사용자 진입 파일이고 `talk/packs/<팩 ID>/`가 팩 하나다. 동봉 팩은 새 설치에 함께 들어가는 `byulkkori`(별꼬리 기본 대화, 28개 파일·111개 장면·5변주)와 선택 설치하는 `nadir-and-star-tail`(기존 나디르·별꼬리 전용 26개 파일·144개 장면)이다. 설정 → 대화팩에서 설치·제거하며 제거한 팩은 재시작으로 되살리지 않는다. 팩 장면 key에는 팩 ID가 붙어 두 팩이 같은 장면 ID를 써도 충돌하지 않는다.

기본 대화팩은 공통 범위의 새 header `speakers: random`과 변수 `character.count`로 1~8명을 다룬다. 혼자면 A만 쓰는 장면이 열리고, 8명이면 둘·셋·넷 장면이 seed에 따라 다른 친구 조합으로 열리되 여덟 명이 한 번에 말하는 장면은 없다. 교감처럼 대상 자리가 정해진 사건은 자리 모드를 유지한다. 예전 talk 호스트의 "두 번째 자리 대사가 있으면 혼자일 때 건너뛰기" 특례는 평가기의 화자 검사로 대체했다. 위젯 사건 fallback은 활성 인원이 1명이어도 오류 없이 동작하도록 나디르·별꼬리 검사를 자리 무관으로 바꿨다.

새 설치의 기본 캐릭터는 별꼬리 이미지팩 한 명이며 일반 캐릭터팩으로 가져오므로 제거·복제·편집 규칙이 같다. 같은 날 앞선 A/B 기본 결정은 이미 A/B를 가진 설치를 보존하는 범위로만 남는다. 0.5.0 설치의 `talk/` 폴더에 그대로 남아 있던 나디르 대본은 모든 파일이 동봉 원본과 같을 때만 `packs/nadir-and-star-tail/`로 옮기고 사용자 진입 파일을 비운다. 한 파일이라도 고쳤으면 그대로 두고 기본 대화팩만 추가한다. 이 과정에서 대화 기록·기억·친밀도·개인 단어장은 바꾸지 않으며, 옮긴 나디르 장면의 `talk_history` key는 팩 ID가 붙은 새 key로 바뀌어 cooldown이 한 번 초기화된다.

현재 작업 트리에서 Rust 라이브러리 308개, 대본 CLI 2개, 프런트엔드 23개 파일 133개 테스트와 TypeScript·oxlint, `cargo clippy --lib --tests --example talk -- -D warnings`, `talk check talk`(묶음 55개 파일)를 통과했다. 새 회귀는 두 팩의 fixture 커버리지·5변주·cooldown, 혼자·8명 무작위 화자, 같은 seed 재검증, 팩 key 분리, 잘못된 팩 ID 무시, 설치·제거·재시작 보존, 0.5.0 대본 이동과 수정된 대본 보존, 감시기의 팩 변화 반영, 새 설치 별꼬리 단독 시작과 제거, 설정 화면의 대화팩 목록·설치·제거·오류 표시를 다룬다. 기존 회귀는 테스트 전용 A/B 초기화(`initialize_for_tests`)로 기존 전제를 유지한다. 실제 데스크톱에서의 팩 설치 뒤 재로딩, 이미지 별꼬리 첫 실행, Windows와 모델 의미 품질은 이번 변경에서 검증하지 않았다.

미커밋 상태의 나디르·별꼬리·선택지 스토리·암호화 대본 재생·이름과 아이콘·구조 리팩토링을 원격의 다중 캐릭터·표정 이미지·데스크톱 장난감·모델 목록·updater·Changesets와 통합했다. 앱과 패키지 이름은 `comet`, 원격에서 확정된 `0.4.1` 버전을 유지하며 다음 minor 변경 노트를 추가했다. 아래의 이전 네이티브 관찰은 각 변경 당시 결과로 보존한다.

이번 작업에서 Rust 라이브러리 253개와 대본 CLI 2개, 프런트엔드 19개 파일 115개 테스트가 통과했다. 전체 Rust target 컴파일·strict Clippy, TypeScript·oxlint·Vite 빌드와 위키 타입 검사·빌드도 통과했다. source pair·cast와 스토리가 세 번째 자리의 캐릭터 및 자리 변경 후 같은 정체성을 따르는 회귀를 포함한다.

Windows CI에서 Git의 CRLF 변환이 암호화 파일 헤더를 바꾸는 문제가 확인되어 `.gitattributes`에서 `.talk`·`.enc`의 원본 바이트를 보존한다. `core.autocrlf=true`에서도 동봉 파일 28개의 checkout 바이트가 저장소 원본과 동일한 것을 확인했다.

이번 통합에서는 실제 데스크톱 조작·Windows 실기·LLM 의미 품질을 다시 검증하지 않았다. 이전 버전의 테스트 수·패키징·실행 결과를 이번 결과로 간주하지 않는다.

## 0.4 통합 작업본의 기존 검증

2026-09-19 기준 소스 구현과 릴리스 인수는 구분한다. 1~8명 ID 기반 대화, JSON v2 패키지와 v1 호환, 기본 캐릭터 동봉 콘텐츠, 출처 정보 영속 편집, 독립 데스크톱 물체, 장난 FSM, 트레이 직접 호출, 숨김 상태 보존, 서명된 앱 업데이트 경로를 통합했다. 기존 생성 대사의 30분 회상 변경도 원문 기록과 분리해 보존한다. 장난 설정 해제·전체 화면 진입·정리 시 자동 놀이의 대기·재생 중 반응을 취소하며 수동 놀이·타이머·저장된 일지는 유지한다. 자동 말풍선과 표정은 macOS `orderFront`, Windows `SW_SHOWNOACTIVATE`로 표시하고 명시적인 입력창 호출만 포커스를 요청한다.

업데이트 서명 공개키와 CI secret을 설정했으며 두 OS 산출물을 준비하는 workflow를 추가했다. 2026-09-19에 최초 공개 릴리스 v0.5.0을 게시했다. 공식 GitHub 채널을 통한 이전 버전에서 새 버전으로의 설치는 아직 인수하지 않았다. Apple notarization과 Windows Authenticode 서명은 제공하지 않으며 updater 서명과 구별한다.

자동 검사는 Rust 라이브러리 214개와 프론트엔드 16개 파일 103개 테스트, 예제 컴파일, Clippy(`--lib --bins -- -D warnings`), doc-test, TypeScript·정적 검사·프론트엔드 빌드, 위키 타입 검사·빌드를 통과했다.

[GitHub Actions](https://github.com/fleetia/comet/actions/runs/35437429763)에서 macOS arm64·Windows x64의 테스트, native bundle 빌드와 artifact 업로드를 확인했다. 이 결과는 Windows 실기 실행이나 설치 검증을 대신하지 않는다.

설치 파일 workflow 후속 변경은 macOS `.dmg`를 기존 앱 ZIP·Windows NSIS `.exe`와 함께 Actions artifact에 포함한다. [후속 Actions 실행](https://github.com/fleetia/comet/actions/runs/35439148164)에서 두 OS 검사·빌드·업로드가 성공했다. macOS는 앱 서명과 DMG 무결성 검사를 통과했으며, 내려받은 DMG에 0.4.0 arm64 앱과 Applications 바로가기가 포함된 것을 확인했다. Windows 설치 파일 생성은 실기 설치·실행 검증과 구별한다.

태그 기반 Release에도 DMG를 올리고 파일 누락과 무결성 오류를 검사한다. Release 본문과 Actions 실행 요약에는 실제 DMG·EXE 다운로드 링크, 설치 안내와 변경 노트를 함께 제공한다. [v0.5.0 빌드](https://github.com/fleetia/comet/actions/runs/35445568168)는 두 OS 검사·패키징·업로드와 macOS 서명·DMG 무결성 검사를 통과했으나 draft 임시 URL을 거부해 publish job이 실패했다. 해당 draft의 저장소·태그·URL을 대조하는 수정 스크립트로 실제 업로드 파일을 검증하고 manifest와 본문을 생성한 뒤 [v0.5.0](https://github.com/fleetia/comet/releases/tag/v0.5.0)을 수동 공개했다. 두 설치파일의 비로그인 HTTP 200과 공개 manifest의 정식 태그 주소를 확인했다. 배포 자동화 테스트 14개를 통과했으며, 수정 workflow 자체의 원격 실행 성공이나 실제 설치·업데이트 인수로 해석하지 않는다.

Changesets 후속 구현은 변경셋의 main 병합 후 버전 PR을 만들고, 버전 PR 병합 후 서명된 데스크톱 Release workflow를 직접 호출한다. package.json·Tauri·Cargo manifest·lock의 버전을 동기화하고 해당 CHANGELOG 항목을 Release와 앱 updater의 업데이트 노트로 사용한다. 초기 상태·이미 공개한 버전은 발행을 건너뛰며 기존 태그를 다른 커밋으로 옮기지 않는다. 모든 updater 플랫폼 URL을 같은 Release의 공개 다운로드 주소로 정규화한 manifest를 업로드한 뒤 공개한다. 동기화·노트·태그·manifest 검사는 통과했으며 실제 설치·업데이트 인수는 별도로 남는다.

CI 최적화는 branch push·PR의 중복 실행과 문서 변경의 native 빌드를 줄이고, 공통 프론트엔드 검사를 Ubuntu로 옮긴다. main에서 저장한 Rust 의존성·고정 sidecar 캐시를 Verify와 Release가 공유한다. PR에서는 두 OS의 Rust 테스트까지 수행하고, main·수동 실행·Release에서 패키징과 서명/무결성 검사도 수행한다. 실행 조건과 캐시 무효화 기준은 [릴리스 문서](development/releases.md#ci-실행과-캐시)를 따른다. 설정 변경만으로 빌드 시간 단축률이나 Release 설치 인수를 선언하지 않는다.

macOS 별도 QA 앱을 빌드하고 `codesign --verify --deep --strict`를 통과했다. 캐릭터를 숨긴 상태에서 메모를 열고 저장했으며 재시작 후 숨김 값과 설치한 위젯 여섯 개의 보존을 DB에서 확인했다. 최신 native 공 꺼내기는 위젯 관리 화면의 포커스를 바꾸지 않았고, actor ID를 포함한 정지 결과 한 건을 기록했다. 설정에서 장난감 정리와 업데이트 정보 없음 상태, 입력창 포커스와 메뉴 복귀도 확인했다. 별꼬리 v2 파일의 미리보기·설치 후 활성 A/B가 유지됐으며 관리 화면에서 빈 제작자·출처 URL을 저장하고 DB의 빈 문자열을 확인했다. 외부 앱의 입력 포커스, 클릭 통과·드래그·창 충돌, 다중 모니터, 숨김 재시작 후 트레이 직접 호출, Windows 실기와 공식 배포 채널을 통한 두 OS 업데이트 검증은 아직 인수하지 않았다. 전체 완료는 이 실기 조건을 충족한 뒤 판단한다.

별도 macOS 업데이트 QA 앱은 전용 서명 키와 loopback 서버로 0.4.0→0.4.1 설치를 확인했다. 연결 실패·다운로드 404·변조된 파일의 서명 실패에서 기존 0.4.0 실행 파일의 hash가 유지됐다. 정상 파일은 설치 후 이전 프로세스가 종료되고 새 버전에서 업데이트 확인이 다시 실행됐으며, 재실행 화면의 최신 버전 표시와 설치된 앱의 서명을 확인했다. 설치 파일까지 갖춘 최종 fixture에서 캐릭터 3개·팩 1개·표정 이미지 9개·단어장 2개·위젯 6개·메시지 29개·놀이 결과 11개와 검증용 기억·ID별 친밀도 각 1개의 영속 내용을 비교했다. 공·비행기·펫은 사양대로 정지 시각과 revision만 갱신됐다. 위젯 설치 파일의 hash와 여섯 위젯의 활성 상태도 유지됐고, 업데이트 후 실제 메모 창에서 기존 내용을 확인했다.

추가로 QA 앱에서 기존 Qwen3.5-4B 파일을 직접 지정해 앱 소유 `llama-server`를 실행했다. 부모·자식 PID가 살아 있는 상태에서 설치를 시작한 뒤, 자식 추론 프로세스가 먼저 종료되고 이전 앱이 종료되는 순서를 관찰했다. 새 PID로 재시작된 0.4.1 창과 설치 서명도 확인했다. 이 검증은 macOS의 해당 로컬 모델·QA endpoint에 한정되며 공식 GitHub 배포 채널과 Windows 설치 검증은 별도로 남는다.

같은 QA 앱에서 1명 활성 구성의 독백 메뉴와 개인 입력 대상, 8명 활성 구성과 9번째 활성화 차단을 확인했다. 8번째 캐릭터의 실제 얼굴에서 연 입력창은 해당 캐릭터 ID를 따르고 `모두에게` 선택도 동작했다. 최종 소스로 빌드한 앱에서 전체 선택에 맞춰 입력란의 접근성 이름이 바뀌는 것도 확인했다. 이 관찰은 관리 UI와 개별 창·입력 대상 연결에 한정되며 여덟 창을 동시에 확인하거나 LLM 대화를 생성한 결과는 아니다.

별도 대화 QA 앱에서는 기존 Qwen3.5-4B 파일로 8명·2명·1명에게 실제 입력을 보냈다. 각 구성에서 활성 캐릭터 ID마다 한 개씩, 각각 8개·2개·1개의 응답이 `complete`로 기록됐으며 실패 행이나 중복 응답은 없었다. 입력·답변 준비 표시와 완료 후 얼굴 창으로 복귀하는 흐름을 관찰하고 QA 앱과 소유 모델 프로세스를 종료했다. 응답에 반복 경향과 요청보다 긴 두 문장이 나타나, 이 결과를 모델의 의미 품질이나 엄격한 길이 준수의 합격으로 보지는 않는다.

Figma에는 기존 Lagrange 프레임과 글꼴을 유지해 [장난 설정](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=142-578)의 네 장난감 Checkbox·정리 버튼, [업데이트](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=142-642)의 확인·설치 버튼, [1~8명 대화](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=142-765)의 Select와 순차 생성·질문 대기 안내, [출처 저장](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=142-774)의 빈 원작자·출처 URL TextField와 저장 버튼을 반영하고 시각 검증했다. 기존 컴포넌트의 정적 상태를 반영한 범위이며 전체 앱 화면 복제나 작동하는 프로토타입을 뜻하지 않는다.

## 2026-09-19 위젯 공통 창 배치

개별 도구 22종과 낱장 메모는 `WidgetFrame`의 제목·× 한 줄 고정 헤더와 스크롤 본문, 선택적인 하단 고정 조작 영역을 공유한다. 제목 위의 분류 표기와 개별 창의 위젯 관리 버튼은 제거한다. 메모 생성, 바탕화면 장난감 꺼내기·정리와 수집함 전체 정리는 오른쪽 아래에 고정하고 하단 테두리·박스를 두지 않는다. 낱장은 새 메모·글자 크기 조작과 저장 상태를 하단에 둔다. 타이머·폼 저장·조회 결과의 새로고침 등 내용에 붙는 조작은 본문에 유지한다. 본체 메뉴·트레이의 위젯 관리와 헤더 없는 바탕화면 물체는 유지한다. 제품 계약은 [개별 도구 배치](widgets/installation.md#관리-화면과-개별-도구)와 [창 이동과 닫기](product/desktop.md#창-이동과-닫기)를 따른다.

메모 목록의 생성·열기·넣기·삭제는 같은 명령 잠금을 사용하고, 낱장은 기존 저장 성공 후 생성·닫기 순서를 유지한다. 이번 변경에서는 Figma를 수정하지 않았다. 실제 데스크톱 드래그·창 크기 조절·OS 닫기와 Windows 실행은 별도 인수 대상이며, 이전 메모 QA 결과를 이번 창 배치의 실측으로 재사용하지 않는다.

하단 조작 영역으로 옮기기 전, 컴포넌트 폴더 이동을 반영한 공통 헤더 작업본에서 `pnpm check`, `pnpm build`, 위젯·WindowHeader 관련 8개 파일 58개 테스트를 통과했다. 당시 브라우저에서는 22개 도구를 296×360으로 확인해 분류·관리 버튼 제거와 가로 넘침 없음을 확인했다. 할 일 본문을 스크롤해도 헤더의 상단 좌표는 0을 유지했다. 낱장 메모는 최소 크기 260×220에서 우측 버튼이 창 안에 남고, 40줄 본문 스크롤 중에도 헤더가 고정됐다. 브라우저 예시 데이터 관찰이며 네이티브 창 이동이나 저장 검증은 아니다. 위키 타입 검사와 빌드도 통과했다. 이 기록은 하단 고정 조작을 적용한 이번 배치의 검증 결과가 아니다.

하단 고정 조작을 적용한 작업본에서 `pnpm check`, `pnpm build`, 위젯·WindowHeader 관련 8개 파일 59개 테스트를 통과했다. 메모·장난감·수집함의 하단 조작과 본문 조작이 같은 명령 잠금을 유지하는지 검사했다. 브라우저 예시 데이터로 22개 도구를 최소 크기 296×320에서 확인했고, 가로 넘침과 문서 전체 스크롤 없이 제목·×가 한 줄에 남았다. 수집함 본문을 111px 스크롤해도 헤더 상단 0과 하단 조작 상단 268px가 유지됐다. 낱장은 260×220에서 모든 하단 버튼이 보였으며, 40줄 본문을 440px 스크롤해도 헤더와 하단 조작이 고정됐다. 위키 타입 검사·빌드도 통과했다. 이 확인은 브라우저 배치와 코드 동작에 한정하며 실제 데스크톱 창 이동·저장은 이번 작업에서 다시 검증하지 않았다.

## 낱장 메모 검증

2026-09-19 메모 변경은 목록과 메모별 낱장 편집 창을 분리한다. 제목 입력 없이 빈 메모를 만들고, 본문·글자 크기를 자동 저장하며, 꺼내 둔 낱장은 설치·활성 상태를 확인한 뒤 재시작 시 다시 연다. 기존 본문·공백·줄바꿈·제목 메타데이터를 보존한다. 목록 닫기와 낱장 넣기·삭제, 위젯 끄기·제거의 범위는 [낱장 메모 계약](product/planning.md#낱장-메모)을 따른다.

이번 변경에서 `pnpm check`, 관련 프런트엔드 5개 파일 34개 테스트, Rust 메모 5개 테스트와 `cargo clippy --lib --bins -- -D warnings`를 통과했다. 자동 저장 중 추가 입력, 실패 초안 보존, 저장 후 닫기, 끄기·제거 전 저장 요청·결과·편집 잠금 해제를 자동 검사했다. 호스트가 요청 ID·창 이름을 대조하고 모든 저장 성공을 기다리는 경로는 소스와 단위 테스트로 확인했으며 실제 데스크톱의 끄기·제거 조작은 아직 검증하지 않았다.

별도 macOS 앱 `Comet Memo QA`를 식별자 `space.starlight.comet.memo-qa-20260919`로 빌드했다. 실제 화면에서 빈 낱장 생성, 낱장의 **+**로 다른 빈 낱장 생성, 앞뒤 공백·줄바꿈을 포함한 첫 메모 편집과 글자 크기 16→14→12px 변경을 확인했다. 두 번째 낱장을 넣어도 첫 번째는 열려 있었고 목록은 각각 **넣기**와 **꺼내기**를 표시했다. QA SQLite를 읽기 전용으로 조회해 본문과 글자 크기 12px, 각 메모의 `isOpen` 저장값을 확인했다.

실제 앱 재시작에 따른 창 복원, 위젯 끄기·제거 전 저장 확인, 창 드래그·크기 조절, OS 닫기 요청과 Windows 실행은 이번 데스크톱 관찰에 포함하지 않았다. 아래 과거 위젯·공통 창 조작·패키징 결과를 이번 메모 변경의 검증으로 재사용하지 않는다. 모델 의미 품질은 이 로컬 메모 기능의 검증 범위가 아니다.

후속 검토에서 Tauri의 기본 `Any` listener가 다른 창을 대상으로 보낸 이벤트도 받는 것을 확인했다. 메모 닫기·저장 요청·잠금 해제 listener에 해당 창 target을 명시하고 관련 프런트엔드 34개 테스트를 다시 통과했다. 이 후속 수정은 위 macOS 조작 이후에 적용했으며, 여러 창의 이벤트 분리와 끄기·제거는 최종 빌드에서 다시 조작하지 않았다.

Figma의 [메모 프레임](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=167-671)을 브라우저에서 만들고 자식 프레임의 글꼴을 앱의 대체 글꼴에 맞췄다. MCP 호출 한도로 라이브러리 인스턴스·토큰 연결은 완료하지 못했으며 부분 반영으로 남긴다.

Node.js 24의 `pnpm docs:check`는 통과했다. `pnpm docs:build`는 기존 `docs/index.md`와 이 상태표에서 연결하는 `product/desktop#제품-이름과-아이콘` 앵커 누락 2건으로 실패했다. 메모 변경 범위에서 해당 앵커를 수정하거나 빌드 오류를 무시하지 않았다.

### 격리된 macOS 앱 검증

현재 작업 트리에서 프런트엔드 전체 Vitest 21개 파일 123개 테스트, TypeScript, oxlint, Vite production build, 위키 typecheck·Docusaurus production build와 `git diff --check`가 통과했다. Rust `cargo check --locked --all-targets`, lib 테스트 264개, `cargo clippy --locked --all-targets -- -D warnings`도 통과했다. 브라우저에서는 기존 Vite 미리보기에서 기념일 설정의 표시 설정 펼침, 3×3 배치 선택, 별도 표시 화면의 D-day 렌더링과 저장된 위치의 정렬을 확인했으며 저장·파일 선택은 데스크톱 전용 경로라 실제 브라우저에서 실행하지 않았다.

실제 macOS/Windows 창의 생성·항상 위 표시·배경 파일 선택, 다중 모니터 위치와 장시간 자원 사용은 아직 이 절의 확인 범위가 아니다. Figma Playground의 이번 표시 창 상태는 Figma MCP 호출 한도로 동기화하지 못했으며, 코드와 기존 Lagrange 토큰을 기준으로 구현했다.

## 공통 창 조작 검증

2026-09-16 공통 창 조작 변경은 TypeScript·정적 검사·Vite 빌드와 `cargo check`를 통과했다. 마지막 관련 회귀 검증은 5개 파일 39개 테스트를 통과했으며 제목 드래그와 버튼 분리, 로딩·오류 상태의 닫기, 본체 숨기기와 위젯 닫기 명령을 확인했다. Figma의 기존 설정 화면 헤더에 내부 ×를 반영했다.

별도 프로필 `space.starlight.comet.window-qa`의 macOS 테스트 앱을 빌드하고 `codesign --verify --deep --strict`를 통과했다. 설정·캐릭터 관리·위젯 관리·메모 위젯의 네이티브 제목 표시줄 제거와 내부 × 닫기, 본체 ×의 숨기기와 기존 말풍선 닫기를 실제 앱에서 확인했다. 최신 빌드의 메모 창에서 제목 드래그를 실행하고 더블클릭 후에도 360×480 크기가 유지되는 것을 확인했다. 위젯을 닫고 관리 화면으로 돌아왔을 때 설치·사용 상태가 유지됐다. 이 확인은 별도 테스트 앱의 결과이며 기존 실행 앱 교체, Windows·다중 모니터 검증이나 모델 의미 품질 검증을 포함하지 않는다.

공통 헤더의 후속 변경은 드래그 범위를 창 `(0, 0)`부터 보이는 헤더 하단까지 확장했다. 원점·바깥 여백, 본문·스크롤바 경계, 입력과 열린 대화상자 제외를 포함한 관련 4개 파일 31개 테스트와 TypeScript·정적 검사·Vite 빌드를 통과했다. 별도 `space.starlight.comet.drag-qa` macOS 앱을 빌드·서명 검증한 뒤 위젯 관리의 왼쪽 위 여백 `(12, 12)`에서 드래그를 실행하고 본문 탭 전환과 X 닫기가 유지되는 것을 확인했다. 창 이동 좌표는 별도 계측하지 않았으며 기존 실행 앱은 교체하지 않았다.

확장한 여백에도 드래그와 같은 판정으로 `grab` 커서를 적용했다. 조작 요소·본문으로 이동하거나 스크롤·초점 이동·창 이탈이 발생하면 임시 커서 스타일을 해제한다. 이 커서 변경은 관련 2개 파일 10개 테스트와 TypeScript·정적 검사·Vite 빌드를 통과했다. Figma의 공통 헤더 조작 명세에도 반영했으며, 이번 커서 변경의 네이티브 화면 표시는 별도로 검증하지 않았다.

## 아직 구분해야 할 검증

- 변경별 자동 테스트·정적 검사·패키징 결과는 이 상태표의 해당 절과 연결된 검증 기록에서 확인한다. [위젯 검증 기록](VALIDATION-WIDGETS.md)은 해당 위젯 변경 시점의 결과다.
- macOS 네이티브 실행 결과는 해당 기록의 관찰 칸에 실제 수행한 범위만 적는다.
- Google 실제 계정 OAuth 동의·token 갱신과 Windows 네이티브 설치·실행은 미검증이다.
- 장시간 CPU·메모리·배터리·다중 모니터·접근성 전수 검증과 모델 대사의 의미 품질은 이번 자동 테스트의 증명 범위가 아니다.
- RSS, Todoist·TickTick 원본 대체와 Google Calendar 쓰기는 구현 범위에서 제외한다. Apple EventKit 읽기 연결은 2026-09-20 플래너 R2에 추가했다.

## 나디르·별꼬리 패키지와 선택지 스토리

2026-09-19 소스 변경은 기존 factory 대사를 나디르·별꼬리로 교체하고, 행동별 변주·위젯 없는 시간/날씨 fallback·친밀도 공개 단계·시간당 선택지 스토리·암호화 대본 재생을 추가했다. 이전 통합 소스에는 암호화 대본 editor가 포함됐지만 현재 앱에서는 제거했다. [캐릭터팩](product/characters.md#나디르별꼬리-추가팩), [스토리 조건](product/conversation.md#나디르-선택지-스토리), [암호화·별도 editor 경계](product/talk.md#암호화-저장과-별도-talk-editor-경계)가 현재 계약이다.

사용자 대화 기록·기억·관계·수정한 정의와 대본은 삭제하지 않는다. 위젯 부재·미완료·스토리 닫기·미루기는 감점하지 않는다. 호감도 변동은 선택한 결과에만 적용한다. 일반 대화의 일일 친밀도 한도와 스토리의 선택 보상은 별도로 계산한다.

최종 소스에서 Rust 전체 218개 테스트, 프론트엔드 87개와 대본 CLI 2개 테스트, TypeScript·oxlint·Vite 빌드, `cargo clippy --lib --tests -- -D warnings`, Docusaurus 빌드를 통과했다. `.talk` 144개 장면의 조건별 5변주와 180개 고정 입력, source identity 자리 교환, 공개 단계·중복 보상·취소·절전 제외 업타임, 암호화 손상·revision 충돌·migration을 검증했다. smoke 예제는 컴파일만 했으며 모델 다운로드나 실행은 하지 않았다. 예제의 기존 unused/dead-code 경고가 있어 all-targets의 warnings-as-errors 통과를 뜻하지 않는다.

별도 `space.starlight.comet-nadir-qa` macOS 앱을 패키징하고 서명을 검증했다. 위젯 없이 시작하는 나디르·별꼬리, 캐릭터 관리의 기본 정의, (당시 존재하던) 대본 editor의 실제 복호화·문법 오류와 초안 보존·다시 불러오기·성공 저장, 선택지 스토리 파일 열기를 조작했다. 저장 후 앱 데이터의 `.talk` 26개와 story 파일이 암호화 envelope인 것도 확인했다. 이 editor 조작·저장 결과는 현재 앱의 검증이 아니다. 실제 1시간 대기 후 선택지 출현, Windows 실행, LLM 의미 품질은 미검증이다. 기존 사용자 앱은 교체하지 않았다.

Figma의 [선택지 상태 설계](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=139-576)와 후속 별도 talk editor를 위한 [대본 editor frame](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=139-592)을 갱신했다. MCP 호출 한도 이후 브라우저에서 이어 작업했으며 해당 frame은 현재 Comet 앱 화면이 아니다.

나디르·별꼬리의 표정 후속 교정은 설명형 문장 대신 기존 A/B의 문자 이모티콘 6종을 사용한다. 이미 설치된 정의도 이전 기본 표정 전체와 일치할 때만 교체하며, 직접 수정한 표정과 이름·대사·관계는 보존한다. 캐릭터 관련 Rust 19개·화면 관련 21개 테스트와 TypeScript·oxlint를 통과했다.
