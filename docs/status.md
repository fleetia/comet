# 구현 상태와 남은 검증

공식 위젯 22개와 선택 설치·추가·중지·제거, `.talk` 파일 대본을 구현했고, 2026-09-19에는 나디르·별꼬리와 선택지 스토리·암호화 대본 에디터를 추가했다. 소스 구현, 자동 테스트, 실제 데스크톱 동작, 외부 계정 인증과 모델 의미 품질을 각각 구분한다. 위젯 변경의 실행 근거는 [위젯 검증 기록](VALIDATION-WIDGETS.md), 별도로 진행한 보조 화면 UI 정리의 범위는 아래에 기록한다.

기존 작은 A/B·내장 인사·단어장·기록·기억·친밀도는 유지한다. 캐릭터 관리·JSON 공유의 0.3.0 검증은 [기존 기록](VALIDATION-0.3.0.md), 0.2 기능과 당시 실측은 [제품 사양](PRODUCT.md)과 [0.2 기록](VALIDATION-0.2.0.md)에 보존한다. 과거의 네이티브 관찰·테스트 수·모델 성능을 새 위젯 결과로 재사용하지 않는다.

## 2026-09-19 main 통합 검증

미커밋 상태의 나디르·별꼬리·선택지 스토리·암호화 대본 편집·이름과 아이콘·구조 리팩토링을 원격의 다중 캐릭터·표정 이미지·데스크톱 장난감·모델 목록·updater·Changesets와 통합했다. 앱과 패키지 이름은 `comet`, 원격에서 확정된 `0.4.1` 버전을 유지하며 다음 minor 변경 노트를 추가했다. 아래의 이전 네이티브 관찰은 각 변경 당시 결과로 보존한다.

이번 통합 소스에서 Rust 라이브러리 253개와 대본 CLI 2개, 프런트엔드 18개 파일 109개, 배포 자동화 JavaScript 5개·Python 8개 테스트가 통과했다. 전체 Rust target 컴파일·strict Clippy, TypeScript·oxlint·Vite 빌드, 위키 타입 검사·빌드와 Changesets 검사도 통과했다. source pair·cast와 스토리가 세 번째 자리의 캐릭터 및 자리 변경 후 같은 정체성을 따르는 회귀를 포함한다.

Windows CI에서 Git의 CRLF 변환이 암호화 파일 헤더를 바꾸는 문제가 확인되어 `.gitattributes`에서 `.talk`·`.enc`의 원본 바이트를 보존한다. `core.autocrlf=true`에서도 동봉 파일 28개의 checkout 바이트가 저장소 원본과 동일한 것을 확인했다.

이번 통합에서는 실제 데스크톱 조작·Windows 실기·LLM 의미 품질을 다시 검증하지 않았다. 이전 버전의 테스트 수·패키징·실행 결과를 이번 결과로 간주하지 않는다.

## 0.4 통합 작업본의 기존 검증

2026-09-19 기준 소스 구현과 릴리스 인수는 구분한다. 1~8명 ID 기반 대화, JSON v2 패키지와 v1 호환, 기본 캐릭터 동봉 콘텐츠, 출처 정보 영속 편집, 독립 데스크톱 물체, 장난 FSM, 트레이 직접 호출, 숨김 상태 보존, 서명된 앱 업데이트 경로를 통합했다. 기존 생성 대사의 30분 회상 변경도 원문 기록과 분리해 보존한다. 장난 설정 해제·전체 화면 진입·정리 시 자동 놀이의 대기·재생 중 반응을 취소하며 수동 놀이·타이머·저장된 일지는 유지한다. 자동 말풍선과 표정은 macOS `orderFront`, Windows `SW_SHOWNOACTIVATE`로 표시하고 명시적인 입력창 호출만 포커스를 요청한다.

업데이트 서명 공개키와 CI secret을 설정했으며 두 OS 산출물을 준비하는 workflow를 추가했다. 2026-09-19에 최초 공개 릴리스 v0.5.0을 게시했다. 공식 GitHub 채널을 통한 이전 버전에서 새 버전으로의 설치는 아직 인수하지 않았다. Apple notarization과 Windows Authenticode 서명은 제공하지 않으며 updater 서명과 구별한다.

자동 검사는 Rust 라이브러리 214개와 프론트엔드 16개 파일 103개 테스트, 예제 컴파일, Clippy(`--lib --bins -- -D warnings`), doc-test, TypeScript·정적 검사·프론트엔드 빌드, 위키 타입 검사·빌드를 통과했다.

[GitHub Actions](https://github.com/fleetia/comet/actions/runs/35437429763)에서 macOS arm64·Windows x64의 테스트, native bundle 빌드와 artifact 업로드를 확인했다. 이 결과는 Windows 실기 실행이나 설치 검증을 대신하지 않는다.

설치 파일 workflow 후속 변경은 macOS `.dmg`를 기존 앱 ZIP·Windows NSIS `.exe`와 함께 Actions artifact에 포함한다. [후속 Actions 실행](https://github.com/fleetia/comet/actions/runs/35439148164)에서 두 OS 검사·빌드·업로드가 성공했다. macOS는 앱 서명과 DMG 무결성 검사를 통과했으며, 내려받은 DMG에 0.4.0 arm64 앱과 Applications 바로가기가 포함된 것을 확인했다. Windows 설치 파일 생성은 실기 설치·실행 검증과 구별한다.

태그 기반 Release에도 DMG를 올리고 파일 누락과 무결성 오류를 검사한다. Release 본문과 Actions 실행 요약에는 실제 DMG·EXE 다운로드 링크, 설치 안내와 변경 노트를 함께 제공한다. [v0.5.0 빌드](https://github.com/fleetia/comet/actions/runs/35445568168)는 두 OS 검사·패키징·업로드와 macOS 서명·DMG 무결성 검사를 통과했으나 draft 임시 URL을 거부해 publish job이 실패했다. 해당 draft의 저장소·태그·URL을 대조하는 수정 스크립트로 실제 업로드 파일을 검증하고 manifest와 본문을 생성한 뒤 [v0.5.0](https://github.com/fleetia/comet/releases/tag/v0.5.0)을 수동 공개했다. 두 설치파일의 비로그인 HTTP 200과 공개 manifest의 정식 태그 주소를 확인했다. 배포 자동화 테스트 14개를 통과했으며, 수정 workflow 자체의 원격 실행 성공이나 실제 설치·업데이트 인수로 해석하지 않는다.

Changesets 후속 구현은 변경셋의 main 병합 후 버전 PR을 만들고, 버전 PR 병합 후 서명된 데스크톱 Release workflow를 직접 호출한다. package.json·Tauri·Cargo manifest·lock의 버전을 동기화하고 해당 CHANGELOG 항목을 Release와 앱 updater의 업데이트 노트로 사용한다. 초기 상태·이미 공개한 버전은 발행을 건너뛰며 기존 태그를 다른 커밋으로 옮기지 않는다. 모든 updater 플랫폼 URL을 같은 Release의 공개 다운로드 주소로 정규화한 manifest를 업로드한 뒤 공개한다. 동기화·노트·태그·manifest 검사는 통과했으며 실제 설치·업데이트 인수는 별도로 남는다.

CI 최적화는 branch push·PR의 중복 실행과 문서 변경의 native 빌드를 줄이고, 공통 프론트엔드 검사를 Ubuntu로 옮긴다. main에서 저장한 Rust 의존성·고정 sidecar 캐시를 Verify와 Release가 공유한다. PR에서는 두 OS의 Rust 테스트까지 수행하고, main·수동 실행·Release에서 패키징과 서명/무결성 검사도 수행한다. 실행 조건과 캐시 무효화 기준은 [릴리스 문서](development/releases.md#ci-실행과-캐시)를 따른다. 설정 변경만으로 빌드 시간 단축률이나 Release 설치 인수를 선언하지 않는다.

macOS 별도 QA 앱을 빌드하고 `codesign --verify --deep --strict`를 통과했다. 캐릭터를 숨긴 상태에서 메모를 열고 저장했으며 재시작 후 숨김 값과 설치한 위젯 여섯 개의 보존을 DB에서 확인했다. 최신 native 공 꺼내기는 위젯 관리 화면의 포커스를 바꾸지 않았고, actor ID를 포함한 정지 결과 한 건을 기록했다. 설정에서 장난감 정리와 업데이트 정보 없음 상태, 입력창 포커스와 메뉴 복귀도 확인했다. 별꼬리 v2 파일의 미리보기·설치 후 활성 A/B가 유지됐으며 관리 화면에서 빈 제작자·출처 URL을 저장하고 DB의 빈 문자열을 확인했다. 외부 앱의 입력 포커스, 클릭 통과·드래그·창 충돌, 다중 모니터, 숨김 재시작 후 트레이 직접 호출, Windows 실기와 공식 배포 채널을 통한 두 OS 업데이트 검증은 아직 인수하지 않았다. 전체 완료는 이 실기 조건을 충족한 뒤 판단한다.

별도 macOS 업데이트 QA 앱은 전용 서명 키와 loopback 서버로 0.4.0→0.4.1 설치를 확인했다. 연결 실패·다운로드 404·변조된 파일의 서명 실패에서 기존 0.4.0 실행 파일의 hash가 유지됐다. 정상 파일은 설치 후 이전 프로세스가 종료되고 새 버전에서 업데이트 확인이 다시 실행됐으며, 재실행 화면의 최신 버전 표시와 설치된 앱의 서명을 확인했다. 설치 파일까지 갖춘 최종 fixture에서 캐릭터 3개·팩 1개·표정 이미지 9개·단어장 2개·위젯 6개·메시지 29개·놀이 결과 11개와 검증용 기억·ID별 친밀도 각 1개의 영속 내용을 비교했다. 공·비행기·펫은 사양대로 정지 시각과 revision만 갱신됐다. 위젯 설치 파일의 hash와 여섯 위젯의 활성 상태도 유지됐고, 업데이트 후 실제 메모 창에서 기존 내용을 확인했다.

추가로 QA 앱에서 기존 Qwen3.5-4B 파일을 직접 지정해 앱 소유 `llama-server`를 실행했다. 부모·자식 PID가 살아 있는 상태에서 설치를 시작한 뒤, 자식 추론 프로세스가 먼저 종료되고 이전 앱이 종료되는 순서를 관찰했다. 새 PID로 재시작된 0.4.1 창과 설치 서명도 확인했다. 이 검증은 macOS의 해당 로컬 모델·QA endpoint에 한정되며 공식 GitHub 배포 채널과 Windows 설치 검증은 별도로 남는다.

같은 QA 앱에서 1명 활성 구성의 독백 메뉴와 개인 입력 대상, 8명 활성 구성과 9번째 활성화 차단을 확인했다. 8번째 캐릭터의 실제 얼굴에서 연 입력창은 해당 캐릭터 ID를 따르고 `모두에게` 선택도 동작했다. 최종 소스로 빌드한 앱에서 전체 선택에 맞춰 입력란의 접근성 이름이 바뀌는 것도 확인했다. 이 관찰은 관리 UI와 개별 창·입력 대상 연결에 한정되며 여덟 창을 동시에 확인하거나 LLM 대화를 생성한 결과는 아니다.

별도 대화 QA 앱에서는 기존 Qwen3.5-4B 파일로 8명·2명·1명에게 실제 입력을 보냈다. 각 구성에서 활성 캐릭터 ID마다 한 개씩, 각각 8개·2개·1개의 응답이 `complete`로 기록됐으며 실패 행이나 중복 응답은 없었다. 입력·답변 준비 표시와 완료 후 얼굴 창으로 복귀하는 흐름을 관찰하고 QA 앱과 소유 모델 프로세스를 종료했다. 응답에 반복 경향과 요청보다 긴 두 문장이 나타나, 이 결과를 모델의 의미 품질이나 엄격한 길이 준수의 합격으로 보지는 않는다.

Figma에는 기존 Lagrange 프레임과 글꼴을 유지해 [장난 설정](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=142-578)의 네 장난감 Checkbox·정리 버튼, [업데이트](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=142-642)의 확인·설치 버튼, [1~8명 대화](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=142-765)의 Select와 순차 생성·질문 대기 안내, [출처 저장](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=142-774)의 빈 원작자·출처 URL TextField와 저장 버튼을 반영하고 시각 검증했다. 기존 컴포넌트의 정적 상태를 반영한 범위이며 전체 앱 화면 복제나 작동하는 프로토타입을 뜻하지 않는다.

## 2026-09-19 구조 리팩토링

Tauri 진입점에서 앱 상태·초기화·직접 대화·장면 재생·백그라운드 작업·설정·창 명령을 `src-tauri/src/app/`로 분리했다. 저장 계층의 메시지·회상과 기억·관계, 캐릭터 계층의 검증과 소유 대사를 하위 모듈로 나누고 기존 함수 진입점을 유지했다. 프런트엔드는 설정 초안·모델 설정·기억 편집·말풍선 크기 측정을 각각 분리했다. 상세 파일 책임과 동시성 경계는 [구조와 책임](development/architecture.md)을 따른다.

이번 변경은 제품 동작·화면 배치·명령 이름·저장 schema·데이터 경로를 유지하는 구조 정리다. README는 실행과 탐색의 입구, `docs/development/architecture.md`는 코드 책임의 원본으로 정리했다. 아래 과거 검증 결과는 이 리팩토링의 실행 결과로 재사용하지 않는다.

### 격리된 macOS 앱 검증

현재 소스로 `src-tauri/target/debug/bundle/macos/Comet Refactor QA.app`을 빌드하고 `codesign --verify --deep --strict`를 통과했다. 앱 식별자는 `space.starlight.comet.refactor-qa`이며 새 QA 프로필로 실행했다. 기존 사용자 앱을 교체하지 않았으며 제품용 `comet.app`의 새 패키징 결과로 간주하지 않는다. QA 실행 파일 `Contents/MacOS/comet`의 SHA-256은 `89ac2d7ddc712395b5361febb12644f7fb02fbc59a6f0e73966ffe76a0f92e89`이다.

실제 네이티브 화면에서 위젯 첫 선택을 건너뛰고 A/B의 문자 이모티콘 본체를 확인했다. 설정의 잡담 간격과 로컬 자동 준비 설정 초안이 탭 전환 뒤 유지되고 저장이 성공하는 것을 확인했다. 모델 화면에는 내려받은 모델이 없었으며 QA 데이터에 `models/` 디렉터리도 없었다.

키워드 `안녕`으로 등록 대사를 재생했다. 앞뒤 공백과 빈 줄을 포함한 테스트 원문이 표시됐고, 읽기 전용 QA DB 조회로 저장된 단어장 원문과 A/B 두 응답 기록의 일치를 확인했다. 장면이 끝나면 말풍선이 닫히고 본체만 남았다. QA의 `.talk` 파일 26개는 모두 암호화 형식이었다.

모델 없는 자동 잡담도 확인했다. 관찰 중 약 66.8초 뒤 기본 script의 A/B 대사가 모두 표시·기록됐다. 이 시간은 해당 QA 관찰값이며 고정 재생 간격을 뜻하지 않는다. 별도 단어장 장면에서는 A의 첫 대사가 보인 직후 `이야기 닫기`를 누르고, 이후 DB에 해당 장면의 A만 기록되고 B는 재생·기록되지 않은 것을 확인했다. QA 종료·재시작 전후 기존 메시지 row, 단어장 row와 settings JSON이 동일하게 보존됐다.

캐릭터 관리의 기본 정보 화면에서 이름·소개·표정을 조회했다. 이번 리팩토링에서 대본 에디터의 네이티브 수동 조작은 다시 검증하지 않았다. 로컬 macOS에는 Windows 실행 환경이 없어 Windows 네이티브 설치·실행은 확인하지 못했다. 이 QA 결과는 장시간 자원 사용이나 모델 의미 품질의 보장이 아니다.

### macOS release 패키징

현재 소스로 `src-tauri/target/release/bundle/macos/comet.app`과 `src-tauri/target/release/bundle/dmg/comet_0.3.0_aarch64.dmg`를 생성했다. 제품 앱 식별자를 사용한 산출물이며, 사용자 프로필로 실행하거나 설치하지 않았다. ad-hoc 서명 구성이고 Apple notarization 자격 증명이 없어 notarization은 건너뛰었다. `codesign --verify --deep --strict --verbose=2`로 `llama-server`를 포함한 앱 서명을 검사해 exit 0과 `valid on disk`·`satisfies its Designated Requirement`를 확인했다. `hdiutil verify`도 exit 0과 `VALID`로 DMG 무결성 검사를 통과했다. 이 검증은 notarization이나 제품 앱의 실제 실행을 대신하지 않는다.

### 실제 4B 모델 샘플

기존 Qwen3.5-4B 모델로 의미 동작 샘플을 한 번 실행했다. 검사기는 16개 항목 중 15개를 통과했지만 종료 코드는 1이었다. A의 취향 검사에는 `모두 중요하다고`라는 표현을 잘못 판정한 휴리스틱 문제가 있었다. 이 검사기 결과와 별개로 실제 응답에는 사용자와 나디르의 주체 혼동, 정정 뒤에도 B가 커피와 차를 모두 기억한다고 답하는 문제가 확인됐다. 따라서 이번 샘플은 모델 의미 품질 통과로 기록하지 않는다. 단일 샘플 결과를 전체 대화 품질이나 리팩토링에 의한 품질 변화로 일반화하지 않는다. 기억 원문 근거·저장, 감사 점수 +1, 커피→차 기억 정정, 정정 비감점, 자동 장면 저장·사용자 입력 후 무효화와 종료 후 `local_running_after_stop=false`는 확인했다. 모델 다운로드나 개인 DB 접근은 하지 않았다. 이 smoke는 실제 앱의 공개 단계별 `story::profile`·`prompt_history` 경로 전체를 검증한 결과가 아니다.

## 제품 이름과 아이콘 검증

2026-09-19 이름·아이콘 변경은 TypeScript·oxlint·Vite 빌드, `cargo check --locked --all-targets`, 위키 타입 검사와 Docusaurus 빌드를 통과했다. Rust smoke 예제의 unused/dead-code 경고와 위키의 Node.js 권장 버전 경고는 남아 있다. 제공된 SVG의 다섯 path와 색이 보존됐으며 플랫폼 PNG는 정방형 RGBA다. 브라우저 빌드에는 같은 SVG가 favicon으로 포함된다.

`src-tauri/target/debug/bundle/macos/comet.app`을 빌드하고 `codesign --verify --deep --strict`를 통과했다. `CFBundleName`·`CFBundleDisplayName`·`CFBundleExecutable`은 모두 `comet`이며, bundle의 ICNS는 새 아이콘과 일치한다. 기존 앱 식별자·SQLite 파일명·자격 증명 서비스·암호화 형식은 유지했다. 설치된 앱 교체, 실제 실행 중 Dock·트레이 표시, Windows 설치·실행과 모델 의미 품질은 이번 검증에 포함하지 않는다.

## 트레이 아이콘 검증

2026-09-19 트레이를 `src-tauri/icons/tray.svg` 기반의 흰색 전용 아이콘으로 분리했다. 제공된 다섯 path·흰색 채움과 PNG의 56×56 크기·투명도를 확인했으며 기존 앱 아이콘 파일은 변경하지 않았다. macOS template icon 설정을 적용했다. 원격 `main` 기준의 별도 worktree에서 트레이 변경만 적용한 뒤 `cargo check --locked --all-targets`, 위키 타입 검사·Docusaurus 빌드와 `git diff --check`를 통과했다. Rust smoke 예제의 기존 unused/dead-code 경고는 남아 있다. 트레이 변경 후 실제 메뉴 막대·Windows 트레이 표시와 새 패키징은 미검증이다. Figma는 MCP 호출 한도와 Desktop 앱 부재로 동기화하지 못했다.

트레이 단독 변경의 위 기록은 당시 결과다. 이후 통합 소스의 Rust 검사와 별도 QA 앱 패키징·실행 범위는 [구조 리팩토링 검증](#2026-09-19-구조-리팩토링)에서 확인한다.

## 생성 대사 회상 검증

2026-09-19 변경은 생성 출처와 회상 수명을 원문 기록과 분리한다. LLM 출력을 확정 설정으로 승격하지 않으며, 출처가 없는 과거 기록은 `unknown`으로 남긴다. 직접 대화로 아직 유효한 회상을 연장하되 자동 잡담으로 이전 대사를 연장하지 않는다. 회상 만료는 원문·사용자 기억·친밀도·작성 대본을 보존한다. 자세한 계약과 인수 조건은 [대화와 기억](product/conversation.md#생성-대사의-출처와-회상-수명)을 따른다.

Rust 라이브러리 테스트 179개, production Clippy(`--lib -- -D warnings`), 변경한 Rust 파일의 포맷 검사와 문서 빌드가 통과했다. 만료 시각의 경계, 직접 대화의 연장과 자동 잡담의 비연장, 원문·사용자 기억·관계 보존, 저장 실패 rollback, 과거 출처 마이그레이션, 재시작·시계 역행 뒤 망각 유지, 재생 중 정리 방지와 숨김·일시정지 중 정리, 부분 재시도의 만료 대사 제외를 자동 테스트로 확인했다. 프롬프트는 소개 전달과 최대 프로필·JSON escape 상황의 입력 예산, 긴 소개보다 재시도 질문과 직전 답변을 우선하는 동작도 확인했다.

실제 데스크톱에서 30분을 기다리는 동작과 새 앱 패키징·실행, 모델 대사의 의미 품질은 이번 검증에 포함하지 않았다. 기존 사용자 기억 분석의 AI 호출은 유지한다. 아래 과거 테스트 수와 네이티브 관찰은 이번 변경의 검증 결과가 아니다.

## `.talk` 대본 검증

2026-09-16 Rust 라이브러리 172개·CLI 2개·프론트엔드 83개 테스트와 Clippy·doc-test를 통과했다. 기본 대본은 130개 장면, 검증 fixture는 166개, 공개 변수는 109개다. 의미 있는 상태별 범위는 [기본 대본 범위](development/talk-coverage.md)를 따른다.

실제 macOS에서 모델 없이 22개 기본 위젯 상태의 대본, 실제 사건과 외부 조회, 파일 재로딩·오류 복구, 조합·자리 교환, 입력·숨김·일시정지 중단, 재시작 보존과 자연 자동 수다 교대를 확인했다. 실제 장면 기록과 관찰 방법은 [대본 검증 기록](VALIDATION-TALK.md)에 남긴다. Google·음악 계정 연동과 Windows 실행은 이번 검증에 포함하지 않는다. 이 결과를 기존 UI·위젯 검증 기록의 실측으로 소급 적용하지 않는다.

## 보조 화면 UI 검증

2026-09-15 비위젯 UI 변경 전 테스트 28개를 기준으로, 탭 이동·초안 유지·저장 중 입력 차단·삭제 확인·메뉴 복귀 검증을 보강했다. 2026-09-16 최종 확인에서 `src/__tests__`의 6개 파일 33개 테스트, TypeScript·정적 검사·Vite 빌드를 통과했다.

브라우저 미리보기에서는 설정 760×760, 캐릭터 관리 960×760과 좁은 390×844 화면을 확인했다. 설정·단어장·캐릭터 초안 유지, 저장 실패 후 초안 유지, 변경 취소와 키보드 탭 이동을 확인했다. 말풍선의 입력·기록에서 메뉴 복귀, 입력 초안과 일시정지 상태 표시, 본체 112×88도 확인했다. 실제 저장과 파일 공유는 네이티브 앱 기능이므로 이 브라우저 검증으로 증명하지 않는다. 이번 UI 정리에서는 네이티브 설치물을 다시 빌드하거나 실행하지 않았다.

## 위젯 UI 검증

2026-09-16 위젯 디자인 정리 후 전체 프론트엔드 13개 파일 79개 테스트를 통과했다. 마지막 할 일 설정 요약 보완은 관련 2개 파일 20개 테스트로 다시 확인했다. TypeScript·정적 검사·포맷 검사·Vite 빌드를 통과했다. 관리 탭의 선택 유지, 오류 복구, 수정 취소, 실패 초안 보존과 캘린더 중복 표시를 회귀 검증했다.

브라우저 예시 데이터로 22개 도구를 최소 296×320에서 열어 가로 넘침과 오류 표시가 없는지 확인했다. 관리 화면은 880×760과 최소 560×480, 대표 도구는 360×480에서 확인했다. 할 일의 입력 초점·접힌 기한 오류 복구·선택 설정 요약, 관리 화면의 탭 키보드 이동·설치 선택 유지·확인 필요 필터도 조작했다. Figma에는 관리 화면 두 상태와 대표 도구 배치를 반영했다. 이 검증은 실제 저장·외부 연결·22개 기능의 네이티브 조작을 증명하지 않으며, 위젯 디자인 정리의 최종 소스로 네이티브 앱을 다시 패키징하지 않았다.

## 공통 창 조작 검증

2026-09-16 공통 창 조작 변경은 TypeScript·정적 검사·Vite 빌드와 `cargo check`를 통과했다. 마지막 관련 회귀 검증은 5개 파일 39개 테스트를 통과했으며 제목 드래그와 버튼 분리, 로딩·오류 상태의 닫기, 본체 숨기기와 위젯 닫기 명령을 확인했다. Figma의 기존 설정 화면 헤더에 내부 ×를 반영했다.

별도 프로필 `space.starlight.comet.window-qa`의 macOS 테스트 앱을 빌드하고 `codesign --verify --deep --strict`를 통과했다. 설정·캐릭터 관리·위젯 관리·메모 위젯의 네이티브 제목 표시줄 제거와 내부 × 닫기, 본체 ×의 숨기기와 기존 말풍선 닫기를 실제 앱에서 확인했다. 최신 빌드의 메모 창에서 제목 드래그를 실행하고 더블클릭 후에도 360×480 크기가 유지되는 것을 확인했다. 위젯을 닫고 관리 화면으로 돌아왔을 때 설치·사용 상태가 유지됐다. 이 확인은 별도 테스트 앱의 결과이며 기존 실행 앱 교체, Windows·다중 모니터 검증이나 모델 의미 품질 검증을 포함하지 않는다.

공통 헤더의 후속 변경은 드래그 범위를 창 `(0, 0)`부터 보이는 헤더 하단까지 확장했다. 원점·바깥 여백, 본문·스크롤바 경계, 입력과 열린 대화상자 제외를 포함한 관련 4개 파일 31개 테스트와 TypeScript·정적 검사·Vite 빌드를 통과했다. 별도 `space.starlight.comet.drag-qa` macOS 앱을 빌드·서명 검증한 뒤 위젯 관리의 왼쪽 위 여백 `(12, 12)`에서 드래그를 실행하고 본문 탭 전환과 X 닫기가 유지되는 것을 확인했다. 창 이동 좌표는 별도 계측하지 않았으며 기존 실행 앱은 교체하지 않았다.

확장한 여백에도 드래그와 같은 판정으로 `grab` 커서를 적용했다. 조작 요소·본문으로 이동하거나 스크롤·초점 이동·창 이탈이 발생하면 임시 커서 스타일을 해제한다. 이 커서 변경은 관련 2개 파일 10개 테스트와 TypeScript·정적 검사·Vite 빌드를 통과했다. Figma의 공통 헤더 조작 명세에도 반영했으며, 이번 커서 변경의 네이티브 화면 표시는 별도로 검증하지 않았다.

## 아직 구분해야 할 검증

- 변경별 자동 테스트·정적 검사·패키징 결과는 이 상태표의 해당 절과 연결된 검증 기록에서 확인한다. [위젯 검증 기록](VALIDATION-WIDGETS.md)은 해당 위젯 변경 시점의 결과다.
- macOS 네이티브 실행 결과는 해당 기록의 관찰 칸에 실제 수행한 범위만 적는다.
- Google 실제 계정 OAuth 동의·token 갱신과 Windows 네이티브 설치·실행은 미검증이다.
- 장시간 CPU·메모리·배터리·다중 모니터·접근성 전수 검증과 모델 대사의 의미 품질은 이번 자동 테스트의 증명 범위가 아니다.
- RSS, Todoist·TickTick 원본 대체, Google Calendar 쓰기, Apple EventKit 직접 연결은 구현 범위에서 제외한다.

## 나디르·별꼬리 패키지와 선택지 스토리

2026-09-19 소스 변경은 기존 factory 대사를 나디르·별꼬리로 교체하고, 행동별 변주·위젯 없는 시간/날씨 fallback·친밀도 공개 단계·시간당 선택지 스토리·암호화 대본 에디터를 추가한다. [캐릭터팩](product/characters.md#나디르별꼬리-기본-패키지), [스토리 조건](product/conversation.md#나디르-선택지-스토리), [암호화·편집](product/talk.md#암호화-저장과-에디터)이 현재 계약이다.

사용자 대화 기록·기억·관계·수정한 정의와 대본은 삭제하지 않는다. 위젯 부재·미완료·스토리 닫기·미루기는 감점하지 않는다. 호감도 변동은 선택한 결과에만 적용한다. 일반 대화의 일일 친밀도 한도와 스토리의 선택 보상은 별도로 계산한다.

최종 소스에서 Rust 전체 218개 테스트, 프론트엔드 87개와 대본 CLI 2개 테스트, TypeScript·oxlint·Vite 빌드, `cargo clippy --lib --tests -- -D warnings`, Docusaurus 빌드를 통과했다. `.talk` 144개 장면의 조건별 5변주와 180개 고정 입력, source identity 자리 교환, 공개 단계·중복 보상·취소·절전 제외 업타임, 암호화 손상·revision 충돌·migration을 검증했다. smoke 예제는 컴파일만 했으며 모델 다운로드나 실행은 하지 않았다. 예제의 기존 unused/dead-code 경고가 있어 all-targets의 warnings-as-errors 통과를 뜻하지 않는다.

별도 `space.starlight.comet-nadir-qa` macOS 앱을 패키징하고 서명을 검증했다. 위젯 없이 시작하는 나디르·별꼬리, 캐릭터 관리의 기본 정의, 대본 에디터의 실제 복호화·문법 오류와 초안 보존·다시 불러오기·성공 저장, 선택지 스토리 파일 열기를 조작했다. 저장 후 앱 데이터의 `.talk` 26개와 story 파일이 암호화 envelope인 것도 확인했다. 실제 1시간 대기 후 선택지 출현, Windows 실행, LLM 의미 품질은 미검증이다. 기존 사용자 앱은 교체하지 않았다.

Figma의 [선택지 상태 설계](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=139-576)와 [대본 에디터](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=139-592)를 갱신했다. MCP 호출 한도 이후 브라우저에서 이어 작업했으며 에디터 frame에는 실제 macOS 화면을 참조 이미지로 반영했다.

나디르·별꼬리의 표정 후속 교정은 설명형 문장 대신 기존 A/B의 문자 이모티콘 6종을 사용한다. 이미 설치된 정의도 이전 기본 표정 전체와 일치할 때만 교체하며, 직접 수정한 표정과 이름·대사·관계는 보존한다. 캐릭터 관련 Rust 19개·화면 관련 21개 테스트와 TypeScript·oxlint를 통과했다.
