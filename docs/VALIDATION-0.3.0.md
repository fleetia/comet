# 0.3.0 캐릭터 검증 기록

2026-09-15 macOS Apple Silicon에서 [캐릭터 사양](product/characters.md)을 검증했다. 0.2의 큰 화면 없는 본체·말풍선 구조를 유지하면서 캐릭터 관리와 JSON 공유를 추가했다.

## 코드와 설치 파일

- 프런트엔드 `check`, 테스트 24개, production 빌드 통과.
- Rust 라이브러리 테스트 67개와 전체 target 테스트 통과. 예제에 중복 포함된 모듈 테스트는 개수에 더하지 않았다.
- Production `cargo clippy --lib --bins -- -D warnings` 통과. 예제 target에는 기존 미사용 코드 경고가 남는다.
- 0.3.0 macOS arm64 앱·DMG 빌드, `codesign --verify --deep --strict`, `hdiutil verify` 통과. 로컬용 ad-hoc 서명이며 notarization된 배포본은 아니다.
- Docusaurus 타입 검사와 엄격한 링크 검사를 포함한 빌드 통과.

## 실제 앱에서 확인한 흐름

상세 조작은 식별자를 `space.starlight.comet-character-qa`로 분리한 동일 소스의 debug 앱에서 수행했다. 실제 데이터의 SQLite 백업을 복사했고 테스트 프로필에서 LLM·API 자동 생성을 껐다. 모델 파일은 복사하지 않았다.

| 항목 | 관찰 결과 |
| --- | --- |
| 가져오기 | 네이티브 파일 선택으로 솔·달 예제 JSON을 열어 이름·성격·표정·인사·대사를 미리 보았다. 설치만 했을 때 기존 A/B 배치는 유지됐다. |
| 둘의 적용 | 별도의 적용 버튼을 누른 뒤 A=솔, B=달로 바뀌었다. 기존 기본 캐릭터는 목록에 남았다. |
| 편집 | 솔의 이름을 솔이로, 평온 표정을 느긋함으로 변경하고 앞뒤 공백과 빈 줄이 있는 인사를 저장했다. 버전이 1에서 2로 증가했다. |
| 공유 파일 | 현재 둘을 네이티브 저장 창으로 내보냈다. 정의와 조합 대사·키워드만 포함했으며, 선택하지 않은 개인 단어장 2개와 대화·기억·관계 데이터는 없었다. 수정한 인사·표정과 원래 대사의 공백·줄바꿈·순서를 파일 내용으로 비교했다. |
| 재가져오기 | 내보낸 파일을 다시 열어 미리보기와 설치에 성공했다. 기존 캐릭터를 덮어쓰지 않고 별도 항목으로 추가됐다. |
| 등록 대사 | 모델 없이 `별사탕`을 입력해 A→A→B 세 줄이 재생됐다. 저장된 메시지와 팩의 원문을 비교했으며 솔이의 당시 이름·버전 2가 화자 정보에 기록됐다. |
| 재시작 | 앱 종료·재실행 후 달 본체와 솔이/달 배치가 유지됐다. 메뉴의 수다 실행으로 수정한 여러 줄 인사가 재생됐다. |
| 복사본의 기존 기록 | 검증 전 복사한 대화 159개와 개인 단어장 2개의 모든 행이 설치·편집·공유 후에도 동일했다. |

이후 기존 0.2 프로세스를 정상 종료하고 실제 데이터의 별도 백업을 만든 뒤 **최종 release 앱**을 실행했다. 새 캐릭터 관리 메뉴·편집 화면·가져오기·내보내기 버튼을 확인했다. 이전 대화 173개의 원문 행과 기존 단어장·기억·친밀도 행을 비교해 보존을 확인했고 기본 A/B 배치를 유지했다. 관리창을 닫으면 작은 본체만 남는다.

## 자동 검증이 보완하는 경계

- 캐릭터별 관계 점수, 자리 교환·복귀, 늦게 끝난 분석의 원래 대상, 기존 데이터 이전의 반복 실행.
- 이름 변경 뒤에도 과거 화자 이름·버전 유지, 새 캐릭터에 이전 캐릭터의 대화 문맥 전달 방지.
- 교체 중 재생·생성 취소, 오래된 응답·재시도 차단, 저장 실패 시 배치와 revision의 원자적 복구.
- 개인 단어장 우선, 단독·조합 소유 대사 범위, 자리 교환 시 화자 매핑, 원문·공백·줄바꿈 보존.
- 같은 팩의 중복 설치·복제 후 단어장 ID 충돌 방지와 제작자·배포 조건 보존.
- JSON 필드·버전·크기 검증, 실패한 저장의 기존 파일 보존, 공유 데이터의 허용 목록.
- 편집 초안·저장 오류·중복 적용 방지, 설치와 적용 분리, 선택한 캐릭터의 이름·표정과 과거 이름 표시.

## 남은 범위

Windows 네이티브 파일 창·설치, 다중 모니터, 장시간 CPU·메모리 사용은 검증하지 않았다. 이번 검증에서는 LLM의 캐릭터 성격 반영을 프롬프트 구성·문맥 경계 테스트로 확인했으며 새 캐릭터의 실제 4B/9B 응답 품질 비교는 수행하지 않았다. [0.2 검증](VALIDATION-0.2.0.md)의 모델 관찰을 새 캐릭터 품질 근거로 사용하지 않는다.

이미지·스킨, 온라인 마켓·원격 자동 업데이트, SSP 파일 호환, 22개 선택 위젯과 Widget SDK는 이번 구현에 포함하지 않았다. 관리 화면의 선행 구조와 구현 비교는 [Figma 프레임](https://www.figma.com/design/vKl8h9uoXUUljJ5yEAcNpr?node-id=72-447)에 있다.
