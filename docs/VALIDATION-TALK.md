# 대사 스크립트 검증 기록

2026-09-16에 모듈형 `.talk` 실행 기능과 공식 위젯 대사를 검증했다. 병행 변경이 남아 있는 현재 checkout 전체를 빌드했으며, 이전 [위젯 검증](VALIDATION-WIDGETS.md)이나 0.2·0.3 검증 결과를 이번 실행 결과로 재사용하지 않았다. 문법과 사용법은 [대사 스크립트](product/talk.md), 공개 변수·사건은 [작성 참조](development/talk-reference.md), 입력별 기대 장면은 [분기 검증표](development/talk-coverage.md)를 따른다.

## 빌드와 검증 환경

| 항목 | 이번 실행 |
| --- | --- |
| 소스 | Comet 0.3.0, 현재 작업 checkout의 미커밋 변경 포함 |
| 운영체제·구조 | macOS, Apple Silicon |
| 앱 | `src-tauri/target/debug/bundle/macos/Comet Talk QA.app` |
| 독립 프로필 | `space.starlight.comet.talk-qa` |
| 빌드 종류 | debug `.app`, ad-hoc 서명. 배포·notarization 없음 |
| 실행 파일 SHA-256 | `45875885ec5cc00441143520942f083d63db0845ef269a23718d319ca286bf08` |
| 모델 | 다운로드·추론 프로세스 없이 내장 대사와 `.talk` 사용 |

QA 설정에서 `productName`과 `identifier`를 바꿔 빌드했으며, 실제 사용자 프로필과 분리된 앱 데이터 디렉터리를 사용했다. 공식 22종은 네이티브 UI에서 설치했다. 검증 종료 후 QA 대본의 기본 진입 파일과 삭제 시험 파일을 수동 복구하고 앱을 종료했다.

## 자동 검사

아래 Rust 명령은 `DEVELOPER_DIR=/Library/Developer/CommandLineTools`를 지정해 실행했다. 전역 Xcode 설정은 변경하지 않았다.

| 검사 | 명령·대상 | 결과 |
| --- | --- | --- |
| Rust 전체 | `cargo test --manifest-path src-tauri/Cargo.toml` | lib **172개 통과**, main·doctest 실패 없음 |
| CLI | `cargo test --manifest-path src-tauri/Cargo.toml --example talk` | **2개 통과** |
| Rust lint | `cargo clippy --manifest-path src-tauri/Cargo.toml --lib --bins -- -D warnings` | 통과 |
| 프론트엔드 타입·lint | `corepack pnpm check` | 통과 |
| 프론트엔드 테스트 | `corepack pnpm test` | **13개 파일, 83개 통과** |
| 프론트엔드 빌드 | `corepack pnpm build` | 통과 |
| 네이티브 패키징 | `corepack pnpm tauri build --debug --bundles app --config /tmp/comet-talk-qa.json` | 최신 앱 생성 성공 |
| 서명 검사 | `codesign --verify --deep --strict` | 통과 |
| 변경 공백 검사 | `git diff --check` | 통과 |

번들에는 **26개 `.talk` 파일, 130개 장면, 166개 검증 입력**이 있다. 실제 production parser·evaluator를 통해 모든 입력을 실행했고, 모든 장면에 선택되는 입력이 있는지 확인했다. registry는 **109개 변수와 18개 발생 계기**(`idle`과 사건 17종)를 제공한다. CLI의 검사·변수 출력·고정 seed 모의 실행·잘못된 입력의 실패 코드·캐릭터 ID 출력을 실행했으며, 읽기 전용 DB 실행 전후 파일 해시가 유지됐다.

검증 책임은 다음과 같이 나뉜다.

- 파서: import의 조합 범위·중복·순환·누락·루트 이탈, 원문·주석·위치 정보, 여러 줄과 이스케이프, 변수·조건 타입·화자·표정 진단.
- 컨텍스트: 미설치·비활성·미설정·조회 중·연결 오류·오래된 정보·정상 빈 값의 구분, 비밀정보와 맞히기 정답 제외.
- 번들: 166개 입력과 별도로 실제 저장소에 설치·조작한 위젯의 사건을 기존 큐에서 꺼내 컨텍스트와 장면 선택까지 연결하는 7개 테스트.
- 선택·기록: 조합 우선과 공통 대체, 일반 수다와 교대, cooldown, 준비만 한 장면의 이력 미소비, 첫 표시와 기록의 원자적 저장, 재시작·중복 표시.
- 취소: 참조한 여러 위젯 중 하나의 revision 변경, 대본·캐릭터 교체, 입력·숨김·일시정지·자동 설정 등 10개 무효화 경로. 실제 표시된 줄만 기록되는지 확인.
- 시간 변화: 준비 후 타이머의 남은 시간이 줄어도 같은 조건의 대사는 준비 당시 치환값으로 재생하며, 조건 분기 변경·만료·null 전환은 취소.

## macOS: 공식 22종 대사

각 위젯 파일을 QA 프로필의 진입 파일에서 차례로 import하고 네이티브 메뉴의 **둘이 이야기해 봐**로 재생했다. 기본 위젯 파일의 대사·조건·cooldown은 수정하지 않았다. 각 첫 대사는 접근성 정보로 직접 관측했고, 마지막 줄의 표시 시간을 지난 뒤 저장된 A/B 표시 기록을 대조했다. 모든 줄을 각각 화면 캡처한 시험은 아니다.

| 위젯 | 확인한 상태 | 완료된 장면 |
| --- | --- | --- |
| 할 일 | 등록된 항목 없음 | `todo.empty` |
| 캘린더 | 연결 미설정 | `calendar.unconfigured` |
| 집중 타이머 | 시작 전 | `timer.idle` |
| 준비 봉투 | 봉투 없음 | `preparation.empty` |
| 완료 구슬병 | 완료 구슬 없음 | `jar.empty` |
| 시계 | 기념일 없음 | `clock.no-anniversary` |
| 메모 | 빈 메모 | `memo.empty` |
| 날씨 | 위치 미설정 | `weather.unconfigured` |
| 음악 | 조회 동의 전 | `music.permission-needed` |
| 기기 | 조회 동의 전 | `device.permission-needed` |
| 교감 | 간식 6개 남음 | `interaction.snacks` |
| 공 | 정지 | `ball.still` |
| 종이비행기 | 날리기 전 | `plane.ready` |
| 비눗방울 | 떠 있는 방울 없음 | `bubbles.empty` |
| 작은 승부 | 승부 기록 없음 | `match.new` |
| 맞히기 | 게임 시작 전 | `guessing.idle` |
| 낚시 | 시작 전 | `fishing.idle` |
| 운세 | 오늘 운세 보기 전 | `fortune.fresh` |
| 화분 | 물주기 필요 | `plant.dry` |
| 펫 | 휴식 | `pet.resting` |
| 수집함 | 수집품 없음 | `collection.empty` |
| 관찰 일지 | 기록 없음 | `journal.empty` |

이 표는 각 위젯의 실제 재생 경로를 확인한 결과다. 모든 166개 입력을 실제 UI에서 재현했다는 뜻은 아니다.

## macOS: 실제 조작과 외부 조회

| 조작 | 관측한 결과 |
| --- | --- |
| 주사위 굴리기 | A 5·B 2의 실제 결과로 `match.winner-a`의 두 줄 표시. 원래 사건 문구와 구조화한 `mode`·`outcome` 보존 |
| B 선택 후 간식 주기 | 간식 6→5, `interaction.snack`에서 대상인 B가 먼저 반응하고 A가 이어서 발화 |
| 1분 집중 타이머 | UI에서 60초로 시작하고 실제 경과 후 `timer.finished-focus` 표시·기록 |
| 기기 조회 허용 | 실제 macOS 배터리 24%·방전 상태를 읽어 `device.enough`에서 수치 치환 |
| 서울 날씨 설정 | 공개 위치 검색과 실제 날씨 조회 후 15.5°C·맑음·관측 시각 수신. `weather.mild`에서 기온 치환 |
| 기본 인사와 단어장 | 첫 인사 재생 유지. 사용자 입력 `안녕`이 기존 단어장 답변으로 연결 |

배터리와 날씨 수치는 이 빌드 관측 시점의 값이다. 공개 날씨 조회와 OS 기기 조회를 외부 계정 인증 검증으로 해석하지 않는다.

## macOS: 편집·선택·중단·재시작

이 절은 QA 프로필에만 추가한 짧은 대본과 긴 첫 줄의 취소 시험 대본을 사용했다. 제품 번들에는 시험용 장면을 넣지 않았다.

| 항목 | 관측·근거 |
| --- | --- |
| 여러 파일 편집 | 공통 파일 수정이 저장 후 반영되어 새 문구 표시 |
| import 오류와 복구 | 누락 파일에서 CLI의 파일·행·열 오류 확인. 앱은 마지막 정상 조합 대사를 유지. 파일을 추가한 뒤 수정된 공통 대사가 표시됨 |
| 조합 우선과 cooldown | 기본 A/B 조합 대사 먼저 표시, 30초 cooldown 동안 같은 조건의 공통 대사로 대체 |
| 자리 교환 | 기본 A가 B 슬롯, 기본 B가 A 슬롯에 있을 때 선언한 캐릭터 신원에 따라 대사가 올바른 슬롯으로 재매핑 |
| 다른 캐릭터 ID | UI에서 복제한 캐릭터를 적용하자 기존 조합 파일이 제외되고 공통 장면 선택 |
| 재생 중 대본 교체 | 긴 첫 줄 표시 중 `format: 1`만 있는 정상 빈 진입 파일을 저장하자 말풍선 종료. 남은 두 번째 줄은 기록되지 않음 |
| 입력·일시정지·숨김 | 표시 중 대사를 닫은 뒤 각각 입력, 일시정지·재개, 숨김으로 전환. 이전 장면의 두 번째 줄이 다시 표시·기록되지 않음 |
| 재시작과 이력 | 종료 전의 표시 기록·cooldown 이력 유지. 장면 ID를 유지한 파일 이동 후에도 1시간 cooldown 적용 |
| 삭제 파일 보존 | 사용하지 않는 기본 파일을 삭제하고 재실행해도 자동 복원되지 않음 |
| 입력 없는 자동 교대 | 자동 간격 1분에서 `.talk`의 A/B 두 줄을 표시한 뒤 다음 자동 차례에 일반 내장 A/B 두 줄 표시. 중간 사용자 입력 없음 |

입력·일시정지·숨김의 네이티브 시험은 메뉴 조작을 위해 먼저 표시 중 대사를 닫았다. 따라서 이 세 원인 각각이 재생 중 장면을 직접 취소하는지 분리해 관측한 증거는 아니다. 원인별 취소는 Rust 회귀 테스트로 확인했다. 대본 교체에 의한 직접 취소는 첫 줄 표시 중 관측했다.

자동 교대 시험에서 위젯 첫 줄은 네이티브 접근성 정보로 관측했다. 그 뒤 일반 대사 재생은 실제 표시 때 저장되는 A/B 기록과 시각으로 확인했다. 준비만 한 후보 기록은 이 증거에 포함하지 않았다.

## 위키 검사

문법·변수·사건·분기 검증표와 제품 계약을 저장소 `docs/` 원본에 반영했다. `corepack pnpm docs:check`와 `corepack pnpm docs:build`를 통과했다. 최초 빌드에서 발견한 위키 범위 밖 README 링크는 저장소 파일 안내로 고쳤으며, 깨진 링크 검사 정책은 유지했다.

빌드한 사이트를 `127.0.0.1:3000`에서 실행해 다음을 브라우저로 확인했다.

- 사양 첫 화면 → 대본 제품 문서, 사이드바의 개발 → 문법·변수·CLI 이동.
- 한국어 `대본` 검색에서 새 문서가 검색되고 선택한 결과로 이동.
- 대본 문법·CLI 코드 블록과 표 표시, 166개 분기 검증표로 이동.

실행 환경은 Node.js 26.5.0으로, 위키가 지정한 Node.js 24 범위와 다르다는 engine 경고 및 Node의 localStorage 실험 기능 경고가 있었다. 이 환경에서 타입 검사·빌드는 통과했으며, 권장 Node.js 24로 별도 재실행한 결과는 아니다.

## 미검증 범위

- Windows 앱 빌드·설치·실행, Windows 기기·복귀 관찰.
- Google 캘린더 실제 계정 OAuth, Music·Spotify의 인증·곡 재생 연동. 관련 대사의 상태·사건 입력은 자동 검사 범위다.
- 166개 분기의 네이티브 전수 재현, 모든 중단 원인의 독립적인 UI 재현.
- 장시간 CPU·메모리·배터리 사용량, 다중 모니터와 접근성 전수 검사, LLM 응답의 의미 품질.

편집기 UI, SSP·Yarn 파일 호환, 원격 대본 배포는 이번 구현 범위가 아니다.
