# 캐릭터와 만든 한마디를 간직하고 다시 꺼내는 Comet QA

검증일: 2026-10-20. QA 어시스턴트가 합성 프로필로 실제 바탕화면 캐릭터를 사용한 관찰이다. 사용자의 개인 경험이나 장기 사용을 대필한 기록은 아니다.

## 결론

**함께 만든 숲 이야기를 다이어리에 보관하고, 개인 키워드로 등록해 캐릭터에게 다시 듣는 여정은 성공했다.** 생성된 답변을 일회성 채팅이 아닌 나만의 대사로 만드는 경로가 특히 유용했다. 다만 저장 직후 목적지로 가는 연결, 놓친 짧은 장면의 재발견, 자원이 부족할 때 대화를 안전하게 중단하는 경험은 더 명확해질 여지가 있다.

이 보고서는 [#117의 메모·집중·재개](https://github.com/fleetia/comet/pull/117), [#120의 로컬 Vault 원문 검색](https://github.com/fleetia/comet/pull/120)을 다시 쓰지 않는다. 이번 질문은 **“좋았던 캐릭터의 말을 간직하고 다시 들을 수 있는가, 잠깐 놓친 말은 어디에서 찾는가?”**다. 메모 자료형 구별은 기존 관찰의 연장이지 새 저장 버그가 아니다.

## 대상과 증거의 경계

- 새 여정은 **15:31–16:13 UTC**, 클라우드 Linux X11 네이티브 앱에서 수행했다. Mac·Windows 실기나 웹 미리보기 결과가 아니다.
- 실행 앱은 head `7d737d5fcaadef83324c1d1e2886aa5fe27a9b8b`의 기존 CI 패키지다. 보존한 합성 프로필과 **로그만 추가하는 실행기 래퍼**를 사용했다. 공식 배포판 전체 수용 검증이나 이 문서의 기준 main 실행으로 표현하지 않는다.
- 모델은 계속 같은 공식 **Qwen3.5-4B Q4_K_M** 파일을 사용했다. 모델·프롬프트·분류·라우팅·컨텍스트 설정을 바꾸지 않았다. 외부 제공자 계정이나 실제 개인 자료는 사용하지 않았다.
- 아래 숲 문장은 앞선 **14:17 UTC의 실제 AI 응답**이다. 해당 생성은 래퍼를 붙이기 전 동일 패키지에서 완료됐고, 바탕화면에서 다시 열어 확인했다. 이번 저장과 키워드 재생은 그 답변을 재사용한 것이다.
- 앞선 전체 검증에서 완료한 AI 응답은 **6개**다. 이전 패키지와 실행 환경 우회에서 2개, 위 패키지의 변경 없는 실행에서 3개, 보존 프로필·로그 래퍼 실행에서 1개다. **이번 키워드 재생을 일곱 번째 AI 성공이나 AI 응답 속도로 세지 않는다.**
- 네이티브 화면 확인과 읽기 전용 저장·표시 기록 대조를 함께 사용했다. 개인정보·인증정보·프로필 DB·로그·스크린샷은 이 PR에 첨부하지 않는다.
- 보고서 기준 main은 `fa66b852e6f6fad48b432023b571e608eaa9f198`이다. 인용한 저장·빠른 실행·기록 화면 소스 세 파일은 실행 head와 이 main에서 동일하다.

## 1. 좋은 답변을 저장하고 다시 읽기: 통과, 돌아가는 길은 약함

앞선 색 대화에서 캐릭터는 밤하늘색을, QA 입력은 연두색을 좋아한다고 말했다. 실제 응답은 다음과 같았다.

> 연두색이랑 밤하늘색이 섞이면 은은한 초록빛 밤하늘을 담은 숲이 될 거야! 정말 멋진 조합이지?

지난 대화에서 이 답변의 **남기기 → 메모에 남기기**를 골라 제목 `별꼬리와 만든 밤하늘 숲`으로 저장했다. 성공 안내를 확인한 뒤 **내 다이어리 → 메모**에서 같은 제목을 열어 전체 본문이 정확히 일치함을 확인했다. 저장·재열기는 성공했으며 자료 유실은 없었다.

다시 찾는 과정에서는 빠른 실행에서 제목·‘메모’·‘다이어리’를 검색했지만 저장한 항목 자체로 연결되지 않았다. 빠른 실행의 메모 동작은 새 바탕화면 낱장을 만드는 별도 동작이다. **현재 소스에도 이미 ‘새 메모 꺼내기’, ‘바탕화면 낱장 메모’, 저장한 목록·검색은 다이어리에서 볼 수 있다는 안내가 있다.** 목적지 설명이 어디에도 없다는 주장이 아니다.

남는 마찰은 **대화 저장 성공 화면에서 새 메모로 바로 갈 수 없다는 점**이다. 그 화면은 ‘메모에 저장했어요.’와 ‘대화로 돌아가기’만 제공한다. 저장이 끝난 사용자가 목적지를 기억하고 다른 화면으로 찾아가야 한다.

- **제안 우선순위: 중간.** 성공 안내에서 ‘다이어리에 저장했어요’처럼 목적지를 밝히고 **‘저장한 메모 열기’**를 제공한다. 새 빠른 실행 검색 체계나 두 메모 자료형의 통합보다 작은 변경이다.
- **절충:** 좁은 저장 화면에 동작이 하나 늘어난다. 기존 대화 복귀 경로와 미저장 대화 초안을 유지하면서, 실제 저장한 참조를 열어야 한다.
- **후속 확인 기준:** 저장 직후 정확한 메모로 이동하고 다시 대화로 돌아올 수 있어야 한다. 새 낱장을 만들거나 같은 답변을 중복 저장하지 않아야 한다. 이는 제안의 수용 기준이며 구현·검증 완료 주장이 아니다.

소스: [저장 처리와 성공 화면](https://github.com/fleetia/comet/blob/7d737d5fcaadef83324c1d1e2886aa5fe27a9b8b/apps/comet/src/components/Balloon/ConversationSave.tsx#L201-L260), [이미 존재하는 빠른 실행 안내](https://github.com/fleetia/comet/blob/7d737d5fcaadef83324c1d1e2886aa5fe27a9b8b/apps/comet/src/components/Launcher/search.ts#L134-L170).

## 2. 같은 답변을 나만의 암호로 다시 듣기: 통과

같은 실제 AI 답변에서 **남기기 → 대사로 등록**을 선택했다. 제목과 본문은 그대로 두고 키워드 `밤숲 암호`, 대상 `별꼬리 QA`로 등록했다. ‘개인 단어장에 저장했어요.’를 확인한 뒤 새 바탕화면 대화 입력에 해당 키워드를 보냈다.

**16:13 UTC, 떠 있는 캐릭터 말풍선에 원문 전체가 그대로 나타났다.** 새 모델 실행 없이 저장한 대사를 로컬 재생한 결과다. 단순 보관을 넘어, 마음에 든 말을 캐릭터와의 개인적인 호출어로 만드는 연결이 실제로 동작했다.

등록 화면은 ‘등록한 키워드로 재생해요. 자동 잡담에는 넣지 않아요.’라고 구분한다. [저장 코드](https://github.com/fleetia/comet/blob/7d737d5fcaadef83324c1d1e2886aa5fe27a9b8b/apps/comet/src/components/Balloon/ConversationSave.tsx#L215-L234)도 `useForIdle: false`를 설정한다. 자동 잡담 편입·임의 키워드 우선순위·명시적 AI 요청 우회까지 이번 성공으로 확대하지 않는다.

## 3. 잠깐 놓친 “함께 이야기”를 다시 찾기: 재생 성공, 회수 경로 관찰

수동 **함께 이야기해 봐** 장면은 15:31·15:35의 두 장면에서 **두 참여자의 네이티브 표시 확인 기록**이 있었다. 늦게 찍힌 빈 화면만으로는 이를 볼 수 없었다. 따라서 이 장면들을 무응답·침묵 결함으로 분류하지 않는다. 최초 15:28 호출은 같은 수준의 증거가 없어 통과 사례에 포함하지 않는다.

문제는 약 3초의 짧은 말풍선을 놓친 뒤였다. **지난 대화 → 함께**는 여러 참여자가 있는 사용자 대화 세션을 모으며, 이 짧은 주변 장면을 모으는 화면이 아니다. [현재 필터](https://github.com/fleetia/comet/blob/7d737d5fcaadef83324c1d1e2886aa5fe27a9b8b/apps/comet/src/components/Balloon/ConversationHistoryWindow.tsx#L50-L57)도 세션 참여자 수를 기준으로 한다. 해당 목록에서 장면을 못 찾은 것을 저장 누락·삭제로 해석하지 않는다.

- **제안 우선순위: 중간.** ‘함께’ 기록의 범위를 설명하고, 수동으로 요청한 최근 장면을 다시 볼 작은 경로를 검토한다. 상주 캐릭터와 짧은 말풍선이라는 중심 경험은 유지한다.
- **절충:** 모든 자동 잡담을 사용자 대화에 섞으면 기록이 과밀해지고 대화 이어가기의 의미가 달라진다. 재생할 경우 새 AI 생성이 아닌 기존 장면 재생임을 구분해야 한다.
- **후속 확인 기준:** 짧은 장면을 일부러 놓친 뒤 어디에서 다시 볼지 알 수 있어야 한다. 기존 대화 세션·자동 잡담·수동 장면의 구분과 중단 동작을 보존한다. 회수 UI는 아직 구현하지 않았다.

## 4. 짧은 수수께끼로 놀기: 이 자원 조건에서는 완료하지 못함

새 대화에서 **“오늘은 네가 짧은 수수께끼 하나 내 줘. 정답은 아직 말하지 마.”**를 요청했다. 보조 창을 사용한 뒤의 첫 시도는 모델 로딩에서 6분 넘게 진행하지 못했다. 이후 앱을 정상 기준 상태로 다시 열고, 설정·기록·다이어리 창을 열지 않은 채 한 번만 재시도했다.

그 재시도는 모델 로드 **9.003초**, 입력 1,958토큰 처리 **60.029초**까지 진행했지만 답변 없이 앱이 응답하지 않았다. Escape로 화면 복귀도 확인하지 못했다. 이 수치는 **답변 완료 시간이나 생성 속도가 아니다.**

호스트는 약 **10GB RAM, 스왑 없음**이었으며, 두 멈춤 시점의 가용 메모리는 각각 약 1.1GB였다. 앱과 해당 실행기를 중지한 뒤에는 약 4.3GB가 가용 상태였다. **전체 RAM을 모델에 쓸 수 있는 환경이 아니며, 메모리 누수·커널 OOM·특정 I/O 원인으로 단정할 증거도 없다.** 보조 창을 열지 않은 재시도도 실패했으므로 창 누적만으로 설명하지 않는다.

소유한 시험 앱·실행기를 중지하고 보존 프로필을 다시 열었다. 제출한 입력과 최신 초안은 남았으며, 앞선 저장·개인 대사 재생 같은 비추론 경로는 계속 사용할 수 있었다. 같은 모델 요청을 더 반복하지 않았다.

- **평가 경계:** 이 클라우드 자원 조건에서 지속적인 AI 놀이를 완료하지 못한 신뢰성 관찰이다. 답변이 없으므로 수수께끼 품질을 평가할 수 없다. 모든 기기의 성능이나 모델 자체의 원인으로 일반화하지 않는다.
- **검토 우선순위: 높음.** 지원 자원 조건과 준비 상태를 설명하고, 진행이 멈췄을 때 중단·복구·초안 보존을 사용자가 이해하도록 하는 경로를 먼저 검토한다. 원인을 입증하지 않은 메모리 수정이나 모델·라우팅 변경을 이 보고서에서 제안 구현하지 않는다.

## 별도 확정 버그: 바탕화면 대화 버튼의 대비

이 사용 과정에서 밝은 배경 위 다크 테마의 **이어서 하기 / 함께 이야기해 봐 / 지난 대화** 버튼 글자가 읽기 어려운 현상을 네이티브 화면에서 확인했다. 투명 입력창 위의 반투명 버튼 배경이라는 좁은 소스 원인을 분리하여 [수정 PR #124](https://github.com/fleetia/comet/pull/124), head `cfcd41c86150acc56fc75ae117b8e5ede655ebb7`에서 처리한다.

이 문서에는 수정 코드를 포함하지 않는다. **후속 네이티브 확인:** 같은 정확한 #124 패키지에서 흰 배경 위 활성 버튼의 기본·hover 가독성, 지난 대화 열기, 보존된 키워드의 원문 재생을 확인했다. [수용 기록과 남은 범위](https://github.com/fleetia/comet/pull/124#issuecomment-6296584669)를 구분한다. 눌림 순간의 네이티브 픽셀 캡처·다른 테마 실기 행렬은 미수행이며, 수정 전·후 이미지 파일 첨부와 정확한 Figma 구성 연결도 남아 있다. 계산·컴포넌트 검사를 이 범위의 실기 통과로 대신하거나 #124 전체가 완료됐다고 표현하지 않는다.

## 추가 여정: 내 키워드 고치기와 두 친구의 인사 만들기

**17:17–17:30 UTC**, 정확한 #124 패키지 `cfcd41c86150acc56fc75ae117b8e5ede655ebb7`와 독립 복사한 합성 프로필에서 이어갔다. 앞 절의 실행 패키지·프로필과 구별하며 원래 프로필은 변경하지 않았다.

### 저장 전후가 명확한 키워드 수정: 통과

숲 대사의 본문은 그대로 두고 키워드만 `밤숲 암호`에서 `별빛 숲으로`로 바꿨다. **저장 전** 매칭 테스트에서는 새 문구가 일치하지 않았고, **저장 후**에는 새 문구가 해당 대사와 일치하고 옛 문구는 더 이상 일치하지 않았다. 바탕화면에서 새 키워드를 보내자 원래 숲 문장 전체가 정확히 재생됐다.

[현재 테스트 안내](https://github.com/fleetia/comet/blob/cfcd41c86150acc56fc75ae117b8e5ede655ebb7/apps/comet/src/components/WordbookPanel/WordbookPanel.tsx#L756-L758)는 저장된 활성 항목만 사용하고 미저장 수정·대사 재생·AI 호출은 포함하지 않는다고 설명한다. **수정한 내용과 실제 저장된 내용을 구별하며 AI 없이 확인하는 경로**가 잘 동작했다.

### 두 화자 대사: 재생 통과, 매칭과 수신 범위는 구별 필요

제목 `별빛 정리 인사`, 키워드 `오늘의 별빛 정리`로 직접 쓴 두 줄을 등록했다. 활성 상태는 켜고 자동 잡담 사용은 껐다.

1. 별꼬리 QA: “오늘 만든 이야기는 여기 잘 간직해 둘게.”
2. 두 번째 친구: “내일은 다른 색의 숲에서 다시 만나자.”

처음 한 친구에게만 이 키워드를 보냈을 때는 등록 대사가 아닌 **로컬 실행기 경로로 넘어가 즉시 실행기 종료 오류**가 났다. 의도한 AI 시험이 아니었지만 실행기 시도 자체는 있었다. AI 답변은 없었고, 제출 문구가 초안으로 복원됐다. Escape로 1인 대화를 멈춘 뒤에도 초안이 남았다. 이를 새로운 백엔드 결함이나 앞 절의 장시간 자원 멈춤을 재현한 결과로 세지 않는다.

이후 새 빠른 실행 입력에서 **‘모두에게 · 2명 말 걸기’와 두 친구 이름**을 확인하고 같은 키워드를 보냈다. 두 문장이 지정한 화자·순서대로 실제 말풍선에 나타났고, **17:27:59와 17:28:03 UTC**의 네이티브 표시 기록으로 대조했다. 직접 작성한 로컬 대사 재생이며 새 AI 응답이 아니다.

소스상 [1인 수신에서는 다른 화자가 섞인 장면을 키워드 매칭 전에 제외](https://github.com/fleetia/comet/blob/cfcd41c86150acc56fc75ae117b8e5ede655ebb7/apps/comet/src-tauri/src/app/conversation.rs#L49-L85)하며, [기존 회귀 테스트](https://github.com/fleetia/comet/blob/cfcd41c86150acc56fc75ae117b8e5ede655ebb7/apps/comet/src-tauri/src/app/tests.rs#L1217-L1239)도 이를 보호한다. 반면 [설정의 매칭 시험](https://github.com/fleetia/comet/blob/cfcd41c86150acc56fc75ae117b8e5ede655ebb7/apps/comet/src-tauri/src/app/settings.rs#L17-L25)은 수신 대상 없이 키워드를 확인한다. 따라서 매칭 시험의 성공이 모든 수신 범위에서 같은 장면이 재생된다는 보장은 아니다.

또한 소스 검토에서, [빠른 실행 전송](https://github.com/fleetia/comet/blob/cfcd41c86150acc56fc75ae117b8e5ede655ebb7/apps/comet/src-tauri/src/app/launcher.rs#L588-L608)의 ‘모두에게’가 항상 새 대화를 만드는 것은 아니며 **이미 사용자 입력이 있는 대화에서는 처음 참여자를 유지**함을 확인했다. 이는 이번 새 대화의 두 화자 재생과 별개의 [기존 대화 계약](https://github.com/fleetia/comet/blob/cfcd41c86150acc56fc75ae117b8e5ede655ebb7/apps/comet/src-tauri/src/app/conversation.rs#L1785-L1813)이다. 해당 기존 대화 조합을 모두 실기로 시험했다는 뜻은 아니다.

- **제안 우선순위: 중간.** 매칭 시험은 ‘키워드만 확인’한다는 범위와 여러 화자 대사의 수신 조건을 설명한다. 빠른 실행에서는 새 대화의 전체 친구와 기존 대화 이어가기의 참여자를 구분해 안내한다. 의도된 수신 필터를 풀거나 기존 대화에 친구를 몰래 추가하는 변경은 제안하지 않는다. **라우팅 버그가 아니라 시험·수신 범위를 이해하는 UX 관찰**이다.
- **별도 관찰:** 예상하지 못한 오류에서 연한 주황색 오류 글자가 흰 배경 위에 바로 놓여 읽기 어려웠다. #124의 버튼 대비 수정에 포함되지 않는 별도 대상이며, 이 문서에서 수정 완료를 주장하지 않는다.
- **보존·한계:** 17:30 UTC 정상 종료 뒤 프로필의 SQLite 무결성을 확인했다. 앞선 실제 AI 완료 수는 여전히 **6개**다. 모델·분류·라우팅 변경은 없고, 이 추가 문서 작업에서도 앱 실행·모델 요청을 새로 수행하지 않았다.

## 검증 범위와 변경 원칙

- **실제 통과:** 동일 AI 답변의 다이어리 저장·정확한 재열기, 개인 키워드 등록·정확한 바탕화면 로컬 재생, 증거가 있는 두 수동 장면의 표시, 멈춤 뒤 보존된 입력·프로필 확인.
- **미완료·미검증:** 수수께끼 응답, 놓친 주변 장면의 사용자용 회수 경로, 장문 응답 가독성, 실제 한국어 IME 조합, Mac·Windows 실기, 다른 RAM·GPU 조건, 장시간 안정성, 제안의 개선 효과.
- **문서만 변경:** 앱·디자인시스템·Figma·저장 형식·AGENTS.md·모델·분류·라우팅은 바꾸지 않는다. UI 구현이 없으므로 이 PR에서 디자인 동기화를 수행했다고 주장하지 않는다.
- QA 보고서 PR을 허용한 사용자의 명시적 예외 범위다. 다른 문서의 Fleet 단일 원본 원칙을 해제하거나 Fleet 동기화 완료를 주장하지 않는다.
- 내용·중복·고정 소스 링크·포맷·단일 파일 변경만 검사한다. 문서 작성을 위해 앱 빌드·모델 실행을 추가하지 않는다. 게시 후 CI는 문서 커밋의 검사이며, 제품 제안 구현이나 모든 플랫폼의 실제 수용을 뜻하지 않는다. **Draft로 게시하며 병합·배포하지 않는다.**
