# Comet v0.18.0 Linux 실제 사용 QA

검증일: 2026-10-20. 앱 코드 변경 없이 공식 배포판을 직접 조작했다.

## 대상과 한계

- [공식 v0.18.0 릴리스](https://github.com/fleetia/comet/releases/tag/v0.18.0)
- 태그 커밋: `caa588949a6599f6c4295159beb3d71508c79769`
- 실행 파일: `comet_0.18.0_amd64.deb`
- SHA-256: `c965551595c95c269f6427343309af778a3754a8154c8a848aeabc096ca3a719`. GitHub release asset의 digest와 일치했다.
- 일반 설정에서도 버전 0.18.0을 확인했다.
- 클라우드 Linux X11, 화면 1364×1024. 사용자 Mac이 아니다.
- 공식 .deb를 추출하고, 검증된 Debian 런타임을 읽기 전용으로 결합하여 격리 실행했다. 시스템 설치나 WebKit sandbox 해제는 하지 않았다. 일반 Linux 설치 환경 전체에 대한 보증은 아니다.
- 이전 0.16.0 실행을 종료한 뒤 새 바이너리와 새 QA 데이터로 시작했다. 재시작 시험만 같은 QA 데이터를 재사용했다.
- 합성 이름·문장·할 일만 사용했다. 분석 수집은 꺼진 상태를 유지했다. 계정 로그인, API 연결, 모델 다운로드·구매는 하지 않았다.
- 화면은 실제 캡처하여 검토했지만 공유 가능한 이미지 파일로 확보하지 못했다. 이 보고서에 스크린샷 첨부가 있다는 의미는 아니다.
- 조작 도구와 클라우드 렌더 지연을 제품 성능 수치 또는 성능 결함으로 계산하지 않았다.

## 요약

확인한 범위에서 심각한 충돌이나 데이터 유실은 없었다. 오프라인 키워드 대화와 할 일의 완료 취소·편집 취소가 동작했다. 우선 개선 대상은 대화 재개의 비활성 상태와 실패 상태를 사용자가 바로 이해하게 만드는 것이다. 아래 우선순위는 제품 결함의 확정 심각도가 아니라 개선 검토 순서다.

## 검증된 사용성 개선점

### QA-018-01 — 지난 대화의 비활성 입력창이 입력 가능한 것처럼 보임

**우선순위: 중간 / 분류: 사용성, 기능 회귀로 단정하지 않음**

1. 기존 대화를 지난 대화 창에서 연다.
2. 하단의 캐릭터에게 이어서 말하기 입력창을 클릭하고 글자를 입력한다.
3. 위쪽의 별도 ‘이어서 말하기’ 버튼을 누른 뒤 다시 시도한다.

재개 전에는 입력이 반영되지 않았다. 입력창과 보내기 화살표가 보여서 사용자는 입력할 수 있다고 생각하기 쉽다. 실제 전경 창과 데스크톱 화면을 재확인한 뒤에도 같은 결과였다. 저장소의 ConversationHistoryWindow 테스트에도 재개 전 disabled 상태가 명시되어 있어, 의도된 상태 전환을 사용자가 이해하기 어려운 문제로 분류한다.

**제안:** 비활성 placeholder를 ‘이어서 말하기를 눌러 대화를 재개하세요’로 바꾸고 보내기 버튼도 명확하게 비활성화한다. 입력창 클릭 시 재개 안내 또는 명시적인 재개 동작을 제공하는 방안도 검토한다.

**확인 기준:** 처음 방문한 사용자가 입력되지 않는 이유를 알 수 있고, 재개 전후 상태가 시각적으로 구별되어야 한다. 기존 대화 선택·초안 보존 계약은 유지한다.

### QA-018-02 — 실패한 응답의 상태가 기록 첫 진입 시 숨겨짐

**우선순위: 중간 / 분류: 사용성**

1. 모델을 준비하지 않은 상태에서 자유 입력 ‘hello QA 018’을 보낸다.
2. 바탕화면 입력 아래의 로컬 모델 다운로드 안내를 확인한다.
3. 지난 대화를 연다.
4. ‘이어서 말하기’를 누른다.

첫 진입에는 사용자 메시지만 보였다. 재개한 뒤에야 마지막 답변을 마치지 못했다는 안내와 다시 이야기하기·입력 수정·AI 연결 확인이 나타났다. 이전 실패 이유를 놓친 사용자는 기록만 보고 답이 오지 않은 이유를 알기 어렵다.

복구 기능 자체는 동작했다. 입력 수정으로 원문을 불러온 뒤 합성 키워드로 바꾸자 모델 없이 정상 응답했다. 원문 보존 문제로 보고하지 않는다.

**제안:** 재개 여부와 무관하게 해당 턴에 미완료 상태와 준비되지 않은 연결 상태를 표시한다. 오류 가시성과 편집 권한 활성화를 분리한다.

**확인 기준:** 기록 첫 진입, 다시 열기, 재시작 이후에도 실패한 턴의 상태가 바로 보이고, 재시도·수정으로 성공하면 해소된다.

### QA-018-03 — 밝은 테마의 바탕화면 메뉴와 오류 안내 대비

**우선순위: 낮음 / 분류: 시각적 사용성, 현재 Linux 환경 관찰**

방사형 메뉴의 짙은 한글과 두꺼운 짙은 외곽선이 겹쳐 작은 글자가 뭉개져 보였다. 모델 미준비 안내는 바탕화면 위 작은 주황색 글자여서 놓치기 쉬웠다.

**제안:** 테마별 글자 외곽선과 대비를 조정하고, 실패 안내는 불투명 표면 및 ‘AI 연결 열기’ 같은 직접적인 다음 행동과 함께 제공한다. 밝고 어두운 다양한 배경에서 별도로 확인한다.

### QA-018-04 — 빈 할 일의 검증 오류가 저장 장애처럼 안내됨

**우선순위: 낮음 / 분류: 오류 문구 사용성**

할 일 빠른 입력에 공백 세 개를 넣고 Enter를 누르면 ‘title 길이가 올바르지 않습니다.’와 ‘저장을 확인하지 못했어요. 입력을 유지했으니 확인한 뒤 다시 제출해 주세요.’가 표시됐다. 빈 항목은 생성되지 않았고, 입력을 정상 제목으로 고쳐 제출하면 오류가 사라지고 항목 하나가 만들어졌다. 연속 Enter 두 번으로 중복 항목이 생기지도 않았다.

입력 검증은 정상이다. 다만 필드 내부 이름 title과 저장 여부 불명확 안내 대신 ‘할 일 제목을 입력해 주세요’처럼 수정 방법을 바로 알려주는 문구를 제안한다. 데이터 유실이나 실제 저장 장애로 보고하지 않는다.

## 확인된 낮은 심각도 버그: 플랫폼 이름

Linux의 **설정 → 위젯 → 캘린더 → comet에서 저장한 일정**에서 ‘이 Mac에만 저장돼요’가 표시됐다. 플랫폼과 무관한 지역 일정 설명에 Mac이 고정되어 있는 문구 결함이다. [수정 draft PR #110](https://github.com/fleetia/comet/pull/110)에서 ‘이 기기에만 저장돼요’로 바꾸고 회귀 테스트를 추가했다. Apple 연결 전용 문구는 바꾸지 않았다.

발견은 공식 Linux 배포판에서, 수정 후 화면 확인은 별도 소스 웹 미리보기에서 수행했다. 수정된 네이티브 배포판을 실행했다고 주장하지 않는다. 이 QA 문서 PR 자체는 앱 코드를 변경하지 않는다.

## 캐릭터 표시와 이동: 플랫폼 제약 및 오탐 정정

숨기기와 복원은 성공했다. 복원 경로는 **설정 → 일반 → 바탕화면 친구 → 친구 표시**였다. 친구 목록의 ‘말 걸기’만으로 복원된다고 확인하지는 못했다.

데스크톱 자동화 과정에서 본체가 (0,0), 표정 창이 (1244,838)에 있는 상태를 관찰했다. 이후 태그 소스를 확인한 결과, **표정 창은 독립적으로 배치·이동하는 별도 창이므로 본체와 다른 위치인 것 자체는 동기화 버그가 아니다.** 최초 위치 변화의 원인은 입증되지 않았으며 회귀로 주장하지 않는다.

또한 일반 드래그는 쓰다듬기이며, 이동은 Ctrl/Meta 드래그 또는 이동 메뉴로 요청한다. v0.18.0의 Linux에서는 native_handle이 None을 반환하므로 이동 요청이 위치 세션 시작 전에 지원하지 않는 운영체제 오류로 거절된다. Ctrl 드래그로 실제 위치 이동을 확인하지 못한 관찰과 일치하지만, 화면에서 오류 문구를 포착했다고 주장하지는 않는다.

근거는 태그의 [gestures.rs](https://github.com/fleetia/comet/blob/caa588949a6599f6c4295159beb3d71508c79769/apps/comet/src-tauri/src/characters/gestures.rs), [useCharacterGestures.ts](https://github.com/fleetia/comet/blob/caa588949a6599f6c4295159beb3d71508c79769/apps/comet/src/hooks/useCharacterGestures.ts), [desktop.rs](https://github.com/fleetia/comet/blob/caa588949a6599f6c4295159beb3d71508c79769/apps/comet/src-tauri/src/desktop.rs) 및 FaceTag의 독립 창 이동 처리다. Linux 이동 미지원은 플랫폼 제약으로 분류하고, macOS/Windows의 드래그 또는 재시작 후 위치 보존까지 검증한 것으로 세지 않는다.

## 추가 수행: 오프라인 위젯·설정·중단 및 정상 종료

- **집중 타이머:** 활성화와 바탕화면 배치, 합성 1분 세션 시작, 00:47 일시 정지, 접기·다시 열기 후 00:47 유지, 재개 후 완료와 자동 휴식 전환을 확인했다. ‘오늘은 여기까지’로 준비 상태로 돌아왔다. 기록 화면에서 1분/1회 완료 및 제목을 확인했고, 아래 기록은 스크롤하여 접근할 수 있었다. 2분 세션의 조기 중단도 준비 상태로 복귀했다. 0분 입력에는 시작 버튼이 비활성화됐다. OS 알림 대신 앱 말풍선만 선택했다.
- **메모:** 두 줄 합성 메모 자동 저장 후 데스크톱 Alt+F4로 창을 닫았다. 위젯 목록 화살표는 새 빈 메모를 만드는 동작이었다. 이를 데이터 유실로 오인하지 않도록 읽기 전용 저장 데이터와 소스를 확인했다. **내 다이어리 → 메모 → 모든 메모**에서 원문을 찾고 제목을 붙인 뒤 바탕화면에 다시 꺼내는 흐름을 실제 확인했다.
- **테마:** 다크 모드로 전환했을 때 설정, 다이어리, 바탕화면 위젯 및 표정에 반영됐다.
- **로컬 캘린더:** 외부 연결 없이 이 기기에 저장하는 합성 일정, 위치, 메모를 만들고 월 보기와 상세에서 확인했다. 편집 중 제목을 바꾸고 Escape를 누르면 미저장 변경 안내가 나왔다. 변경 버리기로 닫은 뒤 원래 제목이 유지됐다.
- **습관:** 알림 시간을 비운 합성 습관을 만들었다. 오늘 상태를 완료 → 못함 → 아직으로 바꾸자 횟수와 연속 기록 표시가 함께 갱신됐다. 보관 → 보관한 습관 보기 → 다시 시작으로 복구했으며 영구 삭제는 하지 않았다.
- **할 일 경계 입력:** 공백만 제출은 거절됐고, 정상 제목 수정 후 연속 Enter에도 항목 하나만 생겼다. 오류 문구 개선점은 QA-018-04에 분리했다.
- **정상 종료와 복원:** 설정 → 일반 → 종료로 모든 Comet 창이 닫힌 것을 확인한 뒤 같은 공식 바이너리와 QA 프로필로 재실행했다. 다크 테마, 바탕화면 할 일·집중 타이머, 캐릭터 표시가 복원됐다. 다이어리에서 할 일, 로컬 일정, 활성 습관과 알림 꺼짐, 메모 제목·두 줄 본문을 다시 확인했다.

이는 첫 번째 터미널 중단 재시작 시험에 추가한 별도 정상 종료 시험이다. 활성 타이머 실행 도중 앱을 종료하는 시험이나 모든 환경에서의 복원을 검증했다는 의미는 아니다.

## 범위 밖과 플랫폼 한계

- 실제 LLM 답변 품질, API·ChatGPT 로그인, 외부 캘린더 연결, 모델 다운로드 및 결제.
- 캐릭터 파일 가져오기·내보내기, 전체 위젯 21종, 다중 모니터, macOS/Windows.
- 정상 드래그와 위치 저장은 미검증.
- Linux 자동 시작은 일반 설정에서 macOS와 Windows 지원으로 안내됐다. 이를 회귀로 보고하지 않는다.
- 업데이트 서버 연결 실패 안내가 보였으나 클라우드 네트워크·실행 환경 영향을 분리하지 못했다. 업데이트 기능 결함으로 확정하지 않는다.
- 이 보고서는 현재 배포판을 손으로 조작한 QA다. 자동 테스트 전체 실행, 소스 빌드, 일반 설치 검증 또는 이전 버전과의 체계적 회귀 비교를 수행했다는 뜻이 아니다.

## 변경 범위

이 보고서 한 파일만 추가한다. 앱 코드, 디자인시스템, Figma, 설정 계약은 수정하지 않는다. UI 변경이 없으므로 수정 전·후 비교 스크린샷도 없다. 기존 Fleet 단일 원본 규칙에 대해 사용자가 QA 보고서 PR 게시를 별도로 허용한 범위의 문서다. 저장소 전체 문서 정책을 바꾸는 제안은 아니다.
